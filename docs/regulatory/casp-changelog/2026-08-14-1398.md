# #1398 — Hosted X-PAYMENT Relay Preflight

Hosted `haven_settle_mcp_tool` now validates an untrusted, bounded signed
`X-PAYMENT` header against the persisted, agent-scoped x402 intent — including
the delegate captured when the intent was created — before it relays the
separate funding signature. Malformed, unsupported, expired, or mismatched
headers fail closed with a value-free error: neither funding nor the merchant
retry is relayed. The preflight neither stores keys, alters the signed intent,
nor treats API credentials as payment authority; it is not a substitute for
the merchant/facilitator's independent final verification. Real v1/v2 header
tests and material-field mutations prove the no-relay boundary. Perimeter
unchanged.
