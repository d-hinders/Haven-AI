- **#1400** — agent-scoped batch revocation: one owner signature disables every pending and active budget delegation an agent holds. `POST /agents/:id/delegations/revoke-all` (+ `/submit`) mirrors the existing per-hash revoke exactly — same authority rules reused (`loadOwnedDelegationAgent` owner scoping, `loadHybridOwnerConfig` signer reconstruction, `resolveSignatureScheme` passkey/EOA branch, `buildRevocation` per delegation) — with one new mechanic: the `disableDelegation` calls are batched into a SINGLE sponsored treasury UserOp (`prepareCalls`), so stopping an agent with N budgets is one deliberate signed act instead of N. The OWNER signs (WebAuthn or EIP-712 typed data verbatim — never a bare hash, the #829 rule); Haven prepares and relays but signs nothing. Fail-closed ordering: the DB rows flip to `revoked` ONLY after the UserOp lands (a failed submit leaves every row untouched — no optimistic revocation); the batch UPDATE is one statement, agent-scoped (a stray hash from another agent flips nothing, real-DB tested) and status-predicated (re-runs are no-ops). Custody boundaries unchanged: `delegation_json` is never returned (#824 §3), vendor errors pass through `safeDetails` so bundler credentials never reach responses, an empty batch refuses with 409 rather than submitting an empty UserOp, and non-delegation-rail agents are refused (the AllowanceModule teardown remains its own path). Net effect: revocation — the sole authority-ending act — becomes MORE reachable (one signature instead of N) without changing what it does. Perimeter unchanged.
