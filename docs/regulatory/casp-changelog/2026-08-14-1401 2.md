- **#1401** — agent removal becomes a soft ARCHIVE; hard deletion is retired. `DELETE /agents/:id` previously hard-deleted the agent row: it failed with a 500 on any agent that had payment history (payment_intents/approval_requests reference agents(id) with no ON DELETE clause), and where it succeeded it silently CASCADED AWAY seven tables of money-path audit trail (tool invocations, payment evidence, reconciliation events, delegate sweeps, delegations, allowances, passports) — destroying the record of what an agent was authorised to do and what it did. Now: `POST /agents/:id/archive` (migration 060, `agents.archived_at`) requires `status='revoked'` — archiving is a filing action and can NEVER be the thing that stops spending; revocation remains the sole authority-ending act, unchanged. The agent row and every dependent audit row remain and stay reachable by their existing reads (real-DB tested). `POST /agents/:id/unarchive` clears the flag and restores no authority of any kind (status stays revoked). `DELETE` is a 410 tombstone that touches nothing (characterization-tested: zero queries). An archived agent's API key still cannot authenticate — the agentAuth positive allow-list (active/paused) already excludes it by construction, now pinned with an explicit test. Net effect: the audit-trail guarantee is STRENGTHENED (deletion of money-path history is no longer possible through any route), no payment authority, custody, or spend path changes. Perimeter narrowed, not widened.
