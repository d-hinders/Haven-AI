- **#1402 (frontend)** — "Remove agent" becomes ONE user action with three ordered effects: (1) revoke every budget delegation on-chain in a single signed UserOp (the #1400 batch endpoint — the owner signs; Haven never signs), (2) revoke the agent credential (`POST /agents/:id/revoke`), (3) archive the row (#1401 `POST /agents/:id/archive`). Fail-closed ordering is the safety property: the on-chain budget dies FIRST, and a rejected or failed signature aborts the whole flow with "the agent was not removed" — no path can produce a dead credential next to a live spending authority, and no path can produce the inverse (an archived-but-spendable agent) because archive requires status='revoked' server-side (409 otherwise). Partial failure is honest and retryable: budgets dead but filing unfinished leaves the agent visible as revoked in the primary list, and a retry treats the batch endpoint's 409 "Nothing to revoke" as step-1-already-done. Nothing is deleted — "Removed" is a list placement keyed off `archived_at`; every payment record and audit row stays readable, and "Restore to list" restores placement only, never spending authority. The pre-remove delegate-balance warning (#1403) is information, never a gate: a failed read degrades to no warning and cannot block the user from ending an agent's authority. Perimeter unchanged: all spend-authority changes remain owner-signed and on-chain-enforced.
