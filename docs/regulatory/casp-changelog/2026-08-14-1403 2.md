- **#1403 (backend half)** — the delegate-balance read becomes status-agnostic. `GET /agents/:id/delegate-balance` previously resolved agents through the one status-scoped read (`a.status != 'revoked'`), so the moment a user revoked an agent the endpoint 404'd and the sweep page it backs became unreachable — removing the recovery UI in exactly the sequence that strands delegate funds (agent misbehaving mid-x402 → user revokes → transient EOA balance stranded). Now the read resolves revoked and archived agents like any other: it is an owner-scoped, tenant-filtered READ of a public on-chain balance and grants nothing — no payment authority, no signing, no state change. Revocation semantics are untouched (agentAuth still rejects revoked/archived keys; nothing re-enables spending). The old narrow SQL form is retired outright (no remaining callers); a regression test pins that a revoked agent still gets a 200 balance, and a tripwire test refuses any future re-addition of a status filter to this read. Net effect: the sweep/reconciliation guarantee for stranded delegate balances (the CLAUDE.md hot-wallet-minimization discipline) becomes reachable when it is actually needed. Perimeter unchanged.
