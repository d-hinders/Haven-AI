- **#1423** — revoke-all hardening, both #1400-review follow-ups closed. Determination first: `DelegationManager.disableDelegation` is NOT idempotent — the pinned ABI carries an `AlreadyDisabled` custom error — so a crash-window orphan (delegation disabled on-chain, DB row stale-active after a process death between UserOp landing and the UPDATE) bundled into the atomic `BatchDefault` batch would revert the entire retry and jam the one-signature stop path. The prepare step now reads the manager's own `disabledDelegations(bytes32)` view for every candidate hash, heals already-disabled rows to `revoked` (recording what the chain already enforces — authority narrows or stays, never widens), and drops them from the batch; if every candidate was already disabled the route 409s "Nothing to revoke" AFTER healing, which is exactly the step-already-done signal the #1402 retry flow consumes. Availability over blocking: a failed RPC read degrades to the pre-#1423 full batch (worst case the old loud 502, mutation-proven: severing the drop-filter fails the heal tests). Because a heal marks a row revoked WITHOUT an owner signature, the dangerous direction is a FALSE positive (kill switch defeated while every surface says "revoked") — guarded three ways: reads pinned to `finalized` (no reorg transients), disabled counts only when two consecutive reads agree (unit-pinned: a true-then-false flip-flop confirms nothing), and every heal logs distinctly from an owner-signed revoke; a persistently lying RPC stays outside the threat model, as it already sits under gas estimation and submission on this rail. The per-hash revoke route gets the same guard (heal + 409 "Already revoked … reconciled" instead of an eternal 502 on its own orphan), and a coarse pre-read ceiling (100) refuses before any RPC spend for pathological agents. Second: batches are capped at 25 `disableDelegation` calls — past it a 422 names per-hash revocation as the escape hatch, so a pathological agent can no longer construct a doomed mega-UserOp (gas/payload limits) through this route. No new authority anywhere: the reconciliation write only records on-chain state, the owner still signs every batch, Haven still cannot sign, and the per-hash route is unchanged. Perimeter unchanged.
