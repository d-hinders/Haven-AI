- **#1452** — the SDK learns to sign the erc7710 x402 settlement child (`sign_data.signature_scheme = 'eip712_delegation'`), which it previously refused with "refusing to guess a signing scheme". This grants the agent's delegate key no authority it did not already hold: the child delegation is BUILT BY THE BACKEND (`buildSettlementDelegation`) with its bounds already fixed — exact amount, payee pin, expiry clamped to `MAX_SETTLEMENT_WINDOW_SECONDS`, and the #1058 redeemer pin — and every one of those is a caveat enforced ON-CHAIN by the DelegationManager during redemption, not by anything the client does. The SDK's role is narrower than the name suggests: it signs the backend's typed data VERBATIM and never reconstructs it, so it cannot widen a bound it did not compute. What changes is reachability, not power — before this, only a bespoke client written against the raw API could complete an erc7710 settlement; a Haven SDK user could not. Fail-closed posture preserved and tightened: an unknown scheme still throws, `eip191_userop` still throws the retired-rail error, absent scheme still takes the legacy AllowanceModule path, and `eip712_delegation` WITHOUT `typed_data` throws rather than falling back to signing the bare hash — the #829 lesson, which matters more here than on the UserOp path because a settlement signed over the wrong payload is rejected at redemption, after the agent has already told the merchant it paid. The signing test runs against a REAL `buildSettlementDelegation` payload (committed fixture) rather than a hand-written object, with a backend-side guard that fails if the payload's domain, types, primaryType or message keys drift from it — a hand-written fixture that drifted would let a broken signer pass CI and fail on-chain. Mutation-proven both ways: making the branch fall through to `signHash` fails two dispatch tests, and altering the fixture's domain fails the drift guard. No new route, no new credential scope, no key material moved — the delegate key stays where it was, and hosted Haven still never receives it. Perimeter unchanged.
