- **#1456 (SDK half)** — `HavenClient.settleX402Erc7710()` is decomposed into `prepareX402Erc7710()` (authorize: select the scheme, shape the request, return the child to be signed) and `submitX402Erc7710()` (exchange the signed child for the merchant header), with the original method retained as the composition of the two. Refactor only: no request field, no response field, no signing behaviour and no on-chain effect changes, and the twelve existing erc7710 tests exercise the composed method unchanged — which is what proves the split preserved behaviour rather than merely compiling. The reason is a key-custody boundary, not tidiness: the hosted MCP topology cannot call `settleX402Erc7710()` because that method signs in-process with `delegateKey`, and hosted Haven does not hold one and must not. The split lets the hosted server drive authorize and settle while the LOCAL edge signer produces the signature in between — the delegate key stays on the user's machine, and the request shaping stays in ONE place instead of being reimplemented server-side where it could drift from the client's. Authority is unchanged in every direction: the child's bounds are still computed by the backend and enforced on-chain as caveats, the signer still verifies them locally against the Haven-signed expected context (#1455), and nothing here can widen what a merchant may redeem. Perimeter unchanged.
