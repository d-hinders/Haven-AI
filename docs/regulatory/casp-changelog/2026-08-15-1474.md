- **#1474** — the erc7710 authorize response now carries its own Haven-signed expected context (`x402_expected_auth`), matching what the EIP-3009 branch has always emitted. This is a PARITY fix, not a restored boundary, and the distinction is worth recording because the first reading of it was wrong: the local signer's `{ payment_id }` path fetches `GET /x402/:id/sign-context`, where `rebuildDelegationSignContext` already builds a signed context for `eip712_delegation` and the signer REFUSES outright when one is absent — so the expected-binding discipline was already applied on that path, and no erc7710 child was ever signed unverified. What was genuinely missing is a declaration for a client that signs straight from the authorize response, which is what `HavenClient.settleX402Erc7710()` (#1454) does; it previously had none available without a second round-trip. The declaration is signed by `HAVEN_X402_BINDING_SIGNER` — a key this API surface does not itself control — and commits to `payloadHash` (the child hash), `typedDataHash` (the digest of the payload actually signed), plus merchantTo / amount / asset / network / expiresAt. `merchantTo` is `payTo` on this branch BECAUSE payTo being the merchant is what selected direct settlement. Authority is unchanged in every direction: this ADDS a verifiable declaration and removes no check, grants no new scope, moves no key material, creates no route, and changes neither the child's caveats nor what the DelegationManager enforces on redemption. Explicitly NOT covered, and stated so the next reader does not overestimate it: the context binds the DIGEST of the child and Haven's DECLARED fields — it does not prove the child's caveats implement those fields. A backend that declared one payee while pinning another in `AllowedCalldata` would still produce a consistently-bound pair. That local re-derivation is #1455's deliverable and remains outstanding. Proven by an assertion that the emitted declaration's digest equals the digest of the typed data in the SAME response, mutation-verified: binding it to a different payload fails three tests. The 3009 branch is untouched. Perimeter unchanged.
