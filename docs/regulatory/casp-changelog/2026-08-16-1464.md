- **#1464** — a malformed uuid path parameter now produces a documented **400** instead of an unhandled 500, on every route that lets errors propagate to the app handler (a route-local catch-all bypasses it — user-safes deploy has one; noted in the handler's own comment rather than claimed away): the fix is a central mapping of Postgres `invalid_text_representation` (22P02) — SCOPED to uuid casts via the message, so an int/enum/jsonb 22P02 from a server-computed value stays a 500 that pages someone — in the app error handler (`infra/http-error-handler.ts`, extracted from index.ts so it is testable — the previous inline handler had no test, which is how a whole error class shipped as 500s). The choke point is deliberate: per-route schemas would cover only the routes someone remembered to audit, while every uuid path param in the app — 15 routes across 9 files at the time of writing, and every future one — flows through this handler when Postgres rejects the cast. **400 rather than the issue's suggested 404, with the reasoning recorded**: the handler cannot know whether the malformed uuid came from a path param or a request BODY, and a body field must be 400; one consistent answer leaks nothing (the caller can see its own input is not a uuid), and the not-found-or-not-owned 404 indistinguishability for WELL-FORMED ids is untouched because those never raise 22P02 — pinned by a real-Postgres test showing a valid-but-unknown uuid returns not-found, never an error. The PREMISE is proven against the real harness, per the issue's own AC and for the reason it states: the route tests mock db.js, so Postgres's uuid checking never ran and `PUT /contacts/not-a-uuid` passed in tests while 500-ing in production — and the new real-DB test immediately caught the same class in ITS OWN fixture (`'user-1'` as a user id, which every mocked test uses and real Postgres rejects). The raw Postgres message does not leak to the client (asserted); the real error is logged at warn so a 22P02 originating from server-constructed values would surface in logs rather than being masked. Spec updated: EVERY documented operation with a uuid path param now declares the '400' response — verified by walking the COMPILED spec object rather than by the text transform that produced the first, incomplete pass (8 operations, missing /contacts/{id} — the exact route the premise test exercises — and wrongly touching a parameterless route; the review caught both, and the lesson is the tool: regex over a 3000-line literal lies, the compiled object does not). Authority unchanged in every direction — this maps an existing failure to an honest status code, moves no money, signs nothing, and adds no route. Perimeter unchanged; one undocumented 500 becomes a documented 400.
