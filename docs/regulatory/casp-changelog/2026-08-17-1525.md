- **Release 0.1.25-alpha.0 (PR #1525)** — Version strings only across the five published packages, their internal dep pins, the source version constants, and the Supported Runtime Manifest table. **No authority, custody, or execution boundary moves**: no route, tool schema, capability, signing path, caveat, or credential scope changes in this diff, every claim in `casp-risk-guardrails.md` reads identically before and after, and `publish.yml` derives the `alpha` dist-tag from the prerelease version so `latest` is untouched. Recorded because of what the bump CARRIES rather than what it changes: #1511 modified `packages/sdk/src/client.ts` **after** `0.1.24-alpha.0` was already published, and `publish.yml` skips any version already on npm — so promoting without a bump would publish nothing and leave the same version string holding different code on npm and in-repo, with SDK consumers silently retaining the pre-#1511 tarball. The perimeter consequence is a REPORTING one and it is the same defect #1511 fixed: on the hosted erc7710 path a settled payment was reported to the agent as failed, and an agent told a completed payment failed is an agent liable to retry it. The hosted MCP is unaffected either way — it deploys from `main` and links the workspace SDK — which is precisely why the gap is easy to miss and worth writing down: `qa-dev` proves the workspace build, not the published artifact. Verified that this release actually carries the fix rather than assuming a version bump implies it: the built SDK `dist/index.js` contains `noFundingLeg`, #1511's opt-in no-funding-leg path, and 451 tests pass across `sdk` + `mcp-server`. Also verified no wildcard `@haven_ai/*` pin exists in any published package (which would resolve to the wrong version on a user's machine) and that the lockfile change is 13 version-string lines only, the local npm's 39 spurious `dev`/`peer` metadata insertions having been stripped rather than committed. One latent risk is stated and deliberately NOT fixed here: `packages/mcp-server` exact-pins `@haven_ai/sdk` where a private workspace consumer must use `"*"`, so its correct resolution today depends on the pinned version happening to equal the workspace version — tracked as #1526, because changing dependency resolution inside a release commit would make a bad bisect if either turned out wrong. Perimeter unchanged.
