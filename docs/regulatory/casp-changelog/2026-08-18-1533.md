- **#1533 (partial — the nonce-provenance defect)** — Backend infra, relayer nonce handling. **No authority, custody, or execution boundary moves**: no route, tool schema, capability, signing scheme, caveat, or credential scope changes; what the relayer MAY submit, who authorises it, and every spend-guard/budget check around it are byte-identical, and every claim in `casp-risk-guardrails.md` reads the same before and after. What changes is HOW MANY VIEWS of the relayer EOA's nonce exist in one process: `rails/allowance-module.ts` kept its own per-chain `Map` of providers and relayer wallets parallel to `infra/relayer.ts`'s — same key resolved twice, two `JsonRpcProvider` instances, each observing only its own traffic. The shared `withRelayerSendLock` serialised SUBMISSIONS (so this was not a race), but ethers populates each transaction's nonce from the provider its signing wallet is bound to, so the wallet on the less-trafficked provider submitted nonce 775 while the chain stood at 781 (2026-08-18 03:58:50, run 32097250393) — and the owner's Basescan pulls prove the on-chain sequence 780→781→782→785 was strictly sequential with no gaps or reuse, so the stale view was process-local, not the RPC's. The failure mode was availability, never spend authority: a stale nonce is rejected at the mempool, nothing mines, no funds move — a legacy-rail payment simply failed. Fix is deletion, not addition: `allowance-module.ts`'s constructors now DELEGATE to `infra/relayer.ts`'s single instances (exports kept — eight modules import them), so exactly one provider and one wallet exist per chain and there is one place a nonce can be read from. Two prior hypotheses are recorded as dead on evidence rather than quietly replaced: multi-replica key sharing (disproven — the owner's Railway screenshot shows 1 replica, so the config change the issue originally suggested would have fixed nothing) and the Agent Passport lock bypass (disproven — the relayer's full transaction export contains no EAS calls in the window; that bypass is real and still worth fixing, but it did not cause this). This fix itself remains a CANDIDATE for the incident's cause pending the dev backend log for 03:58:50 — the identity defect is objectively wrong regardless, which is why it ships first; the issue stays OPEN until a money-flow run confirms per its own acceptance criteria. Characterization is an IDENTITY test (`relayer-single-nonce-view.test.ts`): both modules must return the same instances, mutation-proven by reintroducing a module-local Map. Matters beyond the deprecated Safe rail: the same nonce lane serves delegation-rail account activation (`hybrid-provisioning`) and the gasless sweep. Perimeter unchanged.
