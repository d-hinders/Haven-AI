- **#1586** — The connector's signer preinstall fails CLOSED instead of silently degrading. Previously a slow or failing `npm install` of the local signer runtime (120s budget — exceeded by any cold cache on a slow link) fell back, with a one-line message, to writing an `npx -y @haven_ai/signer@…` entry into the agent runtime's config: a configuration that structurally cannot start under Codex's 120s `startup_timeout_sec`, discovered only mid-payment (the 2026-08-18 external test: 20+ minutes of integration debugging, an expired first intent, corrupted `_npx` dirs). Now: the install budget is honest (10 minutes, `SIGNER_INSTALL_TIMEOUT_MS`) with console heartbeats every 15s; on failure the setup reports `errorCode: 'signer_runtime_install_failed'`, names the re-run command as recovery, and writes NO runtime configuration at all — not even the hosted entry, because a half-wired setup where quotes work but signing never can is the same looks-fine trap in a different place. **No authority, custody, or execution boundary moves**: the signer key never leaves the machine, nothing changes in what can be signed or spent — this narrows only whether a BROKEN setup gets written. Mutation-proven: restoring the silent fallback fails the fail-closed test. Perimeter unchanged.
