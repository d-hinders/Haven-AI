- **#1616** — The SDK’s MCP/x402 merchant wire handling moves from `HavenClient` into an internal, per-client `McpMerchantTransport`. Direct transport and facade characterization tests pin the existing initialize→notification ordering, protocol version, session and wallet headers, Bazaar detection, JSON/SSE response surfacing, 300-second merchant bound, caller cancellation, request body/header preservation, signed `X-PAYMENT` delivery, non-2xx diagnostics, and post-settlement delivery-failure behavior unchanged. The transport receives only a public wallet address and an already-signed, exact-context-bound payment header; it never receives the delegate key, creates a signature, changes payment state, or gains hosted signing authority. Funding readiness, reconciliation/evidence, and merchant-receipt reporting remain in `HavenClient`; no route, tool schema, public SDK contract, credential scope, custody boundary, or on-chain control changes. Perimeter unchanged.
