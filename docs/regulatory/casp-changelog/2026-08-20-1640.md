- **#1640** — a token carrying a `purpose` claim is no longer accepted as a session credential. The Fortnox OAuth `state` (`purpose: 'fortnox_oauth'`, 10 minutes) is signed with the app JWT secret and travels in a URL query string; it verified like any session token, so `authMiddleware` accepted it as a full Bearer credential on every route it guards — a narrowly-labelled token that was not narrowly scoped, sitting in browser history, provider logs and proxy logs. The guard is stated the safe way round (refuse ANY purpose, not the one known today) so the next single-purpose token inherits the refusal rather than needing to be remembered, and `routes/catalog.ts`'s hand-rolled `jwtVerify` — a second JWT door that silently missed the guard — now routes through the same middleware, leaving exactly one in the source, pinned by a mutation-proven test. **Authentication NARROWS: nothing new is grantable, no authority, custody or execution boundary moves**, and the one flow that legitimately consumes a purpose token (the OAuth callback, which is registered without the auth hook and checks the specific purpose itself) is untouched and still passes. Residual risk named and deferred by the issue: the state remains valid for its full 10 minutes and is not single-use if leaked and replayed against the callback. Perimeter unchanged.
