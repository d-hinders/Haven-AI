- **#1670** — signup and login gain a per-client rate-limit tier, and the deployment gains a `TRUST_PROXY_HOPS` setting that makes per-IP mean the client. **No authority, custody or execution boundary moves and nothing new is grantable** — this narrows what an unauthenticated caller can do to the front door, and only that. The tier is SELF-DISARMING by design: with no trusted proxy every external caller shares one `ip:` bucket behind the deployment proxy, so a limit tight enough to slow bulk account-enumeration (#1654) or credential stuffing would be a cheap global login denial-of-service — the tier therefore returns no limit at all until the operator sets the hop count, and a test pins both states. The setting is a hop COUNT rather than `trustProxy: true` on purpose: `true` takes the leftmost X-Forwarded-For entry, which is whatever the client typed, letting a caller spoof its own bucket; a count walks from the right through exactly the trusted hops. Money-path implications, spelled out as the issue required: credential-keyed buckets (the money-path tier) are keyed on the presented credential hash and do not change under trustProxy; the unauthenticated `ip:` fallback used by the public demo tier gains real per-client isolation instead of one shared proxy bucket — strictly narrower, no bucket gets wider. One residual risk is accepted and named rather than implied: a shared IP means a shared fate — carrier-grade NAT or an office proxy putting many people behind one address shares one bucket, and an abuser behind that NAT can exhaust it for their neighbours; inherent to any per-IP limit, and the ceilings sit where automation is throttled and a room of humans usually is not. Flipping `TRUST_PROXY_HOPS` in an environment is an operator action, never an agent's, and the env examples direct the operator to verify the hop count empirically before trusting it — the "one Railway edge proxy" claim is an assumption to confirm per environment, not a fact the code can know. The #1654 acceptance stands and its spec text is updated in the same change: throttled is not closed — one request against one address still answers definitively. Perimeter unchanged.
