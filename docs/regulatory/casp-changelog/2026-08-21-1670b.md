- **#1670 (follow-up)** — the trust-proxy state becomes observable and its parsing defensive, after the first dev rollout demonstrated the silent-disarm failure mode live: the operator set `TRUST_PROXY_HOPS=1`, the service kept answering, and 32 probe logins still went unthrottled — with nothing anywhere saying why. **No authority, custody or execution boundary moves and nothing new is grantable.** Two changes. `/health` now reports `trustProxy: { hops, authRateLimitArmed }` — not secret (the setting is documented in .env.example, and a hop count reveals topology no more than a traceroute), and necessary because the tier's deliberate no-limit-when-untrusted is indistinguishable from a variable the process never saw. And the env parser strips dashboard paste artefacts (quotes, whitespace) while refusing to guess at anything else: a non-numeric value — `true` above all, the spoofable Fastify mode this setting exists to avoid — warns LOUDLY at boot and stays disarmed, mutation-proven both ways (quoted `"1"` arms; `true` warns and does not). Perimeter unchanged.
