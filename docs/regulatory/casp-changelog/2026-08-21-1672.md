# 2026-08-21 — #1672: detection-first runtime resolution in the connector

Connect's runtime selection became detection-first (#1672): the dashboard setup
command stops embedding `--runtime` for command-path runtimes, the connector
resolves the runtime from the environment it executes inside
(`CLAUDECODE`/`CODEX_*`/`VSCODE_*` markers), a detection that contradicts an
explicit hint wins with a printed notice (`--runtime-force` is the escape
hatch), and a run with neither detection nor flag refuses before any side
effect. The frontend picker collapsed its three command-path rows into one
"AI agent" entry, and runtime-specific copy keys off the runtime the connector
reports back. Authority and custody are untouched: which MCP **config file**
gets written moves, never what may be signed or spent — the delegate key is
still generated locally and never leaves the machine, Haven still receives only
the public address plus proof, budgets and on-chain caveats are unmodified, and
the refusal path cannot strand a half-created agent or burn a setup token
(asserted by the #1672 tests: refusal before `resolveSetup`, no credential
write, no key mint). No payment, settlement, or sweep surface changes.
Perimeter unchanged.
