- **#1681** (PR #1729) — `connect` gains `--tombstone <dir>` (with `--reason` / `--replaced-by`): a local, operator-invoked retirement marker for an agent credential directory. The command replaces the directory's `bin/haven-signer.mjs` with a self-contained diagnostic script (stderr notice + exit 1, so a stale long-lived MCP host logs the retirement instead of a masked `Connection closed` on every re-probe) and writes `TOMBSTONE.json`; `--doctor` reads the marker in its superseded-agents scan, and the setup/Hermes/README restart guidance widens to "restart EVERY long-lived host". **No custody or authority boundary moves.** The tombstone touches no key material and revokes nothing — the #1688 rule ("connect reports, the user decides") is preserved verbatim, and this is mutation-proven in two directions: (a) `writeAgentTombstone` leaves `identity.json`/`signer.json` byte-for-byte untouched; (b) a tombstoned directory whose key is still present is still live-probed by the doctor and still fails the check if spend-capable — a tombstone is a marker, never a revocation, so it can never green-wash a key that still spends. The reachable signing surface narrows on the retired path: the old wrapper stops being a signer at all and becomes a non-signing diagnostic that exits 1. Secret hygiene: `--reason`/`--replaced-by` are passed through `redactSecrets` at the write layer (a pasted `sk_agent_` key or private key cannot persist into `TOMBSTONE.json` or the repeatedly-logged stderr notice — mutation-proven), the generated script embeds all content via a single `JSON.stringify` (no injection path), and CLI output stays redacted like every other connect path. No route, credential scope, key-material handling, or signing path is added or widened; the parent doc's custody and authority claims read identically before and after this diff. Perimeter unchanged.
