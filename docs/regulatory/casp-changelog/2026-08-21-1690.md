- **#1690** — the edge signer can now detect that it is signing ANOTHER AGENT'S quote, and refuses with the diagnosis instead of letting the mismatch surface as an on-chain revert three layers later. **This narrows what can be signed; no authority, custody or execution boundary moves and nothing new is grantable.** The x402 expected context gains a payer identity (`payerDelegate` + `payerAgentId`), carried INSIDE the Haven-signed binding message — outside it the claim would be forgeable, and the tests prove the property both ways: stripping or tampering the field breaks the binding signature, and a payer-carrying context stamped with a lower version is refused because the version is contents-derived, never caller-chosen. The guard mirrors the sweep path's existing `authorization.from` check and runs only AFTER binding verification, so an unverified claim can never be used to deny service; its refusal names both agent ids and both delegate addresses plus the remedy, which is the entire diagnosis a stale-host operator previously reconstructed by hand (#1681's field report: a long-lived host authenticating as the old agent while the new signer sat on disk). Versioning follows the established contents-derived pattern: payer present ⇒ expected-context **version 3**, `SUPPORTED_X402_EXPECTED_VERSIONS` widened to [1, 2, 3], and a v3 context on an older signer produces the machine-readable version-skew refusal rather than a misleading binding error. **Rollout is two-phase and signer-first:** this change ships full signer/SDK/relay support while the backend keeps emitting version 2 byte-identically — v1/v2 signing behaviour is characterization-tested in a commit that predates the change — and the emit flip is `X402_EMIT_PAYER_CONTEXT`, an operator env flip per environment, never an agent's, documented with the explicit warning that flipping before the signer population upgrades blocks payments honestly but blocks them. Perimeter unchanged.
