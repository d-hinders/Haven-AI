- **#1696** — `connect` gains `--name <slug>`, the user-facing half of epic #1694's multi-agent capability: a named agent gets the #1695 `haven-<slug>` / `haven-signer-<slug>` MCP pair, its credentials at `~/.haven/agents/<slug>/` (unnamed keeps the historical `~/.haven/agents/<agent-uuid>/`), and the slug recorded as `server_name` in both runtime sidecars. **No custody or authority boundary moves.** Nothing about key generation, key storage permissions, registration, spend authority, or the signing path changes — a named agent mints its own keypair locally exactly as an unnamed one does, Haven still receives only the public signing address, proof signature and API-key hash, and what an agent may spend remains the on-chain delegation plus the #1690 signer-side payer guard. Two properties are worth stating positively because they are what keeps multi-agent from becoming a credential hazard: (a) **validation precedes every side effect** — the slug's charset/length and the reserved names (`haven`, `haven-signer`, and the `signer`/`signer-*` collision family from #1695) are refused in argument parsing, which touches no filesystem, AND again inside `runConnect` itself, because that function is exported: review found that CLI-only validation let a library caller register a live agent and write real key material to disk under a reserved name before failing deep in the config writer, so the check now sits at the library boundary too (mutation-proven), and a slug whose directory already holds credentials refuses BEFORE a key is minted or an agent registered, so a name clash can neither overwrite credentials (connect never does) nor orphan a live registered agent; (b) **the credential path is stable across a re-key by construction** — it is keyed on the slug, which never rotates, which is what lets #1700 rewrite credentials in place rather than stranding a dead path. Omitting `--name` is byte-identical to previous behaviour (characterization-pinned), so no wired host changes. `--doctor`/`--repair` remain scoped to the bare pair until #1697 adds per-agent inventory; that gap is recorded in the contract doc rather than papered over. Perimeter unchanged.
