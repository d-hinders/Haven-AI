The bound exists because that wait runs inside #1673's advisory-lock critical section: the connection hold inherited its unboundedness, and #1686's accept of that hold assumed a chain round-trip. The value is bracketed, not round — above a healthy one-confirmation deploy on 2 s Base blocks, and below the #1558 bump worker's 180 s adoption age, so the caller has released the lock before another owner can take the transaction. A null receipt takes the same branch for the same reason (#690: a lagging RPC can return null for a confirmed tx) — "no receipt" is not "reverted". A genuine mined-and-reverted deploy still closes the record failed, unchanged.
