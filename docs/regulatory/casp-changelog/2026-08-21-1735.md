- **#1735** — the passport anchor's confirmation-wait EXPIRY stops being recorded as a revert, and the outbound bump worker stops fee-replacing submitters whose recovery is keyed off their own tx hash. **No authority, custody or execution boundary moves and nothing new is grantable** — an EAS attestation is governance metadata, carries `value: 0`, targets the pinned EAS contract and involves no user key, delegation or allowance, so nothing in this diff can move funds or change what may be spent or by whom. What changes is the honesty of the durable outbound record (#1556), which transaction the relayer will replace, and how a stuck relayer nonce lane is surfaced. `anchorOnChain` already bounded its wait at 120 s; ethers v6 rejects a timed-out `wait()` with `code: 'TIMEOUT'`, and that rejection landed in the same `catch` as a genuine `CALL_EXCEPTION`, so a transaction that had merely not mined yet had its record closed `failed` with a message asserting a revert that never happened — the database disagreeing with the chain, in the audit trail, for the one on-chain artifact Haven signs as issuer. An expiry now leaves the record `broadcast` and raises a distinct `PassportAnchorUnconfirmedError`; a null receipt takes the same branch (#690: a lagging RPC can return null for a confirmed tx), and a genuine mined-and-reverted attestation still closes the record failed, unchanged. **This is deliberately NOT #1722's hand-off**, and the difference is the substance of the issue. `hybrid_deploy` is idempotent on-chain, so a deploy can be handed to the bump worker and replaced freely. `passport_attest` is not: a second broadcast mints a second real, revocable credential. Less obviously, it may not be REPLACED either — a same-nonce replacement is safe on-chain (at most one transaction per nonce mines) but mints a new tx hash, while #1043's `recoverAnchorFromReceipt` is keyed off the hash `onBroadcast` persisted, so a replaced attest becomes permanently unfindable and issuance re-mints for real. `REBROADCAST_SAFE_SUBMITTERS` gated only the orphan path, leaving the stale-broadcast scan free to replace attests; it now gates both, and the chain-first closes (mined / mined-and-reverted) still apply to the withheld rows, which is precisely what makes leaving the record `broadcast` a reconciliation rather than a leak. So `broadcast` here buys chain-first reconciliation, not a bump, and the retry owner stays #1043. **One accepted residual, stated as an outage shape rather than a footnote:** a stuck attest is no longer replaced, so it blocks the relayer's nonce lane on that chain until an operator acts. That is the deliberate trade — a blocked lane is loud (alerted every tick), bounded and human-recoverable, while a duplicate attestation is silent, permanent, and the exact failure #1042/#1043 exist to prevent. The operator runbook (check the hash; if still pending, cancel the nonce with a 0-value self-send, never by re-broadcasting the attest calldata) is in `delegation-rail-vendor-ops.md` §3, and `backend-scaling.md`'s "self-healing on the queue lane" claim is corrected to name the exception. Automating the cancel is a new mechanism and an owner decision, deliberately not taken. Second residual, unchanged from before: a non-TIMEOUT wait error still closes the record failed. **Third residual, surfaced by this change's own review and deliberately NOT fixed here (#1745):** the PASSPORT-level retry is not gated on the outbound record — `markFailed` clears the anchoring claim and the backoff is 60 s, so ≈180 s after broadcast the sweep reads a null receipt, presumes the transaction dropped when it may merely be pending, and mints a fresh attest at the next nonce; if the original then mines, the agent holds two live credentials. That race predates this change and is unchanged by it — what changes is that the bump worker no longer offers a SECOND, independent route into the same state — but it is recorded here rather than left implied, because it is the one path by which a duplicate credential can still arise, and the operator runbook in `delegation-rail-vendor-ops.md` §3 now sequences around it (check for an already-queued duplicate BEFORE cancelling a stuck nonce, since cancelling releases the duplicate to mine). Mutation-proven in both directions — removing the unconfirmed branch, widening it to any wait error, removing the bump gate, and inverting the gate each fail exactly the assertion that guards them. Perimeter unchanged.
