# 2026-08-22 — #1711: self-service catalogue submission queue (epic #1717, SI1)

Adds `POST /catalog/submit`, the first slice of the Verified Payable
Directory. A merchant self-submits a payable (x402/MCP) endpoint by writing a
`catalog_submissions` queue row; the response carries an `id`, and a
`verify_token` for the later domain-ownership proof **only on the request that
created the row** — a request that de-duplicates onto an existing pending
submission gets `id` and `status` alone, so naming a hostname cannot disclose
another party's proof credential. The submission request
path makes **no outbound request of any kind** — no probing, no fetching, no
signing, no payment — which is test-pinned in the route suite. Everything
after the write (ownership proof #1712, the SSRF-hardened verification probe
#1713, lifecycle #1714) is async on the leader-locked monitor in later slices
and does not exist yet.

Perimeter check against the CASP guardrails: this slice moves no money,
authorizes nothing, and touches no payment, signature, allowance, custodian,
or authority surface. Anti-abuse is layered (honeypot, self-disarming per-IP
rate limit mirroring the #1670 auth tier, per-hostname dedupe enforced as a
database invariant, capped pending queue), and public listing still requires
both domain-control proof and a live 402 verification that arrive in later
slices. `catalog_submissions` holds pointers (URL, normalized hostname,
verification state) only — no 402 bodies, no probe history. One personal-data
point is recorded and worth naming rather than leaving implicit: the
submitter's IP address is stored on the row as anti-abuse metadata. Retention
and purge for these rows is #1714's scope; nothing in this slice deletes them.
The change is a
new additive table (`066_catalog_submissions`) plus a public write endpoint;
no existing money-path behaviour is modified, so no characterization test is
required by the money playbook. Guardrails unchanged.
