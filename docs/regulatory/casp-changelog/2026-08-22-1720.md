- **#1720** — Removed the connect modal's runtime picker. The dashboard no
  longer asks which agent client a user is in, no longer sends `runtime` in the
  create-setup payload, and no longer spells `--runtime` into any generated
  command; the connector resolves the runtime itself through the #1672/#1719
  ladder. No new authority, custody, route, or key-handling surface: the change
  removes an input and a command argument, and touches no signing, allowance,
  delegation, payment, or approval path. The setup token, challenge, proof
  signature and credential-write boundaries are byte-identical, and the
  connector still generates the signing key locally and sends Haven only the
  public address plus proof. One validation was deliberately LOOSENED —
  `local_mcp` no longer requires a named runtime — which is not a perimeter
  move: `local_mcp` selects the MCP topology on the user's own machine (local
  stdio versus hosted tools plus local signer), never who may spend or sign,
  and an explicitly-named unsupported runtime is still refused at setup time.
  The connector's own runtime check (`supportsLocalMcp`, refusing before
  `/resolve` and before any side effect) is unchanged and remains the binding
  one. Mutation-proven: restoring the `--runtime` emission, re-tightening the
  `local_mcp` condition to refuse a missing runtime, restoring the
  runtime-specific consent line, re-adding `runtime` to the create-setup
  payload, dropping the local-MCP constraint from its label, and re-gating the
  approval heads-up each turn a named guard red, and all restore green.
  Perimeter unchanged.
