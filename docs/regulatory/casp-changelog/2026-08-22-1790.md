- **#1790** — `release-bump.mjs` now writes the *Supported Runtime Manifest* table in `docs/operations/mcp-runtime-compatibility.md` that it previously left a human to copy by hand out of the file the script had just written. **Nothing about spend authority, publishing, versions or pins changes**: the diff adds a documentation write plus a check, and the table holds exactly the values it held before (proven, not asserted — the new check passes against the unmodified table). No version field, cross-package pin, dist-tag, build step, publish trigger, credential path, signing surface or route moves; `publish.yml` is untouched; no release is cut. The classification is `money-path` because `scripts/release-bump.mjs` is on the money-path file list — the release train ships spend-authority code, so a change to what the bump writes is reviewed as if it could — and stating that is the point of this shard rather than claiming an exemption. The one hazard this change could have introduced is the defect class the repo has produced repeatedly: a script that writes a value and then verifies its own write, which is a guard that cannot fail. It is structurally excluded — the verification is never passed the version the run computed, and instead re-reads the doc and each row's own constant from disk and compares them row by row (`sdkVersion`/`signerVersion`, `MCP_VERSION`, `CONNECTOR_VERSION`), so a table agreeing with itself and nothing else fails. Mutation-proven four ways: hand-editing one row of the REAL contract doc fails CI with no release involved; handing the verifier the computed version fails a structural guard; rewriting the table to a version no source carries reports all four rows; and a renamed constant or a removed row fails rather than passing quietly. The same check runs on every pull request, not only at release time, so the table cannot drift into a false compatibility claim between releases. The coupling gate is **not** weakened — a bump alone still cannot produce a green release PR — but the review pass sharpened WHY, and the sharper version is recorded here rather than the comfortable one. The gate excuses a doc on FILE PRESENCE alone, so the bump's own write now excuses `mcp-runtime-compatibility.md` by itself; before this change only a human edit could put that file in a release diff. What still forces hand-written content into every release PR is `casp-risk-guardrails.md`, whose `covers:` spans the published packages and which only a hand-written shard satisfies — a real guarantee, but one resting on another doc's coverage breadth, which is now pinned by a test (a bump-only diff with no shard must fail the strict gate; removing CASP's published-package coverage fails that test rather than silently removing the human-read requirement). What was automated is four identical version strings; what carries an argument stays with a person. Perimeter unchanged.
