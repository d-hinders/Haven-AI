- **#1826** — Decides the question [#1826](https://github.com/d-hinders/Haven-AI/issues/1826) raised about the published `@haven_ai/cli`: `packages/cli/src/**` and `packages/backend/src/routes/agents.ts` join this doc's `covers:`. No executable behaviour changes — the diff is front-matter, a doc section and this shard; no route, credential scope, key material, signing path, lifecycle transition or ownership check moves, and every custody and authority claim in the parent doc reads identically before and after. The issue's premise is **corrected, not adopted**: it argued the CLI belongs inside the perimeter because it can `agents revoke`, `agents rotate-key` and `agents pause`, but the CLI decides none of that. It is a thin HTTP client with zero runtime dependencies — no `viem`, no `ethers`, no crypto, no signing path, no key material — whose authority commands are single bare calls (`api.post('/agents/:id/revoke')`, `api.post('/agents/:id/rotate-key')`) to routes that generate the rotated key server-side and re-derive ownership from the JWT's `sub` on every request; a CLI edit cannot grant authority the backend does not already grant, and the stated reason would equally justify covering `curl`. The surface that *was* ungated is the decision point the issue walked past: `routes/agents.ts`, where revoke, rotate-key, pause and resume are decided and enforced, sat under no contract doc at all. Measured, not asserted: before this change `node scripts/docs/coupling-gate.mjs --strict --changed=packages/backend/src/routes/agents.ts` exited 0 with four advisory findings across 28 commits in ninety days, and `--changed=packages/cli/src/commands.ts` exited 0 with two advisory findings across 19 commits; after it, both runs exit 1 naming this doc. #1736's rule decides both — coverage by some other doc is a different obligation, not a substitute for a perimeter analysis, and the four architecture docs describe the API shape without asking the authority question. Covering the client while leaving its decision point outside would have been worse than covering neither. The CLI is covered on the narrower argument that survives #1739's discipline of naming the gated event — an *edit to the command surface*, never a user running `haven agents revoke`: it holds a user JWT, the same credential the dashboard holds, at 0600, and sends it as a Bearer token to whatever `baseUrlFor` resolves, which reads a user-supplied `--api-url` first, so an edit that logged it, loosened those perms or widened its destination is a credential change under Red Line 3; and it prints a freshly rotated agent API key to stdout. The `ship-next` money-path list is **not** widened and needs no new judgement: the binding in "What `covers:` must span" is a floor, not a ceiling — it forbids adding to that list without adding here, never the reverse — and this list already spans `connect/**`, `mcp/**`, `signer/**`, `mcp-server/**`, `demo-merchant-mcp/**`, all of `sdk/**`, `routes/passkeys.ts`, `routes/catalog.ts`, `routes/reporting.ts`, `routes/accounting.ts` and `config.ts`, none of which appear on it. Perimeter unchanged; the set of changes *asked* the perimeter question widens.
