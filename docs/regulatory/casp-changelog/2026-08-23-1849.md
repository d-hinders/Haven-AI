- **#1849** — The re-key `issue` leg now plans the budget carry against the clock the remainder was **measured** on (`agent_rekeys.metered_at`) rather than the clock the owner happened to finish signing on. `planCarry` takes both: the metering clock anchors the period boundary and every classification (expired, dormant, live), and the issue-time clock is used for exactly one thing — dropping a piece whose window the delay has already outrun. **No authority, custody or execution boundary moves, and nothing new is grantable.** The remainder frozen by the revoke is still a hard ceiling, the caveat enforcers are unchanged, the delegate key and recipients are untouched, and Haven still signs nothing on this path. What changes is *which period* the frozen remainder is charged against.

  **The defect was an under-grant, and that direction is the regulatory-relevant fact.** A re-key spans several requests with an owner signature in the middle, so the meter reading and the issue can fall in different budget periods. The route passed the issue-time clock for both, so `currentPeriodBoundary` computed the boundary of the period the owner *finished* in and the remainder of the period the revoke *froze* was spent against it. This could never over-grant — `planCarry` refuses a remainder larger than the granted budget and refuses a reading that did not come from the chain, and both refusals are untouched — but it silently under-granted: an owner who left a signing prompt open across a daily boundary had a spent period's remainder charged to a fresh one, at worst leaving an agent on **zero** for a period it was owed a full budget in. The no-refill invariant that §6a of the delegation-rail security model records ("carrying only the amount would turn a rate limit into a tally") is therefore unaffected in the loosening direction; the fix tightens correctness without touching the ceiling.

  **A missing measurement is refused, not defaulted.** `metered_at` has been on the row since migration 065 and was never read. The issue handler now returns `409 rekey_out_of_order` when it is absent rather than falling back to `now`, because that fallback *is* the defect: it would restore the old arithmetic for exactly the rows that lost the measurement. `planCarry` likewise refuses a clock that runs backwards (`now < metered_at`) rather than planning against it. Both refusals fire **before** any delegation row is written and before `markIssued`, so a refused issue leaves the re-key at `metered` and retryable — the #1868 stranding boundary is respected, and this diff adds nothing to the post-revoke path.

  **A dropped grant is reported, never silently omitted.** Pieces the delay outran are returned in the response's `skipped` list with the closed window named to the second, and are not persisted — a row written for a grant the client is never asked to sign would be a pending delegation that can never activate, leaving `complete` waiting on a signature nobody requested. `insertRekeyDelegation` is asserted to be called exactly once, for the piece actually handed back.

  **Money-path, and by the union rule rather than by the file list.** `routes/agent-rekey.ts` and `modules/agents/rekey-*.ts` are not on the `ship-next` money-path glob list — the same #1698-era gap #1870's shard records — but this endpoint builds an agent's replacement **on-chain spend authority**, and the issue carries the `money-path` label besides. Classified money-path on both halves of the union. Characterization tests were written and run green **before** the behaviour was touched, per `money.md` §2: the same-period path (metered and issued inside one period) is pinned at both layers — `planCarry` returns the identical plan byte-for-byte, and the route returns the identical paired `carry`+`steady` with an empty `skipped` — and is unchanged by the diff.

  **Mutation-proven at both layers, because the planner was never the thing that was wrong.** The unit suite alone could not have caught #1849: `planCarry` did correct arithmetic with whatever clocks it was given, and the caller gave it the wrong one. A route-level file (`routes/__tests__/agent-rekey-issue-clock.test.ts`) therefore asserts the owner-visible consequence — after a boundary-crossing re-key the agent holds a grant for the **full** budget, live now, and no grant below it. Five mutations were applied and each verified by content before restoration. At the route: passing `meteredAtSec: nowSec` (the exact pre-fix state) turns three assertions red, while the same-period characterization stays green — which is the proof that the characterization pins behaviour rather than the fix. At the planner: anchoring the boundary to `now` kills five tests; removing the outran-piece filter kills two; removing the dormant-liveness check kills one; removing the backwards-clock guard kills one. Recorded because of what the route mutation *also* showed — under the defect the response is still a well-formed 201 that conforms to the spec, so any test built on shape rather than on the budget figure could not have failed on this defect at all.

  **One defect in this diff was found by review and fixed before merge, and it is recorded because of its shape.** The block choosing the "nothing left to carry" message had no test at all — neither branch, in either direction — and one combination of inputs made it contradict itself: when the remainder was zero **and** the delay outran the grant's own remaining life, the zero remainder produced no *carry* drop, so the guard let the generic branch fire and the response told the owner "authority resumes at the original boundary" one line before the drop reason said that grant's window had closed. Response text only — nothing extra was built, signed or persisted, and no spend authority was affected — but it is precisely the "no silent case" property this change exists to establish, so it is a defect against its own acceptance criterion rather than a cosmetic one. The message is now chosen by a named helper with three branches (the spent period has ended and the replacement is live; the grant had no period after the spent one; the delay outran the period there was), each covered by a route test and each verified by mutation. Worth noting that the first mutation of the fix **survived** the initial test: the double-drop assertion checked what the message must not say without checking which of the two remaining messages it did say, so dropping the distinction substituted a quieter falsehood ("the grant had no period after that one" — there was one) for the loud one. The assertion was tightened until that mutation died. Recorded because a green test over a branch that has never been mutated is the failure mode the money-path bar exists to catch, and it recurred here inside the fix for it.

  **Backward compatibility.** No request or response field is added, removed or retyped; `skipped` already existed and already carried free-text reasons. An in-flight re-key at `metered` on deploy has a `metered_at` (the stage that sets it is what put it there) and issues correctly under the new arithmetic. Perimeter unchanged.
