# 2026-08-24 — #1714: catalogue entry lifecycle, re-verification + retention (epic #1717, SI4)

Wires the ingestion pipeline that SI1–SI3 built into a running, bounded
monitor: the leader-locked `catalogIngest` tick walks `catalog_submissions`
rows through domain-ownership proof (SI2) and the SSRF-hardened read-only
verification probe (SI3), re-verifies `verified_payable` entries on a 24-hour
cadence, degrades sustained failures to `failed`, purges terminal rows after
30 days, and raises ops alarms for stuck and mass-failure conditions. Adds
migration `068_catalog_lifecycle` (six additive columns plus two indexes) to
the existing SI1 table.

Perimeter check against the CASP guardrails: this slice moves no money,
authorizes nothing, and adds no route. The probe remains quote-only by
construction — it never signs, never pays, and the module imports no signer
or settle path (pinned by the existing probe import-surface test). The
ownership gate and SSRF guard behave exactly as in SI2/SI3; lifecycle only
decides when to retry, when to give up (3 consecutive probe failures, or the
7-day ownership token TTL), and when to delete a terminal row (30-day
retention). The one personal-data point already named in the SI1 shard — the
submitter `ip` on the queue row — is now bounded: rows are purged at
retention, so the IP never outlives the row. No existing money-path behaviour
is modified, so no characterization test is required. Guardrails unchanged.
