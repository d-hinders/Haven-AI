# 2026-08-24 — #1715: verified-directory listing + public submission status + dashboard flow (epic #1717, SI5)

Two delta surfaces on top of the SI1–SI4 pipeline, for both read-only
discovery and the dashboard self-service flow.

`GET /catalog` now merges `verified_payable` self-submitted rows after the
operator-curated ones, each branded by `source: operator|ingestion` plus the
`domain_verified` / `verified_payable` badge fields; the same rail/category/
search filters apply to both halves and agent clients (an x402 endpoint is
self-describing about chain at pay time, so no chain filter is attached to
directory rows). Adds the public status endpoint `GET /catalog/submit/:id`:
coarse status only, ownership-instruction payloads while the row can still
prove ownership, never the `verify_token`, never internal failure detail
(no internal-DNS or probing oracle). The dashboard gains a Verified badge +
All/Verified/Operator-curated filter and a "List your payable service" flow
(submit form with honeypot, token + one-line well-known instruction with copy
buttons, 15-second live status polling that stops at terminal states).

Perimeter check against the CASP guardrails: this slice moves no money and
changes no authority. Discovery is read-only; the status endpoint makes no
outbound request and reveals only coarse states plus the same one-line
ownership instructions SI2/SI3 already treated as publishable. The submission
POST is unchanged from SI1 (queue-only write, honeypot, rate-limited, token
returned exactly once). The verification probe remains quote-only — this slice
does not touch it. No existing money-path behaviour is modified, so no
characterization test is required. Guardrails unchanged.
