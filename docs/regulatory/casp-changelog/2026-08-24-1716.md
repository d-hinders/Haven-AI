# 2026-08-24 — #1716: verified discovery + agent-side submission in SDK and MCP (epic #1717, SI6)

Exposes the SI5 verified-directory listing through the agent surfaces that
already consume the catalog.

`@haven_ai/sdk` `HavenCatalogEntry` now carries `source` / `domainVerified` /
`verifiedPayable`, `discoverTools` gains a client-side
`verified: 'any' | 'verified' | 'operator'` filter, and two new methods wrap
existing backend routes: `submitCatalogEntry(resourceUrl)` (POST to the SI1
queue-only endpoint; returns id + `verify_token`) and
`getCatalogSubmissionStatus(id)` (the SI5 public status read). The local and
hosted MCP surfaces mirror this: `haven_discover_tools` returns the badge
fields + accepts the `verified` filter, and a new `haven_submit_catalog_entry`
tool posts through the identical rate-limited pipeline.

Perimeter check against the CASP guardrails: this slice moves no money and
changes no authority. Discovery and status reads are read-only against the
same endpoints SI5 documented. The submission tool is a thin client wrapper
over SI1's POST — queue-only write, honeypot preserved, rate-limited, and the
verify token is still returned exactly once; domain-ownership proof and the
SSRF-hardened quote probe (SI2/SI3) still gate any listing and cannot be
skipped from the agent side. No existing money-path behaviour is modified, so
no characterization test is required. Guardrails unchanged.
