- **#1868** — A re-key abandoned **after** the revoke no longer forfeits the agent's spend authority. The revoke-prepare handler's no-live-delegations branch now consults `adoptAbandonedCarry` (`infra/repositories/agent-rekeys.ts`) before walking the empty path: when the agent's most recent **abandoned** re-key froze a carry snapshot after its own on-chain revoke, the fresh re-key inherits that snapshot together with the predecessor's `revoked_at`, `metered_at` and revoke tx hash, and the issue step then builds the same carry+steady pair the abandoned attempt would have. **No authority, custody or execution boundary moves, and nothing new is grantable.** The inherited remainder was frozen by an on-chain revoke and cannot have moved since — a revoked delegation cannot spend — so the ceiling is the same remainder the #1694 ordering already established; the caveat enforcers, the delegate keys and the recipients are untouched, and Haven still signs nothing on this path. What changes is that "abandon, then start again with a fresh key" now restores the agent's authority instead of stranding it behind a manual owner re-grant that could not preserve the period boundary.

  **The abandonment signal is the owner's explicit abandon, never a clock — stated because the alternative fails open.** Adoption's predecessor predicate is `stage = 'abandoned'`, written only by `POST …/abandon` under the owner's session. A merely slow re-key is structurally unreachable: it still holds the `idx_agent_rekeys_one_in_flight` slot, so a successor cannot even OPEN, and there is no `NOW() - metered_at` predicate anywhere in the diff — a timeout that guessed wrong on a live re-key would free authority still in use (fail open) where the wedge at least failed closed. The positive control is a real test: a re-key at `metered`, aged 48 hours by direct UPDATE, still refuses a successor at the unique index and is left untouched (`agent-rekeys.test.ts` › "POSITIVE CONTROL — a live, slow re-key is structurally unreachable").

  **The over-grant guard is the regulatory-relevant refusal.** Adoption is refused when ANY delegation was granted to the agent after the abandoned revoke — whatever its current status, because a since-revoked grant still spent — excepting only the abandoned re-key's own `pending` issue rows, which are permanently inert (completion requires stage `issued`; `abandoned` is terminal). Without the guard, "abandon at metered → owner re-grants a full budget → agent spends it → owner revokes → re-key" would stack the old remainder on top of a budget already spent in the same period. A refusal falls through to the pre-#1868 empty walk: authority stays absent until the owner re-grants, which is the fail-closed direction. A **completed** re-key's snapshot is likewise never adopted — its carry was already issued and possibly spent.

  **The measurement clock is inherited, not re-stamped — #1849 composes instead of being bypassed.** The adopted row carries the predecessor's `metered_at` wholesale, so `planCarry` still anchors the remainder to the period it was measured in; a boundary crossed while the flow sat abandoned drops the outrun carry and issues the steady grant from the true boundary, exactly as a slow un-abandoned re-key would. Stamping adoption time over `metered_at` would re-create the #1849 under-grant through a side door, and that exact mutation is proven caught (below). The inherited pair satisfies migration 065's `meter_after_revoke_check` because the predecessor's did; the stage CHECKs are unchanged and no migration ships in this diff.

  **Money-path, by both halves of the union rule.** The issue carries the `money-path` label, and the branch decides whether an agent has any on-chain spend authority at all — the #1870 shard already records that `routes/agent-rekey.ts`'s absence from the file list is an artefact of the list predating #1698. Characterization first, per `money.md` §2: the pre-existing empty walk (nothing adoptable → `markRevoked`+`markMetered([])`, `tx_hash: null`, empty carry) and the live-delegations path (adoption never consulted) are pinned as route tests and unchanged by the diff. The load-bearing wedge reproduction ran RED on the pre-fix tree first — 4 named failures (`Tests 4 failed | 1 passed`), including the inherited-carry assertion receiving `[]` — and green after.

  **Mutation-proven, six mutations, each verified landed by content before its run and restored by hash after.** Widening the predecessor predicate to include `completed` kills the named completed-snapshot test; deleting the `NOT EXISTS` over-grant guard kills two named refusal tests; re-stamping `metered_at = NOW()` kills the clock-inheritance and chain-of-abandonments tests; counting the abandoned re-key's own pending rows kills the inert-pending test; dropping the `jsonb_array_length > 0` floor kills the empty-snapshot test; making the route ignore the adoption result (the pre-fix behaviour) kills both wedge tests at the route layer. Every run produced a `Tests N failed` summary line with the named `×` — no kill was accepted from a run that executed nothing. No sweeper, cron or background job is added.
