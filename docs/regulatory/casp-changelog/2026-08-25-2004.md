- **#2004** — **CASP Red Line #4 ("Off-Chain-Only Spend Control") gets the on-chain half of its proof back.** This closes a gap that two earlier slices of epic #1440 created and each reported honestly rather than hid, and it is worth recording why the gap existed at all: the delegation rail did not weaken the red line, it moved the enforcement out of TypeScript and into Solidity — and the proof did not follow it. On the legacy AllowanceModule rail, "the on-chain policy is the final gate" was checkable in a unit test because the check was arithmetic Haven itself performed (`computeEffectiveAllowance`, `decideCoverage`) against a number read from the chain. #1986 retired that rail, so those cases could no longer reach a spend; #1987 then deleted the arithmetic outright, at which point the surviving `not.toHaveBeenCalled()` spies became **true by construction** — a guard over the empty set that would pass just as happily with the whole payment route deleted. #1987 re-based the claim structurally (the arithmetic is not merely unused but not *bound* into `routes/payments.ts` at all, asserted over parsed import bindings with a positive control proving the extractor can say yes) and filed the remainder as this issue: **nothing in the repository proved that the DelegationManager's caveat enforcers actually refuse an out-of-policy redemption.** The practical exposure was small — audited MetaMask contracts, exercised by #1450's mainnet canary — but "we rely on an audited third-party contract" is a materially different regulatory statement from "we prove it on every pull request", and the guardrails document made the second claim.

  **What now exists:** `packages/backend/src/routes/__tests__/non-custody-onchain-enforcer.contract.test.ts` compiles a delegation with Haven's real caveat compiler (`buildBudgetDelegation` — no mocks, no fixtures, no hand-written terms), extracts the `terms` bytes that compiler produced, and hands them to the enforcer contract **deployed at Haven's pinned address** on Base Sepolia — the same bytecode `rails/delegation-contracts.ts` pins for Base mainnet, byte-compared there when it was pinned (#908). Six assertions, three refusals each paired with an in-policy acceptance on the same enforcer: an **over-budget** redemption reverts `ERC20PeriodTransferEnforcer:transfer-amount-exceeded` while a within-budget one is allowed; a **wrong-recipient** redemption against a recipient-pinned delegation reverts `AllowedCalldataEnforcer:invalid-calldata` while the pinned recipient is allowed; an **expired** delegation reverts `TimestampEnforcer:expired-delegation` while a live one is allowed. The pairing is not decoration — three refusals alone would pass against an enforcer that refuses everything, or against terms so malformed the enforcer cannot parse them, which is precisely the defect class the two preceding slices were rebuilt to remove.

  **No new authority, no new custody surface, and no key.** The proof reaches the enforcer through `beforeHook`, which is that enforcer's entire decision and is callable by an unsigned, unmined `eth_call`: nothing is broadcast, no account is funded, no private key exists in the process, and `assertTestnetOnly` refuses every chain id but Base Sepolia — Ethereum mainnet, Base mainnet and Gnosis are named in an explicit deny list rather than left to a heuristic. The perimeter is unchanged; what changes is what the repository can demonstrate about it.

  **A transport failure must never read as a verdict, and the availability policy is itself proven offline.** The one way a proof like this goes false is by reading an unreachable RPC as "the enforcer allowed it". Every probe therefore ends in exactly one of three outcomes — allowed, reverted with the decoded on-chain reason, or a distinct thrown `EnforcerProbeTransportError` — and the unreachable path fails the run with a message that says in words that it is not a policy result. The four availability modes follow the real-Postgres harness's decided policy (#1763): reachable → run; unreachable in CI → **fail**, never skip; unreachable locally → fail by default, narrowing only on an explicit `HAVEN_SKIP_ENFORCER_PROBE=1`, which is deliberately powerless in CI. That policy is a pure function with its own network-free unit suite, because a guard against "the proof did not run and nobody noticed" must not itself go quiet when there is no chain.

  **One defect was found in this slice's own guard by testing it, and is recorded because it is the same defect twice over.** The suite's first shape skipped via `HAVEN_SKIP_ENFORCER_PROBE === '1' ? describe.skip : describe`. Run with `CI=1` set, it **skipped the regulatory proof in CI** — the exact outcome `decideProbeMode` exists to forbid. The unit tests said `fail-ci`; the suite skipped anyway, because a collection-time `describe.skip` reads the raw environment and never consults the policy. The decision now happens inside `beforeAll`, so the asserted policy and the actual behaviour are the same thing, and all three paths (CI+acknowledged+unreachable → fail; local+acknowledged+unreachable → skip; reachable → run) were re-verified by running them.

  **Mutation evidence, both directions.** Each mutation was verified to have LANDED before its result was believed, and restored from a task-named backup verified by content. Inflating the compiled period budget 1000× turns exactly **one** named assertion red (the over-budget one). Compiling the recipient pin to a different address turns **two** red — the wrong-recipient refusal *and* its positive control — which is what proves the controls are load-bearing rather than ornamental. Dropping the expiry from the timestamp caveat turns exactly one red (the expired one). Making the probe report a revert as `allowed` turns all **three** refusals red and leaves all three positive controls green, showing the two halves fail independently. And a deliberate **negative control** — mutating a delegation-identity string this suite makes no claim about — **SURVIVED**, 6/6 green, demonstrating the rig can report survival and is not simply red under any edit.

  **What is still NOT proven, stated plainly.** That the DelegationManager runs the full caveat stack, in order, during a real `redeemDelegations`. Each enforcer's own verdict on Haven's own terms is now proven; their composition is not. Closing it needs a deployed and funded testnet delegator plus a signature — operator-held keys, outside an automated suite — and the honest standing claim for that remainder is the live evidence (#1450's mainnet canary, the #820 Base Sepolia matrix), not a per-PR gate. Red Line #4 in `casp-risk-guardrails.md` now says exactly that, and neither the new suite's header nor the guardrails text lets its green be read as closing it.
