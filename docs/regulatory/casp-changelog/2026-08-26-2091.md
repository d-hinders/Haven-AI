- **#2091** — `@haven_ai/connect` setup-refusal legibility only; **no spend
  authority, key role, refusal *policy*, or perimeter moved**. Three changes,
  all on the pre-credential failure path: (1) the `--json` failure record now
  carries `error.message` (redacted, `ConnectError` vocabulary only — a plain
  `Error`'s message, which can hold server/filesystem detail, stays out of the
  JSON, pinned by test) and `error.allowed_runtimes` on the three
  runtime-selection refusals, closing the Codex field deadlock where the
  backend's setup prompt permitted a retry only with "the values that refusal
  lists" while `--json` discarded the list; (2) every `--json` failure path
  mirrors the redacted message to stderr (stdout stays one pure-JSON line);
  (3) a dead setup token (410 expired / 401 invalid) is classified
  `setup_challenge_expired_or_invalid` → `return_to_haven_for_fresh_setup`
  instead of generic `connect_failed`, at BOTH token-bearing calls —
  `resolveSetup` and `registerSetup`, since the 30-minute TTL can lapse in
  the gap between them.
  Custody posture unchanged: every touched refusal still fires **before any
  side effect** (no agent registered, no key minted, no credential written,
  setup token unused — the #1161 discipline, re-pinned by the new tests), and
  redaction is strengthened, not weakened — the serialized message passes
  through `redactForAutomation` (secrets + credential-file paths), and the
  `secureLogger` path-redaction was deduplicated onto the same helper. No API
  credential gains authority; nothing here can spend, sign, or move funds.
