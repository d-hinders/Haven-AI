- **#2118** — the approval-keyed evidence/reconciliation **write** builders are
  deleted from `infra/repositories/machine-payments.ts`. **No control, refusal,
  record or authority moves, and no historical record becomes unreadable — the
  change removes code that could not execute.** After #2085 narrowed the `kind`
  discriminator, every caller resolved its reference column through
  `referenceColumnForPayment` (`modules/mpp/evidence.ts`) or the inlined literal
  in `reconciliation.ts`, and both always answered `'payment_intent_id'`; the
  approval-anchored branch of `upsertEvidenceBase`, `attachEvidenceProof`,
  `upsertReconciliationEvent`, `findReconciliationEvent` and
  `resolveReconciliationForPayment` was therefore unreachable, along with the
  `EvidenceReferenceColumn` union and its five `*_FOR_APPROVAL_SQL` statements.
  **The deletion stops at the write path, and that boundary is the whole
  compliance argument.** The `approval_request_id` COLUMN survives on
  `machine_payment_evidence` and `machine_payment_reconciliation_events`, and so
  does every READ of it. Migration 070 dropped `approval_requests` with
  `DROP TABLE ... CASCADE` *specifically* so historical evidence and
  reconciliation rows would survive holding their values — its header calls the
  alternative an FK hazard that would cascade away proof-of-payment records —
  and `mapEvidence` uses the column as those rows' only `payment_id` anchor,
  reachable today through `GET /receipts`. Removing the column or the
  `payment_intent_id ?? approval_request_id` fallback would return
  `payment_id: null` for every pre-#2055 receipt, i.e. would silently orphan
  settled-payment evidence. That is a **records-retention** outcome, not a
  refactor, which is why it is asserted rather than intended.
  **Proven, not reasoned.** `infra/repositories/**` is on the money-path
  perimeter, so per `money.md` §2 the characterization test was written BEFORE
  the deletion, and per epic #1219 it runs on the real-Postgres harness because
  the claim is about database behaviour rather than call choreography
  (`infra/repositories/__tests__/approval-reference-unreachable.test.ts`, 6
  tests). It has two asymmetric halves: the write half pins that no reference
  union, no `*_FOR_APPROVAL_SQL` constant and no approval-keyed `ON CONFLICT`
  exists in any production module; the read half inserts a genuine pre-#2055
  row — `approval_request_id` set, `payment_intent_id` NULL — via raw SQL
  (deliberately not via the helper being deleted) and asserts it still lists and
  still maps to `payment_id = <approval id>`. **Mutation-proven in three
  directions**, each confirmed to have landed as valid, type-checking code
  before its colour was read: stripping the column from the evidence INSERT
  (over-deletion), dropping `mapEvidence`'s fallback (read regression), and
  re-introducing an approval-named constant (regression of the deletion itself).
  Each turns exactly one test red. The over-deletion mutation is the one that
  matters — without it the write-half assertions would all still pass on a tree
  that had orphaned every historical anchor.
  **One existing test was deleted, not skipped:** `'the approval-anchored upsert
  dedupes on its own partial unique index'` exercised
  `UPSERT_EVIDENCE_BASE_FOR_APPROVAL_SQL` and lost its subject when that
  statement went. The partial unique index it covered still exists on the table
  and still protects the historical rows; what is gone is Haven's ability to
  write a NEW row through it. Recorded here because deleting a money-path test
  should never pass unremarked.
  `approvalRequestId` survives on both input types **pinned to the literal
  `null`**, so a new approval-anchored row is impossible by type rather than by
  convention, while the INSERT statements still carry the column. Five
  corresponding PREPARE checks were removed from `db-schema-smoke.ts`; the
  remaining curated money-path queries all still match the schema. No route,
  schema, migration, authority, credential, signing surface or custody boundary
  moved. Perimeter unchanged.
