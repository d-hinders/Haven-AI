- **Release 0.1.31-alpha.0** — The release diff itself changes only version strings across the five published packages and private lockstep `mcp-server`, exact internal pins for published consumers, the mirrored source constants (`MCP_VERSION`, `SIGNER_VERSION`, `HOSTED_SERVER_VERSION`, `CONNECTOR_VERSION`, `CLI_VERSION`, connect's `runtime-manifest`), the deterministic lockfile version lines, and the generated Supported Runtime Manifest rows; no route, handler, caveat, enforcer or signing path is touched by the bump. It carries fourteen commits merged after 0.1.30-alpha.0. **One is a genuine surface addition and is called out rather than folded into the prose:** **#1716** registers a fifteenth MCP tool, `haven_submit_catalog_entry`, whose whole payload is `{ resource_url, website? }` POSTed to the public self-service submission queue `/catalog/submit` (#1711, promoted on this same `dev → main` merge, and already hardened for input handling and queue-cap bypass under #1711's own shards). It submits a URL for review. It moves no value, signs nothing, reads no key, quotes no price, and grants, raises or consumes no allowance — it cannot reach a delegation, a redemption or a funding leg by construction, so it adds no authority, custody or discretionary-execution surface. Its one operator-visible consequence is procedural and is recorded in `mcp-runtime-compatibility.md`: `computeConsentHash` hashes the sorted registered tool names, so the added tool invalidates every stored consent hash and the first launch on 0.1.31-alpha.0 re-prompts for acknowledgement — the consent gate doing exactly what it exists to do when a new tool is exposed. The remaining thirteen commits narrow or correct existing surfaces without widening any: **#2145** and **#2115** stop the payment-status response asserting a settled or approvable state it cannot support, **#2145** giving the funded-but-undelivered case a reachable retry instead of "confirmed, nothing to do"; **#2131** withdraws agent-facing guidance that gated on a `next_action` nothing emitted, leaving `assertCanResumeX402` and the hosted-server gate fail-closed and unchanged; **#2117** and **#2092** complete an unreported erc7710 settlement by passive on-chain observation behind a scheme-agnostic seam, proposing nothing from transfer shape alone; **#2054** and **#2041** bind the price cap to the authorized option and thread idempotency on erc7710 — each a tightening of what can be signed, never a loosening; **#2100/#2101/#2098**, **#2086** and **#2063** re-base tool prose, the first-launch consent copy and residual queue-and-approve wording off the retired Safe rail, changing description strings only; and **#2091** carries the allowed-runtime list and a redacted message into connect's `--json` refusal and classifies a dead setup token, emitting no secret and no new network mutation. **One published type is REMOVED by this cut, and is recorded here rather than left to a consumer’s compiler:** #2115 drops the exported SDK type `PendingApproval`, which asserted a narrowing that became unreachable when the approval queue was retired and whose wire twin had already left the OpenAPI spec. Verified rather than assumed, by the SKILL’s own compatibility check — diffing the built `packages/sdk/dist/index.d.ts` against the published `@haven_ai/sdk@0.1.30-alpha.0` tarball shows exactly two declarations added (`CatalogSubmissionAccepted`, `HavenCatalogSubmission`, from #1716) and that one removed, with no other export gained or lost. It is a compile-time break for a TypeScript consumer importing that name and nothing more: the type carried no authority, gated no execution path, and its removal narrows what the SDK describes rather than widening it. Every carried change was independently perimeter-reviewed in its own shard; this cut re-publishes them under a new version and adds one non-financial submission tool. `publish.yml` derives the prerelease `alpha` dist-tag from the version, so `latest` is untouched on all five packages. Perimeter unchanged.
