- **#2136** — **verification record only; no behavioural change, and none intended.**
  The #2117 passive settlement sweep was built twice in parallel (PR #2135,
  merged; PR #2134, closed unmerged). This change absorbs the coverage the
  merged branch did not carry and changes no production code path: it adds a
  real-Postgres eligibility test for the sweep's candidate query, registers that
  query in the `db:schema-smoke` curated money-path list, and adds three refusal
  cases to the SDK's evidence-retry test. **No authority moved, no spend limit
  changed, no signing scheme touched, and no fund movement was added, changed or
  initiated.** The only files whose bytes change outside `docs/` are two test
  files and one developer script; every production module named below is read,
  not written.
  **What is now proven rather than assumed.** `FIND_SWEEPABLE_ERC7710_INTENTS_SQL`
  decides which settled payments the leader-gated tick may push into a user's
  books, and `settlement-sweeper.ts` re-checks none of its conjuncts before
  calling `observeErc7710Settlement` — the query IS the admission control. Its
  only prior execution coverage was migration 072's index-parity test, which
  seeds two rows differing solely in `tx_hash` and asserts the candidate set is
  unchanged with and without the index. That harness does prove a narrow slice
  of the predicate in passing — its settled control row is excluded, so
  `status='submitted'` and `tx_hash IS NULL` are exercised — but two of roughly
  eight conjuncts were the whole of it. Every conjunct is now exercised on both
  sides — the row that must be returned and the row that must not — for the
  lifecycle guards (`status='submitted'`, `tx_hash IS NULL`, delegation rail,
  `settlement_scheme='erc7710'`), for the rail read through
  `COALESCE(payment_rail, source)`, for `delegation_hash IS NOT NULL`, for the
  90-second minimum age that keeps the sweep off the happy path, for the
  24-hour recovery horizon, for oldest-first ordering, for the per-tick limit,
  and for the selected column list the two downstream consumers read positionally
  by name. The bounds asserted are the ones a production tick actually passes,
  behind a positive control, so a query that returned nothing at all could not
  satisfy the exclusion assertions.
  **The pre-#2094 exclusion is now a stated decision.** `delegation_hash IS NOT
  NULL` means an intent authorized before the intent-unique settlement salt can
  never be completed by observation, and because that filter sits in the SQL
  rather than in the tick, such a payment is not even counted as `unresolved` —
  the sweeper's own "log the residue loudly" complement does not reach it. The
  exclusion is unchanged by this PR and is pinned by a named test so it reads as
  a decision rather than an accident of the WHERE clause; the surfacing gap is
  filed separately.
  **Schema-drift guard.** The candidate query reads columns no other curated
  money-path query reads together (`delegation_hash`, `machine_metadata`,
  `execution_rail`) and is the sole consumer of migration 072's partial index.
  Drift there is silent in production — the tick logs a warning and confirms
  nothing — so the query now PREPAREs against a from-scratch migrated schema in
  `db:schema-smoke`, proven by mutation to fail that check when a column name
  drifts.
  **SDK refusal classification.** The evidence-report retry predicate is an
  equality on `503`, not a "retry anything non-terminal" rule. A terminal `400`,
  a terminal `404`, and a transport-level `HavenApiError` with `statusCode` 0 are
  now pinned as not-retried; widening the predicate to "anything that is not a
  409" reddens exactly those three and nothing else. This bounds retry traffic
  against an already-paid resource and cannot change any caller-visible outcome.
  Ten mutations, ten kills, each landing confirmed by file hash before its run
  was read and each restore verified against the git blob, with positive controls
  on both halves. Perimeter unchanged: Haven still custodies nothing, still signs
  no settlement, and this change moves no money in any direction.
