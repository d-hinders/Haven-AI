- **#2187** — the user-facing sentence refusing a `--rekey-finish` with no new
  API key existed in two files (`args.ts` and `rekey.ts`) with nothing pinning
  them together; it now lives in one leaf module both import. **No custody or
  authority boundary moves, no behaviour changes, and no message text changes** —
  the same sentence, the same two refusals, the same exit codes.

  **Why this touches re-key at all, and why it is still not authority.** Re-key
  rotates an agent's on-chain spend authority, so anything in `rekey.ts`
  deserves a second look. What changed here is a string's *home*: the two
  `throw new Error(...)` sites now reference `REKEY_FINISH_NEEDS_API_KEY`
  instead of each carrying their own copy. No rotation logic, no credential
  write, no API call, no key generation and no ordering is touched. The
  connector still never calls the owner-authenticated re-key routes.

  **Both guards deliberately survive, and the decision is recorded rather than
  implied.** The issue proposed deleting the `rekey.ts` guard as unreachable
  dead code — `args.ts` refuses the same condition at parse time and
  `finishRekey` is not exported. On inspection that framing was wrong:
  `startRekey` and `finishRekey` share one `RekeyOptions`, so `newApiKey` is
  optional in the type only because phase one takes none. For `finishRekey` it
  is required in practice, and the guard is what makes that contract honest at
  runtime — `options.newApiKey` otherwise flows into `probeIdentity` and then
  into the written credential, failing later and less legibly. Deleting it
  would have removed a real check on the path that rewrites signing
  credentials. Both layers are now pinned by test, so neither can be removed
  silently.

  **Evidence.** Vitest in `packages/connect/src/rekey.test.ts` drives both real
  paths — `parseArgs(['--rekey-finish'])` and `finishRekey({}, {})` — and
  asserts each still refuses and that the two messages are identical. The
  equality is asserted between the two PATHS rather than each against the
  constant, so a site that stopped importing it would still fail. Four
  mutations, each turning exactly one test red: either site drifting back to
  its own literal, and either guard being deleted. Perimeter unchanged.
