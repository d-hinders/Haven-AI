- **Release 0.1.32-alpha.0** — The release diff itself changes only version strings across the five published packages and private lockstep `mcp-server`, the exact internal pins those published consumers carry, the mirrored source constants (`MCP_VERSION`, `SIGNER_VERSION`, `HOSTED_SERVER_VERSION`, `CONNECTOR_VERSION`, `CLI_VERSION`, connect's `runtime-manifest`), the deterministic lockfile version lines (11, all of them workspace `version` fields or `@haven_ai/*` pins — the #1663 guard fails the bump otherwise), and the generated *Supported Runtime Manifest* rows; no route, handler, caveat, enforcer, redemption path or signing path is touched by the bump. It carries eleven issues merged after 0.1.31-alpha.0, and **none of them moves an authority, custody or discretionary-execution boundary** — each was independently perimeter-reviewed in its own shard (#2136, #2155, #2169, #2173, #2174, #2175, #2179, #2184, #2187, #2243, #2247), and this cut re-publishes them under a new version.

  **What the published surface does, measured rather than asserted.** Diffing the built type declarations against the published 0.1.31-alpha.0 tarballs: `@haven_ai/sdk`'s `index.d.ts` is byte-identical (its only change this cut is a test file); `@haven_ai/signer`'s differs in exactly one line, the `SIGNER_VERSION` literal; `@haven_ai/connect` gains four declarations (`CONNECT_OUTCOME_FILENAME`, `writeConnectOutcomeRecord`, `failureOutcomeFor`, `installedClientHint`) and one exported type (`InstalledClientHint`) with **nothing removed or renamed**, so the one commit in this cut labelled a refactor (#2187, giving the `--rekey-finish` missing-API-key sentence a single home) is confirmed to have dropped no export; `@haven_ai/mcp` and `@haven_ai/cli` have no source change at all beyond their version constants. The registered MCP tool set is therefore **unchanged at 15 keys** — verified by diffing the tool-name set in the published `@haven_ai/mcp@0.1.31-alpha.0` d.ts against this branch's, identical — so, unlike the previous cut, `computeConsentHash` produces the same hash and no stored consent is invalidated. There is no consumer-visible compile-time break in this release.

  **Why none of the eleven reaches the perimeter.** Nine are `packages/connect` changes, and connect is a *setup and teardown* tool that never holds spend authority: it generates the delegate keypair locally, writes MCP config, and reports — Haven signs nothing on its behalf and the connector never calls an owner-authenticated route. #2169 (`--unwire`) is the only one that removes anything of value, and it removes **local** key material while explicitly not revoking on the backend, so the spend-capable surface it touches only narrows; its one new risk — a remover reaching another agent's wiring — is closed by refusing rather than guessing when two unnamed agents share a `haven` / `haven-signer` pair. #2155 (tombstone mirror) and #2173 (terminal-outcome record) both add a file inside the existing 0o700 credential directory at 0o600 whose content is a record already emitted on a stream, secret-free by construction and pinned so by test — no key material, no API key, no full credential path; #2173's write is deliberately best-effort, which is the safe direction because nothing gates on the artifact's presence. #2174 decorates the `runtime_undetermined` refusal with which agent clients are installed, and the invariant that matters in custody terms — the scan populates choices and never selects, so key material is never placed by inference — is pinned at exactly the point it would be cheapest to break. #2175 and #2184 change what a *failed* command puts on stdout, with success payloads byte-identical, exit codes unchanged, and `message` gated to connector-authored `ConnectError`s so a bare OS error's raw path text stays on stderr and out of the machine channel. #2179 is test-only and touches zero production source. #2187 changes a string's home, not its text.

  **The two money-path-glob changes are both non-executable.** `packages/signer/` is a money-path glob (`.github/money-path-globs.json`, #1896) because the edge signer holds delegate key material, so #2243 and #2247 land inside the perimeter's file boundary — and both are documentation of a guard rather than a guard. #2243 re-verified the published `@haven_ai/signer` README against the source and corrected a false premise (the signer *does* make one authenticated read-only `GET /x402/:id/sign-context` since #1263, so a guarantee stated as "it makes no network calls" now names the actual mechanism). #2247's entire production diff is a corrected comment in `signSweepAuthorization`: the guard expressions are byte-identical before and after, and what the comment now states truthfully is that the `from` check is unconditional while the *destination* check is credential-dependent — absent a local account address, the sweep destination rests on Haven's binding signature plus the canonical-USDC token/chain assertion, authenticated but not independently re-derived locally. Naming that distinction is a disclosure improvement, not a widening: the behaviour it describes predates both changes and the owner explicitly declined the fail-closed alternative because refusing a sweep without a local account address would break the documented `HAVEN_DELEGATE_KEY`-only **recovery** path. #2136 is a verification record only — real-Postgres coverage for the erc7710 settlement-sweep candidate query and three SDK retry-refusal cases — adding no fund movement and changing no production code path.

  **Custody is unchanged in the way that matters most: Haven still custodies nothing.** User funds remain in the user-controlled Hybrid DeleGator; authority remains the signed budget delegation enforced on-chain by the audited caveat enforcers during redemption; the delegate key is still generated on the user's machine, still loaded only in the signer's `core.ts`, still never transmitted and never written to an audit row. The retired Safe/AllowanceModule rail is untouched by this cut and still fails closed. `publish.yml` is byte-unchanged since the previous bump and still derives the dist-tag from the version, so this prerelease goes to `alpha` and `latest` is untouched on all five packages. Perimeter unchanged.
