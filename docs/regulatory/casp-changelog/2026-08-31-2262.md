- **#2262** — Agent-facing next-action text, not a rail change. The SDK's
  `nextActionForStatus` answered `wait_for_user_to_complete_payment` for the
  `approved` status; it now answers `stop_and_tell_user` with an explicit
  message, completing the #2101/#2145 sweep of the retired approval queue's
  statuses. **Unreachability was re-verified against the emitters rather than
  inherited from the claim in `types.ts`:** `approved` was an
  `approval_requests` status, #2055 dropped that table, and every INSERT/UPDATE
  of `payment_intents.status` in `infra/repositories/payment-intents.ts`,
  `x402-authorizations.ts` and `agent-rekeys.ts` writes one of
  `pending_signature`, `submitted`, `confirmed`, `expired`, `failed` — no write
  in the repository can mint it. The branch is a fail-closed fallback that
  fires only when the backend omits `next_action`
  (`raw.next_action ?? nextActionForStatus(...)`), so this is a **next-action
  correction on an unreachable branch, not a behaviour change on any live
  path**: no reachable payment changes its verdict, no authority, custody,
  route, refusal or signing scheme moves, and no money-movement code is
  touched. Confirmed independently that the backend cannot override the fix as
  it did before PR #2125: `messageForRail` — which used to overwrite the SDK's
  text for exactly these four statuses on `GET /payments/:id` — is deleted, and
  that endpoint does not route through `payment-state.ts` at all
  (`mapPaymentStatusResult` passes the server's own fields through). The
  OpenAPI half is documentation-only: `x-enumDescriptions` added to
  `AgentPaymentPhase` / `AgentPaymentNextAction` (mirrored from the SDK and
  pinned verbatim by `agent-payment-taxonomy.parity.test.ts`), the
  unemittable `type: 'approval'` member removed from the activity `oneOf`, and
  two always-null/always-zero fields annotated in the #2055 wire-compat style.
  Mutation-proven: restoring the wait, deleting the corrected message branch,
  and a positive control that answers `stop_and_tell_user` for every status
  each produce a named red in `payment-mappers.test.ts`, with each restore
  verified by `git diff --exit-code`. Perimeter unchanged.
