- **#2264** (epic #1440) — the CI harness stops pinning the retired rail, and the
  money-path perimeter gains the delegation rail's activation route. **No
  control, refusal, record or authority moves; one perimeter entry is ADDED and
  one dead SQL statement is deleted.**
  **Perimeter WIDENED, deliberately.** `packages/backend/src/routes/agent-connection-setups.ts`
  joins `globs` in `.github/money-path-globs.json` (and `.github/labeler.yml`
  and the `ship-next` Merge Gate, which CI pins to it in both directions). It is
  where an owner's approval becomes an agent's on-chain spend authority:
  `POST /agent-connection-setups/:setupId/budget-approval` calls
  `verifyDelegationSetupAuthority`, which reads `listActiveDelegations` and
  matches token, budget amount and period before the setup — and, since #1069,
  the agent — flips to `active`; the same file emits the `allowance_granted`
  funnel event and enforces one-budget-per-agent on the delegation rail. Its two
  siblings `routes/agent-delegations.ts` and `routes/agent-rekey.ts` were both
  already listed on exactly that rationale (#1892), and since #1984 made connect
  the ONLY onboarding path, the Safe retirement moved this third member of the
  family into the list's blind spot: a PR touching only this route got no
  `money-path` label, no `money.md` routing and no `qa-freshness` requirement.
  `globs` and not `controlGlobs`, because this is runtime code on the live rail
  that the deployed money-flow harness exercises — the same test that made
  #2200's docs-gate entry a control glob makes this one a real one.
  **One money-path SQL statement DELETED, and it could not execute.**
  `INSERT_LEGACY_INTENT_SQL` / `insertLegacyIntent`
  (`infra/repositories/payment-intents.ts`) wrote the AllowanceModule-rail
  `payment_intents` row. It has had **no production caller** since the rail
  retirement — verified by importer across `packages/`, not asserted: the 15
  live call sites were its own repository test plus 2 references in
  `modules/payments/__tests__/status-domain.test.ts`, and `routes/payments.ts`
  states the reason in place ("its `sign_hash`/raw-ECDSA sibling is gone").
  Every payment entry point answers HTTP 410 for an `allowance_module` account
  (#1986) **before** any intent row is reached, so the statement stood behind a
  refusal that fires first. **Nothing becomes unreadable:** no column, table,
  index or row is touched; existing legacy `payment_intents` rows keep every
  value and every read of them is unchanged, including `execution_rail IS NULL`
  rows written before #745. Its corresponding `db-schema-smoke.ts` PREPARE check
  goes with it — the same discipline `casp-changelog/2026-08-27-2118.md` records
  for the five approval-keyed checks, and the same one `db-schema-smoke.ts`
  already applies to `approval_requests`. The remaining curated money-path
  queries all still PREPARE against the schema.
  **The type it shared did NOT die with it.** `insertSendIntent` — the live
  `POST /machine-payments/send` insert — borrowed `NewLegacyIntent` for its
  column set. Deleting the interface with the statement would have deleted a
  live rail's input type by association, so it is renamed `NewSendIntent` and
  declared beside its one real consumer. No field changes; no wire or DB change.
  **The repository's lifecycle tests move to the live insert, not away from
  coverage.** `infra/repositories/__tests__/payment-intents.test.ts` seeded every
  claim/release/confirm/expire case through the legacy insert, i.e. proved the
  double-spend CAS on a rail that cannot spend. They now seed through
  `insertDelegationIntent` — same rows, same guards, a rail `POST /payments`
  can actually reach. The guards are columns of `payment_intents`, not of a rail.
  **Not run locally, and stated rather than glossed:** these are epic #1219
  real-Postgres tests and this machine has no Docker daemon, so they are proven
  by CI on this PR, not by a local green.
  **Harness truth, which is the issue's headline.** The Playwright fixture
  `e2e/fixtures/haven-api.ts` carried NO `account_type`, so `railOf` read every
  spec as a legacy Safe user and `browser_smoke` + `design_visual` pinned the
  rendered behaviour of a configuration that answers 410 in production. The
  default is now `delegator_hybrid`, with an explicit `legacySafe` opt-down — the
  inversion `scripts/screenshot.mjs` was corrected to across #2205/#2227/#2233.
  This is TEST-harness truth only: no product code changes, and the CASP-relevant
  consequence is that the evidence CI produces now describes the live rail.
  No route, schema, migration, credential, signing surface or custody boundary
  moved.
