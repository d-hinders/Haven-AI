- **#2295** — Contract documentation and one client-side display correction; no behavioral change on any money path. The `allowance_amount` field carried two incompatible wire shapes under one name — ATOMIC on the connect-setup budget request (`AgentConnectionAllowance*`), HUMAN-DECIMAL on the delegation-rail budget projection (`AgentAllowance`, produced solely by `rails/delegation-budget-view.ts` via `formatTokenValue`) — with nothing in the OpenAPI spec recording which. Both shapes are now named schemas (`allowanceAtomicAmount` / `allowanceHumanAmount`), the same distinction is applied to `configured_amount` and `onchain.amount` on `GET /machine-payments/allowances`, and `packages/core/src/api-types.ts` is regenerated. The shapes themselves are deliberately UNCHANGED: every route emits exactly what it emitted before, no request is validated more or less strictly (the spec is served as documentation by `routes/openapi.ts` and is not a Fastify validation schema), and no stored value is rewritten. The one code fix is the frontend catalog's advisory "within budget" badge, which compared a human-decimal budget against an atomic price via `BigInt()` inside a `try`/`catch` and silently answered "unknown"; it now scales by the token's decimals and answers. That badge is presentational — spend authority is the on-chain delegation and its caveat enforcers, which refuse an over-budget redemption regardless of what the badge said. No new authority, custody relationship, route, signing surface, signed-intent mutation, or API-credential spending ability. Perimeter unchanged.
