- **#2307** — Removes **56 unfalsifiable money-path test guards** across seven backend suites and adds the mechanical guard that stops them coming back. No production code changes: the diff is test files plus one new test-infrastructure module, and `git diff` against `dev` touches zero files under `routes/`, `rails/`, `modules/` or `infra/`. **Perimeter unchanged** — no new authority, no new custody relationship, no route, no signing scheme, no migration, no funds moved. What changes is the *evidence* behind an existing claim, which is why it is recorded here rather than absorbed.

  **The defect.** `rails/allowance-module.ts` exports six symbols (`AllowanceInfo`, `getProvider`, `getRelayerWallet`, `getTokenAllowance`, `getTokenBalance`, `getTokensForDelegate`). Seven test files mocked it with the wholesale-replacement form `vi.mock(spec, () => factory)` and declared five names it does **not** export — `getLatestBlockTimeSec`, `computeEffectiveAllowance`, `generateTransferHash`, `recoverSigner`, `executeAllowanceTransfer`. Vitest accepts a factory entry for a non-export silently, as a new function nobody calls, so every `expect(mocks.executeAllowanceTransfer).not.toHaveBeenCalled()` passed **unconditionally**. These were the money path's "the retired AllowanceModule rail cannot spend" guards (#1986, epic #1440). None of them could fail. Census re-derived independently with `/usr/bin/grep` on `origin/dev@0880131c`: 56 guards, matching the issue's per-file table exactly (x402 15, machine-payments 12, payments 11, payments-session-rail 7, non-custody-authz 5, allowance-rail-retired 4, non-custody-relay 2), plus 35 factory keys and 83 setup lines referencing the same five names. All 183 tests in those files pass identically before and after removal, which is itself the proof that the removed references were inert.

  **The property was real, so it was replaced rather than dropped — the #2202 rule.** Each removal was dispositioned against what it claimed. The "no spend executed" family could not be re-anchored onto another spy, because #1987 deleted the spend machinery: there is no surviving function for a spy to watch. It is now asserted **structurally** in `routes/__tests__/allowance-rail-retired.test.ts` § *the spend machinery is GONE, not merely refused* — the five deleted symbols are proven absent from backend production code outside comments and string literals, which is strictly stronger than a spy (a spy proves one request did not spend; absence proves no request can). That assertion carries a positive control proving the scanner can say *yes* and a population floor rejecting an empty scan, per the false-zeros discipline (#1897). Mutation-proven: re-exporting `executeAllowanceTransfer` from `rails/allowance-module.ts` turns it red **by name**. Three x402 validation cases whose only allowance-side assertion was a phantom were re-anchored onto the query log ("nothing beyond auth ran"); mutation-proven by issuing one lookup before the 400, which that assertion alone catches while the status assertion stays green. Comment and title text naming the deleted symbols as live was corrected in place.

  **Fail-closed re-measured after the sweep, because a suite that lost 56 assertions must be shown to still bite.** Three mutations, `dist/` rebuilt before each. (A) Removing the account-level refusal — `resolveExecutionRail` returning `delegation` for a legacy account — turns **83** named assertions red across five of the seven files. (B) Removing the intent-level refusal, `isRetiredAllowanceIntent` returning `false`, turns **11** red and is what covers the two contract suites that mutation A leaves green; that the two seams are separately mutable is the reason both were exercised rather than one. (C) Downgrading the 410 to a 403 turns **96** red across **all seven** files. Every one of the seven files goes red under at least one mutation, so none has had its guard removed along with its phantom. All production files were restored and verified with `git diff --exit-code`, never by inverting the edit.

  **The durable output is the guard against the fourth regrowth**, `packages/backend/src/testing/__tests__/mock-factory-exports.guard.test.ts`. It statically extracts every `vi.mock` factory's keys and every mocked module's real export names — following barrel re-exports — and fails on any key that is not an export. It lives in the backend suite (a required check) rather than in a lint rule, because an ESLint rule is one `eslint-disable` from being silenced in exactly the file that needs it; it reads the real export list every run rather than a hard-coded roster, so it stays correct when #2259 deletes three of this module's six exports; and anything it cannot parse is reported as a **failure**, never skipped, because a silent skip is how the first three rounds of this defect survived their own cleanups (#1987 → #2048 → #2044/#1993). It is itself mutation-proven by twelve fixture cases covering every factory shape in the tree.

  **The first draft of that guard had the defect it was written to catch, and `haven-reviewer` found it by injection rather than by reading.** It matched only a literal empty `()` parameter list, so `vi.mock(spec, async (importOriginal) => ({ ...(await importOriginal()), key }))` was neither checked nor reported — invisible. That silently excluded **26** factories, three of them on `rails/allowance-module.js` itself, and a phantom key injected into one of them was not detected. A guard with an unreported blind spot over the exact module the defect keeps regrowing on is the thing this issue exists to end, so it is recorded here rather than quietly fixed. The parser now walks each `vi.mock` call instead of pattern-matching one shape, and handles parameterised factories, `importActual` statement bodies whose returned literal carries the overrides (31 occurrences — the intermediate draft reported all of them as unreadable, which would have been a red gate over legitimate code), and factory-less auto-mocks. **The invariant is now pinned mechanically:** checked + unparseable + auto-mocked must equal the raw count of relative-specifier `vi.mock` calls in the tree, so a future parser change that stops seeing a shape fails the gate instead of shrinking the guard's reach in silence. Re-running the reviewer's exact injection now turns it red by name. **Round two of the same review then found the invariant itself had a hole**: the detector and the auditor each carried their own single-quote-only specifier regex, so a double-quoted `vi.mock("…", …)` was invisible to BOTH at once — phantom undetected and invariant silent, which is the one shape a cross-check cannot catch when the two halves can drift apart. Both now read one exported quote-agnostic expression (`countRelativeMockCalls` / `MOCK_SPEC_QUOTES`), mutation-proven with the reviewer's own double-quoted phantom. Two residuals recorded rather than fixed: a statement-body factory with multiple `return {` literals would have only its first read (zero occurrences today), and the string-stripping limit above. Accepted residual, stated because it is a real limit: the structural absence assertion strips string literals, so a reintroduction assembled from string fragments would evade it; the threat model is accidental regrowth by ordinary editing, and deliberate evasion is a `CODEOWNERS` and review control, not a source-scan one. Run against `dev` it immediately found a **57th** instance the issue's five-name census could not see: `modules/mpp/__tests__/delegation-remaining.test.ts` mocked `infra/repositories/agents.js` declaring `listAllowanceConfigForAgent`, a function #2020 deleted, on a module that unit never imports — the #2048 shape, regrown. Removed in this PR.
