- **0.1.34-alpha.0 release** — **three fixes to the published packages; no
  authority, custody or execution boundary moves.**
  Carries exactly three commits touching the published set since the
  `0.1.33-alpha.0` tarballs (built from `main@9c015a2c`, promoted earlier the
  same day):
  **#2361** (PR #2364) — the x402 v2 payment envelope echoes the merchant
  challenge's `resource`/`extensions` verbatim, per the spec MUST and the
  Base-mainnet live bisection that confirmed the missing echo as CoinGecko's
  rejection cause; per-change analysis, invariants and residual risk are in
  this changelog's `2026-09-01-2361.md` shard and are not restated here.
  **#2362** — comment and agent-facing string wording (Haven "declared", not
  "authorised"); attribution language only, no behaviour.
  **#2359** — the shipped skill text no longer instructs agents to pass an
  undeclared `payment_required` argument to `haven_complete_mcp_tool`;
  guidance text only, no tool schema or behaviour change.
  **Release mechanics:** versions, cross-package pins, source version
  constants and the runtime-manifest table were rewritten atomically by
  `release-bump.mjs` (nothing hand-edited); publishing remains gated on the
  `dev → main` promotion, whose deploy also carries the server-side half of
  #2361 (the widened hosted-relay preflight) in the same merge — so no
  published client can outrun the prod validator that accepts its envelope.
  The consent surface is byte-unchanged since the `0.1.33` tarballs
  (`packages/mcp/src/tools.ts` and `consent.ts` verified identical to
  `35ea2701`), so no operator is re-prompted on upgrade.
  Perimeter unchanged — this release alters what the wire envelope carries
  around an unchanged signed authorization, and nothing about who may spend,
  sign, or execute.
