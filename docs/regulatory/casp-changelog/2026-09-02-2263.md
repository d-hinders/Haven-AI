- **#2263** — **dropped five inert Safe/session-rail schema objects and repointed `user_safes.execution_rail`'s DEFAULT from the retired AllowanceModule rail to the live delegation rail. No authority, custody or execution boundary moves; the only behavioural change is what an insert that says nothing gets.**
  Migration `075_drop_inert_safe_rail_schema` (epic #1440). Two halves, and only
  the first is behavioural.
  **The DEFAULT was the live hazard.** `036_execution_rail.ts` created
  `user_safes.execution_rail` as `NOT NULL DEFAULT 'allowance_module'`, and no
  later migration touched the default — `041` dropped only the CHECK. Nothing
  was broken, because the sole live insert (`routes/hybrid-accounts.ts`)
  hardcodes `'delegation'`; the hazard was latent and forward-looking, in that
  a future insert omitting the column would have silently provisioned a NEW
  account onto a rail that fail-closes at payment time (#1986). Repointed at
  `'delegation'`. **Existing rows are deliberately NOT rewritten** — a
  `SET DEFAULT` touches no row, and an `UPDATE` here would have been the
  authority-relevant change this one is not: it would silently promote retired
  accounts onto the live rail, the opposite of fail-closed. A row marked
  `allowance_module` or `session_key` keeps its value and keeps resolving to
  its own tombstone through the unchanged `resolveExecutionRail` seam, with
  its own 410 body. Pinned by a real-DB test that inserts without the column
  and asserts `'delegation'`, and by a paired test that seeds a legacy row,
  re-runs `up()` and asserts it still reads `allowance_module`.
  **The five drops are inert by construction**, each verified by grep across
  `packages/` and `scripts/` in both package-path and same-directory relative
  import forms before the change, not inherited from the issue:
  `agent_allowances` (last writer deleted by #2020; the agent `allowances`
  projection has come from active `agent_delegations` since #1090),
  `self_sign_agent_allowances` (untouched since migration `004`; its live
  sibling `self_sign_agents` is deliberately spared),
  `agents.session_permission_id` (Smart Sessions, rail retired by #834; every
  live grep hit was on `payment_intents`), `payment_intents.session_user_op`
  (in the INSERT list but bound `?? null` with zero suppliers, superseded by
  `prepared_user_op`), and `payment_intents.session_permission_id` (the same
  no-supplier proof, but PUBLISHED — removed from both `agent-activity.ts`
  feed queries, from `GET /agents/:id/activity`, from the OpenAPI spec and
  from the generated `api-types` in this same change, so schema and wire move
  together). `069_drop_safe_approver_metadata.ts:22` had spared
  `agent_allowances` citing "four live writers and five live readers" — true
  when written, falsified by #2020; its shrink guard is updated here rather
  than deleted, to the narrower claim that 069 is not the migration that
  dropped it.
  **`payment_intents.allowance_nonce` is DECIDED and KEPT, not deferred a
  third time.** It is inert in the same sense — `NOT NULL` since
  `000_initial.ts`, all three live writers pass a literal `0` — but unlike the
  five above it is read back and published as `sign_data.components.nonce`
  (`routes/payments.ts`), inside a block whose shape mirrors the
  `executeAllowanceTransfer` argument list. Dropping it is therefore a change
  to a money-path RESPONSE shape, needing characterization tests over that
  surface, and does not belong in an otherwise purely subtractive-and-inert
  migration. Recorded at the column's three writers, at its publication site,
  in the migration header, and pinned by an assertion that fails loudly if the
  column is later dropped without the reshape.
