  budget, balance or wire format is touched, no key or signature is created,

  **What the entry guards.** The hosted MCP server (`packages/mcp-server/`,
  Docker-deployed from `dev`, never on npm) constructs and relays payments over
  Streamable HTTP and holds no key — the edge signer signs (§ *Hard Architecture
  Invariants*, `docs/architecture/08-local-vs-hosted-mcp.md`). Its `tools.ts`
  is where a caller's intent becomes a sequence of Haven API calls, and that
  sequencing is a money decision: #2282 (PR #2296) was `haven_settle_mcp_tool`
  relaying the funding userop *before* checking the merchant-call context
  existed, stranding the caller with a `funded_but_unsettled` intent —
  reproduced on dev with real Base Sepolia transactions; #2312 (PR #2355)
  measured over a real transport that the MCP SDK strips undeclared keys before
  the handler, so a caller's `tx_hash` was silently dropped on
  `haven_report_x402_outcome`; #2348 (PR #2368) measured that a stripped
  `idempotencyKey` on `haven_send` sent `POST /payments` with no
  `idempotency_key` at all — a retry was a second spend — and on
  `haven_pay_mcp_tool` *replaced* the replay scope with a 300 s bucketed hash of
  the merchant quote; #2051 was a merchant-steerable cap bypass in the same file,
  measured at 900 USDC authorized against a stated 1 USDC cap. PR #2296 changed
  `tools.ts` and carried `area:mcp, area:docs` — the #1896 shape, a file whose
  omission gave the right answer for the wrong reason, because a human had
  labelled the issue.
