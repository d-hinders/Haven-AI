- **#2403** — **a test-and-docs-only change: ten added unit tests pin existing
  demo-merchant refusal behaviour, and one README paragraph stops carrying a
  test count. No production code, no authority, no perimeter movement.**
  `assertExtensionsEchoed` in `packages/demo-merchant-mcp/src/x402.ts` runs,
  in order: the `x402Version` cross-check; an early accept when the CHALLENGE
  advertised no `extensions`; a presence/shape guard on the echoed
  `extensions`; and subset containment via `objectContainsSubset`. After
  #2361 and #2397 (PR #2401) the version cross-check, a dropped echo, an
  overwritten value and an append were pinned. The README section #2383
  (PR #2399) wrote from code inspection and a live capture also claims that a
  non-object echo (array, string, `null`), a dropped top-level or nested key
  and `extensions: {}` are refused, that a refusal is an HTTP 402 re-sending
  the challenge in `PAYMENT-REQUIRED` with the body's `error` replaced, and
  that the `X-PAYMENT` alias is enforced identically — none of which a test
  pinned. This adds those tests in `src/x402.test.ts` (seven cases: array,
  string, `null`, top-level drop, nested `echoRule` drop, `{}`, and the
  no-advertised-extensions accept) and `src/http.test.ts` (three cases at the
  HTTP boundary asserting the exact refusal strings the README quotes, the
  `PAYMENT-REQUIRED` re-send, the absence of `PAYMENT-RESPONSE`, and the alias
  path through `getPaymentHeader`). `src/x402.ts` and `src/http.ts` are
  byte-unchanged, verified by `diff -q` against `cp` copies taken from
  `origin/dev` before any mutation run.
  **Why a test-only diff is on the CASP record at all.** It is not a
  money-path change — `packages/demo-merchant-mcp` appears on no glob in
  `.github/money-path-globs.json` (zero matches), the issue carries no
  `money-path` label, and the demo merchant is a counterparty in the QA
  harness, never a custodian of user funds. The shard exists because
  `casp-risk-guardrails.md` declares `covers: packages/demo-merchant-mcp/src/**`,
  which is broader than the money-path perimeter and fires the blocking
  contract-doc gate on any change under that path, tests included. The gate
  firing is not evidence of perimeter movement.
  **Direction of risk: none, in either direction.** Nothing is grantable that
  was not grantable before, and nothing that was refused before is now
  accepted; no non-test byte moved, so what the merchant settles and what any
  refusal says are unchanged. The merchant's deliberate strictness — a Haven
  client that stops echoing fails in the Sepolia QA harness rather than at
  the first strict mainnet facilitator — is unchanged in substance and is now
  pinned on every branch the README describes, at both the rule and the wire.
  **Mutation-tested, each new test red by name.** Ten mutations of the two
  guarded files, each restored via `cp` and verified with `diff -q` (exit 0)
  before the next: deleting the version check reds the two version tests plus
  the new alias test; weakening the presence guard to `!echoed` reds the
  array and string cases and nothing else; letting `null` through reds the
  `null` case alone; deleting the no-advertised-extensions early return reds
  that accept test alone; tolerating a missing key reds top-level drop, nested
  drop, `{}` and the HTTP `{}` test; skipping nested containment reds nested
  drop and the existing overwrite test; swapping subset/superset reds `{}`,
  nested drop, the existing append test and the HTTP `{}` test; dropping the
  `X-PAYMENT` fallback in `getPaymentHeader` reds the new alias refusal and
  the existing alias accept; treating `PaymentError` as a fault reds all three
  HTTP tests and the existing #1517 policy-rejection test; re-sending the
  `PAYMENT-REQUIRED` header without the reason reds the dropped-echo HTTP test
  alone. Where a mutation reds more than one test the tests share the guard,
  and each still has a distinct red-set across the ten. Suite 53/53 on the
  restored tree; the full package suite 105/105.
  Perimeter unchanged — tests and one README paragraph were added or edited,
  no production code was touched, and nothing about who may spend, sign, or
  execute is different.
