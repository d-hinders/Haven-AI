- **#2424** — **`@haven_ai/connect` gains an explicit, developer-local runtime-spec override (`HAVEN_SIGNER_SPEC` / `HAVEN_SDK_SPEC` / `HAVEN_MCP_SPEC`) that changes which signer/SDK/MCP build npm installs on the developer's own machine. No authority, custody, signing or execution boundary moves; a production install with no variable set is byte-for-byte unchanged.**
  Slice 4 of epic #2420. `prepareSignerRuntime` and `prepareLocalMcpRuntime`
  read the three variables from the injected `env` (default `process.env`)
  BEFORE creating any directory or invoking npm; a set-but-malformed value
  (empty, whitespace, control character, shell metacharacter) is refused with
  an error naming the variable and nothing on disk. An active override installs
  into `~/.haven/signer-runtime/override-<12-hex sha256 of the resolved specs>`
  (or `mcp-runtime/override-…`), never into the version-named directory the
  pinned path reuses; is never reused between runs; is printed first in setup
  output (`RUNTIME SPEC OVERRIDE ACTIVE …`, and by `--rekey-finish`); is
  recorded in the sidecar under `runtime_spec_override` with the versions npm
  actually laid down; is written as a comment into the wrapper the agent client
  launches; and is reported by `--doctor` as a FAILING `runtime_spec_override`
  check whenever the sidecar records one or a variable is set in the doctor's
  shell. The env is threaded through `installRuntime`, `--doctor --repair` and
  `--rekey-finish`, each proven by execution. Environment variables rather than
  a flag, so all three entry points honour one override and it never appears in
  the dashboard-minted command.

  construction: an agent following the printed setup command cannot pass it by
