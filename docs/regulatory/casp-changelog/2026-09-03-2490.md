# 2026-09-03 — #2490: split the demo merchant's settlement-gas readiness signal into warn and fail bands

One safety-gate change in `packages/demo-merchant-mcp` and the QA harness that
reads it, and the gate LOOSENS in exactly one place by design: until now
`settlementReadiness()` reported a single boolean (`ok`, below
`MIN_SETTLEMENT_HEADROOM = 25`), `preflight.ts` mapped `ok === false` into
`blocked`, and the warning threshold acted as an incident — three consecutive
`qa-dev` failures at 24 settlements, one below the floor (#2485), while ~3
runs of real capacity sat unused. The signal is now a three-state band
(`SettlementBand = 'usable' | 'warn' | 'fail'`) carried from the merchant on
`/healthz` as `status` plus both floors (`warn_floor`, `fail_floor`, alongside
the pre-existing `settlements_remaining`/`cost_per_settlement_wei`); the
harness renders the merchant's own band (`ResourceCheck.warn` → `⚠`, printed
on every run with the top-up action) and sets `blocked` ONLY on the fail band.
Floors: warn stays 25 (the old value, now occupying its documented
"warning for a slow drain" role); fail is NEW at 12 — one full run (~8
settlements: seven 0.001-USDC merchant legs plus the 0.010 direct settle) plus
half a run of headroom — so the gate still refuses a run that cannot complete
(the #1530 255-gwei condition: 0 settlements, far below 12, still blocks, and
that state is pinned by test) without re-creating the #2485 dead-wallet shape.

Perimeter check against the CASP guardrails: **the perimeter is unchanged** —
checked, not assumed: no edit to `.github/money-path-globs.json`, no new
endpoint, no route, no schema, no authority/custody/signing surface touched,
and no money moves. `packages/demo-merchant-mcp/src/x402.ts` + `src/http.ts`
are inside the guardrails doc's existing `covers:` globs
(`packages/demo-merchant-mcp/src/**`); the change is observability plus the
block/refuse boundary moving DOWN from 25 to 12 — fail-closed remains
fail-closed for the state that cannot complete a run (0 settlements still
refuses, pinned), and what loosens is only the band that was documented as a
warning all along. `ok` stays on the wire additively, and a merchant predating
the band field degrades to the old single-boolean behaviour (pinned), so the
rollout cannot silently pass a wallet that today would block. Both packages'
suites and typechecks run green in this PR; the fail floor's value is
justified against #1530 in the PR body.
