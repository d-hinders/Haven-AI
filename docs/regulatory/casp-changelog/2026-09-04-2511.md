# 2026-09-04 — #2511: the Base Sepolia RPC default became visible and the QA observer node became configurable

Configuration visibility, not a money-path change. `packages/backend/src/config.ts`
gained `warnPublicBaseSepoliaRpc`, a boot warning that fires once when
`RPC_URL_BASE_SEPOLIA` is unset (the default public endpoint
`https://sepolia.base.org` in use, outages surfacing as qa-dev failures), and
`packages/qa-agent/src/lib/chain.ts` reads `QA_RPC_URL_BASE_SEPOLIA` instead of a
hardcoded constant, so the harness's observer node can be moved without touching
the node the backend writes through. Two env knobs, deliberately kept two.

**Why it touches the CASP perimeter at all.** `casp-risk-guardrails.md` covers
`packages/backend/src/config.ts` by exact path, so any change there is asked
whether it moved a safeguard. This one did not: the change adds a `console.warn`
at boot and wraps an existing `optionalEnv` resolution — the resolved value is
byte-identical to the previous default (`https://sepolia.base.org` when unset),
the warning carries no secret and prints no credential, and no route, policy,
spend-authority check, signing path or gate reads the new function. The QA-side
change is in a test-only package that holds no keys and writes nothing on-chain;
the scenarios' two-node property is preserved by construction (the observer
default is unchanged; only its configurability was added).

**Why the two endpoints must stay two.** The harness deliberately reads a second
node: an on-chain assertion verified on the node the backend wrote through would
only prove the backend agrees with itself. The new `QA_RPC_URL_BASE_SEPOLIA`
therefore gets its own variable, defaulting to the same public endpoint, and the
runbook records that pointing both variables at one URL would delete that
independence.

**Mutation-checked by unit test, both directions.**
`packages/backend/src/__tests__/config-rpc-sepolia.test.ts` asserts the warning
fires exactly once on the public default and is silent on a configured provider
endpoint; the boot behaviour itself was proven by running the backend both ways
(unset → warning present; set → absent) and recorded in PR #2511's body.

Perimeter unchanged: no key, credential, custody or authority surface moved;
the diff's only runtime effect is a log line and an env-read default that
resolves to the same URL as before.
