# 2026-09-04 — #2515: the connector command examples in two package READMEs became channel-neutral

Served-prose only. No code, no route, no policy, no gate. `packages/connect/README.md`
and `packages/signer/README.md` printed `npx @haven_ai/connect@alpha` in their command
examples; those examples now read `@haven_ai/connect@<channel>`.

**Why it touches the CASP perimeter at all.** `casp-risk-guardrails.md` covers
`packages/connect/**`, so any change under that path is asked whether it moved a
safeguard. This one did not: the connector's behaviour, the signer's refusal to sign an
`x402_expected_context_version` it does not know, and every spend-authority check are
untouched by a README's prose. What changed is which package a *reader* is told to
install.

**The defect it fixes, stated as the artifact.** `README.md` is in each package's
`files` array, so it ships inside every tarball and is the npm landing page for every
channel. A `@dev` snapshot's landing page therefore instructed its tester to install the
**production** connector. Measured on `dev` before this change: `packages/connect/README.md`
carried 10 × `connect@alpha` against 2 × `connect@dev`, and `packages/signer/README.md`
1 × `connect@alpha`. Measured here rather than quoted from the issue: `npm pack @haven_ai/connect@dev`
fetched `0.0.0-dev.202609031827.893d74f`, whose `dist/` contains **zero** hard-coded
channel strings (#2423 assembles the spec at runtime from `HAVEN_CONNECTOR_CHANNEL`)
while the `README.md` in that same tarball carries **10** × `connect@alpha`. The code
half of epic #2420 already worked; only the prose disagreed with the artifact shipping
it, in the artifact itself.

**Why a placeholder rather than a release-time rewrite.** Two shapes were open (#2515
names both). The examples already carry placeholders — `hv_setup_...`, an
`api.haven.example` URL — and the README already tells the reader to copy the dashboard's
command instead of these. The channel was the one concrete token in an otherwise
non-copy-pasteable line, which is false precision rather than convenience. Teaching the
reader to read `connector_package` from the setup response also matches the mechanism
#2422 established as authoritative. The alternative — teaching `release-bump.mjs` to
rewrite prose — would add a new class of work to the release path, which today rewrites
only structured constants and one generated table.

**Money-path classification, corrected.** An earlier reading of this change called it
not-money-path. That was wrong, and wrong twice over: `packages/signer/**` is a
package-wide entry in `.github/money-path-globs.json`, so `packages/signer/README.md`
matches the perimeter by FILE, and issue #2515 also carries the `money-path` label — the
rule is label OR file. Re-take it rather than trusting a number here:

```
node scripts/ci/money-path-classify.mjs $(git merge-base origin/dev HEAD)
# MONEY-PATH (globs)  packages/signer/README.md  ["packages/signer/**"]
```

The matched file and the verdict are what this shard asserts; the classifier also
prints a ratio against the diff's total file count, which moves with every commit to
the branch and is not quoted here for that reason. Two earlier readings in this PR got
it wrong in opposite directions — a `0 of 0` from running the classifier before
committing, against an empty diff, and then a `1 of 5` that was already `1 of 7` by the
time the commit asserting it had finished growing the diff. Both were the same mistake:
a figure measured at one moment and quoted at another. Nothing further is owed beyond this shard: no runtime code, no
route, no policy and no gate changed. The `dev → main` promotion will ask for a covering
green money-flow QA run because a runtime glob matched, which is mechanical overhead
rather than a signal about this change.

Production is still `@alpha`, and each README says so in prose beside its first
example; the later command examples carry a one-line pointer back to that definition
rather than repeating it.
