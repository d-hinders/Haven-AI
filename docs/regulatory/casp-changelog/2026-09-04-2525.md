# 2026-09-04 — #2525: the CLI gains a machine contract; no authority, no key material, no new dependency

CLI-only. `packages/cli/src/**` — new `errors.ts` (exit-code taxonomy),
`output.ts` (the `--json` emitter), `token.ts` (reads `exp` out of the stored
session JWT), `agent-guidance-text.ts` (generated copy of the #2523 runbook),
and a rewrite of `commands.ts` so every command and every refusal emits through
one place. No backend, route, schema, rail, budget, delegation or signing
change.

**Why it touches the CASP perimeter at all.** `casp-risk-guardrails.md` covers
`packages/cli/**`, so any change under that path is asked whether it moved a
safeguard. The classifier's file half says no — re-take it rather than trust
this shard:

```
node scripts/ci/money-path-classify.mjs $(git merge-base origin/dev HEAD)
```

No `packages/cli/src/**` path is in `.github/money-path-globs.json` under
`globs` or `controlGlobs` (the classifier's own self-test lists
`packages/cli/src/commands.ts` as a known negative), and the issue carries no
`money-path` label.

**What changed, as authority.** Nothing. The CLI could already do exactly these
things; what changed is how it *reports* them. Every command it dispatches is
the same owner-authenticated read or backend-only management call it made
before — no route was added, and the on-chain actions this CLI has never been
able to perform (budgets, sends, signer changes, re-key) are still absent from
its dispatch table. The exit-code split (`3` not authenticated vs `4` refused)
changes which number a caller sees, never which call is permitted: a 403 that
was refused before is refused now.

**Custody.** Unchanged, with one new read worth stating precisely. `token.ts`
base64url-decodes the *payload segment* of the session JWT to report
`expires_at` in `whoami --json` and `login --json`. It does not verify the
signature and must not be used to decide anything but what to print — the CLI
holds no verification key, and a forged `exp` would only mislead the user about
a token the backend rejects on its own terms. The token itself is never logged,
echoed or returned; a test asserts that neither the password nor the token
appears in stdout or stderr in either output mode. The session file, its 0600
permissions and its location are untouched.

**One secret does reach stdout, deliberately and unchanged:** `agents
rotate-key` prints the new API key, because the key IS that command's payload
and printing it once is the point. What moved is the *sentence* around it,
which now goes to stderr under `--json` so stdout stays a single parseable
object — the secret is in exactly one field rather than adjacent to prose.

**No new dependency, and that is a safeguard rather than an aesthetic.** The
issue specified an exact-pinned `@haven_ai/sdk` import for `haven guide`. That
would put ethers + viem + x402 — ~94 MB measured in this repo's `node_modules` —
on the `npx @haven_ai/cli` path, which is the path an agent uses, and would
widen the CLI's supply-chain surface from zero runtime dependencies to a full
crypto stack in order to print one Markdown string. Owner decision in-session:
generated copy plus a byte-equality test, the
`packages/frontend/src/lib/agent-skill-bundle.ts` precedent. A test asserts the
package's `dependencies` stay empty, so the constraint is enforced rather than
remembered.

**Mutation-proved by execution**, each file restored from a content-verified
backup afterwards (the table with SHAs is in the PR body): (1) the pre-parse
`--json` scan removed → 44 contract assertions go red; (2) one byte changed in
the generated runbook → the parity test goes red; (3) a command dropped from
`COMMANDS` → the drift test that reads `dispatch`'s own case labels goes red.

Perimeter unchanged.
