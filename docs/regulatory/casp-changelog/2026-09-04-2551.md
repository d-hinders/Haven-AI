# 2026-09-04 — #2551: a bare connector setup over a live previous agent is decided before registration, not overwritten and warned about afterwards

Connector-only. `packages/connect/src/**` — a new `wiring-collision.ts`, and
`runtime.ts`, `args.ts`, `connect-error.ts`, `unwire.ts` (two helpers extracted,
behaviour unchanged) and `installed-clients.ts` (one function exported). No
backend, route, schema, rail, budget, delegation or key-handling change.

**Why it touches the CASP perimeter at all.** `casp-risk-guardrails.md` covers
`packages/connect/**`, so any change under that path is asked whether it moved
a safeguard. The classifier's file half says no — re-take it rather than trust
this shard:

```
node scripts/ci/money-path-classify.mjs $(git merge-base origin/dev HEAD)
```

No `packages/connect/src/**` path is in `.github/money-path-globs.json` under
`globs` or `controlGlobs`, and the issue carries no `money-path` label.

**What changed, as authority.** Nothing. A second setup on one machine used to
resolve an existing-agent collision *after* the fact: the #1569 remove-first
install re-pointed the bare `haven` / `haven-signer` pair at the new agent, and
the #1688 heads-up then told the user their previous agent still held a live
key. The connector now resolves it *before* `POST /agent-connection-setups/:id/register`
— a terminal is asked to replace or install alongside; a non-interactive run
refuses with `wiring_collision`, minting no key, registering no agent, writing
no file, leaving the setup token unused. The `--replace` path re-points the pair
exactly as before and then retires the superseded directory **locally**:
tombstone (#1681), then the same key-material teardown `--unwire` (#2169)
already performs, and only once the runtime install actually completed. That
narrows local exposure — a directory `--doctor` would have called
`superseded` (still spend-capable) now reads `retired` — and widens nothing.

**What it deliberately does not do.** The connector never calls
`POST /agents/:id/revoke`. That route reads `request.user.sub` — owner
authentication — and the connector holds agent API keys only; an agent
credential revoking a sibling agent would be exactly the "agent editing its own
authority" the re-key routes (#1694) refuse. The replace path prints the
superseded ids and the dashboard instruction; the owner revokes. The dashboard-
side offer is #2561, filed separately because it lands on
`routes/agent-connection-setups.ts`, a money-path glob. The one backend
sentence this change would have liked — the setup prompt naming the collision
refusal as a relay case beside `approval.required` — is handed to B6 #2528,
which already rewrites that prompt's `--json` paragraph on that same
money-path file. The refusal's own message carries the relay instruction, so the
connector behaves correctly without it.

**Custody.** Unchanged. No key leaves the machine; the delegate key is never
read by the collision check (it reads `identity.json` for `api_key` presence
and `agent_id`, `TOMBSTONE.json` for existence, and `signer-runtime.json` for
`server_name`). The teardown deletes `signer.json` and `rekey-pending.json` and
strips `api_key` from `identity.json` — the #2169 teardown, byte-for-byte the
same helper.

**Mutation-proved by execution**, each cell restored from a content-verified
backup afterwards (the table with SHAs is in the PR body): (1) the collision
check skipped → the refusal test goes red on `registerSetup` having been
called; (2) the prompt gate loses its TTY half → the shared-gate test goes red
on a prompt reaching a non-TTY run; (3) retirement ignores a failed install →
the errorCode test goes red on a tombstone that should not exist; (4)
retirement moved before the install → the same test goes red for the same
reason.

Perimeter unchanged; local exposure narrowed on the `--replace` path.
