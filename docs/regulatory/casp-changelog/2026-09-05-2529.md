- **It reads. It never writes.** `queryFunnelSegments` issues one `SELECT`.
  `emitFunnelEvent`, the only writer in the file, is untouched — byte-for-byte
  identical, and its existing tests are unchanged.
- **`queryFunnel` is untouched.** The segmented read is a SEPARATE exported
  function rather than a widened one, so the unsegmented path still runs the
  same two statements in the same order. This is why no characterization test
  was required: no existing money-path behaviour changed. A caller that omits
  `segment` receives a byte-compatible body — asserted, not assumed
  (`analytics.test.ts`: "omits segment and segments entirely when none was
  asked for").
- **Authorisation is unchanged.** The route keeps `authMiddleware` and the
  `DashboardJwt` security requirement it already had. No new route, no new
  credential, no public surface. The middleware matcher change is on the
  FRONTEND and adds observation only — it logs a User-Agent classification and

- **No new data is collected.** Every value read here was already stored and
  already echoed into funnel metadata by #2522 and #2528. This slice queries
  what exists; it adds no field, no header and no ingest endpoint. The #2302
  rule that there is no unauthenticated analytics write endpoint is preserved
  — nothing here accepts a write at all.

## One correctness property worth recording

The metric is **per-user attributed**, not per-event. `handoff_via` and
`run_mode` are written by only two emissions (`signed_up`, `agent_created`);
`first_payment_settled` carries neither. A per-event split therefore reports
agent-driven signups and then zero agent-driven first payments — a number that
reads as "agents never convert" and means only that a later event does not
restate the marker. That is a reporting-accuracy concern rather than a
regulatory one, but it is the kind of plausible-looking wrong number this
document exists to keep out of a metric, so it is pinned by a real-DB test and
mutation-proven: making the query per-event turns 4 of 10 tests red.

`segment=via` reads the metadata key `handoff_via`, never the older `via` key
that names which code path created a record. Pointing it at `via` turns 5 of 10
tests red.
