## Why this document was implicated at all

`docs/regulatory/casp-risk-guardrails.md` `covers:` `packages/sdk/src/**`, and
this change edits `packages/sdk/src/agent-guidance.ts`. That is the coupling
working as intended: the file it edits is **agent-facing product copy that makes
an authority claim**, which is exactly the class § *Product Copy Rules* governs.
A diff can be non-money-path and still need this document read.

## What the copy claims, checked against the Use/Avoid lists

The prompt tells an agent who authorises what. Audited against § *Product Copy
Rules*' avoid list by executing the check over the **rendered** string rather
than reading it:

```
avoid-list hits: none
positive control ("Haven sponsors") found: true
attribution present: true
```

The positive control is the point: a "none found" from an instrument that cannot
find anything is not evidence. `Haven sponsors` is a phrase the prompt genuinely
contains, matched by the same substring check that reported zero avoid-list hits.

Attribution, in the prompt's own words:

- "Please set up Haven so you can pay for things **within a budget I approve**";
- "Two things only I can do: **approving that budget with my passkey**, and
  funding the account";
- the budget-approval rule is `AGENT_APPROVAL_RELAY_JSON_SENTENCE`, imported
  verbatim, so the prompt cannot restate the approval gate in weaker words than
  the setup prompt uses.

Nothing says Haven holds, manages, transfers, executes, or gives an agent access
to a wallet. `Haven sponsors the gas` is pre-existing product copy, already in
the `/for-agents.md` funding hand-off (#2523), and it describes gas sponsorship —
not custody and not a transfer on the user's behalf.

## The three invariants this slice could have weakened, and did not

Epic #2519's own list, checked against the diff rather than assumed:

1. **The human keeps every signature.** The prompt adds no capability. Both
   commands it names existed before it: `haven login` mints a `purpose:
   owner_cli` token that is fail-closed and cannot sign, approve a budget,
   change signers or re-key (#2526), and `haven agents connect` calls the same
   owner routes the dashboard modal calls (#2527). This change adds no route, no
   allow-list entry and no permission.
2. **No headless account path.** The prompt's first sentence is *"I have a Haven
   account and I am signed in"* — it is offered only to a signed-in user, and on
   the dashboard it is additionally gated on `hasAccounts && canConnectAgents`.
3. **Never suggest the agent enters the user's password.** Stated explicitly and
   asserted by test: *"It prints a link and a code and does not need my password
   — it must never ask for it."*

## No secret, and that is asserted rather than intended

Unlike the setup prompt, this string carries no one-time token and no
credential — which is what makes it safe to render on an empty state, before any
setup exists. `packages/frontend/src/lib/__tests__/agent-onboarding-prompt.test.ts`
asserts the absence (`sk_agent_`, `sk_live_`, `--setup `), so a later edit that
introduced one would fail rather than ship quietly.

## Scope of this shard

It covers the copy's authority claims and the invariants above. It does **not**
re-verify the rest of `casp-risk-guardrails.md`; per the #2323 advisory the
parent's § *Product Copy Rules* was re-read against this diff and needs no edit,
and that is recorded here rather than by bumping a date on a document this change
does not alter.
