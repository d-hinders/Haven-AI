- **#2548** — **npm metadata only: the five published packages' `package.json` `homepage` field is repointed from the dead `https://haven.xyz` to the public repository (`https://github.com/d-hinders/Haven-AI`). No key, signature, payment, authority, custody or execution boundary moves; nothing executable changes.**
  The five packages are `@haven_ai/sdk`, `cli`, `connect`, `mcp` and
  `signer`; the diff is one string in each `package.json` and nothing else —
  no version, no dependency pin, no `scripts`, no `files` field, no engine
  range. `git diff` on this PR shows exactly five one-line changes plus the
  new guard test and this shard.
  **Why this is money-path at all.** By the FILE half only:
  `packages/signer/**` is a perimeter glob (#1896/#1905 — the package that
  holds the delegate key). The `homepage` field is registry-page metadata
  npm renders on npmjs.com; it is not imported, compiled, executed or read by
  the signer package or by anything that depends on it, and no route, tool,
  schema or signing scheme is touched. No request that was accepted before is
  refused now, or the reverse.
  **Why it is worth a CASP read anyway.** The npm page for `@haven_ai/signer`
  is a disclosure surface of the custody-adjacent artifact: an auditor —
  human or agent — landing there follows the Homepage link to answer "what is
  this, who ships it". Until this change that link resolved to
  `Could not resolve host`, the same defect class #2520 found in the
  agent-readable artifacts: a dead pointer that nothing failed on. The
  repository is now the advertised home, which is the same target #2520 used
  for the product-docs link; a production host does not exist in this repo
  yet and was deliberately not invented.
  **What this shard does NOT claim.** That the npm pages are updated: npm
  renders the field from the published tarball, so the five pages carry the
  new link with the next publish, and no release is cut by this issue. Nor
  that a homepage link is a security control — it is a disclosure correction,
  enforced henceforth by `scripts/ci/npm-homepage-guard.test.mjs`.
  **Enforcement.** The new guard fails any `packages/*/package.json` whose
  `homepage` names one of the three dead hosts (`haven.xyz`,
  `app.haven.xyz`, `docs.haven.xyz`), points at a host outside the
  allow-list (`github.com` only), or drifts from the other packages' value.
  Positive controls: the guard is an exported function over synthetic
  manifests and its self-tests assert it reports the exact pre-fix value
  `https://haven.xyz` as a violation. Mutation proof on the real tree:
  repointing `packages/sdk/package.json` at `https://haven.xyz` turned
  "the real workspace is clean" red (10 pass / 1 fail); the file was restored
  byte-identical (sha256 `3c1680d86d4961451362547726241cad4e3a897df7c5d886c3495bdc002386cf`
  before and after) and the suite returned to 11/11.
