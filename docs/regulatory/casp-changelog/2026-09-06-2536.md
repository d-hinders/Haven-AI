**#2536 — the CLI's `--help` banner said the tool is a companion to the dashboard.** Text
only: one line in `helpText()` (`packages/cli/src/args.ts`), its pinning assertion in
`commands.test.ts`, and a README restructure. No route, no schema, no credential path, no
signing surface, and nothing that executes differently.

The perimeter argument is that this corrects a claim about **who does what**, on the
surface a reader meets first. The banner read *"terminal-native companion to the Haven
dashboard"*, which was true when the CLI only read and renamed things, and stopped being
true when C1/#2526 gave it a device-code login and C2/#2527 gave it `agents connect`. The
reader it misleads is the one with no alternative: an agent cannot open the dashboard, so
being told this tool complements one is being told the path it is on is a side path. The
2026-09-06 cold run showed the same class of error one level down, when an agent read
`--help`, did not find `agents connect`, and concluded the command did not exist (#2590).

The replacement states the custody boundary rather than a positioning claim — *set up and
run a Haven agent from the terminal; it never signs* — which is the same line every other
Haven surface draws, and the one an agent needs before it promises its user anything. The
CLI still signs nothing: budgets, key rotation and fund movement remain owner-signed in
the dashboard, and the `owner_cli` allow-list still refuses every one of them. Nothing in
this change touches what a session may reach.

Two properties are asserted rather than left to review. The retired phrase is pinned
ABSENT as well as the new one present, because the old test matched the retired string
positively and would have stayed green on it forever — mutation-proven by restoring the
old banner. And the README's account of the scoped session was re-derived against
`OWNER_CLI_ALLOWED_ROUTES` rather than paraphrased: creates and manages agents, reads the
account, and cannot approve a budget, rotate a key, change a signer or move money.

Recorded because it is a live risk rather than a solved one: the `--api` default now has
four prose homes (`helpText()`, the SDK runbook, the README's new section, § Config). All
four agree today, and a change to the real default would need all four. That is the shape
#2590 and #2591 exist to prevent, named here rather than claimed closed. Perimeter
unchanged.
