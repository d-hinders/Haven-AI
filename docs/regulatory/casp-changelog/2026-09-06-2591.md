**#2591 — the agent runbook told a human to send USDC "on Base" from a Base Sepolia
deployment.** Copy only: the funding step and its hand-off script in
`HAVEN_AGENT_RUNBOOK_MD` (`packages/sdk/src/agent-guidance.ts`), with the served
`/for-agents.md` and the CLI's generated copy regenerated from it. No route, no schema,
no credential path, and nothing that executes. It is filed as a money-path-adjacent copy
change rather than a docs tidy because of where the sentence sits: **step 2 is the one
step where the human moves funds themselves, from a wallet Haven does not control, in a
direction Haven cannot undo.**

The defect was structural rather than a typo. This page is a single static file served
unchanged from every deployment, so any chain it names is wrong somewhere — and
"somewhere" includes a testnet, where the instruction sends real money to an address that
will never hold it. The 2026-09-06 cold-agent run (#2538) fetched the page from the dev
preview, saw `environment: "dev"` and `chains.deployable: [84532]` in the well-known
manifest while the funding script said "USDC on Base", and escalated the contradiction to
its user rather than resolving it: *"I don't want you sending real money to a testnet
address."* That the agent behaved correctly is not a reason to leave the sentence; it is
the measure of how bad the sentence was, because the next reader may resolve it the other
way.

The fix names the SOURCE of the chain instead of a chain: `haven wallets funding` prints
the address, the amount and the network, and the dashboard shows the same for an agent
with no CLI session — a route the first draft of this change omitted, which would have
left a no-terminal agent told to read a number from somewhere it cannot reach. The
hand-off now asks the human not to send to any address or chain the agent has not
confirmed with them, which puts the check on the side of the transaction that can still
stop it. `expect(served).not.toMatch(/USDC on Base\b/)` pins the shape, with a positive
control so the negative is a fact about the page rather than about the regex, and both
mutations (restoring a hard-coded chain; dropping the `--api` clause) turn the suite red.

The same change closes a second finding from that run, on a different failure mode: no
agent-facing surface named the CLI's API base, which defaults to `localhost:3001`. An
agent that followed the prose path and skipped the manifest was issuing commands this
very page told it to run against a host that is not Haven — a silent, misattributable
failure, and one that could have been read as Haven being down.

Nothing here changes what any credential may do, what the enforcer permits, or how a
payment is constructed. The custody boundary is untouched: the human still creates the
account, funds it, and signs every budget. What changed is that the page no longer states
a fact about the deployment that the deployment can contradict. Perimeter unchanged.
