- **0.1.36-alpha.0 release** — **two issues reach npm (#2618 and #2617, both
  CLI), plus a one-character copy fix made in the release branch itself; no
  custody, signing or execution boundary moves.** Cut one day after
  `0.1.35-alpha.0`, because that release's CLI login work was superseded on
  `dev` before anyone could use it.

  **This entry has been amended twice before promotion, and that is the entry's
  most useful fact.** Draft 1 said three issues, measured from the previous
  *bump commit*; two of them were already on npm. Draft 2 said one issue and
  was correct for 76 minutes, until #2617 merged and joined the same promotion.
  The lesson is not "be careful" — it is structural: `publish.yml` builds
  tarballs from **`main`'s tree at promotion time**, so a release record
  written when the bump is cut is wrong by construction the moment anything
  lands behind it. Every figure below is measured against `origin/main`
  (`783300eb`) at this branch's head, and must be re-measured if the promotion
  slips. Both amendments were found by `haven-doc-reviewer`, neither by the
  author.

  **What is already on npm, and therefore is NOT this release.** Probed against
  the published tarballs. Each probe is `npm pack @haven_ai/<pkg>@0.1.35-alpha.0`,
  extract, then `grep -rIo <needle> package/` — the scope is stated because an
  earlier attempt grepped a path absent from the bundle and read a meaningless
  zero. Counts vary with grep scope, so only presence is load-bearing:

  Ancestry agrees: `466a6a32` (#2619) and `e8aec20b` (#2627) are ancestors of

  **What actually reaches a user's disk: 12 files, +182/-31.** The tarball
  contains `dist/`, `package.json` and `README.md` — verified by listing one
  (`tar tzf` shows zero test files) — so the shipped delta is source-minus-tests
  plus `packages/cli/README.md` (+37/-13, which rewrites the bare-`npx`
  guidance and documents `--no-wait`/`--poll`). A `--stat` over `*/src` alone
  reads 11 files / +354/-24, but 219 of those lines are test files that never
  ship and it omits the README that does; earlier drafts quoted that figure as
  "new-to-npm", which overstated the published surface roughly twofold in one
  direction while missing a shipped file in the other.

  **#2618 — non-blocking CLI login.** `--no-wait` documented in help,
  `haven login --poll <device_code>` as a one-round poll (exit 3 while pending,
  0 once approved), a 30-second `--json` wait, and a password hint. Step 1 of
  the agent onboarding runbook now tells an agent not to hold its process open
  waiting on a human's browser approval.

  **#2617 — the CLI invocation names its channel.** `npx @haven_ai/cli login`
  becomes `npx @haven_ai/cli@<channel> login`, and `GET /discovery` gains a
  `cli_package` field which the capability manifest mirrors as
  `packages.cli.channel` / `packages.cli.one_liner` (the manifest has no field
  literally named `cli_package`). This is #2423's connector-channel rule
  applied to the CLI, closing the same hazard one surface over: a bare
  `npx @haven_ai/cli` resolves the `latest` dist-tag, so on a non-production
  deployment it installs a real-but-wrong build instead of failing. Its
  perimeter analysis is `2026-09-07-2617.md` and is not restated here — per the
  #1503 precedent a release shard may decline to re-verify the shards of the
  work it carries.

  > **Known copy defect shipping with this release, recorded not fixed.**

  > a bare tag — the same shape as the pre-existing `packages.connector.channel`.
  > The runbook tells an agent to read `<channel>` from that field, so a literal
  > substitution composes `npx @haven_ai/cli@@haven_ai/cli@alpha`, which does
  > not resolve; `packages.cli.one_liner` is the field that works. Found by
  > `haven-doc-reviewer` on this amendment. Left for #2617's author rather than
  > rewritten here, because the fix is a product-copy decision (which field the
  > runbook should name, and whether `channel` is the right name for a spec)
  > and not a mechanical correction.

  **One copy fix made in this release branch.** #2617 and #2618 each appended a
  sentence to step 1 of the runbook and the seam between them lost its space —
  `never a tag you pick.Do not hold the process open`. Neither PR could see it:
  each read only its own sentence. It surfaced only when this shard's SDK-delta
  claim was reviewed against the *merged* string. Fixed in all three copies
  (the SDK source, the CLI's generated vendored copy, and the served
  `packages/frontend/public/for-agents.md`), with the byte-length assertion in
  `agent-guidance-text.test.ts` moved 10224 → 10225 and its reason recorded
  there. It never reached npm: `0.1.35-alpha.0` predates #2617.

  **Perimeter reasoning.** `login --poll` exchanges a device code a human has
  already approved in a browser; it acquires a **session**, and specifically the
  `owner_cli` scoped token whose route allow-list was analysed under #2526 — it
  alters *when the CLI stops blocking*, not what the credential may reach.
  #2617 is narrower still: it changes which package version an agent is told to
  install and adds a read-only field to two discovery surfaces. The copy fix is
  one space. None of the three adds a route, a credential, or a signing path,
  and nothing under `modules/x402/`, `rails/` or the payment routes is carried
  by a published package here.

  **What did NOT change, with the qualifier a `main` baseline requires.**
  `git diff origin/main <head> -- packages/mcp/src packages/signer/src
  packages/connect/src packages/mcp-server/src` returns **six changed lines,
  every one a version literal** the bump itself wrote (`MCP_VERSION`,
  `SIGNER_VERSION`, `CONNECTOR_VERSION`, `HOSTED_SERVER_VERSION`, and connect's
  `sdkVersion`/`signerVersion`). Excluding those, the trees are unchanged. An
  earlier draft called that diff simply "empty", true only against the previous
  bump commit where both sides carried the same version. (`mcp-server` appears
  here but not in the shipped delta above: it is `private: true` and not
  published.)

  **`@haven_ai/core` DID change** — one line, `cli_package` added to the
  generated discovery type by #2617. An earlier draft said it was unchanged and
  leaned on that for "no shared-kernel path"; that was the same stale-baseline
  error one claim over. The conclusion survives and is in fact stronger stated
  correctly: **no published package depends on `@haven_ai/core` at all.** `sdk`
  and `cli` declare no `@haven_ai/*` dependency; `mcp`, `signer` and `connect`
  depend only on `@haven_ai/sdk`. There is no shared-kernel path by
  construction, not by coincidence.

  **The SDK exposure, traced rather than assumed.** All four runtime packages
  take `@haven_ai/sdk` as a runtime dependency, and it did change. Two exported
  constants moved: `HAVEN_AGENT_RUNBOOK_MD` and `AGENT_ONBOARDING_PROMPT` (an
  earlier draft named only the first — #2617 moved the second). Neither has any
  importer in `packages/{mcp,signer,connect,mcp-server}/src`, verified with a
  positive control: the same grep unrestricted finds 14 files. So the
  registered tool-name set, `consent.ts`, the signer's #1143 signing-time guard
  and `STRICT_INPUT_TOOLS` are untouched.

  **Therefore no operator is re-prompted on upgrade.** `consent.ts` is
  byte-identical to `main`, and its hash covers three components — identity
  (api-key prefix, api URL, agent id, safe address, delegate address, chain id),
  the canonical tool set, and the canonical allowance set. No version constant
  feeds it.

  **Release mechanics:** versions, cross-package pins, source version constants
  and the runtime-manifest table were rewritten atomically by
  `release-bump.mjs`. Its script-owned diff is 33 insertions / 33 deletions
  across 14 files, version lines only (11 lockfile + 11 `package.json` + 7
  source constants + 4 manifest-table rows). The raw bump commit `49db9079`
  reads **16 files / +134/-35**; the remainder is this shard (99 lines) and two
  hand-written `last-verified` lines, none of which the bump owns. An earlier
  draft said +105, which did not reconcile with its own decomposition.
  `HAVEN_CONNECTOR_CHANNEL` is untouched: `alpha` → `alpha`.

  **Tested, and the gaps named:** `@haven_ai/sdk` 422 and `@haven_ai/cli` 195
  re-run after the copy fix, plus the frontend's `/for-agents.md` parity test
  (10/10) which is the only instrument comparing the served runbook to its
  source. Not run in the authoring environment: the backend suite (no Postgres)
  and the rest of the frontend suite. CI covers both.

  **This promotion is the first to run the `promote-tags` job (#2647),** on a
  credential path never yet exercised. A **half-green** outcome is live: packages
  published, `latest` unmoved. `latest` currently reads `0.1.35-alpha.0` on all
  five, so half-green would strand it there. Verify with
  `npm view @haven_ai/<pkg> dist-tags`, never with a green workflow.

  Perimeter unchanged — this release changes how an agent acquires a session,
  which package version it is told to install, and one space of prose. Nothing
  about who may spend, sign, or execute. The spend authority a delegation grants
  remains bounded on-chain by the same caveat enforcers.
