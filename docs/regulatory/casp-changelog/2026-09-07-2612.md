- **#2612** — read-only CLI surface. `haven budget show <agentId> --hashes` adds
  one boolean flag and one authenticated GET of `/agents/:id/delegations`, a
  route the CLI already called for `budget grant --wait` and `budget revoke`.
  No new route, no new authority, no new custody surface, no write of any kind,
  and nothing signed — the CLI still cannot sign and still never calls
  `activate`. The defect it closes is a discoverability one with a real
  compliance edge: `budget revoke` is the owner's kill switch for a delegation,
  it takes a delegation hash as its second argument, and NO `haven` command
  printed one, while the README and the revoke usage error both said
  `haven agents show` did. It does not — that response carries the allowances
  projection, which has no hash field — so a CLI-only owner could not reach
  their own revoke path without the dashboard. Making a kill switch reachable
  narrows nothing and widens nothing; it removes a gap between what the product
  says and what it does. Both directions are pinned by tests that fail on drift
  and were mutation-proven: renaming the hint constant so the README no longer
  contains it reddens the binding test, and making the flag read the allowances
  projection instead reddens the output test (each restored byte-identically,
  verified with `cmp`). `budget show --json` keeps the bare allowances array it
  has emitted since the first CLI scaffold — the flag exists so that shape does
  not become a union. Perimeter unchanged.
