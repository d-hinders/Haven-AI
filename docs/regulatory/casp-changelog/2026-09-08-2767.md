- **#2767** — **a change to the QA control surface only: `.github/workflows/qa-dev.yml` (a `controlGlob`), and only its FAILURE step. No payment, signing, custody or authorization code moved; the perimeter is unchanged.**
  What changed in the control surface. When the money-flow harness goes red,
  the workflow used to file a new `qa-dev money-flow failed (<date>)` issue on
  the first failure of each day (four such issues between 2026-09-01 and
  2026-09-08, each closed by hand once green). It now calls
  `scripts/ci/qa-failure-issue.mjs`, which upserts ONE standing `qa-failure`
  issue titled `qa-dev money-flow failing`: an open one is rewritten and gets a
  comment, a closed one (closed on green) is reopened, and only when neither
  exists is one created. The trigger line the body carries — the #2271
  provenance record naming the Railway deployment id, deployed SHA and creator
  for a `deployment_status` run, or the dispatching actor for a
  `workflow_dispatch` — is built in the same `case` block as before and passed
  to the script through the environment, not interpolated into a shell command.
  What did NOT change, stated because this file is a control surface the
  promotion gate reads: the `gate` job and its four refusals (#2273), the
  money-flow job and its concurrency group, the coverage-completeness step
  (#1044/#1066), the flake budget, every `QA_*` secret and variable, and the
  run's conclusion — `scripts/ci/qa-freshness.mjs` and
  `scripts/ci/guard-freshness.mjs` read the run and the `money-flow` job, never
  the issue, so how failures are reported cannot admit or refuse a promotion.
  The harness itself (`packages/qa-agent/**`) is untouched. Mutation-tested:
  `scripts/ci/qa-failure-issue.test.mjs` drives the script's CLI with a
  recording `gh` stub on PATH and asserts which subcommands were reached in
  each of the three states; disabling the reopen branch reddens one test (a
  closed standing issue would be replaced by a sibling), disabling the
  unticked-box branch of the companion `scripts/ci/epic-promotion-checklist.mjs`
  reddens three, both restored byte-identical (`cmp`) after. The rest of the PR
  is workflow text (`ship-next`, `new-task`, the three reviewer references, the
  PR and epic templates) and a reporting-only addition to
  `promotion-digest.yml`; none of it is on the perimeter. Perimeter unchanged.
