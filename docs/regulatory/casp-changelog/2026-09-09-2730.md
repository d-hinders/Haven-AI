# 2026-09-09 — #2730: safe-area insets and standalone chrome, so nothing sits under the notch or the home indicator

CSS padding, one z-index token and their tests. `globals.css` gains four
`--v2-safe-*` custom properties reading `env(safe-area-inset-*)` with a `0px`
fallback, plus a `.v2-safe-overlay` utility and the `--v2-z-tab-bar` tier;
`lib/installed-app.ts` adds `viewportFit: 'cover'` to the viewport #2729 landed;
and the app shell, top bar, drawer, `ui/Modal`, `ui/SidePanel` and four bespoke
overlay wrappers consume those variables so no control is painted under the iOS
status bar or home indicator in the installed app. No rail, budget, delegation,
signing, credential, custody or route-authorisation change. No migration. No
API surface, request shape or response shape moved.

**This shard exists for exactly one file.** The contract-doc coupling gate fires
because `packages/frontend/src/components/AddFundsModal.tsx` is on this
document's `covers:` list. The change to it is one class name on the overlay's
`fixed inset-0` wrapper (`v2-safe-overlay`) and the comment above it — the
component's funding flow, its amount handling, its chain and token selection and
every string it renders are byte-identical. `git diff -- packages/frontend/src/components/AddFundsModal.tsx`
is five added lines, four of them a comment. The utility it now carries resolves
to `padding: 0` in any browser reporting no safe-area insets, which is every
browser without a notch and every engine any gate in this repository runs.

**Not money-path, by either half.** The issue carries no `money-path` label, and

0 control-glob matches over the diff, above its own
`=== SELF-TEST PASSED (6 positive, 6 negative) ===` line — the verdict is quoted

document's `covers:` list but is not in `.github/money-path-globs.json`; the two
lists answer different questions and only the second one classifies.

**What the tests prove, and what they cannot.** `viewport-fit=cover` is a
compositing instruction to the OS and `env(safe-area-inset-*)` is inert in every
engine without a notch, so the rules read `--v2-safe-*` and the Playwright specs
override those four properties to reproduce a notch's arithmetic against the
real stylesheet — `e2e/safe-area-insets.mobile.spec.ts` (390x844, chromium-mobile)
and an inset case added to `e2e/modal-action-row-reachability.spec.ts`. Each test
reads the computed padding back before judging any geometry, so a renamed
variable fails the control rather than passing an empty band. Mutation-tested:
each of the six inset rules was removed one at a time and the spec claiming to
cover it went red, every file restored byte-identically afterwards; the results
table is in the pull request. What no local instrument can see — that iOS
reports the insets we assume, and that the status bar tints to
`theme-color #4f46e5` — stays on the epic's device checklist, as it did for
#2729. Perimeter unchanged.
