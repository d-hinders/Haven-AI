- **#2872** — Product doc, provider-generic runbook, decision-log entry, ops signals and the cleanup migration (epic #2858, slice 14 of 14, backend + docs). Two files in the money-path perimeter change: `packages/backend/src/db/migrations/081_drop_fortnox_connections_retired.ts` (new) with its registration in `db/migrations/index.ts`, and `packages/backend/src/routes/health.ts`. **The migration is schema-only and destructive of nothing live.** `up()` is one statement, `DROP TABLE IF EXISTS fortnox_connections_retired` — no `CASCADE`, no `DELETE FROM`, no row read, no environment read. The table is the Fortnox-only copy migration 080 (#2860) renamed instead of dropping, so a rolling deploy with overlap could not lose a committed write; every connection that exists today lives in `accounting_connections`, and the retired rows are the token pairs as they were at 080's migration time, which every refresh since has rotated — dead credential material, and dropping it is the one action that makes it stop existing. Nothing declares `REFERENCES fortnox_connections_retired`; its only foreign key points OUT to `users`. `down()` recreates the table EMPTY in 027's exact column shape (not "irreversible": 080's own `down()` renames it back and needs it to exist), and both directions are idempotent. Sequenced last in the epic, after the owner's product verification on dev, per the epic's promotion checklist. **The route change is two read counters behind the existing operator token.** `GET /health/ops` (404 when `HAVEN_OPS_TOKEN` is unset, 401 on a wrong token, unchanged) gains `accounting: { exhaustedSyncs, connectionsNeedingAttention }` — one aggregate `COUNT(*)` each (`COUNT_EXHAUSTED_SYNCS_SQL`: `failed` rows at the retry cap; `COUNT_CONNECTIONS_NEEDING_ATTENTION_SQL`: rows in `needs_reauthorisation` / `scope_missing` / `revoked_at_provider`), both registered in the schema smoke, both run only after the token check, no per-user, per-payment or provider data on the wire. The OpenAPI schema and the generated `api-types` carry the new field. **Log events move nothing.** `accounting.sweep.run` reshapes the sweep's existing per-tick line, `accounting.sync.exhausted` announces the sweep's existing guarded terminal write, and `accounting.connection.needs_attention` is emitted by `flagConnectionStatus` (`ops-signals.ts`), a wrapper every existing degraded-status write site now calls around the same repository `setStatus`; the event carries `status_reason` — the provider's error code, never token material — and fires after the write. **Authority/custody argument: nothing moves.** No transaction is constructed or signed, no delegation, allowance, relayer, signer or key is touched, no route accepts a write, and the feed's invariants (non-asserting, never blocks settlement, idempotent on `(provider, payment_id, user_id)`) are untouched — the docs rewrite states them and the code that enforces them did not change. **What is mutation-tested**, each planted alone, restored from a `cp` backup and verified by `cmp`, counts from the named scope at the delivered tree (`npx vitest run --root packages/backend` over the two migration tests, the two health tests, `retry-sweep.test.ts` and `feed-orchestrator.test.ts`: 47 tests green): (a) `up()` made a no-op, on a freshly reaped schema reservoir — **3 failed / 1 passed** in `081_drop_fortnox_connections_retired.test.ts` (the at-head drop, the idempotency case and the down/up round trip); on an un-reaped reservoir the harness's reference-schema guard refuses the run before any test body, which is the same defect caught earlier; (b) `COUNT_EXHAUSTED_SYNCS_SQL` counting every `failed` row (the `attempts >= $1` term made vacuous) — **1 failed / 8 passed** (the real-DB route test's `exhaustedSyncs` case, `expected 4 to be 2`); (c) `COUNT_CONNECTIONS_NEEDING_ATTENTION_SQL` counting every non-`connected` row — **1 failed / 2 passed** (`expected 4 to be 3`, the `disconnected` row); (d) the `accounting.connection.needs_attention` emit dropped from `flagConnectionStatus` — **2 failed / 8 passed** in `feed-orchestrator.test.ts` (post-push and pre-push scope cases); (e) the `accounting.sync.exhausted` emit dropped from the sweep — **1 failed / 17 passed** in `retry-sweep.test.ts`.
