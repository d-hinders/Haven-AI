- **#2877** — Multi-currency ledgers for the accounting feed (epic #2858): the reporting feed pushes the currency the connected company books in, converted with the rate frozen at settlement, instead of pushing SEK to every destination. **No production connection is non-SEK today** — the only `live` provider is Fortnox and its `getCompanyInfo` reports `SEK` by construction — so this ships the capability ahead of its first user (the `coming_soon` providers), and the non-SEK path is exercised by the conformance suite and the real-database tests rather than by traffic. One additive migration (`082_evidence_ledger_fx_rates.ts`: `machine_payment_evidence.fx_rates JSONB`, nullable, no backfill and no row rewritten), one new pure domain file (`domain/ledger-currency.ts` — `SUPPORTED_LEDGER_CURRENCIES = SEK, EUR, USD, DKK, NOK, GBP`, read by both `infra/prices.ts` and `modules/accounting/provider.ts` so "accepted at connect" and "a rate the feed can be quoted" are one list), a capture widened in place (`infra/fiat-values.ts` `getBookTimeCapture` — ONE `getTokenPrice` read yielding the SEK value and every ledger rate, so the timestamp and the map cannot come from different fetches across the 60 s price cache), and the currency carried through `entry.ts` → `feed-transaction.ts` → `feed-orchestrator.ts` to the connector as `ledgerCurrency` / `amountLedger`. **Authority/custody argument: nothing moves.** Every file in the diff is downstream of settlement — the payment is already confirmed on-chain before any of this code runs. No transaction is constructed, nothing is signed, and no delegation, allowance, enforcer, relayer, signer or secrets column is read or written; `amount_raw`, `amount_human` and every spend-authority path are never WRITTEN by this change (`amount_human` is newly *read*, as the multiplicand for a non-SEK ledger amount), and the one schema change adds a nullable column to an evidence table that no payment path reads to decide whether a payment may proceed. The perimeter files present (`modules/accounting/**`, `infra/repositories/machine-payments.ts`, `db/migrations/`, `infra/chain`-adjacent none) carry reporting data only. **Red Line #9 (reporting/accounting/tax assertions) is unchanged, and no new assertion is introduced.** The record pushed is still an *unattested* supplier invoice: `assertNonAsserting()` still bans `Account`, `VAT`, `VATType`, `SupplierInvoiceRows` and `VoucherRows`, and this change adds only `Currency` and a `Total` in that currency — the two fields that say what the figure on the source document *is*, which is factual provenance and not an accounting judgment. Nothing is booked until a human attests it. An FX rate is recorded, never asserted: it carries `fx_source` and `fx_at` exactly as the SEK capture has since migration 026, and **a USD-denominated ledger records the rate the source quoted for a USDC payment (≈ 1.0) rather than an assumed 1:1 parity** — Haven states no equivalence between a stablecoin and the currency it is named after, and the accountant confirms that figure like any other on the document. **Three narrowings, no widenings of what Haven may do:** (1) the SEK path is answered from the `amount_sek` COLUMN, never re-derived from the new map, so no existing Swedish ledger can be re-priced by this change; (2) the captured map is frozen **with its timestamp**, not independently: `evidenceBaseUpsertSql` writes `fx_rates` only on the write that first sets `fx_at` (a `CASE`, not the per-column `COALESCE` the SEK columns use), because `recordMachinePaymentEvidenceBase` also runs from the proof-attach path weeks after settlement and re-reads prices there — under a plain `COALESCE` a row whose map was NULL (every row settled before migration 082) would have gained a map taken on the day of the attach while `fx_at` still said settlement, which is a feed-time rate wearing a book-time label. The accepted consequence, stated rather than hidden: such a row keeps no map for good and is **not feedable to a non-SEK ledger at all**, because its book-time rates are not knowable; SEK ledgers are unaffected, reading the `amount_sek` column as always. Found by the independent review pass on this change, before merge, and pinned by a real-database test; (3) a missing rate for the destination's currency is *not ready* — the payment is left unfed and unclaimed for the retry sweep and the backfill — never a SEK substitute pushed into a non-SEK ledger, which would be a wrong number wearing the right label. A computed amount is emitted at `amount_sek`'s own scale (four decimals, migration 026), so no raw-float tail or exponent notation can reach a supplier invoice, and the underlag PDF attached to a record states that record's own figure and currency with the SEK capture kept below it as a labelled reference. The connect-time refusal (#2864) is widened from SEK-only to the six supported currencies but is otherwise identical in mechanism and still refuses before any secret is stored (409 `UNSUPPORTED_BASE_CURRENCY` / `reason=unsupported_currency`, existing row untouched, the already-exchanged grant revoked best-effort where the descriptor declares `revoke`). **What is mutation-tested**, each planted alone, restored from a `cp` backup and verified by `cmp`, every count from one named scope at the delivered tree — `npx vitest run --root packages/backend src/modules/accounting src/modules/mpp/__tests__/evidence.test.ts src/infra/__tests__/fiat-values.test.ts src/infra/repositories/__tests__/machine-payments.test.ts src/routes/__tests__/accounting-connections.test.ts`, **291 tests / 29 files green** at baseline and green again after each restore: (a) `fx_rates = EXCLUDED.fx_rates` instead of the `COALESCE` — **2 failed / 289 passed** (the real-database freeze test and the evidence upsert's own freeze assertion); (b) a missing ledger rate falling back to `entry.amountSek` — **1 failed / 290 passed** (the real-database "NOT READY, not a SEK fallback" test); (c) SEK answered from `entry.fxRates.SEK` instead of the column — **2 failed / 289 passed** (the real-database characterisation test, whose fixture makes column and map disagree on purpose, and the default-currency case); (d) `SUPPORTED_LEDGER_CURRENCIES` narrowed back to `['SEK']` — **6 failed / 285 passed** (conformance case 7d in both runners plus four multi-currency cases); (e) the Fortnox payload hard-coded back to `Total: tx.amountSek, Currency: 'SEK'` — **1 failed / 290 passed** (the connector payload test). Perimeter unchanged — narrowed, if anything: a rate that cannot be proven to be the book-time rate is now never pushed at all.
