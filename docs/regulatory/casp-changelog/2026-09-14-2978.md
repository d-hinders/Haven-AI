  migration 058 seeds its demo-merchant rows as `active` with `verified_at`
  set, so on a FRESH database those rows carry the badge before the first
  refresh tick (the backend runs one at boot; every deployed environment
  re-probes hourly and all live rows carry a probe timestamp) — the badge
  therefore means "seeded-verified or probed", not strictly "probed".

  (the route test file is a mocked-DB serializer test, not a real-DB test);
