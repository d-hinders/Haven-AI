- **#2985** — edge signer liveness: `fetchX402SignContext`
  (`packages/signer/src/sign-context.ts`), the signer's only network call —
  the authenticated read-only `GET /x402/:id/sign-context` behind the
  `{ payment_id }` form of `haven_sign` / `haven_sign_x402` — had no timeout,
  so a hung backend hung the signer tool call and the agent indefinitely
  while the funding window ran out. It now passes
  `AbortSignal.timeout(SIGN_CONTEXT_TIMEOUT_MS = 15_000)` and a timeout
  surfaces as the existing `HavenSigningError` naming the timeout and the
  `typed_data_b64` fallback. No custody, key-handling, binding-verification
  or signing-logic change; the delegate key is still never part of the
  request; no new authority. Mutation-tested: removing the signal makes the
  hung-fetch test exceed its own 2 s timeout. Perimeter unchanged.
