- **#2968** — completes the "settled means verified" vocabulary (#2970's shard
  above covers the gate itself) at the agent-facing surface, narrowing what the
  tool reports and never widening it. Three additive changes, all fail-closed:
  (1) the response-level zero-hash ban — `deliverMerchantPayment` collapses a
  zero/placeholder `settlementTxHash` (the demo merchant's `ZERO_TX_HASH`
  "delivered, not settled" marker) to `null` via the SDK's
  `isZeroSettlementTxHash` recognizer (#2970), on both schemes, so a sentinel
  shaped like a transaction is never rendered as one by any downstream
  consumer; no hash is invented to replace it — `null` means "no transaction
  known". (2) The erc7710 settled arm now also carries `delivered: true`, so
  the delivery half of the vocabulary rides on every arm and the two fields
  cannot disagree in either direction. (3) An unconfirmed erc7710 settlement
  no longer rides silently: it emits a machine-readable
  `SETTLEMENT_UNCONFIRMED` warning (new additive `AgentPaymentWarningCode`,
  SDK types only) carrying the intent's `expires_at`, alongside the existing
  `settled: false` / `code` / `next_action: check_status_later` verdict, so
  the agent can tell "the user has the goods" apart from "the money moved" and
  knows when the settlement window closes. Haven performs no new reads, signs
  nothing, submits nothing, and holds nothing: the warning is bookkeeping
  about an absence of evidence, the nulling removes information from the
  response rather than adding authority, and the settle/complete gate decides
  settlement exactly as #2970 shipped it (backend-verified evidence or
  nothing). Regression tests are mutation-proven: reverting
  `classifyErc7710Settlement` to unconditional `settled` re-fails the
  merchant-200-without-on-chain-confirmation test (`settled` expected
  `false`, got `true`); removing the response-level zero-hash nulling re-fails
  the eip3009-arm zero-hash test (the 32-zero sentinel rides out in the body).
  Tool-contract wording now states the settled-means-verified rule and the
  null-hash rule; qa-agent scenarios assert the settled/delivered fields AGREE
  and ban the zero sentinel from scenario assertions. Perimeter unchanged.
