- **#3015** — boolean environment flags refuse the boot on an unrecognised
  value instead of reading as off. `packages/backend/src/config.ts` gains
  `parseBooleanFlag(name, raw)` — unset / `null` / empty-after-trim → `false`,
  `'true'` / `'false'` accepted (trimmed), **anything else throws** naming the
  variable and quoting the offending value — and it replaces the
  `process.env.X === 'true'` comparison at all six call sites:
  `CATALOG_DISCOVERY_ENABLED`, `HAVEN_FEE_ENABLED`,
  `HAVEN_LEGACY_BOOKKEEPING_ENABLED`, `HAVEN_HOSTED`, and both names inside
  `readAccountingEnabled` (`HAVEN_ACCOUNTING_ENABLED` and the deprecated
  `HAVEN_REPORTING_FEED_ENABLED`, whose #2859 warning is unchanged). Same shape
  as `parseConnectorChannel` (#2423) and `parseAccountingEntitlementMode`
  (#2861) in the same file. **Authority/custody argument: nothing moves, and
  the change can only turn a flag OFF-by-refusal into a loud failure — it can
  never turn one on.** `config.ts` is not in `.github/money-path-globs.json`;
  no payment, delegation, allowance, relayer, signer or key path is touched,
  no route, schema or migration changes, and no flag's *accepted* values
  change: every `true`/`false` that worked before works identically.
  **Why it exists, stated because the failure was live:** `HAVEN_HOSTED` was
  set to `TRUE` on the production backend, `'TRUE' === 'true'` is `false`, so
  `config.hosted` was false in production and `/accounting` told users of the
  hosted service that the feed "is not available on a self-hosted deployment".
  The variable was present in the dashboard, looked set, and did nothing — a
  silently-off flag is indistinguishable from a deliberately-off one, which is
  why it survived and why the same reading error produced a wrong finding on
  epic #2858 before the bytes were read. Corrected in production 2026-09-15 by
  setting the value lower-case; this change makes the next one impossible to
  miss. Case normalisation was the alternative and was **rejected by the owner
  on 2026-09-15** ("flags should fail loudly"): lower-casing fixes `TRUE` and
  still reads `1`, `yes` and `on` as off — the same defect, smaller blast
  radius. **What is mutation-tested**, each planted alone, restored from a `cp`
  backup and verified by `cmp`, counts from the scope
  `npx vitest run src/__tests__/config-boolean-flags.test.ts` in
  `packages/backend` (8 tests green at the delivered tree): replacing the
  `throw` with a silent `return false` — **6 failed / 2 passed**; replacing the
  two literal comparisons with `value.toLowerCase() === …`, i.e. shipping the
  rejected normalising alternative — **4 failed / 4 passed**, so the tests
  distinguish the two designs rather than merely asserting "some error";
  8/8 restored after each. **Operator precondition, and the one risk this
  carries:** the change converts a silent-off into a boot refusal, so any of
  the six variables carrying a non-`true`/`false` value in a deployed
  environment stops the backend from starting. The repository is clean
  (`.env.example` and `.env.dev.example` set all four to lower-case `false`,
  and both now document the contract); the Railway **dev and production**
  projects must be audited for all six before this reaches them. Recorded on
  the pull request. **Perimeter unchanged — no file entered or left
  `.github/money-path-globs.json`.**
