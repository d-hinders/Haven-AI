- **#3015** — backend boot-time configuration: the six boolean feature flags
  (`CATALOG_DISCOVERY_ENABLED`, `HAVEN_FEE_ENABLED`,
  `HAVEN_LEGACY_BOOKKEEPING_ENABLED`, `HAVEN_HOSTED`,
  `HAVEN_ACCOUNTING_ENABLED`, deprecated `HAVEN_REPORTING_FEED_ENABLED`) used
  to compare the raw string to `'true'` and read every other value — `TRUE`,
  `1`, `yes`, a trailing space — as OFF, silently. `HAVEN_HOSTED=TRUE` reached
  production and the hosted service rendered the self-hosted accounting copy
  with nothing logged. `parseBooleanFlag` now accepts exactly `true` / `false`
  (unset or blank = false, "never configured") and refuses the boot on
  anything else, naming the variable and the bytes — the rule
  `HAVEN_ACCOUNTING_ENTITLEMENT_MODE` already followed. Owner decision
  2026-09-15: fail loudly, do not normalise case. A silently-off flag is
  indistinguishable from a deliberately-off one; this closes that gap for
  every flag that gates a money-adjacent surface (fee module, accounting
  feed, catalog ingestion). Operator step before deploy: audit the Railway
  dev and prod values for all six (exact bytes). No payment, custody or
  authority logic change; no migration. Mutation-tested: replacing the throw
  with a silent `return false` re-fails the refusal tests. Perimeter
  unchanged.
