- **#3045** — the delegation-rail idempotency-key lookup
  (`FIND_X402_INTENT_BY_KEY_SQL` /
  `findX402IntentByIdempotencyKey` in
  `packages/backend/src/infra/repositories/x402-authorizations.ts`) expires
  only the newest stale row for a duplicated key, so a key doubled before the
  hosted tools forwarded the key (#3042) answered
  409 "Idempotent replay in progress" on every retry forever: the lookup
  always returned the newest row, lazily expired it once, and then kept
  finding the dead row while the OLDER live row held the partial unique index
  (`idx_payment_intents_x402_idempotency`, predicate
  `status NOT IN ('failed','expired')`) against every fresh insert. The fix is
  an ORDER BY change only — an `expired` row now ranks below live rows
  (`ORDER BY CASE WHEN status = 'expired' THEN 1 ELSE 0 END ASC, created_at
  DESC`); the WHERE predicate is byte-identical to the #961 original, so a
  LONE expired row is still found and the lazily-expire-to-free-the-key path
  (delegationReplay → expirePendingIntent) is unchanged, and the older live
  row becomes reachable — replayed if the request matches, or lazily expired
  on its own turn, after which the key is genuinely free. Authority/custody
  argument: this is a read-side retry-liveness repair inside the existing
  idempotency lifecycle — it writes nothing the #961 flow did not already
  write (the lazy expire is the same guarded, agent-scoped,
  pending-signature-only flip), it does not touch spend decisions, the hourly
  cap ordering (a replay still returns before `agentHourlyX402CapExceeded`
  reads the counter — pinned by test), delegation construction, settlement,
  or the unique index's semantics, and it cannot admit a second spend under
  one key: the index still refuses a live duplicate exactly as before.
  Mutation-tested: reverting the ORDER BY to the pre-fix `created_at DESC`
  turns both new real-Postgres proofs red ("#3045 two rows one key, newest
  expired: the OLDER live row wins the lookup (409-forever regression)" and
  "#3045 walking a duplicated key: each retry reaches a live row until the
  key is truly free") while the lone-expired preservation test stays green.
  Perimeter unchanged.
