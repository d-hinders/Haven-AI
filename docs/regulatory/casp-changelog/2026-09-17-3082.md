- **#3082** — The request-validation layer was **mutating the requests it was
  only supposed to observe**, and that broke the budget-grant path on dev.
  **Perimeter unchanged** — no new authority, no new signing path, no change to
  who may move funds, no migration. What moves is that a measurement layer
  stops editing payments traffic. Recorded here because the convention is one
  shard per money-path change and this diff touches
  `packages/backend/src/openapi/request-validation.ts`, on
  `.github/money-path-globs.json` since #3029 precisely because it sits IN
  FRONT OF every payment route.

  **The defect.** `installRequestValidation` attaches the spec schema to the
  route in **shadow** mode as well as enforce, and `REQUEST_AJV_OPTIONS` sets
  `coerceTypes: 'array'`. ajv coerces **in place**, so validating a request for
  measurement rewrote the payload the handler then read. A JSON `null` became
  `""`. The plugin's own header promises shadow means "no behaviour change on
  any currently-accepted request"; that promise was false from the day it
  landed.

  Live consequence: `POST /agents/{id}/delegations/build` — the grant of an
  agent's on-chain spend authority — answered
  `400 recipient_address must be a valid address when set` for **every open
  (unpinned) budget**, because the handler's `recipient_address != null` guard
  was handed `''`. `DelegationApprovalStep.tsx:77` sends `null`
  unconditionally, so the connect-modal approval could not complete at all.
  An unpinned budget is also the only shape the EIP-3009 bridge can use, so the
  failure fell on the standard x402 onboarding path.

  **Authority, unchanged.** This layer reads shape; it does not authorize,
  alter or construct spend intent, and that is unchanged here. No caveat
  enforcer, delegation payload, signed x402 expected-context or consent hash is
  touched. The change strictly **narrows** what the layer does: it now observes
  without writing. Nothing that was refused becomes permitted — a budget grant
  that was refused for a real reason is still refused, and the enforcers remain
  the only spend control.

  **Scope of the fix, and what deliberately stays.** The body is snapshotted
  before validation and restored after it, for shadow routes only. Querystring,
  params and headers are deliberately **not** restored: they arrive as strings
  on the wire, coercion is what makes a typed spec parameter usable, and the
  handler is meant to see the coerced value (pinned by the `limit=10` case in
  `openapi/__tests__/request-validation.test.ts`). **Enforce mode still coerces
  the body** — deliberate and visible, because an enforced route answers on the
  validation result, so the coerced value is part of a contract a client can
  see and test rather than a silent edit made while claiming to measure. Epic
  #3028 slices 2–4 flip modules to enforce one at a time and should read that
  note before each flip.

  Separately, `recipient_address` on the build request is now declared
  `['string', 'null']`. Its description had always said null means an open
  budget; the declaration said otherwise, and the validation layer reads the
  declaration.

  **Evidence.** The failure and the fix are both mutation-proven rather than
  asserted. With both fixes reverted, the new
  `routes/__tests__/agent-delegations.test.ts` block reproduces the production
  signature exactly: `off` passes, `shadow` **fails**, `enforce` **fails**, and
  a pinned budget passes in all three — the defect is null-specific, and dev
  runs `shadow` by default. Removing only the restore hook turns two
  `request-validation.test.ts` cases red; removing only the nullable
  declaration turns two others red. Backend suite 2963 passed / 860 skipped /
  0 failed at the shipped commit.

  **Why the suite was green while dev was broken.** Every other app in the
  delegation route tests registers the routes alone; production registers
  `installRequestValidation` first. The gap was not a missing assertion — it
  was a test app assembled differently from the one that serves traffic. The
  new cases assemble it the production way, in all three modes.
