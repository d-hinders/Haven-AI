# Preserve x402 selected requirement echoes (#3117)

The SDK preserves the merchant's advertised timeout in its v2 `accepted`
requirements. The signing conversion retains the existing authorization cap
and forward margin. The SDK and signer wire-format tests compare the echo
with the official matcher and independently assert the bounded signed expiry;
a matching offer can still exceed that expiry at facilitator verification.

Backend ERC-7710 settlement recovers metadata only from a unique stored offer
matching the authorized intent and settlement state, including facilitator
pins. It echoes that offer without rebuilding its extra fields. A missing or
ambiguous match in a stored challenge refuses before submission; legacy
intents without a stored challenge retain the previous fallback.

No owner or delegate key handling, budget caveat, signed child, recipient,
amount, asset, relay authority, or account revocation changes. Merchant
metadata is protocol echo data, never authority. API credentials remain
identity-only and cannot spend without the existing independent signatures
and on-chain controls. No schema migration or operator flag is introduced.

The CASP parent's non-custodial authority model and signature-before-status
requirement remain applicable. Focused regressions are in the SDK signing,
local signer wire-format, backend settlement and demo conformance suites.
