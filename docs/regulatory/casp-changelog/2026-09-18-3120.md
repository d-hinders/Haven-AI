- **#3120** — **`--doctor` stops fabricating a green runtime-config verdict when
  no runtime is named. Diagnostic truthfulness only; no authority, custody,
  funding, signing or settlement boundary moves.**
  With `--runtime` absent the doctor used to resolve no config file and report
  `runtime_config` as `ok: true` with a "CLI-managed" justification it could
  not justify — indistinguishable from Claude Code's real, earned skip. Now
  `packages/connect/src/doctor.ts` resolves the runtime explicitly: an explicit
  flag wins verbatim; otherwise the runtime recorded in the agent credential
  directory's `last-connect-outcome.json` (the `ConnectOutcome` both setup
  outcomes already park there, read by a new never-throws
  `readConnectOutcomeRuntime` in `packages/connect/src/storage.ts`); otherwise
  the runtime is UNKNOWN and every verdict says so — `runtime_config` reports
  `ok: false` ("the runtime config was NOT checked"), the restart check stops
  claiming "no restart requirement known", and `--doctor --repair` REFUSES
  before any config write or npm spawn rather than repair an unknown runtime's
  config. No repair string can render a truncated bare `--runtime ` flag
  (every command fragment goes through one guarded constructor,
  `runtimeFlagFor`). Perimeter argument: the connector is onboarding
  diagnostics — the doctor reads the user's own credential directory and
  config files, writes nothing new, performs no network call beyond the probes
  it already made, and `normalizeRuntimeName`'s export widens no permission
  (it is the same alias table an explicit flag always traversed). The record
  read is the same non-secret object the connector already printed to stdout
  (`ConnectOutcome` is secret-free by construction, pinned by its own tests);
  no key, token or credential file is newly readable. The repair refusal is a
  NEW stop before an existing write — repair's blast radius only shrinks.
  Mutation-tested: the fabricated pass (record removed → `runtime_config`
  reports `ok: false` with "Runtime is unknown" and the doctor exits non-zero),
  the resolution (record present → the recorded runtime reaches
  `runtimeConfigPathFor`), precedence (explicit flag beats the record,
  verbatim), `'other'` decided as RESOLVED (the manual profile's honest skip,
  pinned by test), and the never-truncated flag (a rendered-report grep).
  Measured against `.github/money-path-globs.json`: none of the touched files
  matches any glob or control glob. Custody unchanged — Haven still holds no
  key and no funds. Perimeter unchanged.
