- **#3121** — **`--doctor` verdicts gain a third level; the exit code counts
  only real failures. Diagnostic truthfulness only; no authority, custody,
  funding, signing or settlement boundary moves.**
  Every `DoctorCheck` and the `DoctorReport` in `packages/connect/src/doctor.ts`
  now carry `level: 'ok' | 'advisory' | 'failed'`; `ok` is derived from it in one
  place (`true` unless `failed`) so `report.ok` remains the exit code's predicate
  for `--json` consumers, additive within the report's `version: 1`.
  `packages/connect/src/cli.ts` prints `!` for an advisory with its own summary
  line and returns 1 only on `failed`. Two findings move from failed to
  advisory: `signer_runtime` when the install is intact but behind the
  connector's pinned version (the message still names both versions and offers
  `--repair`), and `superseded_agents` when the runtime has no config file the
  connector can read (every Claude Code run), where `agentIsWired` falls back to
  "the selected directory is wired" and a live key in another directory may be
  an agent the user deliberately wired. The classification itself is unchanged;
  only the severity of the check reading it. What stays blocking is live spend
  authority: a stored key that still authenticates in a directory whose
  classification is not `wired` fails the run for every non-wired
  classification whenever the config could be read; the unknown-runtime
  `runtime_config` verdict (#3120) stays `failed`, so an unknown runtime still
  cannot ride a green exit code. Perimeter argument: the doctor reads the user's
  own credential directory and config, performs the same probes as before,
  writes nothing, revokes nothing and deletes nothing; a severity is a label on
  a report, and no check that gated spend-capable key material before now
  passes silently — the advisory names the same live keys the failure did and
  says why the connector cannot classify them here. Mutation-tested: the
  advisory reverted to `failed` (the #2963 drift test and the level test red);
  the config evidence ignored (`classificationUnreliable = true` → the #1688
  superseded proofs and the per-classification tests red); the wired agents
  dropped from the rollup (the #1697 non-primary failure test red); the exit
  code decoupled from the level (`return 0` → two CLI tests red); `ok` derived
  as `level === 'ok'` (the invariant test and three advisory tests red).
  Measured against `.github/money-path-globs.json`: none of the touched files
  matches any glob or control glob. Custody unchanged — Haven still holds no
  key and no funds. Perimeter unchanged.
