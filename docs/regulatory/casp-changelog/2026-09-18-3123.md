- **#3123** — **`--unwire` refuses to destroy a directory's key material
  unless there is nothing to preserve; `--prune-signer-runtimes` reclaims
  unreferenced runtime directories. Connector-only; no backend file touched;
  `area:backend` and `money-path` waived on this slice by owner decision
  (option c — no balance endpoint, no heuristic).**
  Before this change `teardownLocalKeyMaterial` in
  `packages/connect/src/unwire.ts` removed `signer.json`, any parked re-key
  and the API key in `identity.json` unconditionally, while
  `agentAuth.ts`'s sweep-recovery routes still accept a revoked agent's API
  key — so `--unwire` destroyed the only local means of recovering a stranded
  delegate balance without asking what the key was still good for. Now, after
  the runtime configs and the Hermes env are scrubbed (the world-readable
  copies go FIRST, so a refusal leaves the key in the 0o600 file only), the
  connector runs the one read it already has — `probeHostedAgentIdentity`,
  `GET /machine-payments/agent` with the stored key; no new network call, a
  test pins that it is the only call on the path — and refuses on every
  answer: `ok` (the agent still spends; revoke on the agent page first),
  `unauthorized` (the refusal says a stranded balance MAY exist and the
  connector CANNOT check, and names the backend's deliberate ambiguity
  between revoked / archived / paused / rotated rather than asserting a
  revocation), `network_error` / `bad_response` (unknown is not "safe to
  delete"). Only a directory with no stored API key + URL proceeds unprobed.
  `--destroy-key-material` proceeds on every answer and states that local
  recovery ends; `--json` gains an additive `teardown` object. The prune walks
  `~/.haven/signer-runtime` (override-keyed `override-<hash>` directories
  included), keeps every directory any credential directory's sidecar names
  and the current pin, removes the rest, and reports through #3121's levels;
  `--doctor` surfaces unused directories as an advisory. Perimeter argument:
  the connector gains no write it did not have and loses one it should not
  have had by default; it still revokes nothing (#1688); the probe is the same
  authenticated read the doctor already makes; the prune touches only
  directories no credential directory references. Mutation-tested: the
  refusal dropped (four probe-outcome tests red); the `unauthorized` wording
  asserting a revocation (red); the prune ignoring references (three red) and
  walking manifest versions only (the override-keyed test red); the CLI exit
  ignoring a retained teardown (red); the doctor advisory dropped (red).
  Measured with `scripts/ci/money-path-classify.mjs <merge-base>` against
  `.github/money-path-globs.json`: no touched file matches a runtime or
  control glob (`packages/connect/src/**` is `DOC_ONLY` in
  `scripts/ci/money-path.test.mjs`). Custody unchanged — Haven still holds no
