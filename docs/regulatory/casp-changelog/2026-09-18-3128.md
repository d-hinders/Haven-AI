- **#3128** — **The agent's read surface: an empty receipts list says why,
  the list pages, and the two allowance reads agree. Read-only shape work; no
  authority, custody, funding, signing or settlement boundary moves.**
  `GET /machine-payments/receipts` returns a page `{ receipts, total,
  has_more, next_cursor }` instead of a bare `{ receipts }`: `total` is the
  `COUNT(*)` of `machine_payment_evidence` rows for the calling agent, so an
  empty page with `total: 0` means Haven holds no receipt (a receipt row is
  written when evidence attaches, synchronously with the settlement report —
  there is no indexing delay behind this list); `has_more` comes from fetching
  `limit + 1` rows; `next_cursor` is the last returned receipt id and is fed
  back as `?cursor=`, resolved by a keyset predicate on `(created_at, id)` that
  looks the cursor row up under the SAME agent id (`WHERE c.id = $3::uuid AND
  c.agent_id = $1` in `LIST_EVIDENCE_RECEIPTS_SQL`); a cursor is refused with
  400 when it is not a uuid (before any query) or when it names no receipt of
  this agent (one resolver query, `RESOLVE_RECEIPT_CURSOR_SQL`, scoped by agent
  id) — never an empty page beside a non-zero total. The keyset predicate
  remains the second line of defence: an unresolved cursor would yield an
  empty page, never another agent's history. Additive on the wire (the three fields are
  required in the spec's closed schema; `receipts` is unchanged). The SDK keeps
  `listReceipts()` returning the bare array and adds `listReceiptsPage()`; both
  MCP runtimes (`packages/mcp-server`, `packages/mcp`) accept `cursor` and
  return the page object — the ONE non-additive change, argued as an exemption:
  the tool result is agent-read JSON whose shape the tool description is the
  specification of, an array cannot carry `total`/`has_more`, and no
  programmatic in-repo consumer reads the tool result as an array (the
  qa-agent and the SDK read the HTTP envelope's `receipts`, unchanged).
  Allowances: `HavenAllowance.remainingDisplay` (derived client-side from
  `onchain.remaining` and the token's decimals by one function) and
  `HavenAgentAllowanceSummary.id` / `.tokenAddress` are added, so each read is
  a superset of what the other lacked; no backend field moves. Perimeter
  argument: every change is a read of the calling agent's own rows, scoped by
  the authenticated agent id as before; no route gains a write, no key or
  token is newly readable, and the sweep, settlement and signing paths are
  untouched. Mutation-tested: the page cut at `limit` (limit+1 fetched, one row
  dropped, `has_more` true, `next_cursor` the last id) and the cursor reaching
  `$3` scoped to the agent (route tests); an empty page reports `total: 0`; a
  non-uuid cursor refused before any query, and the resolver bypassed (an
  unresolved cursor answered with an empty page instead of 400) — both red;
  the local runtime's handler reverted to the bare array (two red); the two
  allowance reads pinned
  field for field on one fixture (SDK); the hosted and local tools return the
  page and forward `cursor` (MCP suites); a pre-#3128 backend maps the three
  page fields to `null`, never a fabricated 0/false; the keyset itself is
  pinned on the real-Postgres repository harness (newest-first with the id
  tiebreak across an adversarial equal-`created_at` tie, a limit-1 walk that
  visits every row once, another agent's receipt id and an unknown id as
  cursor yielding an empty page, the count the agent's alone — mutations
  red: tiebreak dropped, cursor row unscoped, count unscoped). Measured with
  `scripts/ci/money-path-classify.mjs <merge-base>` against
  `.github/money-path-globs.json`: this PR is MONEY-PATH —
  `packages/backend/src/routes/machine-payments.ts` by name, plus
  `packages/backend/src/modules/mpp/**`,
  `packages/backend/src/infra/repositories/**` and
  `packages/mcp-server/src/**` (the command carries the file count; it moved
  from eight to nine when the repository test landed) — so this PR carries
  the `money-path` label and a dev → main promotion needs a covering green
  money-flow QA run (the first measurement in the PR's draft body read
  "0 of 0" because the classifier was run before the branch diverged from
  dev — a zero that measured nothing, and is corrected here). No touched file moves money, grants authority or
  changes a settlement envelope: every change is a read of the calling
  agent's own rows. Custody unchanged — Haven still holds no key and no
  funds. Perimeter unchanged.
