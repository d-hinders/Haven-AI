  ## Why the perimeter is unaffected — and, on two paths, narrower

  This is a heavier money-path range than a routine promotion: **78 of the 399
  changed files match `.github/money-path-globs.json`**, and it carries three
  new migrations (087 hosted-refusal source, 088 merchants, 089 marketplace
  prospects) plus a modification to 086. Each is addressed rather than covered
  by a blanket sentence.

  **x402 unsupported transfer methods are now refused before funding or
  signing (#3116).** `selectStandardPaymentOption` treated every non-`erc7710`
  entry as EIP-3009-compatible, so an entry advertising
  `extra.assetTransferMethod: 'permit2'`, or an unrecognised `extra.paymentFlow`,
  could be selected and signed into an EIP-3009 authorization payload the
  exact-EVM spec does not define for it — which v2 §6.1 forbids. An entry is
  now EIP-3009-constructible only when the transfer method is absent or exactly
  `eip3009` AND the flow is absent or exactly `authorization`; anything else is
  skipped when a supported alternative exists and refused, **before intent
  creation, funding or signing**, when it is the only option. This is strictly
  fewer payloads Haven will sign.

  **The paid retry can no longer be redirected to a merchant-declared resource
  (#3097).** The retry after payment goes to the URL the caller quoted, never to
  a public `http://` resource the merchant declared in its challenge. A merchant
  could previously name the destination of the authenticated retry. Removing
  that is a narrowing of who chooses where a paid request lands.

  **Advertised accepted requirements are preserved across SDK and backend
  encoding (#3117).** A correctness fix on what is echoed back, not a change to
  what may be spent.

  **Hosted prepare refusals reach the ledger (#3054, migration 087).** Refusals
  that happened in the hosted MCP before any backend call were not recorded, so
  the Analytics "Refused" tile under-counted on exactly the paths an agent hits
  first. This release adds `POST /machine-payments/budget-precheck` and the SDK
  `precheckBudget`. **A precheck is a read**: it answers whether a budget would
  cover an amount and writes a refusal row; it moves no funds, mints no
  delegation and is not a spend authorisation. Recording more refusals is a
  transparency gain, not an authority change.

  **The hosted sufficiency check (#3126) is likewise a read** — an agent can ask
  whether its budget is backed by funds. It answers from balances; it neither
  tops up nor spends.

  **The three migrations add tables and columns; none touches custody.** 087
  adds a source discriminator to the existing refusal ledger. 088 and 089 create
  the marketplace `merchants` and prospects tables — catalogue metadata, with
  chain scoping applied to non-agent reads. No migration alters a delegation,
  a budget, a signer set or an execution path, and all three are code-owner
  gated on merge as direct migration files.

  **No authority, custody or execution change whatsoever.** No caveat enforcer,
  delegation shape, budget, recipient pin or expiry is touched. Haven gains no
  signing capability: every money-path signature is still produced by an
  agent-held delegate key over the account's typed data, verbatim. The retired
  Safe and session rails remain fail-closed at 410. No key material changes
  hands, and the connector work in this range (#3120–#3123) moves in the same
  direction — `--unwire` now refuses to destroy the recovery credential, and
  `--doctor` stops reporting a green verdict it cannot substantiate.

  ## What this release does NOT prove

  Stated so a reader does not infer coverage from silence. The money-flow QA
  harness admitted for this promotion is a `workflow_dispatch` run at
  `6937e314`, dev's tip — dispatched because every recent `deployment_status`
  run had `money-flow` **skipped** by the duplicate-deployment gate, a run-level
  green whose harness never executed. The backend real-DB suites did not run in
  the cutting environment (no Docker daemon); that is an environment limit, not
  a green result. Two unrelated gates are red in that environment and red at
  base: two `chmod 000` tests that cannot fail-as-designed under uid 0, and an
  on-chain enforcer probe with no outbound reach to `sepolia.base.org`.

  Perimeter unchanged; on the two x402 paths above, strictly narrower.
