- **#3127** — **Every converted transaction amount now names its currency, and
  the user's `currency_preference` is honoured. Read-only projection work; no
  authority, custody, funding, signing or settlement boundary moves.**
  Before this change the transaction record carried `amountSek` /
  `fxRateSek` / `fxSource` with the currency baked into the FIELD NAMES — no
  currency field existed, so a consumer had to parse an identifier to know
  what it was reading — and `currency_preference` (a `users` column the
  product offers a setter for) was never read anywhere in the transaction
  path: a user who selected EUR still got SEK on every row, on the API, the
  CLI `--json` and the CSV export. The defect was in how a settled amount is
  REPORTED, not in how it is priced; no funds move, no key is touched, and
  no spend decision reads any of this. Perimeter argument, measured with

  What ships, and why it is read-only: (1) every transaction row gains
  `convertedAmount` / `convertedCurrency` / `convertedFxRate` — the amount in
  the user's preferred currency, the currency as a FIELD, and the rate struck
  at — plus the row's own `fxRates` book-time map, declared on the spec; the
  SEK-named originals stay on the wire byte-identical (additive, nothing to
  dual-emit, no release boundary). (2) The conversion is struck from the
  row's OWN stored book-time capture: SEK from the migration-026 columns,
  USD/EUR from the migration-082 `fx_rates` map that #2877 already freezes
  for every supported ledger currency at settlement — the SAME arithmetic and
  four-decimal scale as the accounting feed's `ledgerAmount` (`valueFormatted`
  × rate, never a serve-time price read, never a SEK fallback under another
  currency's label; a missing rate yields null, which is backfillable).
  (3) `currency_preference` joins the enum dance it never had: SEK — the
  currency every user was already being served — becomes selectable beside
  USD and EUR (one shared list, `domain/transaction-currency.ts`, used by the
  PUT validation, the signup default and the conversion), the no-preference
  default is documented SEK rather than an inherited `'USD'` string, and the
  preference is read once per request on the same scoped repository read the
  preferences route serves. (4) The CSV export stays a DELIBERATE
  fixed-SEK accounting branch — `amount_sek` is the stored book-time column
  accountants file against, and re-expressing a filed figure would be wrong
  — with two columns APPENDED at the end of its contract
  (`reporting_currency`, `converted_currency`) so the file names its own
  currency and the user's effective feed currency without moving an amount or
  shifting a pre-#3127 column index.
