- **#3169** — **`haven_sign` no longer signs a bare `payload_hash`; the
  raw-hash primitive is removed from the edge signer.** Money-path by file
  (`packages/signer/**`); custody argument strengthened, not changed.
  Before this change `haven_sign` called with only `payload_hash` (no
  `payment_id`, no `typed_data` / `typed_data_b64`, no `x402_expected`)
  reached `signer.signPaymentHash` — raw secp256k1 over caller-supplied bytes
  with no Haven binding, no amount, no merchant, no shape check and no domain
  separation. The 2026-09-19 signer scan reproduced two consequences with a
  disposable key and nothing broadcast: (1) the EIP-712 digest of an EIP-3009
  `TransferWithAuthorization` from the delegate wallet to an attacker address
  came back as a valid signature (the delegate wallet holds the full payment
  between Haven's funding leg and the merchant retry on the EIP-3009 rail);
  (2) the #1476 delegation refusal, which keys on the typed data's SHAPE, was
  bypassed by hashing the same `Delegation` first. The arm's only legitimate
  caller was the AllowanceModule rail, retired by #1986 — the surviving rail
  validates typed data and rejects a raw-hash signature on-chain (AA24,
  #1254). Now the arm throws `HavenBareHashRefusedError`
  (`packages/signer/src/bare-hash.ts`): code `BARE_HASH_REFUSED`,
  `next_action: stop_and_tell_user`, a typed next step with no tool and the
  reason (call `haven_sign` again with `payment_id`, `typed_data` /
  `typed_data_b64`, or `x402_expected`); nothing is audited because nothing
  was signed. `EdgeSigner.signPaymentHash` is gone from `core.ts` (the SDK's
  `signHash` primitive stays; inside the signer it is now reached only through
  the verifying methods — `signAndVerify` → `signX402FundingHash`). The
  treasury smart account was never directly exposed (the Hybrid account
  rejects raw-hash signatures); the proven harm was the delegate wallet's own
  USDC while funded and the authority-grant class #1476 stops. Perimeter
  argument: the signer loses a signing capability and gains none; no tool
  added, renamed or re-shaped (`haven_sign`'s arguments are unchanged — the
  refusal is on one COMBINATION of them), so the consent hash and the
  version-skew contract do not move. Mutation-tested (each restored
  byte-identically): the refusal replaced by a success-shaped signature (the
  arm's behaviour put back) → red; the refusal's code downgraded to
  `SIGNING_ERROR` → red; the structured branch in `normalizeError` dropped (the
  refusal falls to the bare `SIGNING_ERROR` envelope) → red. Custody unchanged — Haven still holds
  no key and no funds; the delegate key now signs only what it can verify.
  Perimeter unchanged.
