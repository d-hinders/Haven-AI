- **#3172** — **The edge signer's audit sidecar is owner-only and bounded, and
  the hash arguments it records are bounded on the schema.** Money-path by file
  (`packages/signer/**`); no signing decision, expected-context version or
  binding version changes — what changes is the file the signer writes beside
  the credential and what the schema accepts into it. Before: the signer
  warned the operator to `chmod 600` the credential while creating
  `<credential>.signer-audit.jsonl` with the default `0644` beside it (measured
  on the 2026-09-19 scan: credential `-rw-------`, sidecar `-rw-r--r--`),
  carrying the delegate address, account address, chain id and every payload
  hash; the file had no size bound; and `payload_hash` matched
  `^0x[0-9a-fA-F]+$` with no length, so a caller could write hex of any
  length into a world-readable file (the scan wrote the fixture private key's
  hex into the sidecar through that argument — the signer never logged its
  OWN key; the field was simply passthrough). Now: the sidecar is created
  `0600` (`appendFile` `mode`), a sidecar found permissive is tightened in
  place on the next append — before any rotation, so a legacy file carries
  `0600` into `.1` — with one stderr line per occurrence (a symlink at the
  path, judged by `lstat`, or a refused `chmod` gets the `chmod 600` remedy
  and is left alone), the live file rotates to `<path>.1` at 8 MiB keeping one
  predecessor, an audit write that fails (disk full, read-only, two appends
  racing at the bound) is reported on stderr and never fails a signing call
  whose signature was already produced (review round 1: the unguarded
  `rename` race turned a produced signature into `UNKNOWN_ERROR`), and
  `payload_hash` /
  `typed_data_hash` are `{64}`-bounded (a 32-byte hash) on all four schema
  sites — any other length is `INVALID_INPUT` before signing or auditing. The
  credential warning now shares one implementation with the sidecar check
  (`file-mode.ts`); its wording is unchanged. Perimeter argument: no new
  authority, no new network call, the consent block's audit promise (record
  timestamp, tool, payload hash and delegate address; never the key,
  signature or x402 payment header) is unchanged in text and now also true in
  permissions. Reaches
  machines only after a signer publish. Mutation-tested (each restored
  byte-identically): the `mode` on `appendFile` dropped (red — the new sidecar
  is `0644` again); the tighten step dropped (red — a pre-#3172 sidecar stays
  `0644`, also under `umask 077`); rotation dropped (red — `.1` never
  appears); tighten moved after rotation (red — a legacy `.1` stays `0644`);
  the rename race unguarded (red — one of two racing appends rejects); the
  regular-file guard dropped or `lstat` → `stat` (red — a planted symlink's
  target is chmod-ed); the audit try/catch dropped (red — an unwritable
  sidecar fails a signed call); each of the four `{64}` sites loosened alone
  (red each — an over-long hash is accepted). Custody
  unchanged — Haven still holds no key and no funds.
