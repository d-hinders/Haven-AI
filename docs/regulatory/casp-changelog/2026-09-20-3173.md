- **#3173** — **The edge signer starts in half the time, refuses unknown CLI
  options, and its consent screen is written for the person approving it.**
  Money-path by file (`packages/signer/**`); no signing decision,
  expected-context version, binding version or consent hash changes. Before:
  the signer imported the `@haven_ai/sdk` barrel — ethers, the `x402` package
  and the HTTP client — for a handful of pure helpers and error classes, and
  `x402/schemes` statically for one call on the merchant-header leg; measured
  on the 2026-09-19 scan, `import('@haven_ai/sdk')` was 970–1147 ms of a
  ~1.3–1.5 s start. Unknown flags were silently ignored (`--ack-local-tools`,
  the connector's flag, produced only the consent wall and exit 1); `--help`
  named two of four tools; the consent block rendered ~4.5 KB of agent-facing
  tool descriptions and named neither the connector doctor nor the
  connector-side repair. Now: the SDK gains `@haven_ai/sdk/edge`, an
  ethers-free entry whose import graph is pinned by test never to reach
  ethers, `x402` or the client, with `addressFromKey` / `signHash` /
  `verifySignature` re-implemented on viem + `@noble/curves` and pinned
  byte-equivalent to the ethers forms (same address, same 65-byte low-s
  `r‖s‖v`, same recovery verdicts, raw hash never EIP-191); the signer imports
  only that entry and loads `x402/schemes` on first merchant-header use.
  Measured (median of 5 cold runs): `--help` 1.47 s → 0.71 s; consent refusal
  1.55 s → 0.77 s; barrel 1135 ms vs edge 385 ms; a loader hook resolving
  every module at startup finds zero `ethers`/`x402` packages (positive
  control: the barrel resolves two). tsup splitting makes the barrel and the
  subpath share one chunk, so `instanceof` holds across them (verified ESM and
  CJS) — the signer throws the SDK's error classes and hosted/connect code
  catches them. Unknown CLI options are refused with one stderr line naming
  `--help` and exit 2; `--help` lists every registered tool (pinned against
  `toolSchemas`) and the connector doctor; the consent block summarises each
  tool in one line and ends with `npx @haven_ai/connect --doctor` and the
  `local_signer_ack_required` / `--ack-local-tools` repair, and the no-consent
  exit message names the doctor. Perimeter argument: no new authority, no new
  network call, the same key helpers produce the same bytes (pinned), the
  consent hash (identity + tool names + surface version) is untouched, and the
  new SDK entry is a strict subset of the barrel. Skew: a signer at this
  version needs the SDK at this version (`/edge`); the exact pin and the
  connector's paired install make that the only supported combination, and a
  hand-mixed older SDK fails at import before any key is read. Mutation-tested
  (each restored byte-identically): a runtime file importing the barrel (red);
  `x402/schemes` imported statically again (red); the edge entry re-exporting
  the ethers helpers (two red); high-s signatures allowed (red); yParity
  inverted (red); unknown option silently ignored (two red); `--help`
  hardcoded to two tools (red); the consent block rendering the full
  descriptions (red); the doctor hint dropped from the block (red); the doctor
  dropped from the exit message (red). Custody unchanged — Haven still holds
  no key and no funds.
