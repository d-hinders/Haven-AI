- **#3227** — **three repository writes now enforce tenant scope in their own
  SQL, not only through the route's ownership pre-check. No authority,
  custody, funding, signing or settlement boundary moves; the change only
  narrows which rows a write can touch.**
  `packages/backend/src/infra/repositories/smart-accounts.ts` and
  `agent-labels.ts` sit under the `infra/repositories/**` money-path glob,
  hence this shard.
  **What was wrong.** `setDefaultAccountForUser`, `deleteAccountForUser` and
  `replaceAgentLabels` took the caller's `userId`, but five of their
  statements matched rows by id alone. Ownership was checked only by the
  route in another file, so the repository was not a backstop. On a real
  database, a direct call with a second user's id deleted the victim's
  account and orphaned its agents, left the victim with two default
  accounts, and put the caller's label on the victim's agent. Nothing was
  reachable through the API: each route checks ownership first (pinned by
  tests), and that check is unchanged.
  **What moved.**
  - The account delete and the agent orphan are scoped to the caller
    (`AND user_id = $2`). A delete that matches no row returns `false` and
    promotes nothing.
  - The set-default is scoped to the caller. The clear of the caller's other
    defaults runs only when the named account is theirs, and the legacy
    address mirror is skipped when the set matched nothing.
  - Both label-assignment writes join through an agent the caller owns.
  - Owner decision (2026-09-22): a cross-tenant call is a silent no-op that
    returns the existing "not found" value, with no new error type. The
    routes' 404s are unchanged.
  **Evidence.**
  - `src/infra/repositories/__tests__/cross-tenant-writes.test.ts` runs on
    the real database: the three cross-tenant cases, the owner's own unlink
    and re-default, and the rename control. At the parent commit its three
    cross-tenant cases failed and the control passed.
  - Removing each new condition, one at a time, turns the suite red: eight
    mutations, eight caught (listed in the PR).
  - The unlink guards this document relies on — live delegation, open sweep,
    in-flight re-key — run first and are untouched.
  **The parent's #988 note, read against this.** `casp-risk-guardrails.md`
  says the repository move made the `WHERE user_id = $1` authorization "a
  signature the type checker enforces". That held for the signatures, but
  not for these five statements: each function took `userId`, and the
  statements did not use it. They do now. The repositories README's rule 3
  now says that taking `userId` is not the same as scoping by it.
