- **#3255** — RPC failover for the backend's viem reads; no authority, custody, route or signing change. A new helper, `packages/backend/src/infra/chain/rpc-transport.ts`, builds every backend viem RPC transport as a viem `fallback()` over the dedicated endpoint (`RPC_URL_BASE*`), an optional second provider (`RPC_URL_BASE_FALLBACK` / `RPC_URL_BASE_SEPOLIA_FALLBACK`, new) and the public Base node, and the delegation-rail prepare/treasury clients, the counterfactual-deploy checks, the `disabledDelegations` read, the budget reader and the unused viem chain client now go through it. A transport failure (HTTP 429/5xx, a JSON-RPC quota error in an HTTP 200 body, a timeout) moves to the next endpoint; an `eth_call` revert is terminal and is never asked of a second node (viem's default rule plus JSON-RPC `code: 3`). What decides a spend is unchanged: the budget, recipient pin and expiry are still enforced by the audited caveat enforcers during `eth_estimateUserOperationGas` on the bundler, which this change does not touch, and every UserOp still needs the account signer's signature. The fall-back nodes only answer reads, and each wrong answer a lagging node could give fails safe: a stale nonce is refused by the bundler, a missed deploy reverts on-chain (spending relayer gas, moving no funds), `disabledDelegations` reads at `finalized`, and the budget reader already fell back to the full budget on any failure (#1145), with its total 2 s bound kept by splitting it across legs. The ethers relayer provider, and the log scanners and settlement verifier behind it, deliberately stay on one node (#1533), so no relayer broadcast or settlement verdict reads from a fallback node. Provider URLs are never logged. Tests drive the transport against local stub nodes (quota refusal in both shapes, revert, hang) and a guard test pins that no other backend file builds a viem RPC transport or a second `JsonRpcProvider`; each was shown red under a targeted mutation. Perimeter unchanged.
