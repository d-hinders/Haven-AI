- **#3259** — a failed tombstone mirror no longer leaves a spend-capable directory that reads `retired`. **No custody or authority boundary moves; one local key-hygiene hole closes.** `writeAgentTombstone` writes the diagnostic wrapper and the in-place `TOMBSTONE.json` first, then mirrors the record into the root's ledger (#2155, #3251). That mirror write used to throw. In the `--replace` path (#2551) the throw landed in a catch that skipped `teardownLocalKeyMaterial`, leaving `signer.json` and the `identity.json` API key in a directory that `--doctor` classified `retired`. `wiring-collision` skips tombstoned directories, so no later setup retried it. The mirror is now best-effort: a failure returns `recordPath: null` plus `mirrorError` (the errno code only, never the OS message with its local path detail), and `--replace` still removes the key files, logs a warning and names the failure in the outcome's additive `retirement_mirror_errors`. `--tombstone` exits 0 with the on-disk truth (`tombstoned: true`), and `--unwire --json` gains an additive `mirror_error`. Nothing is revoked (#1688: connect reports, the user decides), and the record's fields and redaction are unchanged. The only behavioural change on a key path is that local key files are now removed in a case where they previously survived; nothing new is created, widened or signed. Mutation-proven: rethrowing the mirror error, or skipping the teardown on it, turns the `--replace` regression test red. **Residual, stated:** if `teardownLocalKeyMaterial` itself throws after `TOMBSTONE.json` is written (e.g. a read-only `identity.json`), the directory still ends tombstoned with its key. `--doctor` reports that as `tombstoned — key material still present`, so it is visible, but nothing retries it, and directories left half-retired by earlier connectors are not repaired. No route, credential scope or signing path is added or widened. Perimeter unchanged.
