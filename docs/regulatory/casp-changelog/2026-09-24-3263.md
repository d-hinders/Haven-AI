- **#3263** — the relayer's outbound pipeline stops re-sending payloads that revert deterministically. **No custody or authority boundary moves.** Two changes, both in `packages/backend/src/infra/`, and both only CLOSE rows; neither sends anything new:
  - **Bump worker orphan path (`outbound-bump-worker.ts`).** A `queued` orphan whose re-broadcast fails with a deterministic revert (ethers `CALL_EXCEPTION` carrying revert data, classified in the new pure `deterministic-revert.ts`) is marked `failed` with the action and 4-byte selector. It is no longer released back to the claim lease to be re-sent every two minutes forever. On dev (Base Sepolia, 2026-09-24), 388 such orphans (EAS `revoke` of UIDs that do not exist, `NotFound()`) were burning the relayer node's quota at roughly 3 calls/s.
  - **`submitRecorded` (`outbound-queue.ts`).** When `populateTransaction` (gas estimation) reverts deterministically BEFORE the record is stamped, the record is closed `failed` instead of being left `queued`. Nothing was signed or broadcast. The error still propagates, so every submitter's own retry path is unchanged.

  Transient failures keep today's behaviour exactly. In ethers v6 every gas-estimation RPC error surfaces as `CALL_EXCEPTION`, so the discriminator is the revert data. A code-30 "free plan" timeout, `gas required exceeds allowance`, a data-less revert, nonce errors and insufficient funds all arrive without it and stay retryable. A revert WITH data can still be state-dependent: it might pass later on different chain state. The guarantee is therefore narrower than "never closed if it could succeed". **A closed row is never re-sent by this pipeline; any later success goes through the submitter's own retry, on a fresh record.** Per rebroadcast-safe submitter:
  - `sweep`: its EIP-3009 authorization is valid for `SWEEP_VALIDITY_SECONDS = 300`, below the orphan age gate `ORPHAN_QUEUED_SECONDS = 600`. Every sweep orphan the worker can claim has therefore already expired and could never have succeeded. On the pre-broadcast path, `modules/mpp/sweep.ts` already marks its own sweep failed and returns 502, so the caller retries. No fund movement is lost.
  - `hybrid_deploy`: the provisioning caller retries on its own record.
  - `passport_revoke`: the DB remains authoritative for revocation (`revocation.ts`), and the reconcile's own backoff retry opens a fresh record.
  - `lane_cancel`: its 0-value self-send to the relayer EOA cannot revert with data. If it ever did, the close carries the cancel's explicit nonce, so the lane cap still counts the attempt.

  No route, credential scope, key-material handling, signing path, fee policy or nonce allocation changes. Stamped (`broadcast`) rows and the same-nonce replacement path are untouched. Perimeter unchanged.
