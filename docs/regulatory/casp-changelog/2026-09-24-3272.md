- **#3272** — the edge signer (`@haven_ai/signer`) stops being a signing oracle for the agent's delegate key. **The perimeter narrows.** Before this change, `haven_sign` signed **any** EIP-712 typed data it was handed. The only exceptions were a `Delegation` without a Haven-signed context (#1476) and a bare hash (#3169). On 2026-09-24 it returned a valid signature over an invented `Probe` message. Three changes:
  - **Allowlist on the unbound branch (`packages/signer/src/tools.ts`).** Without an x402 context, `haven_sign` signs typed data only when all of these hold:
    - it is a `PackedUserOperation` that passes the #3271 binding check;
    - it is on a chain with pinned delegation contracts (Base, Base Sepolia);
    - its sender is the signer's own delegate account (the counterfactual HybridDeleGator for the delegate key, derived offline by CREATE2 in `delegate-account.ts`, with the vendored constants pinned by test to the MetaMask kit and to a captured on-chain UserOp);
    - its `callData` is a single `execute` to the DelegationManager calling `redeemDelegations`.
    
    Anything else is refused with the structured `TYPED_DATA_NOT_ALLOWED`: no signature and no audit entry. That covers arbitrary typed data, a delegate-wallet `TransferWithAuthorization` or USDC `Permit`, a UserOp that calls the account itself (`transferOwnership` and similar), a UserOp for another account, and a UserOp with any other call target. Each case is pinned by test, and the guards are mutation-proven.
  - **Expected-context v1 retired.** Owner decision 2026-09-24; this is Haven's internal bare-hash binding format, not the x402 protocol version. The signer supports expected contexts 2 and 3 only, and `signX402FundingHash` is removed. The backend's `signX402ExpectedContext` now requires `typedDataHash` in its type and refuses at runtime without it, so no site can emit v1. x402 protocol v1 and v2 merchants are unaffected.
  - **Audit and binding integrity.** The audit log records the EIP-712 digest actually signed instead of the caller's `payload_hash`. The x402 typed-data arm's binding check compares Haven's declared digest against the digest of the typed data being signed; before, it compared a value with itself.

  **No custody or execution boundary moves.** Enforcement is still on-chain: the caveat enforcers bound every redemption by budget, recipient pin and expiry. What moves is what the delegate key will sign, and it narrows to the shapes Haven prepares. `createEdgeSigner().signDelegationTypedData` stays a verbatim library primitive; the allowlist is enforced in the MCP tool layer, and embedders that call the core directly own the check. **Residual exposure:** signers installed before this change keep the oracle until upgraded. Haven cannot gate that, because the attack does not pass through Haven and the hosted MCP cannot see the signer's handshake. The remedy is a signer upgrade carried by the release notes. The unanswered upstream questions (self-call reachability of the HybridDeleGator admin functions, ERC-1271 wrapping) are recorded in `docs/security/delegation-rail-security-model.md` §10; the allowlist makes both moot for an upgraded signer. Perimeter narrowed.
