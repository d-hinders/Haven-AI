- **Outbound-queue fail-open policy, revisited (owner decision 2026-09-24)**: a comment and docs change, with no runtime change. The header of `infra/outbound-queue.ts` asked for its fail-open `openOutboundRecord` policy to be revisited site by site once the queue became the only lane (#1557/#1559). This records the answer: the owner kept fail-open at every site. A failed open leaves the send unstamped, so its nonce is guarded only by the in-process lock, and unrecorded, so it is invisible to the bump worker. It puts no funds at risk. A collision only fails a broadcast. The one site that moves funds, the sweep's `transferWithAuthorization`, is signature-bound, and its EIP-3009 nonce stops a duplicate from paying twice. The relayer itself holds only gas. The decision assumes a single backend replica and must be revisited before running more than one. `backend-scaling.md` § *Multi-replica CORRECTNESS* carries the same statement. **No authority, custody or execution boundary moves.** Perimeter unchanged.
