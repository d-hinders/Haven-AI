  **#3303 is additive and moves no authority.** Every published client now names itself in an `X-Haven-Client` header. The backend reads it against `CLIENT_COMPAT`: it hints an update below a `recommended_version`, and refuses with 426 `client_outdated` only below a SET `min_version`, at the payment-creating routes and the signer's two sign-context reads. It never refuses a sweep, sign, settle, evidence or status route, a live idempotent replay, or a retired-rail agent (which keeps its 410). **Every threshold is null at this cut, so no client is hinted or refused by this release.** A refusal, when one is ever configured, writes no payment state and happens before any signature. It can only stop an outdated client from starting a payment, never make one. The signer maps it to `SIGN_CONTEXT_REFUSED` / `client_outdated` with no signature. #3303 carries its own shard.
