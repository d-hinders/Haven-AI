- **#2769 (operator cancel for a relayer nonce lane the bump worker has given up on)**: an operator can now clear one more stuck-lane shape with the existing encoded cancel. No authority, custody, route or signing change, and nothing is triggered automatically. `cancelStuckOutboundLane` (`packages/backend/src/infra/outbound-lane-cancel.ts`, run as `ops:cancel-stuck-attest` or its new alias `ops:cancel-stuck-lane`) burns a stuck relayer nonce with a 0-value relayer self-send at that nonce, through the outbound pipeline. Until now it refused every rebroadcast-safe submitter (sweep, hybrid deploy, passport revoke, lane cancel) unconditionally, because the bump worker fee-replaces those itself. But the worker stops for good once a lane has three counted attempts, and hands the lane to an operator ("nonce lane stuck after 3 replacements — INCIDENT, not retrying"), so a capped rebroadcast-safe lane had no encoded recovery, only the hand-run self-send the runbooks forbid. That shape occurred on dev on 2026-09-25: rows stamped `broadcast` during the dRPC `flashblocks` refusal window never reached a node, their bump attempts failed and reached the cap, and later sends queued behind the hole at nonce 3170. The trigger now accepts a rebroadcast-safe row only when its nonce is AT the worker's cap (`countLaneAttemptsAtNonce` ≥ `MAX_BUMPS_PER_NONCE`); below the cap it still refuses (`automated_recovery_owns_it`) and sends nothing. Every other gate is unchanged: the row must be `broadcast`, stamped, older than the stale threshold and unmined by receipt, the claim is still the `broadcast` → `replaced` flip that lets exactly one trigger proceed, and the cancel is stamped before broadcast. Burning such a payload is safe because each owner retries on a fresh record: a hybrid deploy is re-attempted at the next activation or erc7710 authorize (CREATE2, idempotent), and `reconcileRevocation` submits a fresh revoke. A sweep is not retried automatically: the relay throw marks the sweep failed and its stranded event stays open, so the funds stay on the delegate, visible, until the agent sweeps again; its EIP-3009 authorization is single-use, so a late duplicate reverts and moves nothing. The cancel is a self-send of zero value, so it moves no funds; budget, recipient pin and expiry are still enforced by the caveat enforcers on-chain. Proven on real Postgres in both directions: a sweep one attempt below the cap is refused with nothing sent, and a capped sweep, which the bump tick demonstrably alerts on and walks away from, is cancelled at its nonce. Lowering the gate by one, or removing it, fails the below-cap test; raising it by one, or restoring the unconditional refusal, fails the at-cap test. A cancel on a capped lane starts past the cap itself, so the worker only alerts on it if it sticks. The outcome now says so (`workerResends`), the command tells the operator to re-run it on the cancel row's id, and that re-trigger is accepted; a real-DB test pins the whole sequence, and a boundary test pins `workerResends` at one attempt below the cap. Residual, unchanged: a cancel releases every later nonce at once, so the operator must read what sits above N first, as `stuck-revoke-alarm.md` §4 precondition 5 requires. Perimeter unchanged.
