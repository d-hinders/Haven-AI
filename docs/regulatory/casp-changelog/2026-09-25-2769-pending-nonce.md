- **#2769 (relayer nonce when the RPC refuses `pending`)**: the relayer's nonce source for its own transactions changes on one provider refusal. No authority, custody, route or signing change. Every relayer send (account deploy at first budget activation, sweeps, passport attestations) takes its nonce from `eth_getTransactionCount(relayer, "pending")` in `submitRecorded` (`packages/backend/src/infra/outbound-queue.ts`). dRPC's Base plans, the dev primary since 2026-09-24, answer that `pending` read with "no available upstreams … No label `flashblocks`" while serving `latest` normally. So every relayer send on dev failed from 2026-09-25: a new user's first budget activation answered 502 "Could not deploy the account", and sweeps could not return stranded delegate funds. Payments, x402 settlement and reads were unaffected, because they do not use the relayer's nonce. On that refusal only (`isPendingTagRefusal`), the nonce is now the larger of the same provider's `latest` count and one past the highest nonce this relayer holds a live broadcast at in `outbound_txs` (`maxLiveBroadcastNonce`, backed by the existing partial UNIQUE `idx_outbound_txs_live_nonce`). Every send with a record id is stamped there before it is broadcast, so the ledger sees our own in-flight transactions that the node will not report. Any other error from the `pending` read (timeout, rate limit, dead endpoint) propagates unchanged. The residual is a collision with an unstamped send (a failed-open record, the bump worker's orphan re-send) or another writer on the key. It surfaces as a rejected broadcast, the same failure class a stale `pending` read already had. The send lock, the stamp-before-broadcast fence and the UNIQUE live-nonce index are unchanged. A nonce decides only the ORDER of the relayer's own transactions, never what they do: the relayer still signs a plain factory deploy or a sweep whose destination the account's own delegation fixes, and budget, recipient pin and expiry are still enforced by the caveat enforcers on-chain. Perimeter unchanged.
