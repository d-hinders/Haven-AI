- **#2769 (dRPC batch limit)**: RPC request framing and read caching only. No authority, custody, route or signing change. The relayer's ethers `JsonRpcProvider` (`packages/backend/src/infra/relayer.ts`) now sends each JSON-RPC call on its own (`batchMaxCount: 1`) and detects the chain once (`staticNetwork: true`). The dRPC free plan, the dev primary since 2026-09-24, refuses any batch of more than three calls, so concurrent reads through that provider failed together. That covered balance reads, the log scanners, the settlement verifier and relayer submissions. It showed up as dashboard balances flickering to zero and as intermittent failures of sweep relays and account deploys. There is still ONE provider instance per chain, and the relayer wallet is bound to it, so the single nonce view (#1533) is unchanged. So are the send lock and the outbound-record stamping. The portfolio and `GET /balances` reads no longer cache a result in which any balance read failed. Such a result still reports that token as zero in that one response, but the next request reads the chain again instead of serving the zero for the 30–60 s cache lifetime. These reads are display-only and decide no spend. Budget, recipient pin and expiry are still enforced by the caveat enforcers on-chain. Perimeter unchanged.
