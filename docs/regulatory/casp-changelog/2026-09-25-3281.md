- **#3281** (epic #3284, final slice) — the edge signer's x402 arm stops trusting Haven's binding key for what it signs. **The perimeter narrows.** Before this change, `signX402FundingTypedData` in `@haven_ai/signer` signed any typed data whose digest Haven's x402 binding key had committed to; only an erc7710 settlement child got a meaning check. Under the epic's owner-confirmed threat model the binding key is untrusted, so a compromised key could have had the delegate key sign an empty-context redemption capturing the delegate smart account, a delegate-EOA `TransferWithAuthorization` or `Permit`, or a funding leg paying an attacker. Three changes:
  - **Two shapes only.** The x402 arm now signs exactly:
    - a funding-leg `PackedUserOperation` that passes the #3271 binding against the declared UserOp hash and the #3272 direct-payment allowlist (own derived account, pinned chain, a single `redeemDelegations` of one budget delegation granted by another account);
    - an erc7710 settlement child that passes the settlement-child verifier.

    Everything else is refused with `TYPED_DATA_NOT_ALLOWED` (or `USEROP_BINDING_MISMATCH`), with no signature and no audit entry, however validly it was bound. The checks come from the one guard `@haven_ai/sdk` also runs (#3283).
  - **The funding leg's recipient is pinned locally.** Its single execution must be a `transfer` of the quoted amount of the quoted token to **this signer's own delegate EOA**. That is a value on the user's machine, not from Haven, so through the x402 funding leg even a compromised binding key can move budget only into the agent's own wallet, which the sweep returns. A correctly shaped direct payment still pays whatever recipient the budget allows; that is residual 1 by design. The backend's funding leg is pinned to this shape by a contract test over the production encoders (`funding-leg-signer-shape.contract.test.ts`).
  - **Settlement children must come from the agent's own account.** Every settlement-child refusal is now `TYPED_DATA_NOT_ALLOWED` like the other shape refusals. The verifier also requires the child's delegator to be this signer's derived account, and refuses a ROOT authority (the ROOT refusal already reached this arm via #3283). The exact budget-delegation hash is not checked: it is knowable only by trusting Haven, and the invariant does not need it, because a non-ROOT authority must resolve on-chain to a delegation made to this account, which only its owner can sign.

  **No custody or execution boundary moves.** The caveat enforcers still bound every redemption. **Residual exposure**, as epic #3284 records and the owner accepted:
  - payments within the budget caveats (any recipient for an open budget; narrowed here for the bridge);
  - delegate-EOA balances signed by the merchant header and the sweep;
  - signers installed before this change keep the old x402 arm until upgraded.

  Perimeter narrowed.
