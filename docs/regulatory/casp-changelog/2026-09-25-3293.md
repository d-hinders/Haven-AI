- **#3293:** the outbound bump worker stops raising a permanent "nonce lane stuck" INCIDENT for a row whose nonce another transaction already consumed. **No custody or authority boundary moves. This only closes a bookkeeping row that can never mine.**
  - **The dev case.** On dev (Base Sepolia) a `broadcast` row at nonce 806 raised the INCIDENT every minute, while the relayer's mined nonce was 3142 and the row's hash was unknown to both public nodes checked. Nonce 806 had been consumed on 2026-08-19 by a different transaction from the same key.
  - **The new close.** On the stale-broadcast path, after a `null` receipt and before the non-idempotent gate and any bump, the row is closed `failed` only when all three hold. This is the same evidence chain `classifyAnchorTxLiveness` (#1745) already uses:
    1. the transaction is unknown to the node the relayer provider answers from (`getTransaction` is null). The settled nonce is the CURRENT key's, so for a row sent by an earlier relayer key this null is the only guard. An earlier-key transaction evicted from that node but still pending elsewhere could be closed `failed` and then mine. This is not a regression: such a row had no close before, and `classifyAnchorTxLiveness` carries the same residual;
    2. the relayer's MINED nonce, read at a settled block, is past the row's nonce. It is never read at the head, and no settled block means no evidence;
    3. a last receipt re-read is still null. If it finds a receipt, the row closes `mined` (or `failed` if reverted) from that receipt.
  - **Not affected.** Anything short of that keeps the previous bump-or-INCIDENT path exactly. The worker sends nothing new, and signing, fees and nonce allocation are unchanged. `settledReadBlock` moved from `modules/passport/attestation.ts` to `infra/chain/settled-read-block.ts`, unchanged, so the worker and the passport probes share one definition.
  - **Consequences for other flows.**
    - A consumed-nonce `passport_attest` row is now closed `failed` instead of alarming forever. #1043 recovery reads `failed` like `broadcast`, straight to its nonce evidence, so the anchor still re-anchors.
    - A lane cancel that lost its race (#1743) is closed on its first settled tick instead of after the capped INCIDENT.
  - **Out of scope, stated:**
    - A `replaced` sibling that actually mined stays `replaced`, because no `replaced` → `mined` transition exists.
    - Relayer key rotation is bounded by the `getTransaction` requirement, with no `from_address` migration.

  No route, credential scope, key-material handling, signing path or spend authority is added or widened. Perimeter unchanged.
