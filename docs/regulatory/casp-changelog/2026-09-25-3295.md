- **#3295 (last-known balances + degraded-balance freshness markers)** — display-read resilience across `packages/backend/src/modules/accounts/{balance-freshness.ts (new),portfolio.ts,index.ts}`, `routes/{balances,dashboard,user-accounts}.ts`, `openapi/spec.ts`, the regenerated `packages/core/src/api-types.ts`, and the frontend display surfaces (a shared `BalanceFreshnessIndicator` primitive, the three balance-bearing screens, the aggregation hook, rendered-screen + e2e visual tests). A failed on-chain balance READ no longer renders as a real zero: the portfolio module and `GET /balances/:accountAddress` serve the last successfully read balance for that (chain, account, token), marked stale with its as-of time, or `unavailable` when nothing was ever read; `GET /dashboard/overview` computes its totals from the substituted values and reports its `change` unavailable when some token has no known value (never as a swing computed from a zero).

  Authority and custody argument: the diff touches read paths only. No key material, signing, binding, verification, relaying, or payment execution moves; no new spender, approval, or credential surface is created. The last-known store is per-replica in-process display state, written only by successful reads, and is consulted by nothing that authorizes or moves funds — budget, recipient and expiry remain enforced on-chain by the caveat enforcers, exactly as before. The wire changes are additive OPTIONAL markers (`balanceFreshness`) on three read-only GET routes; every token entry stays present with `balance` a decimal string plus address and decimals, which is the additive constraint that keeps the published CLI's token-registry reads (`packages/cli/src/commands.ts`) working unchanged (the CLI's rendering of the new marker is a deferred follow-up). The OpenAPI descriptions that documented failure-as-zero (`spec.ts` `BalanceItem`/`PortfolioBreakdown`) now describe the marker instead. `routes/user-accounts.ts` in this diff is comment-only: the `/user/accounts/:accountId/funding` endpoint still answers `'0'` on a failed read and computes `funded` from it — behaviour unchanged, the marker gap deferred by name to a follow-up issue. A substituted portfolio result is still excluded from the 30–60 s response caches (#3292 intact), so no degraded answer outlives its request.
