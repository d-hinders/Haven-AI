- **#3329 (epic #3328, slice 1)** — task budgets: a time-boxed ERC-7710 child delegation an agent opens under its own budget delegation for one run (`packages/backend/src/modules/task-budgets/`, `routes/task-budgets.ts` agent-auth, `routes/agent-task-budgets.ts` owner read, migration `095_agent_task_budgets`, `rails/delegation-rail.ts` and `rails/delegation-authorization.ts` redeeming a `[task child, budget]` chain, `modules/x402/x402-delegation.ts` building the settlement child under the task child, `task_budget_id` on `POST /payments` and `POST /x402/authorize`; `@haven_ai/sdk` `task-budget-guards.ts` + a two-link case in `redemption-guard.ts`; `@haven_ai/signer` `haven_sign` with `task_budget_id`; two MCP tools on the local and hosted servers; a reserved-amount line and a task-budget list on the dashboard budget card).

  Authority and custody argument: no new spender and no new key. The child's delegator and delegate are both the agent's own delegate smart account, its authority is the owner's budget delegation, and every caveat on it (amount cap, ≤24 h expiry, optional payee pin) can only narrow what that account could already redeem under the budget; the period budget's enforcer still meters the chain. Haven builds the child unsigned and returns typed data; the agent's local key signs it after the SDK guard re-derives its meaning from the caveats, so a Haven that lied about the child would be refused by the same discipline the settlement child has (#1455, #3281). Closing early is a `disableDelegation` of that same self-granted child from the agent's own account — the one shape the signer learned — and it cannot target the owner's grant or any delegation the account did not make itself. The pre-sign remainder check (`task_budget_exceeds_remaining`) is a convenience refusal in the fail-fast direction, never a policy boundary: the enforcers reject an over-budget redemption exactly as before. Haven signs nothing, holds no key, moves no funds, and the owner's revocation of the budget delegation kills every child under it on-chain. The redemption allowlist in the signer and SDK widens by one precisely described chain (a self-delegated leaf under a foreign grant) and refuses every other multi-link shape; that widening is stated in `delegation-rail-security-model.md` §10.

  Tests: characterization tests pin the pre-change single-delegation redemption bytes and the two-delegation erc7710 permission context before the chain generalisation; the backend↔SDK contract test proves the `[task, budget]` bytes the backend emits are the bytes the edge guard accepts and that a three-link or foreign-leaf chain is refused; real-DB repository tests cover the pending→open→closing→closed transitions and the reserved-sum query; signer tests cover every refusal branch of both new shapes and the cross refusals between task and settlement children. Perimeter unchanged.
