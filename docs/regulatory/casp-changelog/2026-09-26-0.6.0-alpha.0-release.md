The 0.x convention recorded in `docs/operations/mcp-runtime-compatibility.md` and the mcp CHANGELOG makes that a minor step. All other changes in the range are additive or narrow authority. Each merged change carries its own shard, and this entry records what the release bundles and what it does not prove.

  **What the release carries, by effect on authority:**
  - **#3329 (#3354), task budgets.** An agent can open a time-boxed, self-delegated child of its own budget delegation. It is redeemed as a two-link `[task child, budget]` chain and closed with an authority-reducing `disableDelegation`. This can only narrow what the account may already redeem, and it has its own shard.
  - **#3375 (#3376), SDK funding-leg recipient pin.** `HavenClient`'s EIP-3009 funding leg must pay the quoted amount into the agent's own delegate EOA, which narrows residual 1 of epic #3284. It has its own shard.
  - **#3378 (#3379), task budget passed through on four paths.** `task_budget_id` now reaches the wire on the SDK's `payX402Quote` and on the hosted `haven_send`, `haven_pay` and `haven_pay_x402_quote`, each of which had been charging the whole budget delegation instead of the named task budget. Every drop existed only on `dev` (the SDK's `dev` channel and the hosted runtime's `dev` deploy), because #3329 itself ships in this release. The change narrows spending to the task budget the caller named, and it has its own shard.
  - **#3277 (#3380), direct-payment handoff.** The hosted direct payments name the byte-free `haven_sign({ payment_id })` handoff and add old-signer refusal recovery. That is guidance and relay only, with no new signing surface, and it has its own shard.
  - **#3304 (#3367) and #3305 (#3372), public release data.** Read-only data in `/discovery`, `haven.json` and `/releases`, and the bump now generates that data from the CHANGELOGs. **This release is the first bump to regenerate it**, so `/releases` shows `0.6.0-alpha.0` once this is deployed. It never writes `client-compat.ts`, and every threshold is still null, so no client is hinted or refused by this release.
  - **#3306 (#3352), the break above.** Tool-output reshape only, with no authority change.
  - **#3318 (#3349), CLI balance freshness.** `haven wallets balances` renders the backend's `stale` and `unavailable` freshness markers instead of printing them as current. Display only, and it has its own shard. It accounts for 2 of the 3 shipped CLI files.
