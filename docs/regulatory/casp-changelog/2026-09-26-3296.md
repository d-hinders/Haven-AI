- **#3296 (don't write the daily portfolio snapshot from a failed balance or price read)** — the dashboard's first-load-of-the-day snapshot insert is now conditional on a CLEAN portfolio read: `routes/dashboard.ts` consults a new exported predicate `isPortfolioUnpriceable` (`modules/accounts/portfolio.ts`, re-exported through the accounts barrel `index.ts`), which reuses #3292's module-private `degradedResults` marker — a read is unpriceable when a balance leg was rejected, or a held token has no usable price (missing from a partial CoinGecko 200, or a thrown fetch with no #3297 last-good quote). A read valued from last-good prices is priceable by decision; a day on which every load is degraded simply gets no snapshot, and tomorrow reports `change.available = false` rather than a wrong figure. The skip is logged at info with the user id and no amounts. No gap-filling for skipped days: the balance chart plots only the days that exist. Forward-only — already-stored rows are not repaired; the -100 %-swing-on-today's-response defect stays with #3295.

  Authority and custody argument: the diff touches one display snapshot decision. No key material, signing, binding, verification, relaying, or payment execution moves; no new spender, approval, or credential surface is created. The snapshot feeds day-over-day change and the analytics balance chart only — it decides no spend — and the predicate is a pure READ of the existing degraded-result marker: it changes nothing about what is cached (a degraded result still lands in the TTL cache and is dropped right after, #3292/#3297 intact — a price failure must not stop caching, or a 429 would send every dashboard load to CoinGecko) and nothing about what the wire carries (the marker stays off the returned object, whose schema is `additionalProperties: false`). `infra/repositories/dashboard.ts` changes comment-only; the insert's SQL, its DO NOTHING conflict arm and the write-wins baseline semantics are untouched.

  Tests: `modules/accounts/__tests__/portfolio-unpriceable.test.ts` pins the predicate truth table against the real marker — clean false; rejected balance true; held token missing from a partial price map true; empty token with no price false (held is required); last-good-priced true→priceable; rejected price fetch true; and marker survival across a TTL cache hit and a single-flight shared load. Route tests pin the skip itself (no INSERT when any account is unpriceable, info log with the user id only, any-of-accounts semantics, same-day recovery once a clean load arrives) and the clean-read insert byte-for-byte as before; the dashboard-aggregates characterization suite stays green. Perimeter unchanged.
