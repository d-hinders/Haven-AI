- **#3304** — **Haven publishes, as public read-only data, what each client
  package needs to know about releases (epic #3302, slice 2). No funds move, no
  signing path changes, no authority or custody changes.** `GET /discovery`
  gains `client_releases`; `/.well-known/haven.json` extends each `packages`
  entry with the same record; and a new public page, `/releases`, renders it.
  Per published package the record carries: the version released in source,
  the minimum and recommended versions from `CLIENT_COMPAT` (the table the
  backend already enforces under #3303, so the published and enforced minimums
  are one value), the update command on the deployment's channel, and short
  notes. The backend's `client_update` hint now names that page in `notes_url`
  instead of null. The agent runbook (`HAVEN_AGENT_RUNBOOK_MD`, served as
  `/for-agents.md`, bundled in the CLI's `haven guide`, and the text this
  shard's coupling rule tracks) gains one short section. It tells an agent that
  a `client_update` on a result means run its `upgrade_command`, and that
  payments are refused until it does when `required` is true. That is the
  behaviour #3303 already enforces, now written where an agent reads first. It
  adds no instruction to move funds, sign, or widen any budget. Everything
  served is already public elsewhere: the notes restate the published package
  CHANGELOGs, and the thresholds are what every hint already tells the client
  it names. No per-user or per-agent data is added to any document, and no
  route, credential scope, key handling or spend path is added or widened.
  Custody unchanged. Perimeter unchanged.
