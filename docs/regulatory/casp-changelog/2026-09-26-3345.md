- **#3345** — the three ops alerts that POST to `DELEGATE_ALERT_WEBHOOK_URL` (relayer low balance, delegate lingering/dust, catalog ingestion stuck/mass-failure) stop dropping failed deliveries: a new shared sender, `packages/backend/src/infra/delegate-alert-webhook.ts`, checks `res.ok` (fetch resolves on 4xx/5xx), treats a non-ok status and a network error alike, logs the failure with the status and a truncated body (never the URL — a Slack hook URL carries a secret token), and returns a delivery verdict instead of throwing. Both monitors commit their module-private edge state (`lowAlerted`, the delegate `AlertState`) only after a successful delivery, so a rejected webhook re-fires on the next scan while the condition persists; the delegate monitor now carries one message per condition (lingering key `agentId:chainId`, plus the aggregate dust breach) so a partial batch commits only what was delivered; the catalog ingest loop rolls the lifecycle edge back (`resetCatalogAlertStateForTests`) when the sender reports a failed send.

  Authority and custody argument: this is a detect-side alerting reliability change. No key material, signing, binding, verification, relaying, or payment execution moves; no spender, approval, or credential surface is created; the monitors remain read-only (the delegate scan still issues only SELECTs, the relayer scan only an RPC balance read, the catalog tick unchanged). The webhook payload stays the same `{ text }` shape, its text content is unchanged, and the URL is consumed exactly as before — the change governs what happens AFTER the POST (verdict, logging, retry), never who may move money or what authority is checked before anything moves. The failure mode before this change was an undelivered warning; the failure mode after is a logged, retried warning. Neither direction touches the spend perimeter.

  Deliberately untouched: the alert thresholds, classification logic (`classifyDelegateBalance`, the catalog stuck/mass-failure detection), sweep behaviour, and `/health/ops` reads are unchanged; `lastStatus` is still recorded before the alert fires. With the webhook URL unset nothing is sent and the episode counts as handled exactly as before this change — the log warning (already emitted by all three sites) is the whole alert; only a failed SEND ATTEMPT (4xx/5xx, network error) re-arms.

  Tests: the new `infra/__tests__/delegate-alert-webhook.test.ts` pins the sender contract (2xx delivered; 404/500 logged with the status and `false`; network error logged and `false`; the URL never appears in any log call; no throw escapes) without ever constructing the real URL in a log assertion. The relayer monitor gains its first test file (`relayer-balance-monitor.test.ts`, mocking `relayer-spend-guard.js` — not `db.js`, so the db-mock ratchet does not move) covering 404, network error, retry-then-success, and the URL-unset case; the delegate monitor's suite gains `runDelegateBalanceMonitor` delivery tests including the partial-batch case; the catalog suite covers the re-arm. Mutations that commit the alerted state before sending (the original bug) turn these tests red. Perimeter unchanged.
