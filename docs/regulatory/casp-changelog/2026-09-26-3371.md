- **#3371** — **Provider API keys embedded in RPC endpoint URLs no longer leave Haven inside a viem request error. The failover transport (`infra/chain/rpc-transport.ts`) wraps viem's `request` — outside `fallback()`, not via viem `custom()`, which would add its own retry layer — and scrubs the key-like segments of EVERY configured endpoint (dedicated, configured fallback, public) out of the error in place: `message`, `stack`, `metaMessages`, `details`, `shortMessage`, the raw enumerable `url`, nested own properties, down the `.cause` chain. It converges the third copy of the segment helper onto one shared `secretSegments` (with `infra/relayer.ts`'s `keySegments` and `infra/outbound-queue.ts`'s `secretSegments`, both #2769).**
  - **Why.** viem's request errors carry the RPC URL in `message`/`metaMessages` (its `getUrl` strips only `user:password`) and in a raw enumerable `url` own property, so a key in the dRPC path (`/base-sepolia/<key>`), `dkey=`, Infura `/v3/`, Alchemy `/v2/` or QuickNode path survives to logs (pino cause-chain serialisation), `agent_passports.last_error`, and the `/x402/authorize` 502 `details` — surfaces where `redactVendorSecrets`'s fixed patterns deliberately do not know those shapes. PR #3365 closed the same class for the ethers relayer providers; this closes it for the viem transport.
  - **Authority and custody argument: no key material, signing, binding, verification, relaying or payment execution moves; no new spender, approval or credential surface is created.** The scrub is a defensive rewrite of an ERROR OBJECT after a transport failure, never of a request, a signature, or a balance check — the same argument as #3365. It mutates viem's own error instances in place and rethrows them unchanged, preserving class identity, `status`, `headers`, `code` and `data`: viem's retry logic branches on `instanceof HttpRequestError` and on `code`, so a 401 stays one attempt, an `eth_call` revert stays terminal (the fallback never walks to a second node on it), and 408/5xx retry exactly as before — all pinned against real local stub nodes. `computeHybridAccountAddress` derives the counterfactual address locally and needs no RPC with a watch-only owner; its error surfaces were exposed only through the transport this hardens.
  - **Mutation-tested.** Removing the scrub call from the transport's `request` wrap turns six tests in `src/infra/chain/__tests__/rpc-transport-key-scrub.test.ts` red — the surfaced `HttpRequestError`'s own properties (stack included) contain the stub key. The tests scan `JSON.stringify(err)` and every own property through the `.cause` chain for the key shapes.
  - Perimeter unchanged.
