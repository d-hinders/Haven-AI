- **#3378** — **`task_budget_id` now takes effect on four payment tools that accepted it but dropped it (a #3329 follow-up, epic #3328). Spending narrows to what the agent asked for. No authority widens, and no route, credential scope or custody changes.**
  - **Where it was dropped.** #3329 let an agent spend against a short-lived task budget, a self-delegated child of its own budget delegation, and declared `task_budget_id` on the payment tools. Four paths accepted the argument and never sent it: the SDK's `payX402Quote` (reached from local `@haven_ai/mcp`'s `haven_pay_x402_quote`), and the hosted `haven_send`, `haven_pay` and `haven_pay_x402_quote`. On each, the payment was redeemed under the agent's whole budget delegation instead of the task budget. The on-chain caveats still bounded it, but the task budget's lower cap, shorter expiry and optional recipient pin did not.
  - **What changed.** All four now carry it, to `/payments` as `task_budget_id` and to `/x402` as `taskBudgetId` on both the EIP-3009 and erc7710 paths. The backend already enforced task budgets on those routes (#3329), so this change only makes the requested, narrower authority the one that is used.
  - **Exposure.** The drop existed only on the `dev` channel and the dev-deployed hosted runtime. #3329 is in no npm release (`latest` is `0.5.0-alpha.1`) and not on `main`.
  - **Fail-closed consequence (owner-accepted, 2026-09-26).** A task budget pinned to a merchant recipient is declined on an EIP-3009 funding leg, because that leg pays the agent's own delegate wallet first. Before this fix such a payment silently spent from the whole budget; now it is refused with `task_budget_recipient_mismatch`. Both runtimes' `haven_open_task_budget` descriptions say so.
  - **Not fixed here, recorded on the issue.** The backend's idempotent-replay lookup does not key on `taskBudgetId` (pre-existing since #3329).
  - **Tests.** Wire-level tests read the recorded request bodies:
    - the SDK's `payX402Quote` (`funding-leg-pin.test.ts`);
    - local `haven_pay_x402_quote` through a real client (`tools.test.ts`);
    - hosted `haven_send`, `haven_pay` and `haven_pay_x402_quote` on both schemes (`task-budget-forwarding.test.ts`).

    Removing the forwarding turns them red: 1 SDK test, and 4 hosted tests when the hosted change is reverted. The local test failed against the pre-fix SDK build. The stub-only tests that had claimed wire coverage were renamed to the hand-off they actually prove.
  - **Perimeter.** Unchanged, or narrower.
