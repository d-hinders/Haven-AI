- **#3391** — **The RPC transport key scrub (#3371) no longer treats a URL's HOST as a key-like segment. `secretSegments` (`infra/chain/rpc-transport.ts`) now derives its candidates from a parsed URL's path, query and hash parts only (raw, undecoded), falling back to the #3387 whole-string split for strings `new URL` refuses — so `sepolia.base.org`, `mainnet.base.org` and provider hostnames are no longer rewritten to `<redacted>` inside viem request errors. Through the shared helper this is also `infra/relayer.ts`'s `keySegments` and `infra/outbound-queue.ts`'s `fallbackSendError` input; both still replace whole URLs by regex (`<rpc-url>`, `<fallback-url>`), so no URL redaction is lost there.**
  - **Why.** The host-inclusive rule redacted the shared public node out of the exact errors the qa-dev failure classifier keys on (`URL: https://sepolia.base.org`, the #2511 provider signature), misclassifying public-node outages as `unclassified`, and a public-only transport (dedicated `RPC_URL_BASE_SEPOLIA` unset) reported `URL: https://<redacted>` on every failure. Key-shaped path/query segments (`/v3/<key>`, dRPC `/base-sepolia/<key>`, `dkey=`, `/v2/`, QuickNode) are still derived and still scrubbed — pinned in `rpc-transport-key-scrub.test.ts`.
  - **Authority and custody argument: no key material, signing, binding, verification, relaying or payment execution moves; no new spender, approval or credential surface is created.** The change is a narrowing of what an ERROR-OBJECT rewrite hides, never of what a request carries: viem classifies the unscrubbed error inside `fallback()` and no money-path decision reads the scrubbed text (the #3371 argument, unchanged). Residual risk, accepted: a provider that put its key in a SUBDOMAIN would no longer be redacted in the viem error — the ethers side's whole-URL regex still covers it, and none of the vendor shapes pinned in the tests does this. The scrub is also now exception-safe (assign-on-change, per-write guards, cycle guard), so a frozen error, a getter-only property or a cyclic value can no longer throw inside a caller's `catch`.
  - **Mutation-tested.** Reverting `secretSegments` to the whole-string split reddens the host test (`never derives a candidate from the HOST`), the premise test (`a public-host-only endpoint list is NOT a scrub`), and the no-network classifier test (a real viem `HttpRequestError` 503 from `https://sepolia.base.org`, run through the REAL `scrubTransportErrorSecrets` and the REAL `classifyLog`, must classify `provider`). Dropping `'stack'` from the scrubbed property list now reddens the materialize-stack-first test.
