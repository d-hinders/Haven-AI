- **Epic #3302 box 1 (owner decision 2026-09-28, option A): the first client minimum is set — `@haven_ai/signer` `min_version` = `0.6.0-alpha.0`.** Until this change `CLIENT_COMPAT` (`packages/core/src/client-compat.ts`) was all-null, and the #3303 and #3412 entries record that nothing was refused. From this change the backend answers 426 `client_outdated` to a signer below `0.6.0-alpha.0`, on its sign-context reads (`GET /payments/:id/sign-context`, `GET /x402/:id/sign-context`). Signers send `X-Haven-Client` only from `0.5.0-alpha.1`, and a missing header or a `0.0.0-dev.*` snapshot is never refused, so in practice this refuses the one published signer below the line, `0.5.0-alpha.1`, until it runs the upgrade command (since #3412, the connector doctor plus the repair line it prints).

  **Perimeter narrows; no authority is granted.** The change can only REFUSE a signing handoff: the refused signer produces no signature, and the prepared payment takes its existing unsigned or abandoned path. No key, budget, delegation, recipient pin, spend path or route shape changes. It does not stop an older signer that uses the relay path (`payload_hash` + typed data) or a signer that sends no header. `mcp-runtime-compatibility.md` § *Client-version signal* states that limit. A minimum stops the default path and names the fix; it does not guarantee that no older signer ever signs.

  **Promotion condition (S1 of the review).** On production the upgrade command resolves to `@haven_ai/connect@alpha`. At this writing that is `0.6.0-alpha.0`, which predates #3412's multi-agent `--repair` guard. The promotion that carries this minimum to production should also publish a connector that includes #3412 (PR #3415); otherwise the prod half is held. This is recorded as an operator box on epic #3302.

  Tests: a core test pins the live table and the refusal boundary (`0.5.0-alpha.1` below the minimum; `0.6.0-alpha.0` current; a dev snapshot exempt; no header unidentified). The discovery and capability-manifest "follows a min_version change" tests start from the live value instead of `null`.
