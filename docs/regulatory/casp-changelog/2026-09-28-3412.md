- **#3412 (blocks epic #3302's first minimum-version flag) — every "update your signer" hint names a command that works on an existing install, and a connector repair can no longer re-wire a different agent than the one it was meant for.** Before this change, the signer (its `initialize` instructions and out-of-date refusal), the SDK's `signerUpdateFallback`, the hosted MCP's signer-compat notices and server instructions, and the backend's `client_update.upgrade_command` all named a bare `npx @haven_ai/connect@<channel>`. That is a setup command: on an already-set-up machine it stops at "Missing --setup". They now name `npx -y @haven_ai/connect@<channel> --doctor` (`connectorUpgradeCommand` in `@haven_ai/sdk`; a copy in `@haven_ai/core`'s `upgradeCommandFor`, pinned equal by a backend parity test). Separately, `@haven_ai/connect`'s `--repair` rewrites the runtime config from ONE agent's stored credentials, and without `--credentials-dir` it picked the newest credential directory by mtime. On 2026-09-28 that re-wired an owner's prod agent when a dev agent was meant. With more than one agent credential directory it now refuses unless `--credentials-dir` names one, and every repair line the doctor prints names its directory.

  **No custody or authority change.** No key material, signature, spend path, budget, recipient pin or delegation changes. The signer signs exactly what it signed before; only the TEXT of its update hints changes. The repair change NARROWS what a flagless `--repair` may do (it refuses where it used to guess), so no credential can be applied to a runtime the user did not name. No backend route, schema field or refusal point changes; `upgrade_command` keeps its type and only its value changes (an OpenAPI description and two examples are reworded).

  **Operator effect.** A `client_outdated` refusal, once #3302 sets a minimum, now points at a command that works when pasted. Nothing is flagged by this change. `CLIENT_COMPAT` is untouched and all-null, so no client is refused or hinted today, and the new command is observable only in `GET /discovery` → `client_releases.packages[*].upgrade_command`.

  **Not covered, stated:** `--local` (local-stdio) installs — `--repair` refuses that topology and asks for the original `--local` setup command — and signers at 0.4 and older, whose baked-in hints still name the bare re-run. Those send no `X-Haven-Client`, so they are never refused either.

  Tests: the connector's multi-agent repair targeting (a wired agent plus a newer unwired one — the doctor's repair line names the wired agent's directory; a flagless `--repair` refuses and writes nothing; `--credentials-dir` repairs exactly that agent; a single-agent install is unchanged), each mutation-proven red; the signer's out-of-date refusal text, mutation-proven red; `scripts/ci/upgrade-hint-guard.test.mjs`, which fails on a bare connector re-run in an upgrade hint, with an exact-count allowlist for setup-time hints; and the core↔SDK parity test.
