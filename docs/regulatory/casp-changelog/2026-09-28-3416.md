- **#3416** — the delegation-rail bundler credential resolves per chain.
  `delegationRailBundlerUrl(chainId)`
  (`packages/backend/src/rails/delegation-rail.ts`) now reads
  `DELEGATION_RAIL_BUNDLER_URL_<chainId>` first and the unsuffixed
  `DELEGATION_RAIL_BUNDLER_URL` as the fallback. Before this, one value served
  both enabled chains, so a deployment could only reach the bundler of the chain
  its URL named. Observed on prod on 2026-09-28: every Base Sepolia EIP-3009
  funding leg answered a generic 502 "funding authorization failed", which the
  hosted MCP relayed as "retry once". The owner decision on #3416 is to support
  both chains; the rejected alternative was prod serving mainnet bundler legs
  only. The #1053 chain-scope assertion still applies to whichever variable
  resolves, including a per-chain variable holding another chain's URL. A chain
  with no usable credential throws the new `DelegationRailChainUnavailableError`.
  The x402 funding leg (`modules/x402/delegation-authorize.ts`) and `POST
  /payments` (`routes/payments.ts`) answer it as a typed 503
  `rail_unavailable_for_chain` carrying the chain id, never the URL, and book no
  refusal, because nothing was refused on policy grounds. The hosted MCP's
  `normalizeError` maps it to `RAIL_UNAVAILABLE_FOR_CHAIN` with
  `stop_and_tell_user` instead of the 5xx retry. **No custody or authority
  change:** the bundler relays and sponsors a user operation that the agent's
  delegation and its on-chain caveats already constrain. Which credential
  submits it changes neither what may be spent nor who signs, and no key,
  signature, delegation, caveat, budget or recipient pin changes. The chain-scope
  guard still refuses a credential for the wrong chain. A second chain's
  credential only lets payments that the on-chain policy already permits reach
  that chain's bundler; while it is unset they stop, with a typed answer. The
  sponsorship policy id stays one value, so a second chain's URL must come from
  the same Pimlico account under a policy that covers it, or its sponsorship is
  declined and payments pause (never weaken). Mutation-tested, each mutation
  alone, with the file restored from `HEAD` and checked with `git diff --quiet`
  after each: ignoring the per-chain variable fails 3 resolver tests; dropping
  the chain-scope assertion fails 3; an untyped error for an unset credential
  fails 1; removing the x402 mapping fails the x402 route test; removing the
  `/payments` mapping fails the payments route test; and removing the hosted
  `normalizeError` branch fails its refusal fixture. Perimeter unchanged.
