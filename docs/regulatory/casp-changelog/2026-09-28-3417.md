- **#3417** — a replayed idempotency key whose erc7710 payment to the same
  merchant for the same resource already settled is answered as settled
  instead of as a "transient" 500. The backend was already correct:
  `delegationReplay` answers a confirmed key with the stored intent (`to`,
  `resource_url`, `tx_hash`) and no `sign_data`, because nothing is left to
  sign (`packages/backend/src/modules/x402/replay.ts`, unchanged). The SDK's
  erc7710 `prepare()` (`packages/sdk/src/x402-erc7710.ts`) read the missing
  `sign_data` as a scheme mismatch and threw a 500. The hosted MCP relayed it
  with "retry once", and the retry deterministically got the same answer. The
  backend's lookup is keyed on the idempotency key alone, and its confirmed
  branch compares only the task budget (#3392). So `prepare()` now treats a
  `confirmed` answer carrying a `tx_hash` as this purchase only when its payee
  `to` is the merchant this request pays and its `resource_url` the resource it
  names; then it throws the typed `X402Erc7710AlreadySettledError`. Any other
  confirmed row is a 409 key collision. That covers an EIP-3009 funding leg,
  whose payee is the delegate and whose `tx_hash` proves only funding, and a key
  reused for another purchase; neither is ever reported as settled. The three
  hosted erc7710 prepare sites (`haven_pay_mcp_tool`,
  `haven_prepare_catalog_purchase`, `haven_pay_x402_quote`) turn the settled
  error into a done state: `settled: true`, `idempotent_replay: true`,
  `settlement_tx_hash`, and no next tool. It carries no `delivered`, and it says
  Haven cannot re-deliver the merchant's result. **No custody or authority
  change:** nothing is signed on any of these answers, before or after (the old
  refusal signed nothing either). No key, signature, delegation, caveat, budget
  or backend route changes, and the settled answer only reports a settlement
  the backend already recorded for this payee and resource. A `confirmed`
  answer without a `tx_hash` keeps the loud scheme refusal. Mutation-tested:
  removing the SDK branch fails both settled-replay SDK tests; dropping
  `&& raw.tx_hash` fails the no-hash test; dropping the payee check fails the
  funding-leg collision tests (SDK and hosted); dropping the resource check
  fails the other-resource test; a case-sensitive payee check fails the
  checksum test; removing the catch at any one hosted site fails only that
  site's test; and neutering the shared helper fails all three. Perimeter
  unchanged.
