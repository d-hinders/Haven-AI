- **#3418** — the offline receipt verifier stops throwing and stops falsely accusing live-rail payments: `verifyPaymentReceipt` (`packages/sdk/src/receipt.ts`, re-served by both MCP runtimes) gained a guard returning the new `not_a_signed_receipt` reason for anything that is not a signed bundle (a `haven_list_receipts` row, null, undefined, non-objects — the crash the issue reproduces), and for an erc7710 bundle it now rebuilds the EIP-712 delegation digest the delegate actually signs (`keccak256(0x1901 ‖ domainSeparator(DelegationManager, chainId) ‖ signHash)`) from the SDK-pinned DelegationManager address and the bundle's `onChain.chainId`, instead of recovering over the raw struct hash and reporting `signer_mismatch` for every genuine payment. A direct or eip3009 bundle returns the new `not_verifiable_offline` (the signed UserOperation is not in the bundle) — never `signer_mismatch`. Money-path by file: `packages/backend/src/infra/repositories/payment-intents.ts` adds two READ-ONLY columns to `FIND_SETTLED_PAYMENT_RECEIPT_SQL` (`execution_rail`, `machine_metadata->>'settlement_scheme'`), consumed only by `buildPaymentReceipt` to label the bundle's additive `authorization.signatureScheme` selector; no write path, route, signer, relayer or Safe surface is touched, and no code branch reads these columns to authorize, rate-limit or refuse a payment. `packages/mcp-server/src/tools/contracts.ts` changes the strict-input RATIONALE TEXT only (`z.unknown()` and the schema are unchanged). The `signatureScheme` value is a selector, not a trust anchor: a lying value cannot make a forged signature verify because recovery must still return `authorization.delegate`, and the verifier never reads the DelegationManager address from the receipt (pinned in the SDK, `settlement-child.ts`). No key is held, created or moved; no API credential becomes sufficient to spend; no off-chain policy becomes a spend control — the verifier is a pure client-side report (`verified` true/false), and the change strictly NARROWS what it claims: the module docstring's "cryptographic proof the agent authorised exactly this transfer" overclaim is removed, `verified: true` now means only that the delegate key signed the hash named by `verifiedOver`, and settlement stays an on-chain check.
