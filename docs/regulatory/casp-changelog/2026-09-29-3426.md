- **#3426** — the per-agent x402 buyer-side tax declaration opt-in (wg-tax #5
  §2.1). New migration `102_agent_tax_declaration_opt_in.ts` adds
  `agents.tax_declaration_enabled` (BOOLEAN NOT NULL DEFAULT false), and two
  routes under the `/agents` prefix: `PUT /agents/:id/tax-declaration` (owner
  session) and `GET /agents/:id/tax-declaration` (agent key). The owner's
  toggle write is gated IN SQL and DIRECTIONALLY: switching ON requires
  `HAVEN_OWNER_COMPANY_DETAILS` on plus an `owner_company_details` row with a
  VAT number whose `vies_status = 'valid'` (zero rows updated is the
  structured 409 — nothing is written on any refusal), while switching OFF is
  never gated, because an owner whose VIES result dropped is exactly the
  owner who needs to withdraw the opt-in. The agent's content read re-checks
  every condition AT READ TIME (flag, opt-in bit, VAT number present, VIES
  `valid` now) and answers the unsigned §2.1 fields only — `version`
  `x402-tax-1`, `jurisdiction` (the saved country, never derived from the VAT
  prefix), `taxableStatus` `TAXABLE_PERSON`, `taxId`, `validUntil`
  (milliseconds, the lesser of now + 24h and the VIES check's own freshness
  bound) — or the structured `{ available: false, reason }` with one of
  `feature_disabled` / `disabled` / `no_company_details` / `vies_not_valid`.
  The response never carries `principalId`, `principalAttributionHash`,
  `signature`, `org_number` or `legal_name` (the SDK computes the principal
  fields locally, #3427). An agent API key is refused on the toggle route
  with a named 403 before session auth, the same pattern as
  `routes/owner-company-details.ts`. **No custody or authority change:** the
  column is settings-only — no delegation, budget, rule, key, signature or
  enforcement path reads it; the opt-in sends and signs NOTHING (this slice
  never transmits a declaration; #3427 signs it and carries it on EIP-3009
  payments only); the company-details row itself is untouched and the Agent
  Passport EAS schema is unchanged (owner decision on the issue). The VAT
  number reaching the owning agent is not a new exposure: the agent key
  already reads it through the flag-gated receipt (`parties.buyer`).
  Migration-checked: the real-DB suite proves the column defaults off for
  existing and new agents, every refusal writes nothing, and the four
  not-available reasons each fire in the state its name says, including VIES
  dropping after the opt-in and the flag switched off afterwards.
