- **#3430 / PR #3455** — the agent onboarding surfaces stop telling the agent to
  assemble a CLI command from a tag template. Before this change, the runbook
  (`HAVEN_AGENT_RUNBOOK_MD`, `packages/sdk/src/agent-guidance.ts`, served as
  `/for-agents.md` and bundled into `haven guide`) and the onboarding prompt
  (`agent-onboarding-prompt.ts`) rendered step 1 as
  `npx @haven_ai/cli@<channel> login` with instructions to fill `<channel>`
  from `/.well-known/haven.json`'s `packages.cli.channel`. But that field holds
  the bare package name (`@haven_ai/cli`), so following the runbook verbatim
  produced `npx @haven_ai/cli@@haven_ai/cli@dev` — reproduced in the
  2026-09-28 cold run. The fix is text-only at the agent-facing surfaces: step
  1 now says to run the manifest's own `packages.cli.one_liner` (the full
  runnable command the manifest serves) as given, and to read
  `packages.cli.channel` for the channel spec only. **No custody or authority
  change:** no tool, argument, schema, description, consent input, route, key,
  delegation, budget or signing surface moves — the same CLI login flow runs
  the same approval handshake; only the command string the docs hand the agent
  changes, from an assembled template to the manifest-served one. The
  byte-pinned CLI copy (`packages/cli/src/agent-guidance-text.ts`) was
  regenerated from the SDK canonical by the existing sync script, and the
  parity test plus size pins were updated with it (the #2719 mechanism, not a
  new one). No installed runtime reads or parses any of this text: it is
  documentation the agent reads, so no installed sidecar, consent hash, or
  version-skew contract is touched. Perimeter unchanged.
