- **#3431** — `/discovery` (`packages/backend/src/routes/discovery.ts`) and the
  frontend manifest (`packages/frontend/src/lib/capability-manifest.ts`, an
  unmodified pass-through of the backend's value) stop reporting
  `chains.default` as the bare product constant (`DEFAULT_CHAIN_ID`, Base
  mainnet). It now reports the deployment's EFFECTIVE default: the constant
  when this deployment deploys on it, else the first chain it does deploy on
  — derived by `effectiveDefaultChainId` (new, `packages/core/src/chains.ts`).
  Dev deploys Base Sepolia only, so before this fix dev's discovery documents
  named Base mainnet as the default chain — a funding-step trap an agent could
  follow into pointing its user at the wrong chain. **No custody or authority
  change:** this is a read-only, public, unauthenticated GET response field
  (`GET /discovery`, `/.well-known/haven.json`) — no route, key, delegation,
  budget, signing surface, or on-chain call moves. Neither `discovery.ts` nor
  `capability-manifest.ts` matches `.github/money-path-globs.json`;
  `scripts/ci/money-path-classify.mjs` confirms not-money-path against this
  diff. `AGENT_ONBOARDING_PROMPT` (`packages/sdk/src/agent-guidance.ts`,
  covered by this doc via `packages/sdk/src/**`) had the same trap in prose —
  "funding the account with USDC on Base" — made chain-neutral ("funding the
  account with USDC"); its byte-pinned frontend copy
  (`packages/frontend/src/lib/agent-onboarding-prompt.ts`) was edited
  identically and its parity test re-run. Text and a derived integer field
  only: no installed runtime parses `chains.default` as an instruction (no
  published SDK, CLI or MCP consumer reads it; the only code consumer is the
  frontend manifest's pass-through). Perimeter unchanged.
