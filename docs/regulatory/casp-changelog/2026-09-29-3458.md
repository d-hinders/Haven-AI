- **#3458** (epic #3457) — the delegate balance monitor reads balances in
  batches. It used to await one `balanceOf` `eth_call` per active agent, every
  hour and at every boot. It now makes one Multicall3 `aggregate3` request per
  chunk of 200 delegates per chain (`infra/chain/batched-token-balances.ts`).
  **The DETECT control scans the same population:** every active agent with a
  delegate. The scan is deliberately not narrowed, so a balance Haven never
  sent is still found. The four states and the lingering and dust alerts are
  unchanged.

  **What changes when a read fails**, stated because it is where the old and
  new readers differ:
  - **No retries.** The old reader was an ethers provider whose fetch layer
    retried an HTTP 429 with backoff. The new one sends each chunk once, on the
    dedicated RPC endpoint only (no fallback node, as before), and never as a
    burst. A rate-limited or failed chunk is not re-sent that round.
  - **A failure covers more delegates.** A reverted sub-call leaves its one
    delegate unread, a failed request leaves its chunk (up to 200) unread, and
    a chain the reader cannot set up leaves that chain unread. Before, a
    failed read lost one delegate. The next hourly tick reads them again.
  - **Unread is now visible, where before it was silent.** Unread delegates
    are counted in the report and logged at WARN per chain, as not known to be
    clear. A delegate already alerted as lingering keeps its alert state while
    unread, so a failed read does not cause a repeat ping. A dust total from a
    scan with unread delegates does not re-arm the dust alert.
  - **A chain without a viem definition or Multicall3** falls back to one read
    per delegate, so it is still scanned.

  **No custody, authority or execution change:** the monitor stays read-only
  and moves no funds; no key, delegation, budget, route or signing surface is
  touched.

  **Tests.** The request count, peak concurrency, the Multicall3 and token
  targets, and each failure mode are pinned against a real viem client in
  `infra/chain/__tests__/batched-token-balances.test.ts`. The per-chain
  grouping, unread reporting and alert-state handling are pinned in
  `infra/__tests__/delegate-balance-monitor.test.ts`. Each guard was removed
  in turn and its test went red. Perimeter unchanged.
