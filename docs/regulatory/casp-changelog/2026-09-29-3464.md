- **#3464** — the agent's remaining budget had four spellings across one
  hosted-MCP server (`haven_get_agent`'s camelCase `allowances[]`,
  `haven_get_allowances`' nested `onchain.remaining`, the settle-time
  `allowance` block in snake_case, and #1306's catalog preflight block in
  snake_case). This change aligns the settle-time summary and the preflight
  block with `haven_get_agent` — the read the server tells an agent to make
  first — and removes declared values no account can reach. All four surfaces
  are REPORTING: nothing here grants authority, alters signed intent, or
  moves money, and no backend route or wire field changed.

  **What changed, per surface:**

  - `packages/sdk/src/account-reads.ts` (`getPostPurchaseAllowanceSummary`):
    the settle summary now emits the canonical camelCase names
    (`remainingAtomic`, `remainingDisplay`, `resetPeriodMin`, `tokenSymbol`,
    `tokenAddress`) beside the kept snake_case keys, and its
    `remainingDisplay` comes from the ONE shared formatter
    (`formatRemainingDisplay`) `haven_get_agent` uses — previously settle
    omitted the display figure for unknown-decimals tokens where get_agent
    emitted an explicit atomic label. The summary's rail is narrowed at the
    mapping to `'delegation'` with a fail-closed guard (any other rail
    degrades to the existing `allowance: null` + warning). `rail: 'legacy'`
    and `source: 'allowance_module'` are removed from the type.
  - `packages/sdk/src/types.ts` (`PostPurchaseAllowanceSummary`): the type
    carries the optional camelCase keys, marks the snake_case keys
    `@deprecated` with a written removal condition ("once `packages/qa-agent`
    reads the camelCase keys"), and narrows `rail`/`source` to the one
    reachable value. The invariant JSDoc now says the spelling matches
    `haven_get_agent`. The public `HavenAgent.executionRail` union is NOT
    narrowed — the seam stays declared per CLAUDE.md.
  - `packages/mcp-server/src/tools/catalog-purchase.ts` (the #1306 preflight):
    the block narrows to `rail: 'delegation'` and gains `remainingAtomic`;
    `source` is a constant. A non-delegation rail — unreachable from the live
    backend, where `POST /x402` 410s both retired rails and `budget-precheck`
    answers 410 the same way — degrades the block to `null` with an
    `ALLOWANCE_CHECK_UNAVAILABLE` warning instead of fabricating a
    legacy-labelled row. The guard sits AFTER the #2054 settlement-scheme
    selector, so an erc7710-only merchant still refuses with the rail as the
    named reason.
  - Tool descriptions (`contracts.ts` settle/complete/payment-status and the
    catalog preflight; the shared SDK `getPaymentStatus` description, which
    the local `@haven_ai/mcp` composes): name the canonical camelCase keys,
    mark the snake_case keys deprecated, and state the window.

  **What deliberately did NOT change:** every backend snake wire field
  (budget-precheck `remaining_atomic`, the over-budget refusal body and
  `payment_refusals` ledger, rekey/task-budget/merchant `remaining_atomic`,
  `haven_check_funds`' `budget_remaining_atomic`), the raw
  `haven_get_allowances` `onchain.remaining`, and the local MCP surface's
  handler. The out-of-scope rename list from the issue was respected in full.

  **Reachability claim, proven not asserted:** `resolveExecutionRail` refuses
  `retired_session` and `retired_allowance` accounts at `POST /x402`
  (`modules/x402/authorize.ts`), `GET /machine-payments/allowances` 410s
  retired rails (`modules/mpp/allowances.ts`), and `budget-precheck` 410s
  them the same way (`modules/mpp/budget-precheck-guards.ts`). The settle
  summary and the preflight block can only ever describe a delegation-rail
  account, so narrowing the declared types removes arms no caller could
  receive — this supersedes #2265's keep-as-declared rationale, said so in
  the doc and the type.

  **No custody, authority or execution change:** all touched paths are
  read-only reporting attached before or after a payment. No key, delegation,
  budget, route, signing surface, or spend decision moved; the budget
  DECISION stays server-side in `budget-precheck`, relayed byte-identically.

  **Tests.** `agent-info.test.ts` asserts get_agent and the settle summary
  report equal names AND values for one fixture, and that an
  unknown-decimals token gets the shared formatter's atomic label on both
  reads; the settle-summary and preflight fixtures migrated to delegation
  with exact `toEqual` kept (never loosened to `objectContaining`);
  `catalog-purchase.test.ts` and `paid-mcp-completion.test.ts` pin the
  narrowed block shapes; the degraded-rail guard is covered by the
  sufficient-null tests. Perimeter unchanged.
