- **#3509** — the ops console's backend foundation (epic #3507): GitHub
  sign-in for allowlisted founders, an ops session token, an access log, and a
  single-field reveal. Nothing in it can move funds, sign, change signers or
  delegations, or act as a user. The plugin (`packages/backend/src/routes/ops.ts`)
  registers GET routes plus one `POST /ops/reveal` that returns a closed set
  of display fields (`users.email`, `users.name`), and is off (404) until the
  read-only database role from #3510 is wired. The ops token is signed with
  its own secret and carries `purpose: 'ops'`, which `authMiddleware` refuses,
  so it is never accepted as a customer or agent credential; it is not payment
  authority anywhere. `migration 104` adds `ops_access_log`, a record of who
  looked at what — no key material, no spend state. Mutation-tested: the
  invariant suite (`src/__tests__/ops.invariants.test.ts`) walks the ops
  module's transitive imports and goes red when a rail, relayer, outbound-tx,
  chain, payment or signing module becomes reachable (a side-effect import
  and a two-hop import were each mutated in and caught), and when any ops
  route other than reveal accepts a write method; the customer-route refusal
  of an ops token goes red when the `purpose` claim is removed. Haven still
  holds no unrestricted signing authority and the delegation rail is
  untouched. Perimeter unchanged.
