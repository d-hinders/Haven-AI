- **#3513** — the ops console's on-chain account view (epic #3507): `GET
  /ops/users/:id/onchain`, a read-only DB-vs-chain view per supported chain.
  It reads chain state only: whether the pinned DelegationManager reports a
  stored delegation disabled (`readDisabledDelegationHashes`, the same reader
  the revoke-all path uses, at the finalized block with a double read), the
  period enforcer's remaining budget (`readRemainingBudget` with
  `delegation_json`, granted to the ops role by the owner decision recorded
  on #3510), and whether the delegator account has code (`getBytecode`).
  There are no Safe or AllowanceModule reads, no `writeContract`, no
  `sendTransaction` and no signing import anywhere in the new code; the ops
  invariant-1 static test (`__tests__/ops.invariants.test.ts`) walks the
  route module's transitive import graph and pins that, which is why the
  real chain readers live in `modules/ops/onchain-readers.ts`, are injected
  through the route options in `index.ts` (the seam pattern #3509
  established with `readDb`), and are reachable from no module the walk
  covers. The route registers as GET only, mirrors every #3512 route
  behavior (read-only-role executor, one audited `ops_access_log` row
  through the main pool before the response, 404 while unconfigured,
  no-store), and answers per-chain RPC failures as `unavailable` entries
  rather than errors; a failed budget read renders `unavailable`, never the
  reader's fallback figure. Addresses are masked (`maskHex`), and the
  delegation hash and body are used internally only — the response carries
  the chain's answers keyed by position, so no hash, signature or delegation
  body is returned. Rows the environment does not serve (`legacy_safe`,
  chain not in `deployableChainIds()`, chain without delegation pins) are
  listed with a reason and make ZERO RPC calls. Chain reads are batched per
  chain and cached per (chain, user) for 60 s with single-flight (the
  `platform/cache` pattern of `modules/accounts/balance-reads.ts`, #3460),
  so a page view costs one bounded read-set per chain per minute and the dev
  RPC's ~20-call burst limit (#3456) is not spent on repeated views.
  Mutation-tested: routing the view through the main pool, dropping the
  audit row, returning the fallback budget figure, masking the hash instead
  of dropping it, and reading a not-served row each turn a test red.
  Nothing here signs, moves funds, changes a delegation or acts as a user;
  the only chain interaction is a view of state the enforcers already
  enforce. Perimeter unchanged.
