- **#3610** — an x402 payment's status reports what was bought. `POST /x402`
  already accepted a `description` but `modules/x402/authorize.ts` never passed
  it to `runDelegationAuthorize`, so neither delegation-rail leg wrote it and
  `GET /machine-payments/:id/status` answered `description: null`. Now both
  legs persist `machine_metadata.description` at authorize: the body's
  `description`, else the stored verbatim 402's (#1355)
  `resource.description` (`domain/x402-description.ts`). The status reader
  (`modules/payments/agent-payment-status.ts`) applies the same rule on read,
  so rows authorized before this change report it from their stored 402.
  The value is untrusted merchant text: trimmed, bounded to 300 code points,
  reported as display data only and never parsed or acted on. Nothing about
  what is signed, redeemed, funded or settled changes — the description is
  not part of the child delegation, the funding UserOp, the expected-context
  binding or any caveat; no new spender, no key custody, no new write path to
  a money column. Perimeter unchanged.
