# 2026-10-04 — #3617: both `/x402/authorize` legs adopt the budget-scope resolver (epic #3615 S-B)

What changed: `packages/backend/src/modules/x402/delegation-authorize.ts`
stopped resolving task budgets and sub-budgets itself. The local refusal tables
and the two helpers `resolveTaskBudgetOrRefusal` and `resolveSubBudgetOrRefusal`
were deleted. Both legs now take four things from the #3616 module: the scope
(`resolveBudgetScope`), the period pre-check links (`periodPrecheckLinks`, new
in this PR), the per-link pre-check (`evaluatePeriodPrecheck`), and the refusal
body and ledger detail (`buildPeriodExceededBody`,
`periodExceededLedgerDetail`). The both-ids 400 reads the module's verbatim x402
prose (`refuseBothScopeIds`).

Three behaviour changes, measured at `5625382e7` before the adoption. The
characterization suite `x402-sub-budget.test.ts` landed first with seven
`it.fails` cases, plus one in `x402-task-budget.test.ts`. All eight now pass as
plain `it`.

1. **erc7710, sub-budget.** The pre-check used to read only A's budget
   delegation. A request over B's slice got `201` with `sign_data`, and the
   enforcer reverted it at redemption. It now reads B's grant, A's
   parent-child and A's budget. The smallest remaining decides, and the
   request gets the typed `403 delegation_budget_exceeded` before any
   settlement child exists.
2. **erc7710, ordering.** The leg used to select B's own (token, `payTo`)
   delegation first and refuse `403 no_delegation_for_target` when there was
   none. A sub-agent whose only authority is a sub-budget never reached it. The
   scope now resolves first, so such a B pays. For scoped requests a scope
   refusal (404/409) now comes before the no-delegation 403, and that 403
   remains only on the none scope. Its ledger row and body are unchanged.
3. **EIP-3009 funding leg, sub-budget and task budget.** The pre-check used to
   read B's own (token, `payTo`) grant, which is not a link of the chain this
   leg redeems. It now reads the redeemed chain: the three sub-budget links,
   or the task budget's parent by hash (owner decisions 1 and 3 on #3615). The
   scope's recipient on this leg stays `payTo`, the delegate EOA the
   redemption transfers to. That corrects the epic's threat-model line
   ("scope matching against `merchantPayTo`"). Matching a recipient pin
   against the merchant would let a merchant-pinned budget pass a check whose
   redemption reverts on-chain, because the transfer target is the EOA. The
   refusal body and ledger row still name `merchantPayTo` as the merchant.

Hosted MCP (owner decision 2): `plain-http-x402.ts` no longer forwards
`sub_budget_id`. `haven_pay_x402_quote` never declared it, so strict parsing
refused it before the forwarding could run. The refusal is now pinned, and the
description says a sub-agent pays x402 through the local MCP.

Authority/custody argument: the pre-check stays a fail-open mirror that can
only narrow what Haven constructs. A thrown, degraded or unparseable link read
counts for nothing, Haven refuses only on `remaining < amount`, and with no
measurement there is no refusal. The `ERC20PeriodTransferEnforcer` caveats in
the redeemed chain remain the only gate. Reading more links can refuse more
requests early, never fewer. That matters for change 2: a B with no grant of
its own now pays, but only through the chain an owner approved, the sub-budget
grant under A's budget. That chain is redeemed exactly as before; this PR
moves no redemption link, settlement child or signing context (expected-context
versions unchanged). Haven holds no key and signs nothing. The refusal ledger is
still written fire-and-forget, after the decision, with the same bounded
`detail`. Red Lines 2/3/4 and the mirror-only pattern are unaffected. The
refusal census was re-pinned to the moved lines: the same 12 `refuse(` sites
with the same statuses and the same ledger/no-writer split, plus the raw 429
allowlist entry. No `refuse(` call left the file, so `TARGET_FILES` is
unchanged.

Mutation-proven, each restored byte-for-byte (clean `git status` after the
run). Each mutation was run against the six x402 and budget-scope suites
(167 tests):

- P3, the funding leg ignoring `subBudgetId` → 4 red;
- P3, the erc7710 leg ignoring it → 6 red;
- the funding pre-check reading only the last link → 2 red;
- the erc7710 pre-check reading only the last link (the pre-#3617 shape) → 3 red;
- the funding leg skipping the task-budget parent (decision 3) → 1 red;
- the no-delegation check moved back ahead of the scope → 9 red;
- `evaluatePeriodPrecheck` taking the max instead of the min → 5 red;
- `<=` instead of `<` → 2 red, the "spends the LAST of the budget" pins;
- the module's x402 both-ids prose → the new verbatim pin red;
- declaring `sub_budget_id` on the hosted schema → the hosted refusal pin red.

Perimeter unchanged.
