  **What the release carries, by effect on authority:**
  - **#3427 (#3480): the buyer-side x402 tax declaration.**
    - On the paid EIP-3009 merchant retry, the SDK signs the owner's opted-in, VIES-valid company declaration with the payment key and attaches it.
    - It is opt-in per agent (#3426), and the backend flag `HAVEN_OWNER_COMPANY_DETAILS` gates it.
    - It is a statement attached to a payment, not authority: no spend, signer-set or delegation change. This is the subject of epic #3328's release box.
  - **#3506 (#3539): sub-budgets are user-completable.**
    - Agent A submits its own sub-budget signatures (`haven_submit { sub_budget_id }`, SDK `submitSubBudget` / `closeSubBudget`), and the owner route is kept.
    - The signer's consent text names sub-budgets, copy-only: `SIGNER_CONSENT_SURFACE_VERSION` is unchanged.
    - Issuance stays owner-only, and a child is never wider than its parent (the threat model was confirmed by the owner on 2026-10-01).
  - **#3518, #3501, #3531 and #3564/#3569: reporting.**
    - The paying budget and scope in account reads.
    - Task-budget on-chain spent and remaining, plus the new `haven_get_task_budget` tool (hosted and local; the local consent hash changes because of the tool name, so local operators re-consent once).
    - An advisory, history-only `recipient.class`.
    - A receipt-unconfirmed `submissionOutcomePending`.
  - **#3524:** compact `haven_send` / `haven_pay` results by default, with an opt-in relay. Output shape only.
