- **#3693** — `GET /agents/:id/delegations` (the dashboard's delegation
  lifecycle list, `packages/backend/src/routes/agent-delegations.ts`) now
  carries a remaining-this-period figure for every **active** budget:
  `remaining_atomic`, `remaining_from_chain` and `period_end` (null on
  non-active rows) — **opt-in via `?include=remaining`**: without the
  parameter the response is byte-identical to the pre-#3693 shape (no
  enrichment keys, not even nulls; the server-side `delegation_json` fetch
  and the chain read do not run), because the route is polled every 10 s
  and a chain RPC on every poll is a cost none of the pollers asked for.
  The change is strictly **read-only** — it adds a per-row chain READ and
  three response fields; nothing about who may authorise, sign, build,
  activate, revoke or redeem moves.

  - **No new spend path and no new authority surface:** the figure comes from
    the existing `readRemainingBudget`
    (`packages/backend/src/infra/chain/delegation-budget-reader.ts`), the
    same read the analytics budget views already answer with — a public-RPC
    `GET` against the deployed DelegationManager/caveat enforcers. It signs
    nothing, prepares nothing, and its answer is display data only; the
    on-chain allowance remains the real spend control exactly as before.
  - **`delegation_json` stays server-side:** the route now fetches the signed
    delegation objects for the active rows via the existing
    `listDelegationJsonByIds` (`infra/repositories/delegation-budgets.ts`)
    to feed the reader, and the response still excludes them — pinned by an
    assertion that the serialized body never contains `delegation_json`.
  - **Failure degradation is the reader's own contract:** a failed or
    rejected read answers `remaining_from_chain: false` with
    `remaining_atomic === budget_atomic` (the full budget, i.e. the
    CONSERVATIVE bound — the response never under-reports what the enforcer
    allows) and still returns 200; a slow RPC cannot hang the page because
    the reads run through the analytics worker pool
    (`BUDGET_READ_CONCURRENCY = 4` in flight) under the reader's existing
    per-read timeouts (`REMAINING_READ_TIMEOUT_MS`).
  - **`period_end` cannot drift from analytics:** the period-bounds helper
    (`currentPeriodBounds`) moved verbatim from
    `infra/repositories/analytics.ts` into the reader module so the route
    and the analytics budget views call the ONE definition; a route test
    computes the expected value through the shared helper.

  Authority and custody argument: nothing is granted, signed, widened or
  narrowed. The endpoint already exposed budget size (`budget_atomic`) and
  lifecycle status; when asked (`?include=remaining`) it also exposes what
  the chain itself will still allow this period — information the owner
  could already read on-chain and the analytics views already surface. No
  spender, key, ceremony, route order or validation shape changes; the one
  request-side addition is the OPTIONAL `include` query parameter
  (allowlisted to the single value `remaining` in the OpenAPI spec — any
  other value is refused with the 400 envelope before the handler runs),
  which only chooses whether the display enrichment runs. Without it the
  response is the plain lifecycle list, unchanged.

  Tests: route tests (`routes/__tests__/agent-delegations.test.ts`) —
  WITHOUT `include` the response is the plain dev shape: the three keys are
  absent (not null), the server-side json fetch never runs and a mocked
  reader that refuses is never reached; with `?include=remaining` the
  active row carries the mocked reader's answer keyed to its own server-side
  json; revoked/replaced/pending rows carry nulls and are never read from
  the chain; a throwing reader and a failed read both answer the full
  budget with `remaining_from_chain: false` and still 200; ten active rows
  measure `maxInFlight === BUDGET_READ_CONCURRENCY`; an unknown `include`
  value is refused by the enforced request schema before the handler; a
  delegation whose `expires_at` falls before `period_end` keeps the period
  boundary and shows the earlier expiry via its own `expires_at`; the body
  never carries `delegation_json`; the response matches the OpenAPI schema.
  The OpenAPI request schema declares the optional `include` query parameter
  (enum `remaining`), the response schema declares the three fields
  (nullable), and `packages/core/src/api-types.ts` is regenerated
  (`check:api-types` green).

  Money-path by file: `packages/backend/src/routes/agent-delegations.ts`
  and `packages/backend/src/infra/chain/delegation-budget-reader.ts` are on
  the runtime globs. Perimeter unchanged: no new spender, no new key
  custody, no Haven-signed authority, and no widening of any delegation.
