- **#3722 — leaked-credential and stop guidance names the real remedies** —
  copy and help text only; no perimeter change.
  - **The defect:** user-, agent- and CLI-facing copy told a reader whose
    agent credential may have leaked to "pause or revoke" the agent. Neither
    ends a leaked delegate key's on-chain authority: pause is a Haven-side
    block, and `POST /agents/:id/revoke` is a status flip with no on-chain
    call. A holder of the key and the signed delegation could still spend
    within the budget's caveats.
  - **The fix (owner-ruled remedies, 2026-10-07):**
    - a leaked key → **Replace signing key** (the old delegation is revoked
      on-chain and a new one issued);
    - stop all spending now → **Stop budget**;
    - done with the agent → **Remove agent…**;
    - CLI readers → `haven budget revoke <agentId> <delegationHash>`.

    Pause is described only as blocking payments through Haven, with the
    budget still live on-chain. Recovery copy discloses that the signing key
    also controls funds already in the agent wallet and that ending the budget
    does not recover them (`docs/product/copy-guidelines.md`).
  - **Surfaces:**
    - frontend: manual-credential prompt, handoff file, the credential file's
      custody note (`agent-credential.ts`), payment-credentials modal, home and
      how-it-works pages, `llms-full.txt`, design-system showcase;
    - the haven-pay skill (`skill-content.ts` and its byte-identical frontend
      copy);
    - signer consent text;
    - CLI help, the `agents revoke` refusal and the CLI README;
    - connect teardown output;
    - `README.md`, `06-hosted-mcp-connect-flow.md`, `screen-recipes.md`, and
      the canary runbook's control name (`mainnet-canary.md`: "Stop budget").
  - **Signer consent:** the line now reads "the wallet owner can stop the
    agent's budget or remove the agent outside this signer."
    `SIGNER_CONSENT_SURFACE_VERSION` is unchanged; the consent hash covers
    identity, tool names and the surface version, not the wording.
  - **Perimeter:** no route, signature payload, delegation, enforcer, budget,
    key custody or API call changes. Haven gains no signing authority and no
    control is added or removed. The copy now points owners at the controls
    that do end on-chain authority, which narrows what a reader believes a
    Haven-side action achieves. Pinned by literal-string tests on every
    rewritten surface: `useAgentConnectionSetup.test.tsx`,
    `agent-handoff.test.ts`, `agent-credential.test.ts`, `PaymentCredentialsModal.test.tsx`,
    `skill-content.test.ts` with the frontend byte-parity test,
