# 2026-10-07 — #3723: the receipt endpoint's wrapped response verifies; `haven_get_receipt` returns the signed bundle

- **#3723**: `verifyPaymentReceipt` (`packages/sdk/src/receipt.ts`) now accepts
  the response `GET /payments/{id}/receipt` returns — `{ receipt, verification }`
  — as-is: when the top level carries no `authorization` and `.receipt` is a
  non-null object, the bundle inside is verified, one level only, no recursion.
  The wrapper's `verification` is never read: it is Haven's own self-check
  computed on Haven's server, and an offline verifier that trusted it would
  verify nothing but Haven's word. Both MCP runtimes (local `@haven_ai/mcp`
  and hosted `mcp-server`) gain a read tool, `haven_get_receipt
  { payment_id }`, backed by the existing `HavenClient.getReceipt`, returning
  `{ receipt }` only.

  Authority and custody argument: this change adds NO spend path and NO new
  authority surface. `haven_get_receipt` is a read over an existing
  agent-scoped endpoint the agent could already call, under the same bearer
  credential, with the same 404 scoping (unknown id, another agent's id, or an
  unsettled payment — no raw error, no new data reach). It signs nothing,
  prepares nothing, and cannot move funds: no route, OpenAPI, wire field,
  migration or payment-path change (lever 4 of the issue: unchanged), and the
  `agent_tool_invocations` audit allowlist is deliberately not extended. The
  verifier's trust anchor is unchanged — the delegate's own signature over the
  delegation digest, recovered offline; accepting the endpoint's response
  wrapper only changes which layer of an already-fetched object is read, and
  the wrapper's server-computed `verification` is excluded from the evidence
  by construction (guarded by a throwing-getter test on both runtimes and in
  the SDK). The spread form is declared accepted-and-ignored on the hosted
  strict schema — strictness is not dropped; every other undeclared key is
  still refused by name. Receipts remain the agent's to hand over or not: no
  new party reads anything it could not read before.

  Mutation-tested: the SDK suite covers the unwrap (whole response verifies,
  throwing-getter wrapper still verifies, wrong-key wrapper is
  `signer_mismatch`, one level only, wrapped list row stays
  `not_a_signed_receipt`) and both runtimes carry handler-level fixtures over
  a real signed erc7710 bundle (`@haven_ai/sdk/test-support`), including the
  get-then-verify round trip and the structured 404s.

  Perimeter unchanged.
