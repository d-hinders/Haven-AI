- **#3729** — the CLI's `haven agents revoke` now refuses (exit 4,
  `HavenCliError`) while the agent has a live budget delegation, unless
  `--keep-budget` is passed, in which case it revokes and then warns that the
  budget is still live on-chain and lists each live row's exact
  `haven budget revoke <agentId> <hash>` command
  (`packages/cli/src/commands.ts`, `packages/cli/src/args.ts`). The refusal
  names **Remove agent…** in the dashboard, the one-signature route that ends
  every live budget before revoking. Required alongside it:
  `haven budget revoke` accepts a `replaced` row, which the backend's prepare
  route already accepted and which #3542 rules still live.

  - **No new spend path and no new authority surface:** the backend is
    untouched — `POST /agents/:id/revoke` stays a status flip, the delegation
    rows and the on-chain allowances are exactly what they were. The change
    adds two READS (`GET /agents/:id` for the server-computed
    `live_delegation_count`, and `GET /agents/:id/delegations` for the rows)
    in front of the existing POST, and one client-side refusal. The CLI still
    decides nothing: it holds no keys, signs nothing, and every authority
    decision stays server-side, per the #1826 perimeter argument. The guard
    is explicitly a client-side guard, not an authority control — an older
    installed CLI, a direct API call, or the superseded-agent path can still
    leave a budget live, and a budget going live between the read and the
    POST is accepted by design.
  - **Direction of travel is narrowing, not widening:** before, a script
    could revoke an agent and silently leave its delegate key redeemable; the
    default path now makes that state loud (refusal with per-row commands)
    and the override makes it explicit (`--keep-budget` prints the same
    commands under a still-live warning). No credential path moves — the
    session JWT is sent to the same resolved base URL as before, no token is
    logged, no key material is printed (the per-row commands print
    delegation hashes, which `budget show --hashes` already printed).
  - **Mutation-tested:** the unit battery in `commands.test.ts` asserts the
    refusal exits 4 via `HavenCliError` with NO `POST /agents/:id/revoke`
    call, that the printed commands name every live row and no revoked row,
    that `--json` refusal carries `error.live_delegations:
    [{ delegation_hash, status }]`, that `--keep-budget` revokes and returns
    success plus `live_delegations`, that a failed budget check keeps the
    read's own exit class (403 → 4) with a "couldn't check budgets" note and
    still never POSTs, and that `budget revoke` prepares a `replaced` row.
    `json-contract.test.ts` stays green over every command. The backend
    suite is out of scope: no backend file changed.

  Authority and custody argument: nothing is granted, signed, widened or
  moved. The delegate key's authority is unchanged before and after; the
  change only changes whether the CLI lets a script forget that it is still
  there. Perimeter unchanged.
