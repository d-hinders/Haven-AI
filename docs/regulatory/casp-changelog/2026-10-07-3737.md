- **#3737** — the connector names every new agent's MCP pair by default: a
  setup run without `--name`, `--bare` or `--replace` derives the wiring slug
  from the agent's display name and installs a `haven-<slug>` /
  `haven-signer-<slug>` pair
  (`packages/connect/src/wiring-collision.ts`,
  `packages/connect/src/runtime.ts`, `packages/connect/src/args.ts`). The
  slug de-collides against EVERY directory under the credential root —
  tombstoned and key-removed directories included, so a slug freed by
  `--unwire` is never handed out again — and a non-production backend
  (anything that is not Base mainnet, chain id 8453) marks the slug `-dev`.
  The bare pair is now reached only by an explicit `--bare` flag or
  `--replace`; `--bare --name` is a usage error, and the setup prompt's
  command-modification sentence (`AGENT_COMMAND_MODIFICATION_SENTENCE`)
  does not permit an agent to append `--bare`. `--rekey` without `--name`
  auto-selects the sole directory that still holds a stored API key and
  refuses with a list when there are several
  (`packages/connect/src/storage.ts`).

  - **No new spend path and no new authority surface:** the change decides
    only what the new agent's config entries and credential directory are
    NAMED. Every key is still minted locally, still stored under the same
    owner-only permission model, and every budget is still signed by the
    owner in the dashboard before anything can be paid. The derived slug
    never displaces anyone — nothing is overwritten, tombstoned or rebound;
    the wiring-collision refusal (#2551) keeps its exact meaning for the one
    case it still describes, a bare setup over a live bare pair.
  - **Direction of travel is narrowing, not widening:** before, a default
    setup targeted the SHARED bare `haven` / `haven-signer` pair, so "add an
    agent" and "replace my agent" were the same action and the connector had
    to refuse or ask. Now every agent owns its own pair by construction, the
    de-collision is wider than the collision scan (it avoids retired
    directories, not just live ones), and an environment mark (`-dev`) makes
    a dev and a production agent distinguishable in every config. The
    replace-intent residual — a user who MEANT to replace and now
    accumulates agents — is accepted (owner decision 1, 2026-10-07): the
    #3122 pre-write heads-up names every keyed directory before anything is
    written, and revocation stays an owner action on the Haven agent page.
  - **Tested:** `runtime.test.ts` covers the clean-machine derivation, the
    alongside-over-bare run (no prompt, bare pair byte-identical), two
    same-named agents deriving distinct working slugs, a tombstoned slug
    never being reused, an explicit `--name` winning verbatim and unmarked,
    and the production chain deriving the plain slug;
    `wiring-collision.test.ts` pins `deriveServerSlug`'s marking,
    de-collision, fallback and length cap; `args.test.ts` pins the
    derive-by-default, `--bare` parsing and its refusals;
    `rekey.test.ts` pins key-removed directories not counting as candidates
    and the exact `--name` on the repair line; `config-writers.test.ts`
    pins the Hermes completion text naming the written pair.

  Authority and custody argument: nothing is granted, signed, widened or
  moved. The connector's non-custodial invariants — keys never leave the
  machine, connect never revokes, the owner signs every delegation — are
  untouched; the change only removes the implicit targeting of a shared
  pair. Perimeter unchanged (`packages/connect/` is on no money-path glob;
  the backend setup prompt is unmodified).
