- **#3739 — hosted x402 pays from the request, not an agent-copied challenge** —
  narrows risk; adds one read-only route. Money-path by file (`packages/mcp-server/src/**`).
  - **Before:** `haven_pay_x402_quote` built the payment from a ~3 KB
    `payment_required` the agent copied by hand. Nothing checked it was the
    merchant's. On the eip3009 bridge the funding leg moves money before the
    merchant sees the header, so a copying error stranded funds (field case
    2026-10-07, Bitrefill: an agent dropped `extensions.bazaar.schema`, the
    merchant refused the echo, and 0.01 USDC needed a sweep).
  - **Change:**
    - In request mode (no `payment_required`), the hosted server makes the
      unpaid request itself and builds the intent from the 402 it fetched.
    - `haven_quote_x402` now names that step.
    - A cap is required in request mode.
    - `payment_required` mode is unchanged.
  - **Perimeter:**
    - **New reach:** one unpaid probe, under a policy stricter than the quote's
      (https only; no IP literal, loopback, reserved or single-label host; no
      redirect followed; 15 s; 256 KB).
    - **Unchanged:** Haven still never sends a paid request to a plain-HTTP
      merchant. Earlier statements that the pay tool never contacts the
      merchant (`2026-08-31-2292`, `2026-09-29-3475`, `2026-10-07-3727`) were
      about the paid request, and had already overlooked the quote's own probe.
    - **No new state:** the probed challenge is stored where
      `payment_required` was already stored.
    - **One new read-only backend route,** `GET /x402/by-idempotency-key/{key}`
      (agent-scoped, writes nothing). It lets a replay answer before any
      re-probe.
    - No signature payload, delegation, enforcer, budget or key custody
      changes.
  - **Invariant:** for a new request-mode intent, the challenge the payment is
    built from deep-equals the one the merchant returned to Haven's own probe;
    the derived replay key covers the whole challenge, `extensions` included.
  - **Accepted residuals (owner, 2026-10-07):**
    - A merchant host name that resolves to a private address is not blocked
      inside `mcp-server` (#3740).
    - The probe is a second request, so per-request terms are paid on the fresh
      ones, bounded by the cap.
    - JSONB key reordering of the stored copy: the live Bitrefill check is
      pending (operator step on the PR).
  - **Tests:**
    - `plain-http-x402-request-mode.test.ts`: both schemes, every egress
      refusal, not-payable refusals, cap, oversized, replay-before-probe,
      derived key, resume.
    - `hosted-signer-integration.test.ts`: the header decoded from a
      key-reordered stored copy echoes the probed `extensions`.
    - `x402-intent-by-key.test.ts` (real Postgres): the lookup, and a JSONB
      sign-context round trip that deep-equals.
