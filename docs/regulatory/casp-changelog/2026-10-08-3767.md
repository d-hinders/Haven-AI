- **#3767 — every accounting surface books the settlement hash** —
  read/derive change over already-recorded data plus a feed-timing window;
  no authority, signing or fund-movement path is touched. Money-path by
  file (`infra/repositories/**`).
  - **Change:** the accounting surfaces (Fortnox feed, SIE export, the
    legacy Fortnox voucher and the receipt underlag PDF) now book ONE hash
    decided in `toAccountingEntry`: the verified merchant settlement
    (`machine_metadata.merchant_settlement_tx_hash`, recorded and
    chain-verified by #3475) when one is recorded, else the funding hash
    explicitly labelled as funding. This is the same hash #3763 headlines
    in the Haven UI, so the books, the UI and the explorer agree.
  - **Perimeter:** the one write is the booked-hash PIN
    (`PIN_ACCOUNTING_BOOKED_TX_SQL`): an UPDATE of
    `payment_intents.machine_metadata` that records
    `accounting_booked_tx_hash`/`_kind` on the feed's FIRST claim — and on a
    re-claim of a no-pin pre-deploy row, which books the FUNDING hash the
    first render used (the write refuses to overwrite an existing pin,
    `...->>'accounting_booked_tx_hash' IS NULL` guard) and never touches
    status, hashes or money fields. A pinned value wins over a
    later-recorded settlement so a destination never sees two different
    transactions for one payment (stable bytes across attempts,
    `booked-hash.db.test.ts`, including the pre-deploy failed-row race
    window).
  - **Timing:** an eip3009 payment with no recorded settlement is not fed
    until either the #3763/#3764 merchant-report grace window passes
    (the same resolved `merchantReportGraceMin`, never a hard-coded
    copy) or a settlement is recorded — whichever comes first. The
    retry sweep's due query gains a second selection arm for payments
    that have an evidence row but no sync row yet (same gates:
    connected + active destination, auto-feed, FX present).
  - **Mutation-tested:** `booked-hash.db.test.ts` (pin + stable bytes on
    real Postgres), the orchestrator deferral/pin unit tests, the entry
    booked-hash contract tests, per-surface rendering tests (SIE #VER,
    Fortnox comment, receipt PDF), the feed-once-after-settlement test
    in the #3475 evidence suite, and the sweep's second-selection test
    against the real database.
  - **Verdict:** Perimeter unchanged.
