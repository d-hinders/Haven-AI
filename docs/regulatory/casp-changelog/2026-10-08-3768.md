- **#3768 — merchant-issued credentials are withheld from the settled result** —
  an exposure-surface reduction, not a perimeter change.
  - **The defect (prod QA 2026-10-08, payment `79084a5e`, Soundside
    `create_text`, Base mainnet):** a settled `haven_settle_mcp_tool` response
    forwarded the merchant's raw tool result verbatim, including two bearer
    credentials bound to the agent's delegate EOA inside
    `result.structuredContent` (an `x402_session_token` JWT and a
    `wallet_link` URL with an embedded JWT). The agent's context is untrusted
    (prompt injection, transcripts, logs), so merchant-minted credentials
    reached places no credential should.
  - **The fix (issue option 1, withhold by default):**
    `deliverMerchantPayment` redacts the merchant body before any settled arm
    returns it — JWT-shaped strings by shape (including embedded in URLs),
    string values under credential-named keys (`*_token`, `*_link`,
    `access_token`, `session`, plus `secret`/`password`/`api_key`/
    `authorization`/`bearer`/`credential`) whole. Money fields,
    `settled`/`delivered` markers and transaction hashes are never touched,
    and a clean body is forwarded by reference unchanged. The
    MERCHANT_REJECTED_AFTER_FUNDING refusals' bounded `Merchant response:`
    echo redacts unconditionally.
  - **The opt-in is explicit and per call:** `include_merchant_credentials:
    true` on `haven_settle_mcp_tool` / `haven_complete_mcp_tool` returns the
    merchant body unredacted — a merchant session (Bitrefill
    `X-Access-Token`, #3728) is how an agent avoids paying per call, so
    receiving a credential is the agent's deliberate act, never a default.
  - **Perimeter:** no route, signature payload, delegation, enforcer, budget,
    key custody or API call changes. Haven gains no signing authority and no
    control is added or removed; the change narrows what a merchant response
    leaks into the untrusted agent context. The persisted evidence row
    (`attachMachinePaymentEvidence`) records status, challenge, proof and
    receipt headers — never a result body — and no credential value is
    written anywhere. Two body-bearing writes remain verbatim by design,
    both bounded and neither the settled tool result: reconciliation-event
    `retry_body` snippets (written only on a REJECTED retry, from that
    rejection body) and merchant `x-receipt-json` receipt documents (the
    merchant's own document, captured from headers). Both are flagged in the
    contract doc as accepted residual.
  - **Money-path by file:** `packages/mcp-server/src/**` is a runtime glob,
    so the classifier marks this change money-path even though it moves no
    money and alters no spend authority — it changes what a settled response
    exposes. A `dev → main` promotion therefore needs a covering green
    money-flow QA run.
  - **Pinned by:** `credential-redaction.test.ts` (recognizer + the Soundside
    shape through all three settled arms, red by default, verbatim under the
    opt-in, refusal echo redacted) and the byte-parity skill tests
    (`skill-content.test.ts` with the frontend twin).
