- **#3769 — the catalog can express per-call tool arguments and an HTTP
  method/body** — changes what a guided purchase CAN pay for (previously
  unbuyable rows become buyable as listed), not who can pay and not how much
  authority a call carries. Money-path by file
  (`packages/backend/src/**`, `packages/mcp-server/src/**`).
  - **Change:** a `merchant_catalog` row can declare `tool_arguments_schema`
    (migration 108) for a per-call MCP tool;
    `haven_prepare_catalog_purchase` then accepts an optional `arguments`
    input — merged over the row's pinned `tool_arguments` and validated
    against the schema BEFORE the merchant probe. A row without a schema is a
    fixed SKU and REFUSES caller `arguments` outright (`INVALID_INPUT`),
    preserving the CloudNest-tier contract; a schema-violating call is refused
    `INVALID_CATALOG_ARGUMENTS` (400) before any contact, so no payment
    exists on an invalid call. Plain-HTTP rows can declare `http_method` /
    `body_type` / `body_example`: the read-only verifier probes with the
    declared shape, discovery carries `method`/`body` in the
    `haven_quote_x402` hint, and a 402 that structurally advertises its own
    method corrects the row's `http_method` at refresh. The amount, asset,
    network, payTo and scheme still come exclusively from the LIVE merchant
    402 (`accepts[]`), never from the catalog row, the caller's arguments, or
    the new columns — a pinned argument value can never steer price or
    recipient.
  - **Perimeter:** no authority surface moves. The argument schema is an
    input-validation gate (it can only REFUSE, never widen); it is validated
    server-side in the hosted preflight against the OPERATOR-curated row, not
    against anything a merchant or caller controls mid-flight. The
    advertised-method write-back touches only the row's own probe metadata,
    guarded to `protocol: 'http'` rows; it feeds no budget pin, no caveat and
    no signing input. `pay_to` collection (#3331) and
    `asset_transfer_methods` scoping (#3386) are untouched.
  - **Mutation-tested:** prepare with a valid `prompt` succeeds and carries
    the resolved arguments into the probe; prepare with `{}` on a
    schema-declaring row refuses with the catalog read as the ONLY network
    call (no probe, no intent); caller arguments on a fixed-SKU row refuse
    `INVALID_INPUT` before contact; the POST-declared row's hint carries
    `method: "POST"` + a JSON-string body verbatim-acceptable by
    `haven_quote_x402`'s strict schema; the verifier probes POST rows with
    the declared method and body, and a challenge-advertised method is
    written back on http rows only (removing the write or the guard fails the
    tests).
  - **Verdict:** Perimeter unchanged — a new refusal gate on the guided
    path, no new spend authority, no new fund-movement path.
