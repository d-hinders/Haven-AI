- **#3770 — `delivery_quality` report on settled payments** — new evidence-
  only record, agent-scoped; no authority, signing or fund-movement path is
  touched. Money-path by file (`packages/backend/src/**`,
  `packages/mcp-server/src/**`, `packages/sdk/src/**`).
  - **Change:** an agent that paid a settled delivery that turned out
    unusable (or partial) can now say so:
    `POST /machine-payments/{id}/delivery-quality` writes one
    `machine_payment_delivery_reports` row per (payment, agent) —
    `quality` `ok`/`unusable`/`partial` plus a 2000-character-bounded note —
    and the receipt reads (`GET /receipts` rows, the signed receipt bundle)
    carry the verdict beside the payment. A new hosted tool
    (`haven_report_delivery_quality`) exposes it; skill text and the settle/
    complete tool descriptions say when to use it.
  - **Perimeter:** unchanged. The report writes nothing on
    `payment_intents` — `settled`, `tx_hash` and every money field keep the
    values the chain gave them; the handler only refuses (another agent's
    payment 404s, an unsettled payment 409s, a wrong enum or over-bound
    note 400s) and otherwise inserts into its own table, scoped to the
    calling agent from the same agent-auth the evidence attach uses. No
    credentials, keys or budget authority are read or granted; the report
    cannot authorize, move, or claw back anything, and the owner can ignore
    or disagree with it — it is one agent's judgement recorded as evidence.
  - **Mutation-tested:** the module test pins the refusal ladder
    (404 foreign/unknown payment, 409 unsettled, 400 enum/note bound,
    note trimming), the upsert's last-write-wins per (payment, agent), and
    the migration's schema; the receipts SQL carries the join so a recorded
    verdict shows on `haven_list_receipts` / `haven_get_receipt`.
  - **Verdict:** Perimeter unchanged.
