- **#3771 — `purchase_summary.product` falls back to a Haven-derived label** —
  display-only change on the hosted MCP settle surface; no authority, signing
  or fund-movement path is touched. Money-path by file
  (`packages/mcp-server/src/**`).
  - **Change:** when a settled merchant result carries no
    `structuredContent.summary` product name, `buildPurchaseSummary` now fills
    `product` with a label the caller derives from facts Haven itself already
    holds — the merchant host from the resolved call context plus the tool
    name (`<merchant host> <tool_name>`). The merchant's own `product_name`
    still wins whenever present; `invoice_id` and every money, status and hash
    field keep their existing sources, and a merchant that supplies none still
    yields nulls there exactly as before.
  - **Perimeter:** unchanged. The fallback is composed from the settle call's
    own context (the URL the call was resolved against and the tool that was
    called) — never parsed out of the merchant's response body. #1349's
    normalization is untouched: the merchant payload can still set only the
    product name it is explicitly allowed, and nothing the merchant sends can
    move amount, asset, network, merchant identity, status or either
    transaction hash. No route, signer, enforcer or sweep path changes; no new
    Haven read or write exists.
  - **Mutation-tested:** the settled erc7710 arm and the EIP-3009 arm both
    assert the fallback label on a result with no
    `structuredContent.summary` (removing the fallback fails them), and the
    merchant-name-wins case is pinned by the existing CloudNest and NordShield
    summaries, which pass unchanged.
  - **Verdict:** Perimeter unchanged.
