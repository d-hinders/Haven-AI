  guidance and refusal copy only; no payment behaviour changes. Money-path by file
  (`packages/mcp-server/src/**`, `packages/sdk/src/**`). Found by the #3739
  request-mode QA run on dev (PR #3775).
  - **erc7710 settlement.**
    - A successful erc7710 `haven_submit` now names `haven_report_settlement_evidence` (`payment_id` prefilled) as the step after the agent's own merchant retry.
    - Before, it named no Haven tool, and the payment sat at `submitted` until the passive sweeper attributed it.
    - `haven_report_x402_outcome` on an unconfirmed erc7710 payment now refuses with a typed code that names that tool.
      - `ERC7710_REPORT_SETTLEMENT_EVIDENCE` is the code for an `accepted` outcome; the caller's folded hash is carried into `next_arguments` rather than discarded.
      - `ERC7710_OUTCOME_NOT_REPORTABLE` is the code for a `rejected` outcome: nothing moved, so there is nothing to report or sweep.
      - Before, it answered a generic `API_ERROR`.
  - **Correction to `2026-10-07-3727`.**
    - Its test line "erc7710 evidence through the same seam" does not hold for a `submitted` erc7710 payment. `haven_report_x402_outcome`'s funding-anchor gate refuses it before any evidence is folded.
    - The seam that records an erc7710 settlement is `haven_report_settlement_evidence`, which is what the guidance now names.
    - The 3727 shard stays as written; this entry is the correction.
  - **eip3009 and direct `haven_submit`.**
    - A successful `haven_submit { payment_id }` now names its next step by flow, read from one status call: an x402 funding leg retries the merchant and then reports the outcome; a direct payment is done.
    - Anything not yet confirmed, or unreadable, reads the status and never retries the merchant.
    - Before, it returned a bare `{ status, tx_hash }`.
  - **Refusal reasons.**
    - Each request-mode probe refusal now says what happened: no 402, an unreadable 402, no payable option, an oversized answer or challenge, a timeout, or a transport failure.
    - The egress-policy wording stays only where that policy refused.
    - The egress refusal names the argument the calling tool takes: `url`, `merchant_url`, or, for the catalog tools, "pick another entry".
  - **Perimeter:** no signature payload, delegation, enforcer, budget, custody, route or wire field changes. One extra read-only status GET follows a non-erc7710 `haven_submit`.
