- **#3781 — the catalog tier of the purchase label (`catalogName` through
  `mcp_call_context`)** — display-only change across the x402 request schema,
  the settle-leg rehydration endpoint and the hosted MCP settle surface; no
  authority, signing or fund-movement path is touched. Money-path by file
  (`packages/backend/src/modules/x402/**`,
  `packages/mcp-server/src/tools/**`).
  - **Change:** `haven_prepare_catalog_purchase` now persists the catalog
    row's own `name` on the stored `mcp_call_context` JSONB blob (optional
    `catalogName`, both scheme branches); `POST /x402`'s enforced request
    schema accepts the optional key (it was refused under
    `additionalProperties: false`); `GET /x402/{id}/merchant-call-context`
    re-serves it snake_case as `catalog_name`; and at settle
    `purchaseFallbackLabel` prefers the rehydrated catalog name over the
    `<merchant host> <tool_name>` label when the merchant's result names no
    product.
  - **Perimeter:** unchanged. The label is still Haven-derived — a catalog
    row is Haven's own data, never merchant content (#1349): the merchant's
    `product_name` still wins in both cases, a direct `haven_pay_mcp_tool`
    purchase carries no `catalogName` and keeps the host+tool label, and
    nothing the merchant sends can move amount, asset, network, merchant
    identity, status or either transaction hash. No migration (the blob is
    JSONB), no new route, signer, enforcer or sweep path; the new schema key
    is `minLength: 1` display metadata that authorizes nothing.
  - **Mutation-tested:** the catalog prepare tests assert `catalogName` rides
    BOTH scheme branches and that a direct `haven_pay_mcp_tool` authorize
    carries none; the backend rehydration test asserts `catalog_name` is
    served for a catalog row and absent for a direct pay; the settle tests
    assert the catalog name fills the gap on both arms (erc7710 + EIP-3009),
    that the merchant `product_name` still beats it, and that a direct-pay
    settle still reports `merchant.test <tool>` (#3771 pinned).
  - **Verdict:** Perimeter unchanged.
