- **#3797 — publish.yml dependency-presence gate (partial publish safety)** —
  a CI-workflow change that narrows what publishes; it moves no funds and
  touches no signing, authority, custody or key-management path. Money-path by
  file (`.github/workflows/publish.yml` is in `controlGlobs`).
  - **Change:** the publish loop decides each package's internal `@haven_ai/*`
    dependency presence from the run's OWN outcomes — published earlier in the
    loop, or "already on npm" at its own check — never a fresh registry read
    (registry cache and timestamps lag a publish by minutes, #2660). A package
    whose dependency did not reach npm in this run is not published, is never
    nominated for `latest`, joins the failed set (job exits non-zero), and its
    results row reads `**FAILED** — not published: dependency
    <dep>@<version> did not publish in this run`. This closes the
    0.9.0-alpha.0 window (run 37898155685 attempt 1) where `signer`, `mcp` and
    `connect` published while `sdk` had not, leaving fresh installs resolving
    to a nonexistent dependency for ~5 minutes. A non-exact internal pin
    fails the run loudly. The remedy stays "re-run the failed job".
  - **Perimeter:** unchanged. The gate only withholds an npm publish and a
    `latest` nomination; it cannot spend, sign, move or authorize funds, and
    it changes no rule about how a user or agent accesses or revokes anything.
    `assert_publish_allowed`, the snapshot/dev-tag wall and every credential
    path in the workflow are untouched.
  - **Verification:** `npm run release:bump:test` (102/102) runs the REAL loop
    shell against a stubbed `npm`: a failed `sdk` publish holds back
    `signer`/`mcp`/`connect` with no nominations while dep-free `cli` still
    publishes; a just-published dependency still 404ing on `view` does NOT
    block its dependents (the registry-lag case, pinned); a re-run with
    everything on npm reports all five as skipped, never dependency-failed; a
    `^`-range pin fails the run loudly; the loop order is pinned against the
    real `packages/*/package.json` dependency graph; the dev snapshot channel
    publishes all five.
  - **Verdict:** Perimeter unchanged.
