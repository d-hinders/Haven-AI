- **#3802 — expired budgets stop counting as active; "No budget" replaces
  "No spend limits"** — money-path by file (`routes/agent-connection-setups.ts`,
  `modules/mpp/**` in `controlGlobs`).
  - **Change:** every budget-VIEWING read now filters
    `expires_at > EXTRACT(EPOCH FROM NOW())` (the DATABASE clock, exclusive
    bound) beside `status = 'active'`, through ONE shared SQL fragment
    (`delegationLiveWindowSql` in `infra/repositories/delegation-budgets.ts`)
    applied to `listActiveDelegations` (which feeds the dashboard, the agents
    routes and the agent-facing allowances read `modules/mpp/allowances.ts`),
    the analytics budget-remaining slice (`ACTIVE_DELEGATIONS_FOR_USER_SQL`),
    the three ops reads, and the connect activation check
    (`LIST_ACTIVE_DELEGATIONS_SQL` in `agent-connection-setups.ts`).
    `start_date` is deliberately NOT filtered (owner decision 2026-10-09): a
    credential rotation writes a dormant "steady" row with a future
    `start_date` beside the live "carry" row, and filtering future starts
    would hide the whole budget for the carry window. The payment selection
    queries are UNCHANGED — they keep their inline `start_date <= now <
    expires_at` copy, their text is pinned by #1698's characterization tests,
    and the #3802 characterization tests pin that an expired-only budget is
    already refused there (403, `remaining_atomic: '0'`; an expired PIN is
    not a live pin, so the no-merchantTo case answers 403, not 409).
    `GET /agents/:id/delegations` keeps listing every status on purpose
    (round-1's JS windowing there was reverted); the agent-detail
    `DelegationBudgetCard` keeps an expired row's "expired" line but excludes
    it from `hasActive`, so the grant form shows for an agent whose only
    budget expired. Every empty-budget copy surface (dashboard row,
    `AgentCard`, `AccountDetailClient`, `AgentsTable`) reads "No budget" —
    an agent with no live budget cannot spend at all, and the old strings
    said the opposite of the truth.
  - **Perimeter:** narrowed, fail-closed, in the direction of less presented
    authority. Nothing writes a new status; rows keep their bookkeeping
    `active` value and the change only stops an EXPIRED grant from being
    presented as a live budget by any reader, from activating an agent
    through connect, or from being reported to the SDK and hosted MCP — an
    agent whose only budget expired now derives `needs_approval` instead of
    a readiness the on-chain `TimestampEnforcer` would refuse. No new
    spender, no new grant, no signing input touched; the on-chain window was
    already the hard gate and Haven's reporting now agrees with it. Users
    keep every existing path to access and revoke their grants — revoke
    prepares and the calldata-binding sets span `pending`/`active`/`replaced`
    by status in their own queries, not through these views.
