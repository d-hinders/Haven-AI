- **#3816 — hosted MCP contract fingerprint and stale-tool-list reconnect rule** — an observability-and-guidance change; it constructs no payment, signs nothing, and moves no authority boundary. Money-path by file (`packages/mcp-server/src/**`).
  - **Change:** every hosted tool result's JSON payload gains two top-level fields — `contract_fingerprint` (16-hex sha256 over the canonical, sorted-key serialisation of what `tools/list` advertises per hosted tool: name, the SDK's converted input schema, description) and `server_version` — plus the SDK-generated strict-input and unknown-tool refusals gain the fingerprint and a reconnect hint via a CallTool pass-through wrapper. The SDK's shipped `haven-pay` skill and its byte-pinned frontend twin carry the same rule; the docs skew table gains the row.

The wrapper annotates error TEXT the SDK already produced; it never changes which calls reach a handler, never fabricates a success, and never alters a payload's decision fields. The carve-out re-points an agent at the EXISTING resume tools — the same one-payment resume discipline the in-flight carve-outs already enforce (resume, do not re-prepare, do not pay again); no new spending path, no new authority, no key handling. The fingerprint hashes tool advertisement metadata only — no identity, no key material, no consent input: the local consent hash (`packages/mcp/src/consent.ts`) hashes identity + tool NAMES + allowance summary and is untouched, and the hosted server has no consent gate.
