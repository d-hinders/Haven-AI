- **#3819 — publish-loop bash 3.2 compatibility (`declare -A` removed)** —
  a CI-workflow change to how the dependency-presence ledger is stored; it
  moves no funds and touches no signing, authority, custody or
  key-management path. Money-path by file (`.github/workflows/publish.yml`
  is in `controlGlobs`).
  - **Change:** the publish loop's `dep_state` ledger, introduced by #3797
    as a bash associative array (`declare -A`), is now a space-delimited
    `pkg=state` string read by an exact-word `case` lookup. `declare -A` is
    bash >= 4, and `release-bump.test.mjs` executes the loop script under
    the local `bash`, which on macOS is GNU bash 3.2 (#3819). Package
    directories contain no spaces, so the space-padded lookup is an
    exact-word match, semantically identical to the array read it replaced:
    the same packages are held back, marked FAILED and never nominated for
    `latest`, and the re-run remedy is unchanged. No decision site changed —
    only the storage of the same four states
    (published/skipped/failed/dep-failed).
  - **Perimeter:** unchanged. A representation change inside one CI job
    cannot spend, sign, move or authorize funds, and it changes no rule
    about how a user or agent accesses or revokes anything.
    `assert_publish_allowed`, the snapshot/dev-tag wall and every
    credential path in the workflow are untouched.
  - **Verification:** `npm run release:bump:test` (102/102) runs the REAL
    loop shell against a stubbed `npm`: the full gate passes on host bash 5
    and inside a real GNU bash 3.2.57 (musl) container; a negative control
    run in that same container confirms `declare -A` fails there with the
    exact error from #3819, so the fix is what passes. The #3797/#2421
    behavioural tests (dep-failed propagation, skipped-on-rerun, publish
    ordering, dev snapshot channel) exercise the ledger-string lookup
    unchanged.
  - **Verdict:** Perimeter unchanged.
