- **#3776 — decision recorded: no hosted completion for plain-HTTP x402
  (docs only)** — records an owner decision; no code changes.
  - **Decision (owner, 2026-10-10):** option 1 of #3776. The agent keeps
    sending the paid request to a plain-HTTP merchant itself. A hosted
    `haven_complete_x402_request` that would send the paid retry from Haven's
    server, record the outcome and return the merchant body is not built.
    The reasoning is in `docs/architecture/04-x402-payment-sequence.md`
    (*The agent sends the paid request — by decision*).
  - **Perimeter reasoning:** the #3739 statement "Haven still never sends a
    paid request to a plain-HTTP merchant" stays true, and this entry records
    that keeping it true was a deliberate choice. Hosted delivery of an
    agent-signed header would move no custody and grant no authority (the
    header is agent-signed, and budget, recipient and expiry are still enforced
    on-chain), but it would put Haven further into each payment on the user's
    behalf. That is the reading on which MiCA's transfer services (and, with
    USDC an e-money token, PSD2) turn. It would also route value-bearing merchant
    content (gift-card codes) through Haven's server. Reopening it needs counsel
    review, not only engineering review. The MCP-merchant completion tools
    (`haven_settle_mcp_tool`, `haven_complete_mcp_tool`), which already deliver
    the paid retry, are not changed by this entry.
  - **Nothing to mutation-test:** no code, test or guard changes.

Perimeter unchanged.
