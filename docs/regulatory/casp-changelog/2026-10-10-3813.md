- **#3813** — Server-saved dismissals for the dashboard's recurring "Needs you" items: a new `attention_dismissals` table (per-user rows keyed `no-backup`/per-account or `needs-setup`/per-agent, both `ON DELETE CASCADE`), two `routes/user.ts` endpoints (`GET`/`POST /user/attention-dismissals`), a frontend hook and a one-time migration of `RecoveryNudge`'s browser-storage key. No new authority, custody, spend or route surface: a dismissal is presentation-only state — it hides a nagging dashboard row and nothing else, it cannot spend, cannot change an allowance, budget or signer set, and no payment-path code reads the table (the writes are additionally scoped to the JWT subject with an ownership EXISTS, so a dismissal can never be planted for another user's account). The spec's `oneOf` body and the table's CHECK refuse every kind except the two owner-approved ones, so no future dismissal kind can slip through as an accidental permission. Dismissals gate only what the dashboard renders; the underlying state stays visible on the account and agent pages. No payment behaviour changes. Perimeter unchanged.
