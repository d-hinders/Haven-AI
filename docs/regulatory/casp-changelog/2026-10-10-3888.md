- **#3888 — the eip3009 settlement is attributable and detected on-chain** —
  money-path by file (`packages/backend/src/modules/x402/**`,
  `packages/signer/**`, `packages/sdk/**`); moves no money and grants no
  authority. Owner decision recorded on the issue: attribution key option
  (a), the derived nonce. Open owner question 2 (hash-taken precedence) is
  implemented conservatively — log-only, never overwrite an agent-reported
  hash.
  - **Change:** the EIP-3009 nonce is no longer the x402 library's random
    draw. One shared derivation,
    `keccak256(utf8("haven-x402-payment-nonce:") || utf8(payment_id))`
    (`deriveX402PaymentNonce`, SDK edge surface, pinned by a test vector),
    is used by the signer (`packages/signer/src/core.ts`), the SDK header
    builder (`packages/sdk/src/x402-funding-leg.ts`, both the authorize and
    the resume path) and the backend sweep. A leader-gated backend pass
    (`packages/backend/src/modules/x402/eip3009-settlement-sweeper.ts` plus
    the `AuthorizationUsed` reader
    `infra/chain/authorization-used-scanner.ts`) finds an unreported
    settlement by the intent's own derived nonce in the pinned token's
    `AuthorizationUsed(delegate, nonce)` log, verifies it with the existing
    `verifySettlementTransferTx`, records the hash through the existing
    guarded writer, and fires the accounting feed once in the reported
    path's order (base row, hash, feed — the feed never books the funding
    hash ahead of an existing settlement). Past grace, the payment now reads
    `payment_confirmed` / next action `none` instead of "the merchant has
    likely not been paid".
  - **Perimeter:** unchanged in kind, narrowed in reach. The signer change
    overwrites ONE field on the unsigned payload the x402 library's own
    `preparePaymentHeader` built — the signed typed data, the binding
    surface and the spend constraints are unchanged, and `payment_id` was
    already inside the Haven-signed binding the signer verifies, so the
    signer gains no new input. The sweep is read-only chain observation
    (bounded block ranges, fail-closed on any RPC failure, no write until
    the full verifier passes) plus the same evidence write the agent-reported
    path performs; it never signs, never relays, never grants. The derived
    nonce grants no spend capability by construction. Residuals stated on
    the issue and in
    `docs/security/delegation-rail-security-model.md` §8: a `payment_id`
    collision denies one payment on-chain (never a double spend), and
    payments become publicly linkable to Haven through the nonce — which the
    delegate EOA's funding legs already are. Side effect, stated and tested:
    a fixed nonce closes the #3475 re-pay hazard for new signers — a resumed
    payment re-signs the same nonce and is refused as already used.
  - **Mutation-tested:** the derivation is pinned by a test vector
    (`packages/sdk/src/x402-nonce.test.ts`); the signer's v1 and v2 branches
    are asserted to carry the derived nonce; the sweep is exercised on the
    real-Postgres harness with a fixture chain (recorded path, fail-closed
    RPC paths, hash-taken log-only precedence, old-signer random-nonce
    pass-through, status-read regression); the three guard tests that
    previously mocked `createPaymentHeader` move to the new
    `preparePaymentHeader`/`signPaymentHeader`/`encodePayment` entry points
    so they cannot pass vacuously.
  - **Verdict:** Perimeter unchanged — read-only chain observation and a
    signer nonce derivation with no new authority.
