# 2026-10-13 — #3772 (part 1): a replaced agent's own reads warn it

- **#3772 part 1: Haven records that a Connect `--replace` superseded an agent,
  and that agent's reads say so.** Money-path by file: `routes/agent-connection-setups.ts`,
  `routes/machine-payments.ts`, `infra/repositories/agents.ts`, migration 112
  and `packages/mcp-server/src/**` (tests only).
  - **Change.** Migration 112 adds two nullable columns to `agents`:
    `superseded_by_agent_id` and `superseded_at`.
    - **The report.** After a `--replace` whose install completed, the
      connector posts the ids it actually retired to
      `POST /agent-connection-setups/{setupId}/retired-agents`.
    - **Authentication.** The report is authenticated by the NEW agent's API
      key only; a setup token is refused.
    - **What Haven marks.** Haven marks each listed agent of the setup's own
      user as superseded by the reporting agent. Other users' agents are never
      marked, and neither is the reporter itself.
    - **The reads.** `GET /machine-payments/agent` and `/allowances` carry
      `superseded_by`. The SDK, and through it both MCP runtimes, turn that
      into a warning:
      - restart the session;
      - have the user remove the old agent.

    Owner decisions, recorded on #3772 on 2026-10-13: part 1 is built, and
    there is no automatic pause (part 3).
  - **Perimeter.** The change grants, narrows, pauses and revokes nothing.
    - **The superseded agent is unchanged.** Its key, status, delegation and
      on-chain budget are all as before. The record is metadata, and a failed
      read degrades to `null` rather than failing the identity read.
    - **Worst case of a misused report.** It puts a false warning on another
      agent of the reporter's own owner. It cannot reach another user's agent.
    - **Removal is still the owner's.** The owner removes the old agent through
      the existing owner-authenticated control. No agent credential gains a way
      to edit another agent's authority.
    - **Nothing secret travels.** No key or credential material is sent; the
      route refuses private-key-shaped fields.
  - **Tested.**
    - Real-Postgres repository tests cover:
      - never marking another user's agent;
      - excluding the reporter;
      - a later replace overwriting the record;
      - `ON DELETE SET NULL`.
    - Route tests run under both enforce and validation-off.
    - Mutation proofs went red when each of these was broken:
      - accepting a setup token;
      - scoping by the wrong user id;
      - dropping the SQL `user_id` filter;
      - reporting every other agent (`superseded_agent_ids`) instead of the
        retired ones;
      - dropping the connector's 404 tolerance for an older backend.
  - **Verdict:** Perimeter unchanged.
