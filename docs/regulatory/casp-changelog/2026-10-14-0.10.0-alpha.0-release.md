  **What the release carries into published packages, by effect on authority:**
  - **#3888 (#3893): a derived EIP-3009 nonce.**
    - The signer and SDK set the 3009 authorization nonce to `keccak256("haven-x402-payment-nonce:" ‖ payment_id)` instead of a random value.
    - This lets the backend attribute the merchant's `AuthorizationUsed` log to the payment. When a payment id is present (always, for the signer), a resumed payment re-signs the same nonce, so a settled payment cannot be paid twice by an updated client.
    - The signed typed data is still the library's own. The one signer-source change in range, recorded in `delegation-rail-security-model.md` where it merged and re-read at this release.
  - **#3838 (#3853): the SDK signs in to a merchant's SIWX session** before a multi-call flow. It uses the delegate's existing Sign-In-With-X signature, which moves no funds and approves no payment.
  - **#3839 (#3855): discovery entries carry `funding_leg_expected` / `asset_transfer_methods`.** A catalog hint; the quote stays authoritative. Read-only.
  - **#3772 (#3907): `supersededBy` on the agent and allowance reads**, a warning to a replaced agent. Warning only: nothing is paused or revoked.
  - **#3799 (#3827), #3830 (#3851): connect** updates one named pair with `--doctor`/`--repair --name`, refuses ambiguous multi-agent repairs, re-consents local tools without a token, and lists coexisting agents rather than calling them replaced. Wiring and text; no authority change.
  - **#3834 (#3848): out-of-gas `MERCHANT_NOT_READY`** refusals name the operator top-up. Text only.
  - **#3894:** SDK runbook wording; the CLI changes are guidance text only.
