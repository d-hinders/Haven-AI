- **#3922 (budget liveness slice C, epic #3919): clients read one server-derived `is_live` flag instead of restating budget liveness.**
  - **What changed:** an additive `is_live: boolean` field on every budget-shaped wire object. Each value comes from the slice A/B predicates:
    - **Delegation list:** `spendableDelegationSql` with `requireStarted: false`, selected in SQL. This is the budget-view definition, so a dormant future-start re-key row is live.
    - **Task budgets:** a JS mirror of `liveTaskBudgetSql`, the `?status=live` set.
    - **Sub budgets:** a JS mirror of `openSubBudgetSql`.
    - **`parent_sub_budgets`:** `openSubBudgetSql`, selected in SQL.
    - **Allowances rows:** `true` by construction.
    - **Mirror pinning:** real-DB tests and a JS-equals-SQL matrix pin each mirror to its predicate.
  - **New constant:** `@haven_ai/core` exports `STILL_ENABLED_DELEGATION_STATUSES`, pinned to `stillEnabledDelegationSql()` by a backend test.
  - **Clients now reading `is_live`:**
    - the SDK's task-budget summary, where an expired `closing` row no longer lingers;
    - the CLI's grant wait;
    - the frontend budget card, sub-budget "ends" line, eligible parents, budget-caption expiry and fund-merchant replace warning.

    The SDK and CLI fall back to today's derivation when an older backend omits the field.
  - **CLI revoke refusal:** it stays on the still-enabled STATUS set, held in one local copy that a test pins to the core constant. It must refuse while any on-chain authority remains, including against an older backend.
  - **Perimeter:** no payment path reads `is_live`; the spend-time checks and the payment selectors (`requireStarted: true`) are untouched. Nothing about who can sign, move or authorise changes. No enforcer, refusal code, signature or on-chain authority changes. `is_expired`, `live_delegation_count` and `status=live` are unchanged.
  - **The one display change:** a closed or closing sub-budget whose expiry is still in the future now reads "ended" instead of "ends". This narrows what is presented as live authority, so the dashboard no longer overstates spend authority.
  - **Verdict:** perimeter unchanged.
