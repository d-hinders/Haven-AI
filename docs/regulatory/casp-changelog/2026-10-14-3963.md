# 2026-10-14 — #3963: the delivery-reference test stops dialing CoinGecko; the price fetch gets a deadline

**Perimeter: unchanged.** Nothing in this change moves funds, signs anything on
Haven's behalf, or widens any authority. Two bounded, non-custodial
bookkeeping-infrastructure edits:

- **Change:** `packages/backend/src/modules/mpp/__tests__/delivery-reference.test.ts`
  (the #3778 evidence suite) no longer lets the evidence attach reach the live
  CoinGecko price fetch: `getBookTimeCapture` is stubbed to `null`, the module's
  own pricing-outage answer, which the real-DB suite treats identically (the
  capture is backfillable; the test asserts nothing about FX). And
  `packages/backend/src/infra/prices.ts` bounds its `fetch` with a 2s
  `AbortSignal.timeout`, so a HUNG upstream (blackholed DNS, stalled TLS) now
  degrades exactly like a fast failure — throw → `getOrFetch` skips the cache →
  callers fall back to the documented null/backfillable path — instead of
  blocking the evidence attach (whose capture is best-effort by contract) for
  the OS's full connect timeout.
- **Perimeter:** the price cache still serves the same shape to the same
  callers (`fiat-values.ts` book-time capture, the portfolio display); the
  deadline can only turn a would-be hang into the existing failure path, never
  produce a price, widen a spend, or change what an evidence row proves. The
  x402 settlement gate, the delegation rails and every authority surface are
  untouched.
- **Verification:** blackhole probe (fetch pointed at a non-routable IP) —
  `getBookTimeCapture` returned `null` after 2002ms with the deadline, where it
  previously hung for the OS connect timeout; the four affected suites
  (`prices`, `prices-book-time-isolation`, `fiat-values`,
  `mpp/delivery-reference`) pass with no network; full `npm run preflight`
  selection for the touched packages green apart from this shard.
