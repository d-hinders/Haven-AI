- **#3996 — the local MCP server can verify an idempotency collision on chain**
  — `@haven_ai/mcp` now reads per-chain RPC endpoints from the environment
  (`HAVEN_RPC_URL_<chainId>`, e.g. `HAVEN_RPC_URL_8453`,
  `HAVEN_RPC_URL_84532`) and passes them to the SDK as `chainRpcs` in
  `resolveHavenClient` (`packages/mcp/src/server.ts`; the env scan lives in
  `packages/mcp/src/credentials.ts`). With an entry for the payment's chain,
  an x402 idempotency collision is decided by an on-chain balance read of the
  delegate (`delegateCanFund`) instead of refusing `unverifiable` unconditionally.
  - **Change:** an unset variable constructs the client exactly as before —
    every collision refuses `unverifiable`, today's behaviour. With an entry
    set, a collision where the delegate is still funded resumes (the SDK mints
    a fresh authorization; the settled #3996 owner decision) and a drained
    delegate refuses with basis `settled`. The erc7710 path never calls
    `delegateCanFund` and is untouched; no SDK file, key derivation or
    `agentInstruction` byte changes.
  - **Perimeter:** non-custodial stance unchanged. No key material is added —
    the RPC URL is a read-only endpoint the user configures in their own MCP
    client `env` block; Haven holds no new credential and no API credential
    becomes sufficient to spend. No authority surface moves: the change alters
    only the *basis* on which an idempotency refusal is decided, not who can
    spend or how much. Nothing is signed differently and no signed payment
    intent is altered; the user can still revoke the delegate's permissions
    outside Haven exactly as before. A malformed or unreachable URL degrades
    to `unverifiable`, never to a silent spend.
  - **Verification:** the mcp-layer test in
    `packages/mcp/src/server.test.ts` pins `resolveHavenClient` wiring the
    `chainRpcs` entries from the env scalars, ignoring non-positive-integer
    suffixes and empty values, and leaving the client keyless when unset; the
    SDK half (balance-read refusal basis) is already pinned by
    `packages/sdk/src/x402-already-settled.test.ts` and is deliberately not
    duplicated. Package gates for `packages/mcp` run via `npm run preflight`.
