- **#4079** — **`haven_check_funds` calls a short account short, not empty: agent-facing wording only. No payment, signing, custody or authorization code moved; the perimeter is unchanged.**
  What changed. `covered: false` means a live chain read reports that the
  agent's account holds LESS than the checked amount — the balance itself is
  deliberately not returned (#3126). The tool's `next_step`
  (`packages/mcp-server/src/tools/state-direct-recovery.ts`) and its SDK
  description (`packages/sdk/src/tool-descriptions.ts`) worded that case as
  "the budget is backed by an empty account", so an agent relayed a false
  statement to the owner ("your account is empty") when the account merely
  held less (seen live 2026-10-19 on the prod Bik Bok QA buy). Both now say the
  account holds less than the checked amount and to stop and tell the user it
  is short; the hosted description (`packages/mcp-server/src/tools/contracts.ts`)
  says "the account is short" instead of "the funds are missing".
  What did not change. The stop instruction is kept: on `covered: false` the
  agent still does not attempt the payment. `covered` stays a sufficiency
  boolean read from chain; no balance is disclosed; no field, argument, input
  schema, backend route or on-chain check moved. Enforcement stays on-chain.
  Verification. `packages/mcp-server/src/tools/check-funds-token.test.ts`
  pins the three strings (next_step, hosted description, SDK description) and
  fails if "empty account" or "funds are missing" returns; each guard was
  mutation-proven by restoring the old string (each turned its test red).
