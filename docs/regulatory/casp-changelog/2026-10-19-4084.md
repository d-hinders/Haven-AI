- **#4084** — **a column-default change on `feedback` only: migration `115_feedback_expires_at_fixed_window` (a `packages/backend/src/db/migrations/**` file) moves `feedback.expires_at`'s default from `NOW() + INTERVAL '7 days'` to `NOW() + INTERVAL '168 hours'`. No payment, signing, custody or authorization code moved; the perimeter is unchanged.**
  What changed. Postgres adds an interval's `days` field as calendar days in
  the session `TimeZone`, and the backend never pins it (`db.ts` builds the
  pool with no `options`), so 106's default gave rows written in a non-UTC
  session within a week of a DST change a 167 h or 169 h retention window
  instead of the owner-decided seven days (#3597, 2026-10-02). It surfaced as
  `106_feedback.test.ts` failing on a Stockholm-zoned local Postgres on
  2026-10-19 (`expected 608400000 to be less than 604805000`) while CI (UTC)
  stayed green. An hours-only interval is elapsed time, so the window is now
  168 h in every zone. 106 is applied and untouched; existing rows keep their
  `expires_at`; `down()` restores 106's default exactly. Why the perimeter is
  unaffected: `feedback` holds user-submitted CLI text, already scrubbed by
  `redactVendorSecrets` at the write boundary — it carries no key, address
  authority, allowance, delegation or payment state, and no money-path code
  reads it. The read-side `expires_at > NOW()` filter, the leader-gated purge,
  the ops console's audited reveal (#3602) and every grant are unchanged; the
  only effect is that a row can no longer outlive seven days by an hour.
  Mutation-tested: `115_feedback_expires_at_fixed_window.test.ts` evaluates
  the stored default at fixed instants before Stockholm's and New York's DST
  changes in pinned sessions; reverting 115's `up()` to `'7 days'` reddens 5 of
  its 7 tests plus 106's original assertion; dropping the 106 test's
  re-application of 115 reddens that file on `assertWorkerSchemaAtHead`
  (`feedback (columns ~expires_at)`); unregistering 115 from
  `migrations/index.ts` reddens 4 tests across both files — each restored
  byte-identical (`cmp`) after. Perimeter unchanged.
