- **#4099** — **An owner's own send is recorded so the transaction feed names its initiator "You"; a send to another of the user's own accounts is named by the receiving account. Attribution only — no payment, signing, custody or authorization behaviour moved.**
  What changed. The owner-send submit route
  (`POST /accounts/hybrid/:address/transfers/submit`, `routes/hybrid-accounts.ts`)
  now writes one row to a new `owner_transfers` table (migration 116) after the
  UserOp's receipt confirms the transfer: user, account, chain, tx hash, UserOp
  hash, token, recipient, amount. Transaction enrichment matches an outbound
  feed row to that row by (tx hash, account, chain) and by token, recipient
  and amount — so an agent spend bundled into the same transaction is not
  claimed as the owner's — and reports
  `initiatedBy: 'human'` instead of `'unknown'`. The CSV export's `initiator`
  column now uses the app's words ("You", the agent's name, "Unknown") instead
  of the raw enum. The dashboard activity feed names the receiving account on
  a send to another of the user's own accounts.
  `rails/hybrid-transfers.ts` additionally returns the UserOp hash and the
  already-validated transfer to the route; what it submits is unchanged.

  Why the perimeter is unaffected. The record is written only after the
  transfer executed, nothing on any payment path reads it, and a failed or
  slow write is logged and never fails the send or holds its reply past a
  500 ms deadline (a client that timed out might otherwise send again) — it
  changes what the feed CALLS a
  transfer, never whether or what one moves. The owner still signs the exact
  UserOp; Haven still holds no key and gains no authority. A characterization
  test, which passes against the pre-change route as well, pins that
  `submitCall` receives the signed operation unchanged and the signature
  verbatim; the two tests beside it that expect the record to be written fail
  against the pre-change route (`hybrid-signers.test.ts`). The record's insert joins through an
  account the user owns, so it cannot be written onto another tenant's
  account (`cross-tenant-writes.test.ts`). Past owner
  sends have no record and stay "Unknown" (owner decision, 2026-10-19); no
  heuristic infers them, and a test pins it (`initiator-record.test.ts`).

  Perimeter unchanged.
