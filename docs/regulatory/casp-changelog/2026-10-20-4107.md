# 2026-10-20 — #4107: optional pre-trade token-safety check (hosted, advisory)

- **#4107 — hosted `haven_check_token_safety`: an advisory pre-trade token
  check via a third-party x402 gate.** Adds one agent-visible tool; adds NO
  spend path. Money-path by file (`packages/mcp-server/src/**`).
  - **Issue:** Grey Ridge runs a pay-per-call pre-trade token gate on Base
    (`https://x402-data-api.sigrunner.workers.dev`, x402/USDC): a free
    `/gate/swap/preview` and a paid `/gate/swap` ($0.008 per the operator — a
    short-window measurement, not an SLA). Haven has no swap-signing surface
    (`haven_sign` signs only Haven-prepared payloads), so there is no pre-sign
    hook to wire; what fits the agent-first surface is an ADVISORY tool the
    agent can call before acting on a Base token trade.
  - **Change:**
    - New hosted tool `haven_check_token_safety` (capability module
      `tools/token-safety.ts`): input is `token` (0x Base address or the
      operator's demo alias), `side` (default buy), `notional_usd` (default
      100, bounded ≤ 1,000,000). It calls ONLY the operator's free preview
      endpoint and returns the operator's decision/verdict/risk_score/flags
      verbatim, plus a `paid_gate` block naming the ready-to-quote paid URL.
    - The tool NEVER pays. The operator's PAID `/gate/swap` resource is
      reachable only through the existing generic rail (`haven_quote_x402` →
      `haven_pay_x402_quote`), where the price comes from the 402 the quote
      fetches, the cap is the agent's own explicit `max_amount` /
      `max_amount_human`, and every budget and authority gate of that rail
      applies unchanged. No new payment machinery, no new backend route, no
      new stored state.
    - The operator URL is PINNED, not an argument: a caller-choosable "safety
      check" endpoint would be a spoofing vector (a fake oracle answering
      SAFE). No override input exists.
  - **Fail-open vs fail-closed, stated plainly:** the check is ADVISORY — it
    is information, not policy, and nothing in Haven consults it
    automatically (CASP: off-chain policy is never the real spend control).
    Every failure mode (transport, timeout, non-JSON, operator error, shape
    mismatch, over-cap body) is one explicit refusal,
    `TOKEN_SAFETY_CHECK_UNAVAILABLE`, whose message and omitted next step say
    the check did NOT run and is NOT a pass. A guard outage can therefore
    neither silently spend (this tool cannot spend) nor silently mark a token
    safe (there is no pass-shaped failure).
  - **Perimeter:**
    - **New reach:** one unpaid GET to the pinned operator host, under the
      #3747 hosted merchant-egress policy (public https only, asserted before
      connecting), with redirects never followed (any 3xx is an unavailable
      check, not a hop), the policy's while-reading response byte cap, and a
      short timeout (the egress discovery/quote budget; fallback 15s — the
      operator's measured p95 is ~3.4s).
    - **No key material, no signature payload, no delegation, enforcer,
      budget or custody changes.** The hosted server stays keyless; the tool
      signs nothing and relays nothing.
    - **Identity gate:** `haven_check_token_safety` is NOT on
      `IDENTITY_GATE_EXEMPT` — it is gated like every other third-party
      surface (default rule covers it; no code change).
  - **Invariant:** the tool contacts exactly one host — the pinned operator —
    over exactly one method (unpaid GET preview), and its success payload
    never carries a payment field. Pinned by `token-safety.test.ts` (single
    recorded fetch per call, `check.payment_made === false`, no Haven route
    touched).
  - **Accepted residuals:**
    - The check reflects ONE third-party operator's heuristics; its verdicts
      are advisory signals with an explicit disclaimer carried through to the
      agent, not Haven's own analysis. The operator's availability is a
      measurement, not an SLA, and is treated as untrusted.
    - The operator could change its free-preview shape; the tool refuses with
      `TOKEN_SAFETY_CHECK_UNAVAILABLE` rather than guessing (shape check:
      string `decision` and `verdict`).
    - A merchant host name that resolves to a private address is not blocked
      inside `mcp-server` (#3740, same residual as every hosted merchant
      path).
  - **Tests:** `token-safety.test.ts` — verdict mapping, defaults, alias and
    side/notional forwarding, pre-connect token validation, egress refusal
    before connecting, every unavailable-refusal branch (5xx, redirect,
    non-JSON, operator error object, shape mismatch, byte cap, transport
    failure), the omitted-tool next step, and the single-host/single-fetch
    invariant. Registry/census/snapshot companions updated in the same
    commit (`tools-registry.test.ts`, `tools-contracts.test.ts`,
    `strict-tool-input.test.ts`, `next-step-fixtures.ts`,
    `queue-framing-census.test.mjs`, `tools-list.snapshot.json`).
