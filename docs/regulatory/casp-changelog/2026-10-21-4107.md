# 2026-10-21 — #4107: `haven_check_token_safety` removed (revert of PR #4148)

- **#4107 — hosted `haven_check_token_safety` removed before promotion.** Owner
  decision (2026-10-21). Reverts PR #4148 (merge `202687627`) in full: the
  capability module `tools/token-safety.ts`, its registration and contract,
  its tests, and every companion (tools-list snapshot, description-size
  ratchet back to 31,674 bytes / 29 tools, next-step refusal fixtures,
  queue-framing census, qa-agent eval tool lists, the hosted contract docs).
  The tool lived on `dev` only (so at most on hosted dev): `202687627` is not
  an ancestor of `main`, so no production deploy carried it. Money-path by file
  (`packages/mcp-server/src/**`).
  - **Why.** The 2026-10-20 shard (`2026-10-20-4107.md`) stays as the record
    of what was analysed then; it is not edited. This entry records what that
    analysis did not weigh:
    - **Haven presented a third party's answer as a Haven tool result.** The
      shard calls the verdict "advisory signals with an explicit disclaimer",
      but the tool returned `decision` / `verdict` (e.g. `go` / `SAFE`) from
      one commercial operator that nobody at Haven had vetted, under a
      `haven_`-named tool. Pinning the URL stops a caller choosing a fake
      oracle; it does nothing about the pinned operator, who controls the
      answer entirely.
    - **The answer could be for a different token.** The operator stated on
      the issue that past its free tier (3 real-token checks per IP per day,
      and all hosted agents share Haven's egress IPs) the preview silently
      returns a demo token's result. The merged code reported
      `token: body.token ?? token` and never compared the operator's `token`
      with the one requested, so an agent could receive `go` for a token it
      did not ask about. The shard's shape check (string `decision` and
      `verdict`) passes such a response. This was wrong when written; it is
      corrected here, not in the original shard.
    - **Quota exhaustion steered agents to the operator's paid endpoint.**
      Every result carried a `paid_gate` block naming the operator's paid
      `/gate/swap` URL, so the shared free quota running out pushed agents
      towards a paid call to the same vendor. The payment itself would have
      gone through the ordinary x402 rail and its gates, but Haven should not
      be the one recommending a vendor's paid product.
    - **Third-party free text reached agent context verbatim.** `reason`,
      `flags` and `disclaimer` were passed through unfiltered: text an
      outside operator controls, delivered as part of a Haven tool response.
  - **Perimeter.** The removal takes away one unpaid outbound GET to the
    pinned operator host and one agent-visible tool. It removes no spend
    path, because the tool never had one: no key material, signature
    payload, delegation, enforcer, budget, custody or backend route changes,
    in either direction. The x402 rail the paid gate would have used
    (`haven_quote_x402` → `haven_pay_x402_quote`) is unchanged and still
    gates any merchant URL an agent brings itself.
  - **Tests.** `token-safety.test.ts` goes with the module. The registry,
    contract, strict-input, description-size, snapshot, next-step-fixture,
    queue-framing-census and qa-agent eval tests return to their pre-#4148
    expectations (29 hosted tools). A tree-wide `git grep` for the tool name
    and the operator host finds no code or test reference: the tool name
    survives only in the two shards in this directory and in the removal
    note in `docs/operations/mcp-runtime-compatibility.md`, and the operator
    host only in the 2026-10-20 shard.
  - **Verdict:** Perimeter narrowed (one outbound third-party host and one
    tool removed; spend authority unchanged).
