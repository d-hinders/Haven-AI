- **#4248 — follow-ups from the #4242 review: a settlement-child binding is
  never held, and its refusal is structured.** This touches only the local
  signer (`packages/signer/src/core.ts`, `packages/signer/src/tools.ts`, new
  `packages/signer/src/no-funding-leg.ts`). No backend, relay, custody or
  hosted-tool code moved, and nothing Haven signs changed. Nothing the signer
  will sign widens.
  What changed. Since #4242 the signer kept a settlement child's expected
  context in its in-memory binding map until a header attempt that the
  supported erc7710 flow never makes, so that payment context lived until the
  process restarted. The signing branch now stores funding-leg bindings only
  and retires a settlement-child binding as `no_funding_leg` the moment it is
  minted. Every held binding is therefore one a merchant header may be built
  from, which makes "a child is held" and "a child builds a header" the same
  defect, and the #4242 header-time test catches both. The header-time rail
  check that only a held child could reach is removed with it.
  `haven_x402_sign_header` still answers a child's binding with the
  no-funding-leg remedy, from the retired set; past that set's bound of 64 it
  degrades to the unknown-binding refusal, which also builds nothing.
  The refusal is now the structured `NO_FUNDING_LEG`, with
  `next_action: sign_and_submit_payment` and a `next_tool_omitted_reason`
  naming `haven_sign`, then `haven_submit` with `settlement_scheme: 'erc7710'`.
  It replaces a plain `SIGNING_ERROR`. `haven_sign_x402` now checks the
  expected-context version before the settlement-child refusal (#1143
  ordering), so a skewed context gets the version-mismatch refusal and its
  update fallback.
  Tested in `packages/signer/src/x402-binding-rail.test.ts`:
  - the `{ payment_id }` path, where the typed data comes from the
    sign-context fetch, refuses a settlement child with zero signing calls;
  - both refusal sites carry the code, next action and omitted reason;
  - a version-99 context on a settlement child gets
    `UNSUPPORTED_EXPECTED_CONTEXT_VERSION` with zero signing calls.
  The `x402-sign-header-transport.test.ts` success helper now asserts instead
  of throwing, so an over-broad refusal fails as an assertion. The mutation
  record is in the PR. Every mutation was restored byte-identical (sha256) by
  the mutation runner. Perimeter unchanged or narrower.
