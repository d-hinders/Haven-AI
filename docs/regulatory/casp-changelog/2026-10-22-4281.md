- **#4281** — the catalogue's outbound probes go through the SSRF guard.
  Since #4245, `merchant_catalog` is not operator-only: where
  `CATALOG_DISCOVERY_ENABLED=true` (default false), the discovery cron inserts
  URLs that sellers listed in the external x402 Bazaar index. Two paths still
  probed those URLs with the process-global `fetch`, outside the
  resolved-address check that the ingestion probe (#1713) has always required:
  the discovery probe of each candidate and the hourly refresh of every
  non-delisted row.
  What changed:
  - `packages/backend/src/infra/http/ssrf-guard.ts` gains `safeRequest`, which
    sends GET, HEAD, POST, PUT, PATCH or DELETE through the existing guarded
    loop: https on the default port, no IP literals or locally-bound names,
    resolution-time address classification, a socket pinned to the checked
    address, and a total deadline, byte cap and redirect budget. It returns
    any status, because a 402 is the answer a probe wants. It builds the
    request headers itself; the caller chooses only `accept`. It refuses a
    redirect on any method that can carry a body, and a method outside that
    set before any I/O.
  - `packages/backend/src/modules/catalog/merchant-catalog.ts` adds
    `createGuardedCatalogFetch`, a fetch-shaped adapter over `safeRequest`
    (5 s, 256 KiB). `guardedCatalogFetch` is now the default transport of
    `probeCatalogEntry` and `refreshCatalog` for every row, whatever its
    `source`. A refusal is a failed probe: it writes no `pay_to` and counts a
    miss, as a probe that got no 402 already did.
  - `packages/backend/src/modules/catalog/catalog-discovery.ts` probes
    candidates through a separate `probeFetch` (guarded by default). The
    caller's `fetchImpl` now reads only the operator-configured Bazaar index.
  - Comments in `modules/catalog/probe.ts` and `platform/leader-lock.ts`, and
    the guard's header, state the rule that now holds.
  - Docs: `catalog-ingestion.md` gains the rule. `dev-environment.md` and
    `delegation-rail-security-model.md` gain scoped re-verification notes.
  What a successful probe records (`pay_to`, `asset_transfer_methods`,
  `http_method`, prices) is unchanged, and so is the request shape: the MCP
  `tools/call` POST and each row's declared method and example body. Every
  catalogue row seeded by migrations is an https URL on a public host. A row
  whose merchant redirects a POST probe, serves plain http or resolves to a
  non-public address now fails its probe.
  Tests: `modules/catalog/__tests__/catalog-probe-ssrf.test.ts` (new) and
  `infra/http/__tests__/ssrf-guard.test.ts`. The discovery and migration-117
  tests pass their fetch mock as `probeFetch`, since they test parsing and
  inserts, not transport. The three default-transport cases were red on
  `origin/dev` at `a7a1f96da` with the global `fetch` stubbed to answer a
  valid 402. Mutation-tested with `scripts/ci/prove-red.mjs`: each of these
  reddens a test:
  - reverting any of the three defaults to the global `fetch`;
  - probing a discovery candidate with the index fetch;
  - refusing a 402;
  - following a redirect on a body method;
  - dropping the method allowlist, the GET/HEAD body drop or the CR/LF
    `accept` check;
  - dropping the adapter's guard options;
  - turning a refusal into a response;
  - letting a non-string body through.
  The money-path classifier matches `packages/backend/src/db/migrations/**`
  on `__tests__/117_merchant_catalog_source.test.ts` only, a test-file edit.
  Every other changed file is off the perimeter. No custody, signing,
  settlement, funding or budget decision changes, and `globs` and
  `controlGlobs` are not touched. Perimeter unchanged.
