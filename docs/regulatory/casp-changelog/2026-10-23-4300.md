- **#4300** — catalog probe runs are bounded, and the SSRF guard's deadline
  covers name resolution and falls back across checked addresses. This is a
  follow-up to #4281 (PR #4287), which moved every catalog probe behind the
  guard.
  What changed:
  - **Refresh run budget.** `refreshCatalog`
    (`packages/backend/src/modules/catalog/merchant-catalog.ts`) runs
    within a 10 min wall-clock budget (`CATALOG_REFRESH_RUN_BUDGET_MS`). It
    takes rows by `updated_at` ascending and starts a probe only while that
    probe's 15 s budget still fits.
    - A row it does not reach is not written: it records no miss, no step
      toward `degraded`, and no `pay_to` change.
    - The run returns and logs a `deferred` count.
    - Both outcome writes set `updated_at`, so the next run takes the
      unreached rows first.
  - **Discovery run budget.** `ingestDiscoveredCatalog`
    (`modules/catalog/catalog-discovery.ts`) probes candidates within 2 min
    (`DISCOVERY_RUN_BUDGET_MS`). A candidate it does not reach is not
    inserted, and is counted `deferred`.
  - **Bazaar index fetch.** It stays on the caller's `fetch`, since its URL
    is the operator's `CATALOG_DISCOVERY_URL`. Each page now carries a 15 s
    abort signal and a 2 MiB body cap, and a run reads at most 5 pages.
  - **Name resolution under the deadline.** In `infra/http/ssrf-guard.ts`,
    resolution now runs under the same total deadline as the request. The
    request gets what is left after it.
  - **Address fallback.** The guard tries the addresses that resolution
    returned and classification kept, in order, each pinned on its own.
    - It moves to the next one only on `connect_error`: a failure before the
      TLS handshake completed, so no request byte reached a server.
    - While another address is left, the connect phase is capped at 3 s
      (`CONNECT_FALLBACK_TIMEOUT_MS`).
    - A failure after the handshake stays `transport_error` and is not
      retried.
  - **Unchanged.** `safePostJson` still refuses a redirect on a POST.
    `safeGetText` and `safePostJson` keep their budgets.
  Tests:
  - `infra/http/__tests__/ssrf-guard.test.ts`, with the transport and
    resolver injected:
    - a redirect hop gets only the budget left;
    - a slow resolver is cut off at the deadline;
    - a `connect_error` falls back to the next public address;
    - an address the policy refused is never tried;
    - a `transport_error` is not retried.
  - `infra/http/__tests__/ssrf-guard.real-transport.test.ts`, against
    loopback sockets: a closed port answers `connect_error`, a silent
    handshake is cut at the connect cap, and a reset after the request
    arrives answers `transport_error`.
  - `modules/catalog/__tests__/catalog-refresh-rotation.db.test.ts`, against
    real Postgres: two runs whose budget covers half the rows probe each row
    exactly once, and no unreached row gains a failure.
  - `modules/catalog/__tests__/catalog-run-budget.test.ts`: the discovery
    run budget, and the index page signal, byte cap and page cap.
  Mutation-tested with `scripts/ci/prove-red.mjs`: 15 author cells, all
  caught. Each of these edits reddens a test:
  - giving each hop the full budget;
  - resolving outside the deadline;
  - removing the fallback;
  - appending refused addresses after the public ones;
  - retrying a `transport_error`;
  - swapping the connect and transport classification;
  - dropping the connect cap;
  - sorting the refresh newest first;
  - counting an unreached row as a miss;
  - removing either run budget;
  - letting a deferred candidate through;
  - removing the page cap, the byte cap or the signal.
  The money-path classifier finds no file on the perimeter, and `globs` and
  `controlGlobs` are not touched. Perimeter unchanged.
