- **#4324** — the dashboard's "Needs attention" items can be acknowledged
  until something new happens (owner decisions on epic #4322, 2026-10-23,
  reversing the parts of #3813 that made the budget, scope, sponsorship and
  failure items non-dismissible). Presentation only: an acknowledgement hides
  a dashboard row and nothing else.
  What changed on the perimeter:
  - **Migration `118_attention_acknowledgements`**
    (`packages/backend/src/db/migrations/118_attention_acknowledgements.ts`,
    registered in `migrations/index.ts`) on 111's `attention_dismissals`:
    - The kind/shape CHECK now also admits `budget-reached`, `budget-usage`
      and `budget-scope` (per agent, no account), `payments-failed` (per
      agent, or with neither id for the unattributed item) and
      `haven-paused` (neither id). Any other kind is still refused at the
      table edge.
    - `acknowledged_at TIMESTAMPTZ NOT NULL DEFAULT NOW()`, backfilled from
      `created_at` for the rows 111 stored.
    - `acknowledged_period_end TIMESTAMPTZ`, which the CHECK requires on
      `budget-usage` and refuses on every other kind.
    - Two partial unique indexes as upsert arbiters:
      `(user_id, item_kind, agent_id)` for the four per-agent kinds, and
      `(user_id, item_kind) WHERE agent_id IS NULL AND account_id IS NULL`
      for the two user-level kinds. The `account_id IS NULL` term keeps a
      user's per-account `no-backup` rows outside the second index.
    - `down()` deletes the new-kind rows first, then drops both new
      indexes, drops the CHECK and re-creates 111's, and drops the two
      columns.
  - **`packages/backend/src/infra/repositories/attention-dismissals.ts`**:
    `acknowledgeAgentItem` and `acknowledgeUserItem` upsert against the two
    new indexes, and a repeat moves `acknowledged_at` to now; the per-agent
    write also sets `acknowledged_period_end` to the value sent. The
    per-agent write selects through an ownership `EXISTS` on `agents`
    (`id = $3 AND user_id = $1`), so a foreign or unknown agent writes
    nothing. The user-level write carries no foreign id. The list read
    returns both new columns. The permanent `no-backup`/`needs-setup` writes
    are unchanged apart from returning the two new columns.
  - **`packages/backend/src/infra/repositories/dashboard.ts`**, two reads,
    both still `WHERE ... user_id = $1`:
    - `REFUSAL_BUCKETS_BY_AGENT_SQL` adds four `MAX(r.created_at) FILTER
      (...)` columns to the same scan, one per bucket, over the 7-day window
      only.
    - `FAILED_INTENTS_7D_SQL` adds `MAX(GREATEST(pi.created_at, pi.signed_at,
      pi.submitted_at))`. `payment_intents` records no failure time, so this
      is the latest recorded step of any failed intent in the window; an
      intent submitted before an acknowledgement that fails after it does
      not re-arm the unattributed item.
  - **Tests on the perimeter**:
    `db/migrations/__tests__/118_attention_acknowledgements.test.ts`
    (new), `db/migrations/__tests__/111_attention_dismissals.test.ts`
    (reverts and re-applies 118 around its own down/up case),
    `infra/repositories/__tests__/attention-dismissals.test.ts` and
    `infra/repositories/__tests__/dashboard-overview.db.test.ts`.
  Off the perimeter, in the same PR: `routes/user.ts` dispatches the POST
  per kind (before, every kind other than `no-backup` was written as
  `needs-setup`) and refuses a kind it does not know; `routes/dashboard.ts`
  puts the latest times on the overview's `d7` refusal buckets and
  `spend.lastFailedIntentAt`; the OpenAPI spec and `core/api-types.ts`
  follow; the frontend rules, hook, callers and docs change.
  No new authority, custody, spend or signing surface. No payment-path code
  reads `attention_dismissals`, and an acknowledgement cannot change a
  budget, allowance, delegation or signer. The `d7` refusal times are read
  from rows the overview already counted. 33 mutation cells (16 author,
  17 reviewer), all caught, cover the per-kind dispatch, the unknown-kind
  mapping, the re-arm boundaries, the period re-arm, the migration's CHECK,
  backfill, `down()` and indexes, both upserts and the new read columns.
