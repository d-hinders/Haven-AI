- **#4327** — the agent Activity tab exports its ledger as a CSV file, and
  the CSV export's response plumbing becomes one shared helper. Read-only
  exports; no payment, authority or refusal changed.
  What changed:
  - **One CSV-export response helper.** The row cap (`EXPORT_ROW_CAP`,
    10,000), the 413 body, the CSV headers, the UTF-8 BOM and the dated
    filename move from `routes/transactions.ts` and
    `modules/transactions/csv-export.ts` into
    `packages/backend/src/domain/csv.ts`, in two steps: a cap check that runs
    on the row count before any CSV is built and answers the 413, then a send
    step. The 413 states an exact count, or "more than 10,000 rows" when the
    caller holds only a lower bound. `GET /transactions/export.csv` uses the
    helper and answers the same bytes as before.
  - **The agent ledger export.** `GET /agent-activity/{id}/activity/export.csv`
    (`routes/agent-activity.ts`) writes the agent page's Activity tab as
    shown: the agent's own `payment_intents`, failed and pending included,
    under the tab's filters (`status`, `token`, `from`/`to`, `q`), or with
    `status=refused` the agent's `payment_refusals` rows. It answers 404
    unless `agentExistsForUser` confirms the agent is the caller's, as the
    list read beside it does. The payment rows come from
    `listAgentPaymentsForExport` (`infra/repositories/agent-activity.ts`),
    which runs the tab's existing filtered statement
    (`LIST_AGENT_PAYMENTS_FILTERED_SQL`) unpaged with a limit of
    `EXPORT_ROW_CAP + 1`; the refusal rows come from the existing
    `listAgentRefusalsFiltered` with the same limit. An extra row means the
    file would be over the cap, and the route refuses it with a 413 rather
    than write a truncated file. No new SQL statement is added.
  - **The tab.** `AgentActivityTab.tsx` drops its link to
    `/transactions?agentId=` and offers Export CSV through the shared list
    export action (#4328).
  Tests:
  - `routes/__tests__/transactions-export-csv.test.ts`: a characterization
    test, committed before the move, pins the export's exact 413 body and
    exact success headers; the route's existing tests and
    `routes/__tests__/transactions-filterbar.test.ts` pass unchanged.
  - `domain/__tests__/csv.test.ts`: the cap at and over the limit, the exact
    and lower-bound 413 sentences, the cap check sending nothing under the
    cap, the prefixed UTC filename and the send step's headers and BOM.
  - `infra/repositories/__tests__/agent-activity-export.db.test.ts`, against
    real Postgres: the export read returns the filtered population with a
    failed row that has no tx hash, newest first; it returns `cap + 1` rows
    and no more; it returns only the given agent's rows.
  - `routes/__tests__/agent-activity-export.db.test.ts`, against real
    Postgres with request validation enforced: the file's columns, order and
    headers; `status=failed`, the period bounds and `status=refused`; a 404
    for another user's agent; a 400 for a status outside the tab's
    vocabulary; a 413 with the tab's own filters at 10,001 rows.
  - Frontend: `AgentActivityTab.export.test.tsx` (the request's path and
    params, Refused sending no token, the prefix, the empty-file copy, the
    disabled state) and `AgentDetailClient.test.tsx` (no link to
    `/transactions`).
  - Twelve mutation cells, all caught: the export dropping the status
    filter; the export skipping the ownership check; the export read
    dropping rows with no tx hash; the read taking `cap` rows instead of
    `cap + 1`; `status=refused` not switching the population; the agent
    413 stating a count it does not have; the `/transactions` 413 losing a
    word of its filters; the send step dropping the BOM; the tab rendering
    a link to `/transactions`; the tab's request on Refused not asking for
    the refused attempts; the request dropping the token; the action
    enabled on an empty population.
  Perimeter unchanged: both exports read the owner's own rows behind the
  same ownership checks as the reads they mirror; nothing here holds key
  material, signs, moves funds, or changes what a budget, a delegation or a
  refusal permits.
