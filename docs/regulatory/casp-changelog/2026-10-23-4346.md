- **#4346** — free-text search terms match `%`, `_` and `\` literally, plus
  two documentation corrections. Read-only search filtering; no payment,
  authority or refusal changed.
  What changed:
  - **Search escaping.** Every server-side free-text search bound its term
    into `col ILIKE '%' || $n || '%'` unescaped. The term was parameterised,
    so this was never injection, but LIKE read `%` and `_` in it as
    wildcards and `\` as its escape character: `_` matched every row, and
    `a\b` matched `ab` instead of a literal `a\b`. The specs already promise
    a case-insensitive substring search. One helper,
    `escapeLikeContains` (`packages/backend/src/infra/sql-like.ts`), escapes
    `\`, `%` and `_` and keeps `null` as `null`, so the
    `($n::text IS NULL OR …)` short-circuit still means "no search". Each
    predicate declares `ESCAPE '\'`. The sites:
    - `infra/repositories/payment-refusals.ts`: the refusal list and COUNT
      statements, each binding the escaped term;
    - `infra/repositories/agent-activity.ts` and
      `infra/repositories/agent-tool-invocations.ts`: the payment and
      tool-call list and COUNT statements, through the argument builder each
      pair shares;
    - `routes/catalog.ts`: the operator half's SQL predicate. Only the bound
      SQL value is escaped; the ingestion half filters in JS with `includes`,
      which was already literal, and keeps the raw words.
  - **Documentation and comments.** `docs/operations/accounting-feed.md`
    and the comments in `infra/repositories/accounting-feed-syncs.ts`,
    `modules/accounting/feed-sync.ts` and
    `modules/accounting/__tests__/feed-dedup.integration.test.ts` named the
    pre-migration-113 three-column key of `accounting_feed_syncs`; they now
    name `(provider, payment_id, user_id, document_kind)`. The dedup test's
    oracle keeps its three-column model, and its comment says why that is
    still equivalent (the statements it models are scoped to
    `document_kind = 'underlag'`). A duplicate JSDoc block in
    `routes/agent-activity.ts` that documented nothing is removed. No
    accounting behaviour changed.
  Tests:
  - `infra/repositories/__tests__/agent-activity-filters.db.test.ts` and
    `routes/__tests__/agent-activity-refusals.db.test.ts`, against real
    Postgres: for payments, tool calls and refusals, `a_b` finds only a
    literal `a_b` (not `axb`), `a\b` finds only a literal backslash (not
    `ab`), and a lone `%` matches no row without a literal `%`. Each case
    asserts the page and the count. They were red on the unescaped code.
  - `routes/__tests__/catalog-search.test.ts`, against real Postgres: `a_b`
    finds the operator row and the ingestion row that contain it, and
    neither `axb` row.
  - `routes/__tests__/catalog.test.ts`: the two SQL-text pins follow the
    escaped predicate.
  - Eight mutation cells, all caught: the helper skipping each of `_`, `\`
    and `%`; the payment and tool-call argument builders binding the raw
    term; the refusal list and the refusal COUNT each binding it; catalog
    binding the raw word.
  Perimeter unchanged: these reads filter the owner's own rows and the
  public catalog listing; nothing here holds key material, signs, moves
  funds, or changes what a budget, a delegation or a refusal permits.
