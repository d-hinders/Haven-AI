- **#4354** — every transition that settles an agent's payment now writes
  the onboarding funnel's last step, `first_payment_settled`. Before this,
  only `POST /payments/:id/sign` wrote it.
  What changed:
  - **One writer, reading the payment row.** `recordFirstPaymentSettled`
    (`packages/backend/src/infra/repositories/onboarding-funnel.ts`) is a
    single `INSERT … SELECT` into `onboarding_events`.
    - It selects from `payment_intents` joined to `agents`, gated on
      `status = 'confirmed'`, so a call for a row that is not confirmed
      writes nothing.
    - The user is the agent's owner. `rail` is the row's
      `COALESCE(payment_rail, source, 'manual')`, so the direct rail keeps
      the `manual` label the sign route wrote. `settlement_scheme` comes from
      `machine_metadata` when present.
    - `ON CONFLICT DO NOTHING` against the existing partial unique index on
      `(user_id, event)` keeps one row per user.
    - `emitFirstPaymentSettled` is its fire-and-forget form, with the same
      structure as `emitFunnelEvent`: an async body whose errors are
      swallowed, and a `void` return.
  - **The three callers**, each after its own confirm has matched:
    - `routes/payments.ts`: the sign route's existing emission now goes
      through the helper. That route serves the direct rail and the x402
      EIP-3009 funding leg.
    - `modules/x402/settlement-observed.ts` (`observeErc7710Settlement`),
      after `confirmObservedSettlement` returns true. That call commits its
      own transaction before returning, and both callers (the evidence seam
      and the sweeper) pass no executor.
    - `modules/payments/submission-reconciler.ts`, after
      `reconcileOutcomeConfirmed` returns true. The writer is injectable as
      `deps.emitFirstPayment`.
  - **The census behind "three".** On `origin/dev` @ `018c11d4f`, the
    `SET status = 'confirmed'` writes on `payment_intents` with a runtime
    caller are `CONFIRM_SUBMITTED_INTENT_SQL` (the sign route),
    `CONFIRM_SETTLEMENT_OBSERVED_SQL` (the erc7710 seam) and
    `RECONCILE_OUTCOME_CONFIRMED_SQL` (the reconciler).
    `CONFIRM_X402_INTENT_SQL` and `CONFIRM_MACHINE_INTENT_SQL` have no
    runtime caller and are not wired.
  Authority and custody: the change reads a payment row after it is
  confirmed and writes one telemetry row. It does not touch any confirm
  statement, refusal, signature, delegation, key or transfer. No payment
  outcome, response body or status code changes. The emission is a `void`
  call placed after the confirm, so it adds no await on the payment path.
  Tests:
  - `infra/repositories/__tests__/first-payment-settled.db.test.ts`, on real
    Postgres:
    - an erc7710, an EIP-3009 and a direct payment each write one row with
      their rail and scheme;
    - `submitted`, `failed` and `pending_signature` rows write none;
    - a second settled payment writes no second row;
    - an unknown id writes none.
  - `routes/__tests__/payments-first-payment-funnel.test.ts`: the sign route
    writes after a confirm, for a direct payment and an x402 funding leg. It
    writes nothing on a lost confirm (409), a reverted submit or a
    receipt-unconfirmed submit. This test was committed before the change as
    a characterization of the existing emission.
  - `modules/x402/__tests__/settlement-observed-funnel.test.ts`: the erc7710
    seam emits once, after a winning confirm. It emits nothing when the
    confirm matched no row, when the transaction is unverified, or when the
    row is not a pending erc7710 settlement.
  - `modules/payments/__tests__/submission-reconciler.test.ts`: the
    reconciler emits once for a confirmed receipt. It emits nothing for a lost
    CAS, a revert or an elapsed window.
  Mutation-tested with `scripts/ci/prove-red.mjs`: 8 author cells, all
  caught. Each of these edits reddens a test:
  - removing any of the three emissions;
  - emitting before the erc7710 confirm's result is checked;
  - emitting before the reconciler's CAS;
  - dropping the `confirmed` gate;
  - hard-coding `rail` back to `manual`;
  - dropping `ON CONFLICT DO NOTHING`.
  The money-path classifier at the head matches six files by runtime globs:
  - `routes/payments.ts`
  - `modules/payments/submission-reconciler.ts`
  - `modules/x402/settlement-observed.ts`
  - `modules/x402/__tests__/settlement-observed-funnel.test.ts`
  - `infra/repositories/onboarding-funnel.ts`
  - `infra/repositories/__tests__/first-payment-settled.db.test.ts`

  `globs` and `controlGlobs` are not touched. Perimeter unchanged.
