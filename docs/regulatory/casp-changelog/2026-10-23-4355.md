- **#4355 — `haven_get_agent` tells a budget spent for the period from no
  budget** — additive read fields and guidance text; no perimeter change.
  - **Read:** the agent-facing allowances read
    (`packages/backend/src/modules/mpp/allowances.ts`) adds `next_refill_at`
    to each delegation-rail row: the end of the row's current period from its
    own `start_date` and `period_seconds` (the `@haven_ai/core`
    `currentPeriodBounds` the dashboard's refill caption already uses), its
    start for a not-yet-started row, and `null` when the budget's
    `expires_at` comes first. The SDK maps it to `nextRefillAt` and derives
    `budgetRefillsAt` on `getAgentSummary()` for an agent whose every live
    budget is at remaining 0. Read-only and derived: no new query, no write,
    and the on-chain `remaining` figure stays the authoritative one.
  - **Guidance:** `needs_approval` used to tell an agent with a spent budget
    that "nobody approved yet. Ask your user again" — sending the owner back
    to an approval that already happened. The runbook, skill text and tool
    description now separate the two causes. The readiness values are
    unchanged (#4349 decision 5, additive), so no client contract widens.
  - **Perimeter:** no selection, signing, funding, settlement, key,
    delegation, enforcer or budget behaviour changes; the agent gains no
    capability and Haven no authority. The architecture doc
    `04-x402-payment-sequence.md` covers `packages/sdk/src/types.ts` (the
    `HavenAgentSummary` / `HavenAllowance` additions) and stays accurate:
    it uses the allowances read as an input to the #1306 preflight and the
    post-purchase summary, names the row keys those surfaces share, and
    neither consumes the new field. Pinned by `allowances-validity-window.test.ts` (real DB) and the
    SDK's `agent-info.test.ts`. Perimeter unchanged.
