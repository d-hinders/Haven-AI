- **#4379** — the dependency-boundary lint now checks imports between backend
  modules, and the 14 module-to-module deep imports it found are routed or
  waived. Import paths and one constants file only; no payment, authority,
  refusal or settlement behaviour changed.
  What changed:
  - **The rule.** `.dependency-cruiser.cjs` gains
    `no-deep-module-to-module-import`: a file in `modules/<a>/` may not
    import a private file of `modules/<b>/`, only its `index.ts`. The
    existing `no-deep-cross-module-import` excluded every `modules/` file
    from its `from` side, so these imports were never checked. A fixture test
    in `scripts/dep-lint.test.mjs` plants a deep import (fires), the same
    import through the barrel (does not) and an own-module import (does not).
  - **Eight edges through a barrel.** `modules/x402/sign-context.ts`,
    `modules/x402/settle.ts`, `modules/x402/delegation-authorize.ts` (three
    imports merged into one), `modules/mpp/budget-precheck.ts` and
    `modules/mpp/sweep.ts` now import from `modules/payments/index.ts`, and
    `modules/x402/eip3009-settlement-sweeper.ts` from `modules/mpp/index.ts`.
    The same names are imported; only the path changed.
  - **Two edges through `domain/`.** `modules/payments/agent-payment-status.ts`
    read `MAX_SETTLEMENT_WINDOW_SECONDS` and `CLOCK_SKEW_SECONDS` from x402
    files, and an x402 barrel import there would be a cycle. Both constants
    now live in the new zero-import
    `packages/backend/src/domain/x402-settlement-timing.ts` with their values
    unchanged (600 and 120). `modules/x402/x402-delegation.ts` imports
    `MAX_SETTLEMENT_WINDOW_SECONDS` from there and
    `modules/x402/settlement-observed.ts` imports `CLOCK_SKEW_SECONDS`; each
    re-exports its constant under the same name.
  - **Four edges waived.** Each keeps its import of a leaf file and carries a
    `dep-lint-exempt` reason naming the cycle a barrel import would close:
    `modules/accounting/entry.ts` → `modules/transactions/normalize.ts`, and
    `modules/mpp/evidence.ts` → three x402 settlement-evidence leaves.
  - **Test pins.** The refusal census
    (`modules/payments/__tests__/refusal-census.test.ts`) pins source line
    numbers in `delegation-authorize.ts`; its 19 pins there shift by +4 for
    the merged import. The census still enumerates the same refusal sites.
  - **Docs.** `docs/architecture/10-module-boundaries.md` describes both arms
    and the 15 waivers, and names `modules/dashboard/` as the one module
    without an `index.ts` (#3847, #3804). Scoped re-verification notes in
    `docs/operations/mcp-runtime-compatibility.md` and
    `docs/security/delegation-rail-security-model.md` record that their
    covered files changed only in import lines.
  - **Perimeter.** The moved constants are the settlement child
    delegation's expiry clamp (600 s, `modules/x402/x402-delegation.ts`) and
    the clock skew of the settlement-observed and EIP-3009 evidence windows,
    so the money-path list follows them: `.github/money-path-globs.json`,
    `.github/labeler.yml` and
    `.agents/skills/ship-next/references/money-path-perimeter.md` gain
    `packages/backend/src/domain/x402-settlement-timing.ts` and
    `packages/backend/src/domain/x402-sweep-window.ts`. The sweep-window
    file (the settlement sweeper's window constants, #3514) was off the list
    before this change; it is the same family and joins in the same edit.
    Both files join the `covers:` of `docs/regulatory/casp-risk-guardrails.md`,
    and the timing file that of
    `docs/security/delegation-rail-security-model.md` and
    `docs/operations/mcp-runtime-compatibility.md`. The x402 delegation test
    now also asserts the 600 s ceiling as a literal.
  The money-path classifier matches 12 changed files through runtime globs:
  the timing file, `modules/mpp/{budget-precheck,evidence,sweep}.ts`,
  `modules/payments/agent-payment-status.ts`, and seven files under
  `modules/x402/**` (six source files and `__tests__/x402-delegation.test.ts`).
  It matches `.github/money-path-globs.json` through a control glob. In the
  source files every change is an import path, a re-export, a waiver
  comment, or a constant's definition and its doc comment moving to
  `domain/` with its value unchanged. The perimeter grew by the two
  `domain/` files and lost nothing.
