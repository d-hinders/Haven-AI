- **#4390** — the independent exit page now covers Base mainnet, reads each
  delegation's revoke status on-chain, and loads no third-party script; the
  docs state the passkey boundary of the Haven-independent exit. The page
  runs in the owner's browser with no Haven backend and signs nothing; no
  payment, authority, refusal or settlement code changed.
  What changed:
  - **Chains.** `packages/frontend/public/exit/exit-core.mjs` (new; the
    page's logic, moved out of `index.html` so it can be tested) lists Base
    (8453, the default) and Base Sepolia (84532), each with the
    DelegationManager `0xdb9B1e94B5b69Df7e401DDbedE43491141047dB3` and the
    public RPC `https://mainnet.base.org` / `https://sepolia.base.org`.
    `packages/frontend/src/lib/__tests__/exit-page.test.ts` checks both
    managers against `packages/backend/src/rails/delegation-contracts.ts` and
    the table in `docs/exit/README.md`.
  - **Hash and status.** The page computes the delegation's EIP-712 struct
    hash (`delegate, delegator, authority, caveats(enforcer, terms), salt`;
    `args` and `signature` excluded), which is the key of the manager's
    `disabledDelegations`. The test checks it against `hashDelegation` from
    `@metamask/smart-accounts-kit` and against a value read from the
    manager's `getDelegationHash` on Base Sepolia on 2026-10-24. The status
    shown is the answer to `disabledDelegations(hash)`: *not revoked*,
    *revoked*, or *status unknown* when the read fails or is not a boolean.
    Before this change the page labelled every delegation its scan found
    "redeemed" without reading its status.
  - **Discovery.** On 2026-10-24 `sepolia.base.org` limited `eth_getLogs`
    to a 200-block range and `mainnet.base.org` answered "request limit
    reached", so a scan from block 0 does not complete on either. The page
    scans from the manager's first block (found with `eth_getCode`) in
    chunks narrowed to the range the RPC names, stops after 300 queries and
    says how far it got, and accepts another RPC, a later from-block, or a
    pasted delegation.
  - **No third-party script.** ethers 6.16.0 is vendored as
    `packages/frontend/public/exit/vendor/ethers-6.16.0.min.js`: the npm
    `ethers.min.js` byte for byte below a notice carrying its MIT licence.
    `index.html` and `exit-core.mjs` import it by relative path instead of
    from `esm.sh`; the test pins the body's sha256 and refuses an import
    from an `http(s)` URL.
  - **Docs.** `docs/exit/README.md` lists both chains, describes the status
    read and the discovery limits, and states that a passkey is bound to the
    site it was created on (`getDefaultRpId` in
    `packages/frontend/src/lib/passkey.ts` uses the page's hostname), so an
    owner whose only signer is a passkey can sign the revoke only through
    Haven's site; a wallet signer removes that dependency.
    `docs/regulatory/casp-risk-guardrails.md` (the #832 DEMONSTRABLE
    sentence), `docs/operations/mainnet-canary.md` and
    `docs/product/account-recovery.md` say the same. The guardrails sentence
    keeps the 2026-07-11 live verification scoped to Base Sepolia; this
    change adds no live verification of the exit path on Base mainnet.
  Mutation-tested (`prove-red`, nine cells, all caught): dropping 8453, a
  wrong mainnet manager, a status that never reads *revoked*, a failed read
  answering *active*, a reordered hash struct, an `esm.sh` import, a
  narrowing that ignores the named range, a scan without its request cap,
  and an altered vendored body. The money-path classifier matches none of
  the 9 changed files. The exit page reads public chain state and builds
  calldata the owner signs elsewhere; Haven gains no capability and the
  owner loses none. Perimeter unchanged.
