- **#4390** — the independent exit page now covers Base mainnet, reads each
  delegation's revoke status on-chain from an RPC whose chain it has checked,
  tells the account's own budgets apart from its agent's child delegations,
  and loads no third-party script; the docs state the passkey boundary of the
  Haven-independent exit. The page runs in the owner's browser with no Haven
  backend and signs nothing; no payment, authority, refusal or settlement
  code changed.
  What changed:
  - **Chains.** `packages/frontend/public/exit/exit-core.mjs` (new; the
    page's logic, moved out of `index.html` so it can be tested) lists Base
    (8453, the default) and Base Sepolia (84532), each with the
    DelegationManager `0xdb9B1e94B5b69Df7e401DDbedE43491141047dB3`, the
    public RPC `https://mainnet.base.org` / `https://sepolia.base.org` and the
    explorer. `packages/frontend/src/lib/__tests__/exit-page.test.ts` checks
    both managers against `packages/backend/src/rails/delegation-contracts.ts`
    and the table in `docs/exit/README.md`, each RPC against its chain id, and
    each explorer against `explorerUrl` in `packages/core/src/chains.ts`.
  - **Chain identity.** Both chains use the same manager address, so an RPC
    for the other chain would answer every read. Before it scans or checks,
    the page gets the manager from `checkedManager` in `exit-core.mjs`, which
    reads `eth_chainId` from the provider and refuses a mismatch, a failed
    read or an answer that is not a chain id, then builds the contract on that
    same provider. ethers' `staticNetwork` does not ask (with Base selected and
    the Sepolia RPC, `getNetwork()` returned 8453 and `eth_chainId`
    `0x14a34`). The test checks that behaviour on mock providers, including
    that the contract's runner is the checked provider, and that the page
    calls it from both entry points and builds no other contract or provider.
  - **Hash and status.** The page computes the delegation's EIP-712 struct
    hash (`delegate, delegator, authority, caveats(enforcer, terms), salt`;
    `args` and `signature` excluded), which is the key of the manager's
    `disabledDelegations`. The test hashes through `toPlainDelegation`, the
    path scanned and pasted delegations take, and checks the result against
    `hashDelegation` from `@metamask/smart-accounts-kit` and against a value
    read from the manager's `getDelegationHash` on Base Sepolia on 2026-10-24.
    The status shown is the answer to `disabledDelegations(hash)`: *not
    revoked* (in a warning tone), *revoked* (noting that only the delegator
    can `enableDelegation` it again), or *status unknown* when the read fails
    or is not a boolean. The label, class and note come from one table in
    `exit-core.mjs`; the test renders rows in jsdom and checks that each
    answer shows its own label and that *unknown* never shows the *not
    revoked* one. Delegation fields are set as text, never parsed as HTML. A
    pasted salt must be a string. The `disableDelegation` calldata the page
    shows is decoded in the test: its selector is `0x49934047` and the decoded
    delegation hashes to the same value. Before this change the page labelled
    every delegation its scan found "redeemed" without reading its status.
  - **Child delegations.** In the manager's verified source (Sourcify, Base
    Sepolia) `RedeemedDelegation` is emitted for every link of a chain with
    the root's delegator, and `disableDelegation` is `onlyDeleGator` of the
    delegation's own delegator. A scan by account therefore also finds the
    agent's settlement, task and sub-budget delegations, which the owner's
    account cannot disable. The page tells a child from a budget by its
    authority (a budget's is the root authority; the contract requires a
    child's to be the hash of the delegation it was issued under), lists
    budgets first and shows each delegator. It marks a child "issued by your
    agent under one of your budgets — revoke that budget", gives it a note that
    claims no authority of its own, and offers no calldata for it; redemption
    checks `disabledDelegations` on every link, so revoking the budget ends
    the child. A budget whose delegator is not the entered account stays a
    budget and is marked "not this account's budget". The page no longer
    fills the account field with the connected wallet, which is a signer of
    the smart account, not the account.
  - **Discovery.** On 2026-10-24 `sepolia.base.org` limited `eth_getLogs`
    to a 200-block range and `mainnet.base.org` answered "request limit
    reached", so a scan from block 0 to the head does not complete on either.
    The page scans newest first, back to the manager's first block (found
    with `eth_getCode`), in chunks narrowed to the range the RPC names. It
    stops after 300 queries and says how far back it got and that older
    budgets were not searched, refuses a from-block after the latest block,
    and accepts another RPC, a later from-block, or a pasted delegation.
  - **No third-party script.** ethers 6.16.0 is vendored as
    `packages/frontend/public/exit/vendor/ethers-6.16.0.min.js`: the npm
    `ethers.min.js` byte for byte below a notice carrying its MIT licence.
    `index.html` and `exit-core.mjs` import it by relative path instead of
    from `esm.sh`. The test pins the body's sha256 and refuses, in both files,
    a static, side-effect or dynamic import or a `<script src>` from an
    `http(s)` or protocol-relative URL; positive controls show the pattern
    matches each form.
  - **Docs.** `docs/exit/README.md` lists both chains, describes the status
    read, the chain check, child delegations and the discovery limits, and
    states that a passkey is bound to the site it was created on
    (`getDefaultRpId` in `packages/frontend/src/lib/passkey.ts` uses the
    page's hostname), so an owner whose only signer is a passkey can sign the
    revoke only through Haven's site; a wallet signer removes that dependency.
    Its headline, the §2b backstop and §3 now carry that condition ("with a
    wallet signer on the account"), as do the two backstop sentences on the
    page. It and `docs/product/account-recovery.md` name the wallet button as
    it reads, **Or add a wallet**. It no longer says the dashboard shows each
    budget's hash: the dashboard uses the hash only as a key, and the page
    computes it from the delegation. `docs/regulatory/casp-risk-guardrails.md`
    (the #832 DEMONSTRABLE sentence), `docs/operations/mainnet-canary.md` and
    `docs/product/account-recovery.md` state the same boundary. The
    guardrails sentence keeps the 2026-07-11 live verification scoped to Base
    Sepolia; this change adds no live verification of the exit path on Base
    mainnet. Other copy that states the exit without the wallet condition
    (in-app and marketing text, the root `README.md`, a preferred-pattern line
    in the guardrails doc) is unchanged here and left to an owner decision.
