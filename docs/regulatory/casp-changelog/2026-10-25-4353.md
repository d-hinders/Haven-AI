- **#4353 — an ended budget gets its own "Budget ended" attention signal** —
  a display-only read on `GET /dashboard/overview`; nothing moves money and
  there is no migration.
  - **Changed:** the per-agent refusal `budget` bucket now counts
    `delegation_budget_exceeded` only; `delegation_expired` (#4352) gets its
    own `expired` bucket (both windows) and a `d7`-only `lastExpiredAt`, from
    the same single refusal scan
    (`REFUSAL_BUCKETS_BY_AGENT_SQL`, `infra/repositories/dashboard.ts`). The
    user-level `budgetStops` is unchanged: it stays the COMBINED budget +
    expired figure. Each overview agent also gains `budgetEndedAt` (ISO or
    `null`): the latest `expires_at` among the agent's `active` delegation
    rows, on its own account's chain, whose window has closed — the rows
    #3802's live read filters out. It is one grouped query for all agents
    (`LATEST_ENDED_BUDGET_BY_AGENT_SQL`), with a second `<= now` check in the
    route so a live row is never reported as ended; a revoked row never
    counts.
  - **Perimeter:** read-only. No selection, signing, funding, settlement,
    key, delegation, enforcer or budget behaviour changes; the new field
    names no authority and grants none (the on-chain TimestampEnforcer still
    reverts an expired redemption), the agent gains no capability and Haven
    no custody. The schema change is additive (`budgetEndedAt`, `expired`,
    `lastExpiredAt`); the one reinterpreted value is `refusals.budget`,
    which no longer includes expired refusals — the dashboard, the only
    consumer, ships the matching change in the same release. Pinned by
    `dashboard-overview.db.test.ts` (real DB: the bucket split, the
    latest-ended-wins / revoked / live / other-chain cells) and
    `dashboard-aggregates.characterization.test.ts` (wire shape, grouped
    read, `budgetStops` combined).
