- **#4378** — `payment_intents` gains a failure time, so a late
  reconcile-to-failed re-arms the unattributed "A payment failed" item
  (follow-up to #4324/PR #4370, which disclosed this exact limitation).
  What changed on the perimeter:
  - **Migration `120_payment_intents_failed_at`**
    (`packages/backend/src/db/migrations/120_payment_intents_failed_at.ts`,
    registered in `migrations/index.ts`): `failed_at TIMESTAMPTZ NULL` on
    `payment_intents`. Metadata-only `ADD COLUMN` (Postgres 11+), no
    backfill — existing `failed` rows keep the #4370 fallback. `down()`
    drops the column; the pre-120 read path is the code this PR reverts.
  - **`packages/backend/src/infra/repositories/payment-intents.ts`**, the
    three failure writers stamp `failed_at = NOW()` in the same `UPDATE`
    that flips the status: `FAIL_SUBMITTED_INTENT_SQL` (~:638),
    `RECONCILE_OUTCOME_FAILED_SQL` (~:749) and `FAIL_MACHINE_INTENT_SQL`
    (~:833). The CAS guards are unchanged — a guard miss still writes
    nothing, stamp included. `FAIL_MACHINE_INTENT_SQL` has no caller since
    #1987 (the constant is kept for #1990's retirement unit); it is stamped
    so a revival cannot reintroduce an unstamped failure writer.
  - **`packages/backend/src/infra/repositories/dashboard.ts`**:
    `FAILED_INTENTS_7D_SQL`'s `lastFailedIntentAt` becomes
    `MAX(COALESCE(pi.failed_at, GREATEST(pi.created_at, pi.signed_at,
    pi.submitted_at)))` — the true failure time when stamped, the #4370
    fallback when not.
  - **Tests on the perimeter**:
    `db/migrations/__tests__/120_payment_intents_failed_at.test.ts` (new),
    `infra/repositories/__tests__/payment-intents.test.ts` (stamp + CAS-miss
    cells for the submitted and machine writers),
    `infra/repositories/__tests__/dashboard-overview.db.test.ts` (reconcile
    after acknowledgement re-arms; stamped row wins over steps; unstamped
    row keeps the fallback) and
    `modules/payments/__tests__/submission-outcome-reconciliation.test.ts`
    (the reconcile writer's stamp; the confirm arm writes none).
  Off the perimeter, in the same PR: `openapi/spec.ts`'s
  `lastFailedIntentAt` description and the regenerated
  `core/api-types.ts`, plus the dashboard docs
  (`docs/product/screen-recipes.md`) and the
  `delegation-rail-security-model.md` note. No new authority, custody,
  spend or signing surface: `failed_at` is write-only bookkeeping read by
  the dashboard aggregate alone, nothing on the payment path gates on it,
  and the writers' WHERE clauses are byte-identical to before. A
  characterization cell pins that the CAS misses never stamp.
