- **#4394** — the money-path perimeter now names the two catalog files that
  write `merchant_catalog.pay_to`. This PR changes the perimeter's own control
  surface and nothing else: no runtime behaviour, no wire field, no migration,
  no refusal, no key material.
  What changed:
  - **Two files join `controlGlobs`.** `packages/backend/src/modules/catalog/merchant-catalog.ts`
    (the hourly refresh's `persistVerified`, the UPDATE at `:621-645`, which
    sets `pay_to = $7` and `asset_transfer_methods = COALESCE($6, …)`) and
    `packages/backend/src/modules/catalog/catalog-discovery.ts` (the Bazaar
    ingest INSERT at `:326-345`, which writes `pay_to` from `probe.payTo` —
    the same probe's value the refresh records, #3331). Both write the value
    the server fills a merchant-locked budget's `recipient_address` from
    (`routes/agent-delegations.ts:578`), and neither matched any glob.
  - **The same two paths join `.github/labeler.yml` and
    `.agents/skills/ship-next/references/money-path-perimeter.md`**, which
    `scripts/ci/money-path.test.mjs` holds equal to the JSON in both
    directions (#1030, #4177). Editing one copy without the others fails CI.
  - **A dated `$comment` line** in `.github/money-path-globs.json` records the
    decision, cites #3331, #4348 and #4394, names both files with the outcome
    for each, and names `routes/merchants.ts` (`merchantPinStatus`, `:80-81`)
    as considered and excluded: it reads the funding target to report a pin as
    `current`, `stale`, `unverified` or `not_erc7710`, and it authorizes
    nothing.
  - **A named test** in `scripts/ci/money-path.test.mjs` asserts that each of
    the two files is matched by a `controlGlobs` entry and by no `globs`
    entry, and carries an executed mutation cell: the same predicate is run
    against a copy of `controlGlobs` with that file's glob removed, and it
    must go red. Dropping either glob, or moving it to `globs`, fails the test
    by name.
  Why `controlGlobs` and not `globs` (owner decision 2026-10-26): a change to
  either file is money-path and owes this analysis and the CASP shard, but it
  must not count toward `qa-freshness`. The refresh's output is exercised in
  qa-dev by the `merchant-locked-budget` scenario, but discovery has no qa-dev
  scenario at all, so the runtime claim is weak for one of the two and the pair
  is one decision; and the churn is 13 and 10 first-parent commits in 90 days,
  so a runtime entry would hold promotion on a real-payment QA run for a
  catalog metadata write.
  Authority and custody argument:
  - **Nothing reads `pay_to` as payment authority.** The owner still signs the
    delegation, and the enforcer on `transfer(to)` is the authority (migration
    `101_merchant_pay_to.ts`). The dashboard only reads the same value
    (`frontend/src/lib/marketplace.ts:293`).
  - **A wrong `pay_to` strands a pinned budget rather than misdirecting
    money.** The challenge then pays a different address and the pinned
    transfer reverts; a later payTo rotation never re-points a signed grant,
    and the merchant page reports the budget `stale`.
  - **The two refusals that stop a wrong `pay_to` widening authority are
    already on the perimeter**: the own-address refusal
    (`routes/agent-delegations.ts:575`) and the `shared` status
    (`infra/repositories/merchants.ts:483-490`). The value's own derivation is
    covered too — `collectPayTo` sits in `merchant-catalog.ts`, and
    `resolveFundingTarget` (`infra/repositories/merchants.ts:441-497`) is on
    the runtime list through `infra/repositories/**`.
  - **The perimeter widens, deliberately.** #4389 assumed `modules/catalog/**`
    was on the list and it was not, and PR #4393 — which changes which
    `accepts[]` option `pay_to` comes from — classified 0 of 12 files at its
    head `ea8b8210`. The miss had already happened: #4348 changed both write
    paths and merged with `area:backend,area:docs` only. Both files were
    already in `casp-risk-guardrails.md` `covers:` (`:52-53`), so the coupling
    gate already asked a catalog change for a shard; the label and the
    perimeter analysis were the missing halves.
