- **#4458** — the two x402 authorize legs now answer an expired-only budget
  with the typed `delegation_expired` 403 body, and the hosted MCP branches on
  it. This PR changes the SHAPE of a refusal and the client's reading of it;
  the refusal decision itself is untouched.
  What changed:
  - **The body, not the decision.** `buildExpiredBudgetBody`
    (`packages/backend/src/modules/budget-scope/refusal-body.ts`) gains an
    `x402` flavor mirroring the over-budget `X402PeriodExceededInput`, and both
    expired sites in `packages/backend/src/modules/x402/delegation-authorize.ts`
    route through it. The 403 now carries `error_code: "delegation_expired"`,
    `phase: "insufficient_funds"`, `next_action:
    "fund_account_or_raise_allowance"`, `budget_ended_at` (ISO 8601),
    `remaining`/`remaining_atomic` `"0"`, `amount`/`amount_atomic`,
    `shortfall`/`shortfall_atomic`, `rail`, `network`, `resource_url` and
    `merchant_address`. Before, the wire carried a one-line `{ error }` while
    the ledger row already carried the typed detail — the agent was told the
    reason in prose only.
  - **The funding leg names the merchant, never the funding target.** On the
    EIP-3009 leg `merchant_address` is `merchantPayTo.toLowerCase()` — the same
    address that leg's ledger row and over-budget body already use — and never
    `payTo`, which there is the agent's own funding EOA. Recording the funding
    address as the merchant is exactly the account confusion the migration 086
    allowlist exists to prevent; the test asserts both the value and that it is
    not the funding EOA.
  - **The decision is unchanged.** Same 403, one `payment_refusals` row per
    refusal (`reason: "delegation_expired"`, `source: "x402_authorize"`,
    `detail` with `budget_ended_at`), nothing created, nothing signed, no
    delegate account deployed. The two no-delegation 403s beside the expired
    ones stay prose-only and byte-identical, by owner decision (2026-10-26) —
    their bodies and their `no_delegation_for_target` ledger detail are pinned
    by content, not by line.
  - **The hosted readers stop instead of failing open.** Three readers decided
    a budget refusal only on `error_code === "delegation_budget_exceeded"` and
    otherwise degraded: the quote pre-check
    (`packages/mcp-server/src/tools/support/quote-response.ts`), the catalog
    prepare preflight (`packages/mcp-server/src/tools/catalog-purchase.ts`) and
    the shared normaliser (`packages/mcp-server/src/tools/support/errors.ts`).
    All three now recognise a 403 with `delegation_expired` (keyed on the
    status too): the quote reports `budget_check.sufficient: false` (so
    `safe_to_continue` is false) with a new additive `QUOTE_BUDGET_ENDED`
    warning naming the end date and the owner's next step; the catalog
    preflight decides `sufficient: false` and refuses with its own
    `DELEGATION_EXPIRED` code before any funding intent; the normaliser maps
    the refusal to `DELEGATION_EXPIRED` with the owner-sets-a-new-budget
    reason. The over-budget wording ("grant or raise the budget", "wait for the
    period to reset") is never reused: an ended budget has no period left to
    wait for.
  Authority and custody argument:
  - **Authority narrows, never widens.** The quote path previously failed OPEN
    on an ended budget — it reported the check as unavailable and let the agent
    proceed to authorize, where the backend refused. It now stops at quote
    time. No actor gains a capability: the same 403 is decided by the same
    server-side read, and the on-chain caveat enforcers remain the actual gate
    at redemption.
  - **No custody moves.** Nothing is created, signed, funded or deployed on
    either path; the refusal is pre-funding and pre-prepare. Haven still holds
    no key, and the typed body carries no signing material.
  - **No new reader of owner data.** `budget_ended_at` is the expiry of a row
    the refusal already read and already booked into the ledger detail; the
    hosted surfaces relay it, they do not query anything new.
  - **Additive on the published package.** `AgentPaymentWarningCode` gains one
    member (`QUOTE_BUDGET_ENDED`); a client switching over the enum keeps
    compiling, an older backend never emits it, and an older hosted server
    against a new backend ignores the extra body fields and keeps its previous
    behaviour. No migration: the 119 allowlist already carries
    `budget_ended_at`.
  Mutation-tested:
  - `packages/backend/src/routes/__tests__/x402-delegation.test.ts` — both
    #4352 tests now assert the RESPONSE BODY (`error_code`, `phase`,
    `next_action`, `budget_ended_at`, `remaining_atomic`, `amount_atomic`,
    `rail`, `network`, `resource_url`, `merchant_address`), with the 3009 leg
    additionally asserting `merchant_address === MERCHANT.toLowerCase()` and
    not the funding EOA; the existing 403 / prose / one-ledger-row /
    nothing-created assertions still hold.
  - `packages/backend/src/modules/budget-scope/__tests__/builder-literal-ratchet.test.ts`
    — the `this budget ended on` literal joins the allowlist (one home, the
    module) and both x402 legs are pinned as builder callers.
  - Prove-red: flipping `refusal-body.ts`'s body `error_code`
    `'delegation_expired'` → `'delegation_budget_exceeded'` reddens BOTH
    `budget-precheck.test.ts` and `x402-delegation.test.ts` (the scan's M6/M7
    probes: 3 of 45 and 0 of 119 before this PR).
  - `packages/backend/src/openapi/spec.test.ts` — the `/x402/authorize` 403
    description names `delegation_expired` and `budget_ended_at` (the
    response-shape round trip cannot be the instrument: `errorResponse` is
    `additionalProperties: true`).
  - `packages/mcp-server/src/tools/plain-http-x402.test.ts` — a 403
    `delegation_expired` through the quote pre-check yields
    `safe_to_continue: false`, `budget_check.sufficient: false`, the
    `QUOTE_BUDGET_ENDED` warning naming the end date and the owner step, and
    NOT `QUOTE_EXCEEDS_REMAINING_BUDGET`.
  - `packages/mcp-server/src/tools/catalog-purchase.test.ts` — the same 403
    through the prepare preflight refuses with `DELEGATION_EXPIRED` and the
    same words, and no `POST /x402` is made (proving `sufficient: false`, not
    the `null` degrade).
  - `packages/mcp-server/src/next-step-refusal.test.ts` — the normaliser
    answers `DELEGATION_EXPIRED` with a reason that says the owner sets a new
    budget and never "wait for the period to reset"; a non-403 with the same
    code stays the generic `API_ERROR`.
  Perimeter unchanged: the refusal decision, the ledger row, the custody model
  and the on-chain gate are all as they were; the wire shape of one refusal and
  the client's reading of it change, and the quote path stops where it used to
  fail open.
