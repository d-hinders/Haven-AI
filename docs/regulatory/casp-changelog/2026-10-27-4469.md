- **#4469** — the SDK receipt mapper now reads the six fields the receipts
  wire already carries, so `haven_list_receipts` stops dropping the delivery
  verdict, the settlement scheme and the budget hash. Read-only and additive:
  nothing signs, moves or authorises differently.
  What changed:
  - **The mapper reads six keys it used to drop.**
    `mapPaymentReceipt` (`packages/sdk/src/payment-mappers.ts`) gains a
    block-form tail for `settlement_scheme`, `budget_delegation_hash`,
    `delivery_quality`, `delivery_note`, `delivery_reported_at` and
    `delivery_reference`. The backend has emitted all six since #3770/#3778
    (`mapEvidence`, `packages/backend/src/modules/mpp/evidence.ts`), and
    `LIST_EVIDENCE_RECEIPTS_SQL` supplies them, but the mapper named none of
    them — so the hosted tool
    (`packages/mcp-server/src/tools/state-direct-recovery.ts`) and the local
    stdio tool (`packages/mcp/src/tools.ts`) both returned rows without them.
  - **Absent stays absent.** Each field is set only when the raw key is
    present (`if ('delivery_quality' in raw)`), so a row from an older backend
    maps without the field rather than with a fabricated `null`. A key the
    backend states as `null` maps to `null` — "not reported" is a value, not
    an absence.
  - **The domains are stated, not narrowed.** `settlement_scheme` on receipts
    is raw text with no enum on the served schema
    (`packages/backend/src/openapi/spec.ts`), so the SDK types it
    `string | null`: an unknown value is still the backend's record, and
    narrowing it to `null` would erase it. `budgetDelegationHash` is
    `string | null` on receipts (the backend sends `?? null`), unlike the
    status read's `string`.
  - **The vocabulary map moves with the types.**
    `scripts/ci/vocabulary-map.json` gains two converged pairs
    (`settlementScheme`, `deliveryReference` — both surfaces now report the
    same concept under the same name) and four `singleSurface.receipt` entries
    (`budgetDelegationHash`, `deliveryQuality`, `deliveryNote`,
    `deliveryReportedAt`). `npm run lint:vocabulary` was red on the mapper
    change alone and is green with the map.
  - **The texts stop claiming an owner surface reads the verdict.** The
    `haven_report_delivery_quality` description and both byte-pinned copies of
    the skill text said the receipt and the dashboard carry the verdict "so
    the owner does not read the receipt as a success". No file under
    `packages/frontend/src` reads `delivery_quality`/`deliveryQuality` other
    than that skill text, so the claim was false. Both now say the receipt
    carries it and a junk delivery does not read as a success — which is what
    ships. The description also drops "and the dashboard" (18 bytes freed
    against the 31,812-byte MCP description cap; the new text measures 794,
    down from 817).
  Authority and custody argument:
  - **No authority change.** The six fields are evidence about a payment that
    already happened. `delivery_quality`/`delivery_note`/`delivery_reported_at`
    are the paying agent's own verdict (#3770) and gate nothing;
    `delivery_reference` is the non-secret pointer (#3778) whose
    credential-shaped values are refused at the handler, semantic and
    recognizer layers; `settlement_scheme` and `budget_delegation_hash` are
    recorded facts about which branch moved the money and which budget metered
    it.
  - **No custody moves.** Nothing is created, signed, funded or deployed. The
    change is a read mapper plus type declarations; Haven still holds no key
    and no new surface carries a secret.
  - **No new reader of owner data.** Every field was already on the wire the
    SDK reads; the mapper simply stopped discarding it. The dashboard display
    of the verdict remains out of scope — this PR only stops the texts from
    claiming it exists.
  - **Additive on the published package.** All six fields are optional on
    `HavenPaymentReceipt`, a type that is only returned
    (`listReceipts(): Promise<HavenPaymentReceipt[]>`), so existing consumers
    keep compiling and an older backend simply omits them. No migration.
  Mutation-tested:
  - `packages/sdk/src/payment-mappers.test.ts` — a row carrying all six maps
    each value (with `amount` as the control, so a mapper returning `{}`
    cannot pass); a row without the keys maps with all six ABSENT; a row with
    the keys stated as `null` maps them as `null`.
  - `packages/sdk/src/agent-info.test.ts` — `compact: true` keeps all six with
    their values while still dropping the three payload echoes. The assertion
    is on values, not `toHaveProperty` on a null fixture.
  - `packages/mcp-server/src/tools/state-direct-recovery.test.ts` — the hosted
    `haven_list_receipts` drives the whole chain against a stubbed backend page
    whose row carries a reported verdict, and asserts each value reaches the
    agent.
  - `packages/sdk/src/skill-content.test.ts` — the new sentence is pinned
    whole, and the retired "the owner does not read a junk delivery as a
    success" clause is asserted absent.
  - `packages/mcp-server/src/description-size.test.ts` — the 29 descriptions
    stay under `MAX_TOTAL_BYTES` (31,812) and the mean pin.
  Perimeter unchanged: no route signature payload, delegation, enforcer,
  budget, key custody or spend-authority change. The receipts wire is
  untouched; only the SDK's reading of it, its types, the vocabulary map and
  the two texts change.
