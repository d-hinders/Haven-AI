- **#4477** — the agent Settings tab's tax-declaration row is now a shared
  `SettingsRow`, and the long explanation moved behind a closed-by-default
  "What gets sent" disclosure. This PR is a layout change to one settings row:
  no runtime behaviour, no wire field, no migration, no refusal, no key
  material, and no change to what leaves the account. The shard is written
  voluntarily — the gate does not owe it, because
  `docs/regulatory/casp-risk-guardrails.md`'s `covers:` list does not name
  `TaxDeclarationToggle.tsx`, `AgentSettingsTab.tsx` or `AgentPassportCard.tsx`
  — so a later reader does not have to rebuild the argument that moving a
  regulated sentence behind a fold did not widen the claim.
  What changed:
  - **The regulated statement moved from always-visible to behind a fold.**
    "The default setup, a hosted server with a separate signer, sends none."
    used to sit in the checkbox's always-visible helper paragraph. It now sits
    in the disclosure's prose, unchanged in substance, alongside what the
    merchant receives, that nothing is submitted to an authority, and that the
    owner can switch it off at any time.
  - **The visible line keeps the client condition, so the claim does not
    widen.** The row's one-line description reads "Sends your VIES-checked VAT
    number with payments made through a client that holds its own key." A line
    that dropped the client condition ("…travel with this agent's payments")
    would overclaim in exactly the direction #4416 fixed, because the "default
    setup sends none" sentence would no longer be visible beside it. The four
    copy guards #4416 pinned — never "verified", never "every payment", never
    "merchants that ask", never "settle by EIP-3009" — now hold on the
    description itself, with a test aimed at that line rather than at the
    disclosure's text.
  - **The disabled reason stays visible and outside the fold.** #4435's
    one-line reason ("This agent pays through the default setup, a hosted
    server with a separate signer, so no declaration is sent.") renders in the
    row's full-width slot, outside the disclosure and never as the checkbox's
    helper text. It tells the owner the control they can see has no effect, so
    it must be readable without opening anything; a disabled checkbox is not
    focusable, so a reason inside its `<label>` is never announced.
  - **The control is unchanged.** The same `Checkbox` writes the same
    `PUT /agents/:id/tax-declaration` body. It gains a short visible label
    ("Allow") and keeps the full accessible name through `aria-label`, and it
    points at the one-line description through `aria-describedby` because
    moving the explanation out of `helperText` took it out of the input's
    accessible description.
  Authority and custody argument:
  - **No authority moves.** The write path, its gates (owner session, feature
    flag, saved VAT number, VIES `valid`) and the disabled-state rule are
    untouched. The row's shape decides where text renders, not what the
    control authorizes or refuses.
  - **No custody moves.** The declaration is still built at read time from the
    owner's company-details row and signed by the delegate key in the client
    that holds it (`packages/sdk/src/tax-declaration.ts`). Haven still holds no
    key, and the disclosure renders prose — it does not gate, sign or send
    anything.
  - **What leaves the account is unchanged.** The merchant still receives the
    country, the VAT number, the taxable-person status and the signed link to
    the agent's wallet address, and only when the agent pays through a client
    that holds its own signing key and the merchant accepts the declaration.
    Nothing is submitted to an authority. The disclosure states the same set,
    in the same words, one click away.
  Mutation-tested:
  - `packages/frontend/src/components/agent-panel/__tests__/TaxDeclarationToggle.test.tsx`
    — the whole-text pin and the four copy guards still hold against the
    disclosure's text; a new test holds the client condition and the four
    guards on the one-line description; a new test asserts the disabled reason
    is not inside the `<details>` and that the disclosure is closed by default;
    a new test asserts the input's accessible name and its `aria-describedby`
    target; the #3697 wrapper test is inverted — the row is a direct child of
    the section's `divide-y` list and carries no `border-t` of its own.
  - `packages/frontend/src/app/(authenticated)/agents/[agentId]/__tests__/AgentDetailClient.test.tsx`
    — the Settings tab renders two `SettingsSection`s, the six row testids
    survive, the tax row's absence leaves no orphan row, and the section
    heading is asserted by role rather than by the card's text.
  Perimeter unchanged: a settings-row layout change and a disclosure on one
  control; no runtime behaviour, wire field, migration, custody, signing,
  settlement, funding or refusal change.
