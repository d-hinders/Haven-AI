  **What the release carries into published packages, by effect on authority:**
  - **#4534 (#4544): the purchase correlation key.** `reportX402MerchantOutcome` gains two OPTIONAL inputs — `purchaseGroupId` (≤ 128 chars, the merchant's own invoice/order id or a caller-chosen group key) and `merchantResponse` (the merchant's paid response body, read by a small explicit per-merchant map on the backend and never stored; only the derived id is). The receipt gains `purchaseGroupId` and `parentPaymentId`. Both are descriptive metadata on a document the feed already produces: they authorize nothing, produce or consume no signature, and no spend decision reads their value. A caller that supplies neither sends a byte-identical body to before. Recorded in `delegation-rail-security-model.md` and `mcp-runtime-compatibility.md` where it merged, and re-read at this release.
  - **#4530 (#4536): `PaymentStatusResult.merchantSettlementTxHash`.** A read-only status field naming the settlement transaction Haven recorded, under the same presence rule as `merchantSettlementRecorded`: present only when recorded, absent otherwise, never `null` and never the merchant's unverified echo. Additive and optional on a type that is only returned. A read.
  - **#4550 (#4554): canonical low-s EIP-3009 bridge signatures, pinned.** Adds `packages/sdk/src/test-support/low-s.ts` — assertions on the wire bytes of a 65-byte EOA signature, because the malleable twin `(r, n − s, v ^ 1)` recovers to the same address and a recovery-only test cannot catch it. Test fixtures only: nothing the SDK or signer runs imports the entry, and no signing path changes. The same PR moves `@x402/core` from `2.17.0` to `2.29.0` in the **devDependencies** of `sdk`, `signer` and `backend` — a build-time pin, not a runtime dependency. Its own shard is `2026-10-30-4550.md`.
