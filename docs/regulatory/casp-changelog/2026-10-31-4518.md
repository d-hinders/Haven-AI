- **#4518** — an accounting connector for Igdrasil, slice 2 of the Igdrasil
  epic #2875. The descriptor stays `coming_soon`, so no user can connect it
  until the live check (#4519) flips it.
  What changed:
  - `packages/backend/src/modules/accounting/igdrasil.ts` (new): the app's
    endpoints, scope (`companies:read vouchers:write`) and OAuth2 config with
    PKCE on (`pkce: 'S256'`, #4517) and a revoke URL.
  - `igdrasil-client.ts` (new): two calls only —
    `GET /api/v1/external/companies` and
    `POST /api/v1/external/companies/{id}/uploads` (multipart, one `file`
    part). A 2xx counts as delivered only when the echoed `sha256` equals
    the local SHA-256 of the bytes sent.
  - `igdrasil-connector.ts` (new): connect accepts a grant that reaches
    exactly one company (several → `MultiCompanyGrantError`, the fresh grant
    revoked); the push uploads the receipt underlag, and the merchant's own
    invoice as a second document when captured; verify answers from Haven's
    own sync row; disconnect revokes the refresh token.
  - `provider.ts`: `MultiCompanyGrantError`. `registry.ts`: the Igdrasil
    descriptor gains capabilities and `requiredScopes`, availability
    unchanged. `connections.ts`: an Igdrasil branch for the OAuth2 config.
    `routes/accounting-connections.ts`: the callback maps
    `MultiCompanyGrantError` to `reason=multi_company`. `config.ts`:
    `IGDRASIL_CLIENT_ID`, `IGDRASIL_CLIENT_SECRET`, `IGDRASIL_REDIRECT_URI`.
    `src/index.ts`: registers the connector only when all three are set.
  Authority and custody argument: the connector reads the user's company
  list and files a document into the user's own ledger inbox under a grant
  the user gave; it never touches a Haven key, delegate key, delegation,
  allowance, relayer or signer, constructs no transaction and adds no write
  path to any money table. The upload is non-asserting: it carries the file
  only — no account, VAT, voucher or booking — and Igdrasil stores it without
  proposing a voucher. `igdrasil-outbound-allowlist.test.ts` pins every
  request to those two calls plus the token and revoke endpoints, so a
  booking or delete endpoint cannot be added silently. Provider tokens are
  stored through the existing encrypted path (`HAVEN_SECRETS_KEY`,
  `infra/secrets.ts` remains its only reader). The three new variables
  configure a third-party app registration and grant no authority over
  funds. No migration, no schema change, no wire field on a payment path.
  Perimeter unchanged.
