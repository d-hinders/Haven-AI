- **#4567** — display only: one status vocabulary on `StatusBadge`. The
  `/accounting` page's row chip and the per-payment accounting badge now render
  the same `accountingStatusPresentation` function, so one state has one label
  and one tone on both surfaces. What changed:
  - `packages/frontend/src/app/(authenticated)/accounting/page.tsx`: the page's
    own `STATUS` class map and hand-rolled `StatusChip` (Synced / Pending /
    Failed / Skipped) are deleted; the row renders `StatusBadge` from
    `accountingStatusPresentation`, which the badge already used. The page
    passes `liveSyncReady` and the provider descriptor list, so a pushed row on
    a deployment whose live connector is not configured reads **Tracked**
    instead of claiming delivery (SR:1583). This is the one substantive change
    on a money-adjacent surface, and it narrows a claim rather than widening
    one: the row no longer says a payment reached a provider when nothing left
    Haven.
  - `packages/frontend/src/components/accounting/AccountingBadge.tsx`: the
    label/tone decision is extracted into `accountingStatusPresentation`
    (pushed → In <Provider> / Evidence archived / Tracked; pending → Sending…;
    failed or skipped → Not sent). The ledger row and the detail drawer pass no
    `liveSyncReady` — they read only the row's `accounting` object and have no
    feed status to consult — so their pushed label is unchanged.
  - `packages/frontend/src/lib/i18n/messages/en.ts`: `feeding` → `sending`
    ("Sending…"), `notFed` → `notSent` ("Not sent"), plus `tracked`
    ("Tracked"); the backfill dialog's busy label follows the same verb.
  - `packages/frontend/src/lib/payment-status.ts`: `AGENT_STATUS`'s
    `pending_approval` tone moves `warning` → `brand` (owner decision
    2026-10-30). `AgentRow`'s `agentBadge` and `lib/dashboard-attention.ts`
    already said brand; the map was the drift.
  - `packages/frontend/src/components/transactions/TransactionDetailPanel.tsx`:
    the panel's fallback label for a plain settled payment is "Sent" instead of
    "Executed". The #3810 no-badge rule stays a list-row rule.
  - Six ad-hoc tinted pills become `StatusBadge` (`marketplace/OfferRow.tsx`,
    `marketplace/OffersTable.tsx`, `EditBudgetModal.tsx`'s Raise/Lower pair,
    `DashboardActionPickerModal.tsx`'s Default tag).
  - `packages/frontend/src/lib/__tests__/status-vocabulary.test.ts` walks
    `docs/product/design-system.md` § StatusBadge and the code's maps together,
    so a label or tone that drifts from the published table goes red.
  Authority and custody argument: nothing signs, moves, authorises, refuses or
  settles differently. No route, request schema, refusal path, budget cap,
  allowance, delegation, settlement decision or stored value is touched — the
  diff is labels, tones and the components that paint them. The accounting
  feed's backend (`routes/accounting-feed.ts`, `modules/accounting/**`) is
  untouched; the page reads the same `GET /accounting/feed/status` answer it
  read before. The one claim that changes direction is the preview row's: it
  stops asserting external delivery, which is the honest direction for a
  surface that reports where money went.
  Mutation-tested: reverting `accountingStatusPresentation`'s `liveSyncReady`
  branch makes the page test "pushed with the connector not live → Tracked"
  fail naming `In Fortnox`; reverting `AGENT_STATUS.pending_approval` to
  `warning` fails both `payment-status.test.ts` and the vocabulary drift test.
  Perimeter unchanged.
