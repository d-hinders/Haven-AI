- **#4612** — the docs coupling gate stops demanding a hand-written note for a
  diff that changes nothing but a version string, and gains a git-recorded way to
  say "re-read, unchanged". What changed:
  - `scripts/docs/coupling-gate.mjs`: two satisfaction paths join the two that
    existed (doc edited; new file matching its `satisfied-by:` glob).
    **Version-literal partition** — a changed file whose ENTIRE diff is
    release-version constants is removed from the changed set before `covers:`
    matching, reusing `isVersionOnlyDiff`/`partitionVersionOnly` from
    `scripts/ci/qa-freshness.mjs` (#2164) over the constant set
    `scripts/release-version-constants.mjs` owns. **Commit trailer** —
    `Re-verified-unchanged: <doc path> @ <sha>` on any commit in the PR
    satisfies that doc, provided the doc is governed, declares no
    `satisfied-by:`, and the SHA is an ancestor of the PR head. Both are printed
    in the gate's comment; neither is silent.
  - `scripts/release-version-constants.mjs`: `MCP_VERSION` is registered as a
    release-owned constant (`DEDICATED_VERSION_CONSTANT_FILES`, rolled into
    `ALL_VERSION_CONSTANT_FILES`). It is written by the bump's dedicated writer
    rather than the generic loop, so it could not join
    `SOURCE_VERSION_CONSTANT_FILES` — but without it the partition would miss
    `packages/mcp/src/server.ts` and a release would still implicate the
    package-dev-channel doc.
  - `scripts/ci/qa-freshness.mjs`: `isVersionOnlyDiff` and
    `partitionVersionOnly` take an optional `constants` argument. The default is
    the same two constants this gate has always used, so its decisions are
    unchanged.
  - Instructions rewritten to match: `scripts/release-bump.mjs`'s printed
    next-steps block, `scripts/README.md` § *The contract-doc gate*,
    `.agents/skills/release/SKILL.md`, `.agents/skills/ship-next/SKILL.md`,
    `.agents/skills/haven-agent-workflow/references/doc-reviewer.md`, and
    `docs/contributing/docs-quality-system.md`. The release guidance now says a
    bump implicates ONE contract doc that needs action
    (`casp-risk-guardrails.md`, cleared by the shard) instead of five.
  Authority and custody argument: nothing signs, moves, authorises, refuses or
  settles differently. The diff is a documentation gate, its fixtures, and the
  prose that instructs operators; no route, request schema, refusal path, budget
  cap, allowance, delegation, settlement decision or stored value is touched.
  The gate's own trust model is what moves, and it moves in the narrowing
  direction: the partition can only ever REMOVE a file from the changed set when
  every changed line in it is a version literal paired within its hunk, so a
  deletion, a rename, a dependency swap or a move all fail it and the file stays
  behavioural; the trailer can only ever satisfy a doc that declares no
  `satisfied-by:`, so the CASP shard requirement is untouched by construction —
  a PR cannot clear `casp-risk-guardrails.md` or
  `04-x402-payment-sequence.md` with a trailer, and the fixture that adds a
  `*-release.md` shard to a money-path diff still exits 1 on the security model.
  The residual is the one the note already carried: a trailer written without a
  re-read. It is now recorded in git with a SHA a reviewer can check, instead of
  in a doc line nobody can.
  Mutation-tested: removing the partition call from `main()` reds the
  release-bump fixture (exit 0 becomes exit 1, naming the security model);
  removing the `satisfied-by:` exclusion from the trailer path reds the CASP
  fixture (a trailer naming `casp-risk-guardrails.md` would clear it); removing
  the ancestor check reds its fixture (a SHA from a branch the PR does not
  contain would satisfy the gate). Perimeter unchanged.
