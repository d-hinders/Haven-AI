- **#4655 — the CASP signer allow-list now sees the x402 binding key, and the
  binding wallet is constructed in one file** — a test widening plus a boot
  refusal; no signer gains authority and no signed message changes.
  - **The gap.** Invariant 3 of
    `packages/backend/src/__tests__/non-custody.invariants.test.ts` matched only
    `new Wallet(`, so the two production signers built with
    `new ethers.Wallet(` were invisible to the exhaustive allow-list:
    `infra/chain/x402-binding-signer.ts` (signs the x402 expected context and
    derives the published address) and `rails/sweep.ts` (signs the sweep
    authorization binding). Both use `X402_BINDING_PRIVATE_KEY`, which
    `casp-risk-guardrails.md` already lists as a server key role that "does not
    sign the payment or spend funds" — the key was inside the perimeter; the
    test and the documents describing it were not.
  - **Owner decisions (2026-11-04, AntonioSaaranen).** (1) Merge: `rails/sweep.ts`
    stops constructing the binding wallet and gets its sweep signature from
    `infra/chain/x402-binding-signer.ts`, which becomes the one new allow-list
    entry with a file-level message-only assertion. (2) Refuse key reuse at boot.
  - **The scan.** Invariant 3 now matches `new Wallet(`, `new ethers.Wallet(`,
    `new SigningKey(`, `new BaseWallet(` and `Wallet.fromEncryptedJson`. It
    counts files and reads raw text including comments, so a constructor literal
    in a comment of an unlisted file trips it. The allow-list is exactly
    `infra/relayer.ts`, `modules/passport/receipt.ts` and
    `infra/chain/x402-binding-signer.ts`. On the pre-fix tree the widened scan
    goes red naming the binding signer and `rails/sweep.ts`; it goes green only
    with the merge.
  - **Message-only, proven.** The binding signer's new assertion is the receipt's
    regexes plus `.provider`: no `sendTransaction`, no `.connect(`, no
    `getProvider`, no `JsonRpcProvider`, no `.provider`, and it never names
    `RELAYER_PRIVATE_KEY`, `relayerPrivateKeyForChain` or `getRelayer`. The two
    relayer mentions that used to sit in that file (a JSDoc and an error string)
    are reworded to "the relayer key" so the assertion can hold.
  - **Boot refusal.** `infra/binding-key-collision.ts` exports
    `assertBindingKeyNotReused`, which refuses a SET
    `X402_BINDING_PRIVATE_KEY` equal to any relayer key (`RELAYER_PRIVATE_KEY`
    plus every `RELAYER_PRIVATE_KEY_<chainId>`, enumerated by
    `relayerKeyEntriesFromEnv`) or to `PASSPORT_RECEIPT_SIGNING_KEY`. Comparison
    is the shared `sameKey` — the key's VALUE, not its text, so casing and the
    `0x` prefix cannot hide a paste. It moved from `modules/passport/receipt.ts`
    to `infra/key-identity.ts` (and is re-exported from the receipt module) so
    the `infra/` check can share it without a deep cross-module import.
    Unset stays allowed. The error names the variables and never the values.
    `index.ts` calls it immediately after `setReceiptSigningKey`, so the receipt
    check and the binding check run at the same point in boot.
  - **Why the placement.** The check lives outside
    `infra/chain/x402-binding-signer.ts`, following the `relayer-env-keys.ts`
    pattern, because the non-custody invariant pins that the binding signer never
    names a relayer key — the comparison cannot live in the file it constrains.
  - **Authority.** No signer gains a capability: the binding wallet still only
    signs messages, is never connected to a provider, and the signed messages
    (`buildX402ExpectedMessage`, `buildSweepAuthorizationMessage`) and the signer
    address are byte-identical — installed signers pin them via
    `HAVEN_X402_BINDING_SIGNER`. The boot refusal only removes a configuration
    that was already forbidden by the guardrails' "no key above may be reused"
    rule; it grants nothing.
  - **Mutation-tested.** `scripts/ci/prove-red.mjs` cells, all caught at
    `025256d04`: M1 re-adds a binding-wallet construction to `rails/sweep.ts`
    (the widened scan goes red); M2 gives the binding wallet a
    `sendTransaction` surface (the message-only assertion goes red); M3 makes
    the boot refusal accept every collision (both refusal tests go red); M4
    deletes the receipt-key argument from the `index.ts` call (the static pin
    goes red); M5 makes `sameKey` compare text instead of value (the
    casing/`0x` test goes red). Perimeter unchanged.
