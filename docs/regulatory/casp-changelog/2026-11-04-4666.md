- **#4666 — the daily QA balances run warns before a QA budget grant ends** —
  one additive read field and QA-harness logic; no perimeter change.
  - **Read:** the agent-facing allowances read
    (`packages/backend/src/modules/mpp/allowances.ts`) adds `budget_expires_at`
    to each delegation-rail row: the row's own `expires_at` as ISO 8601, or
    `null` when that value is not a representable timestamp. The value was
    already selected for this row. Read-only and derived: no new query, no
    write, and the expiry caveat on the signed delegation is what enforces the
    end date. The computation sits in this handler only, so the dashboard's
    frozen allowances projection does not change.
  - **Consumers:** the SDK rebuilds each allowance row field by field
    (`packages/sdk/src/account-reads.ts`), so an installed SDK drops the new
    field and no SDK contract changes. The only reader in this repository is the
    QA harness; a raw API client sees one additive field.
  - **QA harness:** `packages/qa-agent` reads the field with the QA agent's API
    key and `scripts/ci/qa-balance-issue.mjs` raises a GitHub issue. It runs
    against dev and Base Sepolia only. It takes no signing key, signs nothing, and gains
    no capability beyond the read it already had.
  - **Perimeter:** no selection, signing, funding, settlement, key, delegation,
    enforcer or budget behaviour changes; the agent gains no capability and
    Haven no authority. An end date is not spend authority: knowing it permits
    nothing, and a payment past it is refused by Haven, and reverts if it reaches
    the chain. The field is pinned by `allowances-validity-window.test.ts` (real
    DB) and `machine-payments.test.ts` (the spec, including `null`). Each new
    assertion was mutation-proved with `prove-red`; the cells are in the PR body.
    Perimeter unchanged.
