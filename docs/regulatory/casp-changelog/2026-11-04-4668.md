- **#4668 — `budget_ended_at` is null beside a live budget, as its spec says** —
  one read-only wire value narrowed from a date to `null` in a state the spec
  already described as not ended; no perimeter change.
  - **Read:** the agent-facing allowances read
    (`packages/backend/src/modules/mpp/allowances.ts`) now answers
    `budget_ended_at` only when this chain's `allowances[]` is empty. The
    expired-row query it consults is unchanged and still serves the refusal
    sites; the guard is at the call site, against the chain-scoped `budgets`
    list the response is built from. Before the fix the query ran
    unconditionally, so an ended row left beside a live one — a re-key carry,
    a different pin, a different token — answered a date for an agent that
    could still pay.
  - **Authority:** the change moves no funds and alters no selection, signing,
    funding, settlement, key, delegation, enforcer or budget behaviour. It is
    one read-only wire value, from a date to `null`, in the state the spec
    already describes as not ended. Key presence and type are unchanged, and no
    migration is involved. An end date is not spend authority: knowing it
    permits nothing, and a payment past it is refused by Haven and reverts if
    it reaches the chain. The refusal bodies keep answering the ended row on an
    already-refusing payment, because the shared query was not touched.
  - **Consumers:** the SDK copies the raw value into `budgetEndedAt` with no
    live-row check, so it inherits the corrected value; the MCP servers return
    that SDK summary unfiltered. The agent readiness path already returned null
    when `allowances` had rows, so it is unchanged. The QA balances check loses
    the date when a live pinned row is the only budget — the verdict stays
    `critical`/`noLiveBudget`, which is the honest answer.
  - **Tests:** the characterization commit pinned the old date on one agent
    holding both rows (pinned/open, open/pinned, token A/B, carry/steady,
    ended/dormant); the fix commit flips those five assertions to `null` and
    leaves the cross-chain case answering the date, which is the guard against
    reading `all` instead of `budgets`. The expired-only case still answers the
    row's expiry with `allowances[]` empty, and the `budget-precheck` refusal on
    an expired-only budget still carries `budget_ended_at` — both catch a fix
    made inside the shared query. `prove-red` on the clock re-check in
    `budget-scope/expired-budget.ts` turned `machine-payments.test.ts` red
    before the guard landed; that clause now has a direct test, because the
    guard stops the route test reaching it. Perimeter unchanged.
