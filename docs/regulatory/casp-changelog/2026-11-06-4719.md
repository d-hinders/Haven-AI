- **#4719** — the passport opt-in is offered, and acted on, only where this
  deployment can issue a passport that a merchant can verify. Slice 1 of epic
  #4718; owner decisions 2026-11-06 on the issue.
  What changed:
  - `modules/passport/readiness.ts` adds `isPassportIssuableOnChain` (a
    passport chain whose schema UID is registered here, and the receipt
    verifier on) and `isPassportIssuableForAccount` (the same plus the #2138
    rail allowlist).
  - `routes/auth.ts` adds `passport_issuable` to every session account on
    login and `GET /auth/me`.
  - `POST /agents` (`issue_passport`) and `POST /agent-connection-setups/register`
    ask the account-level question and record no passport row when the answer
    is no. Before, they could record a `pending` row the deployment could never
    anchor, or a row the rail gate then marked `failed`. `FIND_ACCOUNT_INFO_SQL`
    now also reads `account_type` and `execution_rail` for this; the creation
    response does not echo them.
  - `POST /agents/:id/passport` answers 503 while the receipt verifier is off,
    after its idempotent return, so an already-anchored passport still answers 200.
  - The dashboard renders the connect checkbox and the Settings "Issue a
    passport" action only for an explicit `passport_issuable: true`.

  Why the perimeter is unaffected. A passport is governance metadata the
  relayer attests at zero value. This change only narrows when Haven offers or
  records one: it adds refusals and removes none. It moves no funds and signs
  nothing new. No key, delegation, allowance, caveat, budget or payment path
  changes. The two opt-in entry points still run one shared eligibility check
  and still never block, delay or roll back agent creation or registration
  (`casp-risk-guardrails.md` § server key roles).

  Tests:
  - `modules/passport/__tests__/passport-readiness.test.ts`: each leg of the
    predicates.
  - `routes/__tests__/auth-sql.characterization.test.ts`: `/auth/me` true only
    with the chain, the schema UID and the verifier, and false for 8453 with
    every env var set.
  - `routes/__tests__/agents.test.ts`: no row for a non-issuable chain or a
    retired rail. `agent-connection-setups.test.ts`: no row for a
    non-issuable chain, and the setup's account type reaches the predicate.
  - `routes/__tests__/agent-passports.test.ts`: 503 with the verifier off, and
    200 for an already-anchored passport.
  - Frontend tests: the fail-closed gate, the wallet-switch clear and the
    payload guard.

  Perimeter unchanged.
