- **#4723** — Adds a merchant-side Agent Passport verifier to `@haven_ai/sdk`
  (`verifyPassportReceipt`, `checkPassport`) and makes the demo merchant its
  first consumer. The backend's `canonicalize` / `verifyReceipt` now delegate to
  the SDK's single canonicalizer, so there is one copy rather than two that can
  drift. **No new authority, custody or route.** The check is advisory and runs
  AFTER settlement: it reads a signed receipt from the existing unauthenticated
  `GET /passport/verify`, verifies it offline against a pinned issuer, and
  reports `{ standing, checked_at }` or `{ error }` in the purchase response. It
  never refuses a payment, never gates settlement, and never touches the signed
  payment intent — the settle path is byte-for-byte unchanged, pinned by the
  demo merchant's existing settle tests plus the new echo-rule cases. The
  subject binding is the security-relevant part: the lookup is by **payer
  address**, never by the agent-supplied UID (a UID is public on EAS, so a
  UID-only lookup would let any payer present another active agent's passport),
  the receipt's own `issuer` field is never trusted, and a chain or reference
  mismatch is `subject_mismatch` rather than a standing. Refusals held: the
  helper throws on a malformed pin (a programming error, not an answer) and
  `checkPassport` collapses every transport failure — 503, 429, timeout,
  network, non-JSON — into `unavailable`, so a Haven outage cannot become a
  merchant's availability veto. Mutation-proven: a mutated
  `controls.policyEnforcedOnchain` is `not_signed_by_issuer`, an expired receipt
  is `expired`, a non-active standing is `not_active`, the receipt's own issuer
  as the pin is `not_signed_by_issuer`, and a header carrying agent B's UID paid
  by agent A is `subject_mismatch` — each asserted in the SDK suite and
  cross-checked against the backend's `signReceipt` in
  `packages/backend/src/modules/passport/__tests__/passport-sdk-cross-check.test.ts`.
  The demo merchant's new `@haven_ai/sdk` dependency is a workspace `"*"` pin
  (private consumer), and its build/test/typecheck scripts build core and the
  SDK first, so the Railway build command does not change. Perimeter unchanged.
