- **#4710** — A way back into an unfinished connect. Adds one READ
  (`GET /agent-connection-setups/pending`) that lists the signed-in user's
  setups still `awaiting_connection` and unexpired, tenant-scoped to the
  authenticated `sub`, projecting only `setup_id`, `name` and `expires_at` —
  no setup token, token hash, challenge or prompt. The prompt exists only in
  the create response and is never re-issued; the new dashboard row offers
  Open (the existing `/agents?setup=<id>` resume link, #2522) and Start again,
  which reads the setup first, cancels it only while it is still
  `awaiting_connection` (the existing `POST /:setupId/cancel`), and reopens
  the connect flow prefilled so the user creates a NEW setup through the
  ordinary create path. No credential-issuing path is added, no authority is
  widened, and no route's wire changes: the list is a read, the cancel is the
  route that already existed, and the replacement prompt comes from the
  unchanged `POST /agent-connection-setups`. The accepted residual is that an
  old prompt pasted after Start again gets the raw 409 "Setup is not awaiting
  connection" (the connector maps only 410 and 401); `/register` refuses it
  before any agent row is written, pinned by a regression test. Mutation-proven
  both ways: dropping the tenant predicate fails the real-DB tenant test, and
  dropping the `source = 'cli'` exclusion fails the CLI-edge test. Perimeter
  unchanged.
