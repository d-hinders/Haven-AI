- **#4760** — the `POST /payments` create flow moves into
  `modules/payments/create-payment.ts` (epic #4759, slice 1). Behaviour is
  unchanged: same status, same body, same database writes, same order of
  refusals, for every request.

  What changed:
  - The body of the `POST /` handler in `routes/payments.ts` — one closure of
    478 lines — is now `createPayment(input)` in
    `modules/payments/create-payment.ts`, exported through
    `modules/payments/index.ts`. The route reads the request, calls the
    module, and sends the decided `{ code, body }` response it returns.
  - The module takes plain inputs (the authenticated agent, the request body
    fields, a logger) and never receives a Fastify object. It imports its own
    collaborators the way `modules/x402/authorize.ts` does, and every refusal
    goes through the same `refuse()` choke point (#3053) — the ledger write is
    still fire-and-forget and still cannot change the response.
  - `classifyRecipient` (#3531), `findPaymentReplay` (#1207) and
    `replayIntentBody` moved with it, along with the constants and types only
    they and the closure use. `buildResponseFee` stays in the route (only
    `GET /:id` calls it).
  - `resolveToken` moved too, and the route imports it back through the
    barrel. It is called by the create flow (step 3) and by `GET /:id` and
    `POST /:id/sign`; a module may not import the route layer (#994), and the
    retired-rail gate must stay ABOVE token resolution (#2274), so it cannot
    be handed in from the route.
  - `CreatePaymentBody` is exported from the module; the route registration
    still names it.

  Why the perimeter is unaffected:
  - Nothing about who may sign, move or authorise changes. The same
    delegation-rail prepare, the same caveat enforcers, the same two fail-open
    pre-checks (task-budget cap #3500, period budget #3503), the same
    idempotency pin (#1207) and the same insert.
  - The move is a relocation, not a rewrite: the code is verbatim, and the 11
    `routes/__tests__/payments*.test.ts` characterization files are not edited
    at all — they are the proof.
  - `modules/payments/create-payment.ts` joins the money-path perimeter
    (`.github/money-path-globs.json`, `.github/labeler.yml`, the ship-next
    perimeter reference) and this document's `covers:`, because the decision
    moved out of an already-listed file (the #1892 accident-of-location rule).

  Tests:
  - `modules/payments/__tests__/create-payment.test.ts` calls `createPayment`
    directly — no `app.inject` — and asserts a refusal (the 400 non-positive
    amount, decided before any database read) and a success (the 201 body with
    `payment_id`, `status` and `sign_data`), plus the retired-rail 410 and the
    `recipient.class` advisory field.
  - The existing `payments*.test.ts` suites pass unchanged.

  Mutation cells in the PR body: deleting the idempotent-replay branch inside
  the moved code (the `findPaymentReplay` call) turns
  `payments-task-budget-replay.test.ts` red.
