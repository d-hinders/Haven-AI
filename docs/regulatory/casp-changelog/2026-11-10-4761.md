- **#4761** — the `POST /payments/:id/sign` submit state machine moves into
  `modules/payments/sign-payment.ts` (epic #4759, slice 2). Behaviour is
  unchanged: same status and body, same database writes in the same order,
  same claim / release semantics, same sponsored-gas recording on each
  outcome.

  What changed:
  - The body of the `POST /:id/sign` handler in `routes/payments.ts` — one
    closure of 530 lines — is now `signPayment(input)` in
    `modules/payments/sign-payment.ts`, exported through
    `modules/payments/index.ts`. The route reads the request, calls the
    module, and sends the decided `{ code, body }` response it returns.
  - The module takes plain inputs (the authenticated agent, the payment id,
    the signature, a logger) and never receives a Fastify object. Every arm
    that used to answer `reply.code(n).send(body)` now returns the same
    `{ code, body }` pair, and every refusal still goes through the same
    `refuse()` choke point (#3053) — the ledger write is still
    fire-and-forget and still cannot change the response.
  - The two `modules/mpp/` collaborators (`mppDemoRetired`,
    `tryRecordMachinePaymentEvidenceBaseById`) are passed in by the route
    rather than imported by the module. The mpp barrel re-exports `sweep.ts`
    and `budget-precheck.ts`, and both import the payments barrel, so a
    payments module file importing the mpp barrel would close a
    payments → mpp → payments cycle that `no-circular` refuses and no waiver
    can silence. The new file imports nothing from the mpp module.
  - `SignPaymentBody` is exported from the module; the route registration
    still names it.
  - Two comments were reworded in the move, both forced by a gate rather than
    by taste. The `#1328` note on a pre-existing `mpp_demo` intent said
    historical rows "stay readable", which is the single `stays-readable` hit
    `packages/retired-rail-prose-baseline.json` allowed `routes/payments.ts`.
    Moved verbatim it would have counted against the new file, whose allowance
    is 0, and the ratchet refuses to raise one. It now says "remain visible",
    and `routes/payments.ts`'s baseline entry is removed. The `#1987` note
    named the retired legacy bodies by their directory path; the issue's own
    acceptance criterion requires `grep -c "modules/mpp\|\.\./mpp/"` on the new
    file to be 0, so it now says "the mpp module's `{authorize,send}.ts`".
    Neither reword changes a claim about the code.

  Why the perimeter is unaffected:
  - Nothing about who may sign, move or authorise changes. The same
    retired-rail gates, the same expiry flip, the same misdirected-erc7710
    guard, the same atomic claim, the same delegation-rail submit, the same
    caveat enforcers, the same sponsored-gas recording and the same
    confirm / fail / outcome-pending booking split.
  - The order of the claim, the submit and the terminal write is the
    money-path invariant, and the move does not touch it: the claim still
    happens before any on-chain execution, the terminal booking still happens
    after it, and the over-budget arm still releases the claim before
    answering 429.
  - The move is a relocation, not a rewrite: the code is verbatim, and the
    `routes/__tests__/payments*.test.ts` characterization files are not
    edited at all — they are the proof.
  - `modules/payments/sign-payment.ts` joins the money-path perimeter
    (`.github/money-path-globs.json`, `.github/labeler.yml`, the ship-next
    perimeter reference) and this document's `covers:`, because the decision
    moved out of an already-listed file (the #1892 accident-of-location
    rule).

  Tests:
  - `modules/payments/__tests__/sign-payment.test.ts` calls `signPayment`
    directly — no `app.inject` — and covers a confirmed submit, a failed
    submit and the outcome-pending branch, plus the pre-claim refusals.
  - The existing `payments*.test.ts` suites pass unchanged.

  Mutation cells in the PR body: removing the `confirmSubmittedIntent` call,
  the `failSubmittedIntent` call and the `bookSubmittedOutcomePending` call
  each turns at least one test red (`prove-red`).

  Perimeter unchanged.
