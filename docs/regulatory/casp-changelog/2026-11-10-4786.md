- **#4786** — the operator's lane cancel (`cancel-stuck-lane`) can no longer
  exit 0 without running, and the command joins the money-path control list.
  Who may run the action, what it broadcasts and what it refuses are
  unchanged.

  What changed:
  - `packages/backend/src/ops/cancel-stuck-lane.ts` held the command and
    decided whether to start it by comparing its own URL with
    `process.argv[1]`. Node leaves that argument unresolved, unencoded and
    without an extension the operator did not type, so the built tool printed
    nothing and exited 0 when it was started by an absolute path through a
    symlink, from a path with a space, or without `.js`. The file's header
    defines exit 0 as "recovery in motion". The command given in the runbooks
    (a relative path under `/app`, with the extension) was not affected, and
    no occurrence is known.
  - The file is now an entry file that starts the command unconditionally and
    exports nothing. The code moved, unchanged, to
    `packages/backend/src/ops/lane-cancel-command.ts`: the argument check, the
    deferred import of `infra/outbound-lane-cancel.ts`, the call with
    production dependencies, the outcome texts and the exit codes. The `tsx`
    wrapper `packages/backend/scripts/cancel-stuck-attest-lane.ts` imports
    `runCli` from that module. The built path the runbooks name,
    `dist/ops/cancel-stuck-lane.js`, and the npm script names are the same.
  - `packages/backend/src/ops/**` and the wrapper are added to `controlGlobs`
    in `.github/money-path-globs.json`, to `.github/labeler.yml`, to the
    ship-next perimeter reference and to this document's `covers:`. Control
    and not runtime: the money-flow QA harness never runs an operator's lane
    cancel, so the files must not count toward `qa-freshness`. The
    implementation, `infra/outbound-lane-cancel.ts`, was and stays on the
    runtime list.
  - Six `packages/qa-agent/src` command-line files take the resolved entry
    test #4776 gave the repository's scripts. None is on the perimeter.

  Why the perimeter is unaffected:
  - No signing, custody or spend-authority code is edited. The operator
    action is `cancelStuckOutboundLane` with `productionLaneCancelDeps`, both
    in `infra/outbound-lane-cancel.ts`, which this change does not touch: the
    same refusals (a young, mined, already cancelled or still-recoverable
    row), the same relayer self-send at the stuck row's own nonce, chain and
    wallet, the same durable `outbound_txs` record.
  - Who may run it is unchanged: whoever holds the backend environment
    (database URL, relayer key, RPC). The command still reads its only input,
    the row id, from the command line and still validates it as a UUID
    before anything that reads configuration is imported.
  - What changed is that a start which used to do nothing and report success
    now runs the command. That can only turn a silent no-op into the action
    the operator asked for, or into the usage text. One silent start is new
    and is left as it is: `node …/dist/ops/lane-cancel-command.js` prints
    nothing and exits 0, as any module without a start does. No runbook
    names that file.
  - An entry file that always starts would run the command if it were
    imported. `scripts/ci/entry-point.test.mjs` fails on an import of it
    written with a literal specifier on the line of its `from`, `import`,
    `import()` or `require()`, in any tracked code file; it does not see a
    computed specifier. The wrapper, the one former importer, now imports the
    code module.

  Tests:
  - `packages/backend/src/ops/cancel-stuck-lane.process.test.ts` transpiles
    `src/ops` and runs the result under plain `node`: usage text and exit 1
    by a relative path, for an argument that is not a UUID, without the
    extension, by an absolute path through a symlink, and from a directory
    whose real path has a space and a non-ASCII character; no output and
    exit 0 when the code module is only imported. The relative-path case, the
    non-UUID case and the import case (then against the single file) were
    committed on the unchanged file before the change. One more case gives
    the tool a row id in a build whose action module is a stub that refuses
    and echoes the id, to show the id reaches the action; the real action is
    not imported by any case.
  - `scripts/ci/money-path.test.mjs` pins the entry file, the code module and
    the wrapper as control and not runtime.

  Mutation cells are in the PR body (`prove-red`).

  Perimeter unchanged.
