- **#4791** — the local MCP package (`@haven_ai/mcp`) gets a committed golden
  of its `tools/list` contract. Tests, one data file and one script line; no
  runtime code changes.

  What changed:
  - `packages/mcp/src/local-tool-contract.golden.json` holds each local tool's
    name, description and input schema as a client receives them, captured
    through the MCP SDK (`InMemoryTransport` + `client.listTools()`) from a
    server built by `buildMcpServer`.
  - `packages/mcp/src/local-tool-contract.test.ts` fails when the live
    `tools/list` differs from the golden, when the golden's tool names differ
    from the package's registry, or when the golden holds anything but
    `tools/list` (it must not carry the version a release bump rewrites).
  - `packages/mcp/package.json` gains `snapshot:regen`, the regeneration
    command. `files` is unchanged, so the golden is not published.

  Why the perimeter is unaffected:
  - No file that runs in an agent's process, the signer or the hosted server
    changes. Nothing about who may sign, move or authorise changes, and no tool
    contract changes: the golden records today's contract as it is.
  - The test builds the server with a dummy API key and base URL and only
    lists tools; it reads no credential file and makes no network call.
  - `packages/mcp/src/**` is off the money-path perimeter by the #3098 decision
    (pinned doc-only in `scripts/ci/money-path.test.mjs`); this change does not
    revisit that.

  Tests: the three cases of `local-tool-contract.test.ts`. Mutation cells are
  in the PR body.
