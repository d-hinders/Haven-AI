- **#4796** — four MCP tool descriptions named a tool their own surface does
  not register; each now names only tools the agent reading it can call.
  Description text and tests; no handler, schema or refusal changes.

  What changed:
  - `packages/sdk/src/tool-descriptions.ts`: `composeDescription` takes an
    optional MCP surface, and a description may carry `selectionGuidanceFor`
    for a sentence that names a surface-specific tool. With no surface the
    shared text is unchanged (the SDK's direct tool definitions keep it).
  - Local MCP (`packages/mcp/src/tools.ts`): `haven_send` and
    `haven_sweep_delegate` no longer point at `haven_check_funds`, which only
    the hosted MCP registers. They say no tool on the surface checks funds
    against an amount, and name `haven_get_allowances` only for its
    `fundsCoverRemaining` flag.
  - Hosted MCP (`packages/mcp-server/src/tools/contracts.ts`): `haven_send`
    and `haven_pay_mcp_tool` no longer point at `haven_pay_x402`, which only
    the local MCP registers. They point at `haven_quote_x402`, the hosted x402
    entry point.
  - Both `tools/list` goldens are regenerated; only those four descriptions
    differ. The hosted description-size total moves from 31,805 to 31,811
    bytes, and its pin is lowered from 31,812 to 31,811.
  - The local/hosted parity manifest records the result: `haven_send` gains a
    description entry (its two texts now differ on purpose) and three
    description hashes move.

  Why the perimeter is unaffected:
  - Nothing about who may sign, move or authorise changes. No tool, argument,
    schema, handler or refusal changes on either surface; the change is which
    follow-up tool a description names.
  - One money statement is at stake, and the change makes it more accurate,
    not less: the local text does not present `haven_get_allowances` as a
    check of funds against an amount; it names the `fundsCoverRemaining` flag
    that tool already returns. A live budget is spend authority, not proof that funds are
    held, which is the rule the shared descriptions already state.
  - The hosted contract fingerprint moves because it hashes descriptions. That
    is the designed signal for an agent holding a stale hosted tool list to
    reconnect; a prepared or funded payment keeps its id across the reconnect.

  Tests: `packages/mcp-server/src/description-tool-references.test.ts` walks
  every registered description on both surfaces and fails on a tool name the
  surface does not register, a signer tool or one allowlisted reference aside.
  Mutation cells are in the PR body.
