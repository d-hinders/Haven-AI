  **What the release carries into published packages, by effect on authority:**
  - **#4754 (#4756): an x402 v2 payment goes out under `PAYMENT-SIGNATURE` alone.** `x402PaymentHeaderNamesFor` decides by the payload's `x402Version`: v2 gets the one name, v1 (and an unreadable header) keeps both. The signer's `retry_headers` and its `haven_x402_sign_header` description follow the same rule. It changes which HTTP header names carry an already-signed payment; it changes no byte that is signed. This is the fix for a merchant answering HTTP 431 after the funding leg had confirmed.
  - **#4792 (#4803): one copy of the delegate-key credential-file handling.** The code that reads the agent's credential file — the file holding the delegate private key — existed twice, in `@haven_ai/mcp` and `@haven_ai/signer`. The common part is now one module on `@haven_ai/sdk/edge` (not re-exported by the main barrel). Its own shard (`2026-11-11-4792.md`) carries the behaviour argument and its characterization tests; this is the release's one change to how the signing key is read, and it is on the money-path perimeter.
  - **#4721 (#4729), #4722 (#4730), #4723 (#4731): Agent Passport.**
    - The agent reads its own passport reference (`HavenAgent.passport`, `getAgentSummary()`, `haven_get_agent`): `{ attestationUid, chainId, verifyUrl? }` or `null`.
    - When a merchant's x402 v2 402 advertises the `haven-passport` extension, the EIP-3009 envelope adds `attestation_uid` and `chain_id` to that extension and never overwrites a field the merchant set. A merchant that does not advertise the key receives the same bytes as before.
    - `verifyPassportReceipt` and `checkPassport` are merchant-side verifiers against a pinned issuer; `checkPassport` never throws and never refuses a payment. The lookup is by payer address, not by the UID the payment carried.
    - A passport is an attestation about the agent. It authorizes no spend and is not consulted by any signing path.
  - **#4552 (#4558): the merchant's own refusal reason is recorded and echoed** (`merchantReportedError`, code-shaped values only). Merchant-claimed, never verified by Haven; the handoff after a rejected retry is unchanged.
  - **#4577 (#4583): `HavenPaymentReceipt.parentReceiptId`** names the parent purchase receipt's id. `parentPaymentId` still maps the same value and is `@deprecated`, not removed.
  - **#4688 (#4690): `settled` is reported only on confirmed settlement evidence.** The change is in the hosted MCP (`packages/mcp-server`, which deploys and reaches no tarball) and in `packages/sdk/src/client.ts`, which ships.
  - **#4790 (#4801): the local MCP's refusal mapper answers the 20 typed backend codes** as the hosted mapper does. It changes what `@haven_ai/mcp` tells an agent about a refusal the backend already made; neither this nor #4688 moves a signing decision.
  - **#4796 (#4798): tool descriptions name only tools their own surface registers.** `haven_send` and `haven_sweep_delegate` in `@haven_ai/mcp` no longer point at `haven_check_funds`, which only the hosted MCP has. Description text.
  - **#4763 (#4802): the SDK's runtime import cycle is broken.** A module-graph change; the shard `2026-11-11-4763.md` carries it.
  - **#4668 (#4670): `budget_ended_at` is `null` beside a live budget.** A read.
  - **CLI: `haven contacts add` and `haven contacts remove` refuse under any session (#4662)**, since only the owner writes contacts; the backend refuses the same writes from a device-code session. This narrows what an agent-driven CLI can do.
  - **Runbook wording (#4675, #4746):** signup is passkey-only; the release-record link leads "If something breaks". `sdk` and `cli` carry the same regenerated text.
