- **#4790** — the local MCP's refusal mapper learns the 20 typed backend
  `error_code`s, and a parity test pins it to the hosted mapper.

  What changed:
  - `packages/mcp/src/tools.ts`: the `HavenApiError` branch of the local
    `normalizeError` now answers the ten payment-scope refusal codes (a table
    keyed by `error_code`) and the ten hand-written hosted branch codes
    (`rail_unavailable_for_chain`, `task_budget_exceeded`,
    `task_budget_exceeds_remaining`, `delegation_budget_exceeded`,
    `delegation_expired`, `submission_outcome_unknown`,
    `account_validation_failed`, `signature_rejected`, `prepare_reverted`,
    `onchain_execution_failed`) with the hosted mapper's typed `code`,
    `next_action`, named tool and arguments, and `next_tool_omitted_reason` —
    including the body-dependent variants and the 403 guard on
    `delegation_expired`. Any other `error_code` keeps today's generic
    `API_ERROR` answer, and a body's own `next_action` is still passed through.
  - `packages/mcp-server/src/local-hosted-refusal-parity.test.ts` (new) drives
    both mappers with the hosted suite's fixture bodies (`REFUSAL_SITES`) and
    fails on any difference in `code`, `next_action`, `next_tool_name`,
    `next_arguments` or `next_tool_omitted_reason` that its allowlist does not
    name — and on a stale allowlist entry. The allowlist is empty.
  - `packages/mcp/src/refusal-codes.test.ts` (new) pins the generic answer for
    an unknown code and the pass-through of a body-supplied `next_action`.
  - Docs: `docs/architecture/08-local-vs-hosted-mcp.md` states how each surface
    answers a refusal; `docs/operations/mcp-runtime-compatibility.md` records
    the local envelope change; `packages/mcp/CHANGELOG.md` gains the entry.

  Why the perimeter is unaffected:
  - No refusal is created, removed or re-decided. The backend still makes every
    refusal; this change only changes what a local-MCP agent is TOLD about a
    refusal that already happened. No authority, custody, allowance, signing or
    route surface moves, and no hosted runtime file changes.
  - The local mapper reads `error_code` from a body the backend already sent and
    emits a constant answer per code. It names no new tool: the only tool any of
    the 20 answers names is `haven_get_payment_status`, which the local package
    already has.
  - The files are under `packages/mcp/src/**` and `packages/mcp-server/src/**`,
    which are on the money-path perimeter as a whole, tests included; that is
    why this shard exists. The perimeter itself is not edited.

  Tests: `packages/mcp` and `packages/mcp-server` suites and `tsc --noEmit`
  green; `lint:next-steps` green; `npm run docs:coupling` green. Mutation cells
  are in the PR body. Perimeter unchanged.
