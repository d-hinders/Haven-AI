- **#4792** — the delegate-key credential-file handling that the local MCP and
  the edge signer each carried a copy of is now one module in
  `@haven_ai/sdk/edge`, and that module joins the money-path runtime perimeter.
  Who may sign, what input is accepted and what is refused are unchanged.

  What changed:
  - `packages/sdk/src/credential-file.ts` is new and holds exactly the common
    part: `stringField`, `readAccountAddressField`, `readAccountAddressEnv` and
    the raw `account_address | safe_address | safeAddress` shape they read; and
    the permission core, `permissiveMode` (the `stat`/`lstat` + `mode & 0o077`
    check with its `follow` parameter) plus a prefix-taking form of the warning,
    `warnIfFilePermissiveWithPrefix`. It is exported from `@haven_ai/sdk/edge`
    only — the SDK barrel does not re-export the edge entry — and it stays
    ethers-free (`packages/sdk/src/edge-imports.test.ts` green).
  - `packages/mcp/src/credentials.ts` and `packages/signer/src/credentials.ts`
    import the shared module and re-export the two account-address readers from
    their own `./credentials.js`, because their tests and callers import from
    there. `packages/signer/src/file-mode.ts` re-exports `permissiveMode`,
    `PermissionLog` and `PermissiveFile`, so `packages/signer/src/index.ts`
    keeps every name and signature it exported before the move.
  - What stayed in each package: its loader and result type, its `chain_id`
    parsing (the local MCP's `numberField` is lenient, the signer's
    `chainIdField` throws — the two differ on purpose-or-not and #4792 does not
    decide which is right, so neither moved nor merged), each package's read /
    JSON / missing-field error text, the signer's `x402_binding_signer`, the
    local MCP's `api_key`, `api_url`, `delegate_address`, allowance fields,
    split files and env loader, and the signer's `tightenIfFilePermissive`
    (whose one caller is `packages/signer/src/audit.ts`; giving the local MCP
    the signer's tightening behaviour is a behaviour change that needs its own
    issue).
  - The symlink trap is preserved rather than inherited by accident:
    `permissiveMode` defaults to `'nofollow'`, while both credential checks
    follow links today, so both wrappers pass `'follow'` explicitly and the
    shared warning takes `follow` as a required argument instead of defaulting
    it.
  - `packages/sdk/src/credential-file.ts` is added to `globs` in
    `.github/money-path-globs.json`, to `.github/labeler.yml`, to the ship-next
    perimeter reference and to this document's `covers:` (already spanned by
    `packages/sdk/src/**`). Runtime, not control, for the same reason
    `packages/signer/**` is on the list: it is how the key is read. A later
    change to the file therefore owes a covering QA run; that is intended.
    `scripts/ci/money-path.test.mjs` pins it by name, and its doc-only reason
    string and file count for `packages/sdk/src/**` are updated.
  - `scripts/ci/safe-account-rename-census.mjs` allow-lists the new path with a
    written reason and an `ALLOWED_CEILING` entry (7); the ceilings for
    `packages/mcp/src/credentials.ts` (8 → 3) and
    `packages/signer/src/credentials.ts` (7 → 2) shrink with the code that left
    them.
  - `packages/sdk/CHANGELOG.md` gains an `### Added` entry under
    `## Unreleased` naming the new `@haven_ai/sdk/edge` exports — they are
    public, semver-governed symbols. The signer and the local MCP get no entry:
    no surface or behaviour change.

  Why the perimeter is unaffected:
  - No signing, custody or spend-authority code is edited. The permission check
    is the same check: it skips on `win32`, it `stat`s and follows symlinks, it
    swallows a stat error, it tests `mode & 0o077`, and it prints the same
    message modulo the `haven-mcp:` / `haven-signer:` prefix. The
    account-address readers are the same readers: the same precedence
    (`account_address ?? safe_address ?? safeAddress`), the same permanent
    file fallbacks, and the same retired-env refusal with the same text and the
    same reliance-not-presence verdict.
  - No accepted input changes and no new authority appears. The module reads a
    file the process was already handed and warns; it never writes, chmods or
    authorizes anything. `tightenIfFilePermissive` — the one helper that does
    chmod — stays in the signer, unchanged.
  - The move is a relocation, not a decision: the #1892 accident-of-location
    rule is why the glob follows it. `packages/signer/**` covered the signer's
    copy; the local MCP's copy was on no glob at all, so without the new entry
    the permission core would have left the perimeter silently.

  Tests:
  - Characterization first, in its own commit that changes no non-test line:
    `packages/mcp/src/credentials-characterization.test.ts` and
    `packages/signer/src/credentials-characterization.test.ts` are the same
    table-driven test, one per package, over the current exported functions.
    Rows: credential objects with `account_address`, `safe_address`,
    `safeAddress`, all three agreeing and disagreeing, none, non-string values,
    blank and untrimmed strings; env objects with each accepted variable, both
    retired names alone, both agreeing and both disagreeing; file modes `0600`,
    `0640`, `0644`, `0400` on a non-Windows platform, `0644` on `win32`, a
    missing file; and a symlink to a `0600` file (silent) and a symlink to a
    `0644` file (warns, and says `0644`). Each row records the exact warning
    string.
  - After the move the same tables pass unchanged in both packages, and both
    packages' existing suites pass unedited.
  - One body each, not one name each: over `packages/mcp/src`,
    `packages/signer/src` and `packages/sdk/src`, tests excluded, `0o077`,
    `'HAVEN_WALLET_ADDRESS', 'HAVEN_SAFE_ADDRESS'` and
    `raw.account_address ?? raw.safe_address ?? raw.safeAddress` each occur in
    exactly one file, under `packages/sdk/src`; and
    `git grep -cE "^export (async )?function (readAccountAddressField|readAccountAddressEnv)\b"`
    sums to 2, both in the SDK.
  - `packages/sdk`, `packages/mcp`, `packages/signer` and `packages/connect`
    suites and `tsc --noEmit` green; `node --test scripts/ci/*.test.mjs` green;
    `npm run docs:coupling` green.

  Mutation cells are in the PR body (`prove-red`), each turning a test red in
  both packages: the shared permission check returns without warning;
  `safe_address` is dropped from the shared field reader; the disagreement
  throw is removed from `readAccountAddressEnv`; the credential check's
  `follow` is flipped to `nofollow`.

  Perimeter unchanged.
