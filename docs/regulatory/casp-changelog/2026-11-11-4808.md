- **#4808** — the SDK's direct tool definitions and a payment-status message
  named tools the reading agent cannot call, and the SDK advertised a sweep
  tool it could not run. Three parts, all on client surfaces; no backend
  status field, stored value, refusal or message changes.

  What changed:
  - **A — SDK tool descriptions** (`packages/sdk/src/tools.ts`,
    `packages/sdk/src/tool-descriptions.ts`). `havenTools.claude()` and
    `havenTools.openai()` return six tools; three descriptions named five
    `haven_…` names outside that set. `get_allowances` no longer points at
    `haven_get_agent` (the SDK has no identity read), `authorize_x402_payment`
    names `get_payment_status` instead of `haven_get_payment_status`, and
    `haven_sweep_delegate` names `authorize_x402_payment` and `get_allowances`
    instead of `haven_pay_x402` / `haven_get_allowances` / `haven_check_funds`.
    The two shared fragments the first two rows live in are pinned
    byte-for-byte by both MCP goldens, so the SDK variants are derived from
    them at compose time in `tools.ts`; the sweep fragment is composed by no
    other surface and is edited in place. Both goldens are byte-identical.
  - **B — the settlement-evidence message** (`packages/sdk/src/payment-status-message.ts`,
    `packages/sdk/src/client.ts`, `packages/mcp/src/tools.ts`). The backend's
    `message` names `haven_report_settlement_evidence` in two states
    (`delivered_unverified` / `stop_and_tell_user`, and `payment_submitted` /
    `awaiting_settlement_evidence`), a tool only the hosted MCP registers. The
    local MCP's `haven_get_payment_status` handler and the SDK's
    `executeTool('get_payment_status')` now replace `message` whole in those
    two states, keyed on the structured fields and never on the backend's
    sentence, and name no reporting tool. The hosted MCP reads the same SDK
    helper and keeps the backend text verbatim.
  - **D — the sweep tool runs** (`packages/sdk/src/client.ts`). `executeTool`
    gained the missing `haven_sweep_delegate` branch: it calls
    `this.sweepDelegate()` and returns its result as a plain object, reading
    nothing from `input`. Errors propagate unchanged. `packages/sdk/README.md`
    now lists all six tools.

  Why the perimeter is unaffected:
  - No `phase`, `next_action`, status code, stored value or refusal changes,
    and `packages/backend/src/modules/payments/agent-payment-status.ts` is not
    edited. B changes only what two client layers say about a state the
    backend already reports; the hosted instruction stays correct and pinned.
  - B narrows what an agent is told, never what it may do: the replacement
    names no tool for reporting because neither surface has one, and it says
    the merchant delivered, that the settlement sweep may still attribute the
    payment, and to tell the user if it stays unverified.
  - D makes an existing action reachable from one more caller — the
    model-driven SDK tool call — and grants nothing new. The action is the one
    the SDK already exposes as `HavenClient.sweepDelegate()` and the local MCP
    already exposes to an agent. It takes no input, so a model cannot choose an
    amount, an asset or a destination: the sweep goes to
    `getAgent().accountAddress`, the account Haven's API reports for this
    agent. It needs the delegate key the embedding process already holds. The
    residual is unchanged from the local MCP's — an agent can trigger a sweep
    the user did not ask for, which returns funds to the reported account —
    and is the one `docs/security/delegation-rail-security-model.md` §8 already
    records (#3375 names it, does not close it).
  - A is description text only. It moves no golden, no contract fingerprint
    and no tool, argument or schema.

  Tests: `packages/sdk/src/sdk-tool-names.test.ts` walks every description
  `havenTools` returns in both formats and fails on a `haven_…` name outside
  the six; `packages/sdk/src/execute-tool.test.ts` proves the sweep branch and
  walks every advertised tool name against `executeTool` (a made-up name still
  rejects with `Unknown tool`); `packages/mcp/src/payment-status-message.test.ts`
  and the SDK half of `execute-tool.test.ts` pin the two replacement messages
  with `toBe` in both states, twice per state (backend sentence and an
  arbitrary string), and prove pass-through elsewhere;
  `packages/mcp-server/src/payment-status-message.test.ts` proves the hosted
  agent still reads `haven_report_settlement_evidence`. Mutation cells are in
  the PR body: each of the three restored sentences reddens the name scan, each
  removed replacement reddens its own test, moving a replacement into
  `getPaymentStatusWithPostPurchaseAllowance` reddens the hosted assertion, and
  removing the sweep branch reddens both the D test and the class guard.

  Perimeter unchanged.
