- **#4830** — `haven_quote_x402` skipped the `expected_amount` comparison
  silently on both MCP surfaces, answering as if no expectation had been
  stated. Advisory guidance only: no input, `next_action` value, signer
  surface or spend authority changes.

  What changed:
  - **The comparison is decided without the agent read where possible**
    (`packages/mcp-server/src/tools/support/quote-response.ts`,
    `packages/mcp/src/tools.ts`). The agent read only chooses BETWEEN the
    merchant's erc7710 and standard options, so when that choice cannot change
    the answer — one option exists, both carry the same authorization amount,
    or the stated price equals neither — the comparison is decided without it.
    A stated price finer than the token's scale is a decided mismatch on both
    surfaces (the local surface used to skip it).
  - **A comparison that cannot be made says so** (both surfaces). The result
    carries `price_comparison_made: false` with
    `price_comparison_not_made_cause` (`agent_read_failed` |
    `agent_read_refused` | `no_option_selected` | `unknown_decimals`),
    `safe_to_continue: false`, no prefilled `max_amount_human` and no pay step;
    `price_differs_from_expected` is absent because nobody compared the price.
    The quote object itself is still returned, as on today's mismatch stop.
  - **The step follows the cause**, as `normalizeError` decides one: a
    transient agent-read failure (5xx, no answer) is worth one re-quote with
    the same arguments (`retry_with_explicit_context`); a read refused 401/403,
    an unselectable option and unknown decimals stop the agent
    (`stop_and_tell_user`). The handlers keep the read's error instead of
    mapping it to `undefined`. No new `next_action` value.
  - **Texts that enumerate why a quote stops name the new state**: the hosted
    instructions (`packages/mcp-server/src/server.ts`), the skill text
    (`packages/sdk/src/skill-content.ts`) and its byte-pinned copy
    (`packages/frontend/src/lib/agent-skill-bundle.ts`),
    `docs/architecture/04-x402-payment-sequence.md`,
    `docs/operations/mcp-runtime-compatibility.md`, and the quote descriptions'
    stale "Haven is not contacted" claim (`contracts.ts`,
    `packages/sdk/src/tool-descriptions.ts`).

  Why the perimeter is unaffected:
  - This is the ADVISORY price check, not spend authority. The on-chain budget
    and the delegation policy remain the actual gate; nothing here can widen
    what an agent may authorize, and the change only ever adds a STOP where the
    surface previously said "safe to continue" on a price nobody compared.
  - No input, existing field, `next_action` value, refusal code, stored value
    or signer surface changes. The new fields are additive result fields on a
    read-only quote; no payment, signature or funding intent is created.
  - The hosted budget pre-check is skipped on a not-compared quote (as it
    already was on a decided mismatch), so the change removes a Haven call
    rather than adding one, and no warning on that result invites the agent to
    proceed.
  - The local half ships with the next `@haven_ai/mcp` release; the hosted half
    ships with the server.

  Tests: `packages/mcp-server/src/tools/plain-http-x402.test.ts` pins the
  decided-without-the-agent mismatch (read 500, single-entry merchant at 1.5,
  `expected_amount: "0.10"` → `price_differs_from_expected: true`,
  `safe_to_continue: false`), the not-compared answer (two entries priced
  differently, the stated price equal to exactly one, read 500 → the named
  fields, no `safe_to_continue: true`, no prefilled cap, no pay step), the
  cause-following step (5xx → `retry_with_explicit_context`; 401/403 →
  `stop_and_tell_user`), unknown decimals via the cross-network USDC fixture,
  the finer-than-scale mismatch, and the unchanged pinned behaviours (matching
  price continues, no `expected_amount` changes nothing).
  `packages/mcp/src/tools.test.ts` pins the same on the local surface, plus the
  finer-than-scale mismatch and the no-option-selected not-compared answer.
  `packages/sdk/src/skill-content.test.ts` pins the skill text.

  Perimeter unchanged.
