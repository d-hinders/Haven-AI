- **#4881** — The dashboard's receipt-name fallback reads the seller name
  where real merchant receipts carry it: the top-level `saljare.name` (the
  same block the accounting underlag reads), with the flat `merchant_name` as
  the fallback for older receipts whenever `saljare.name` yields no usable
  name. Each name is cleaned (control, invisible and bidirectional characters
  stripped, whitespace including the no-break space collapsed, trimmed) and
  bounded at 120 code points; an empty, non-string or longer name yields no
  name, and the newest receipt with a usable name wins. Addresses now match case-insensitively. **Display only:** a
  read-only change in `infra/repositories/analytics.ts`, used by the activity
  feed, analytics, the top-merchant card, the first-payment card and
  transaction search. No authority, custody, route, address handling for
  payments or money movement changes; the naming order is unchanged.
  - **Residual.** A receipt is relayed by the agent and unsigned by the
    merchant, so the seller name is the payee's own claim and can be false.
    It stays the lowest-priority name in every caller's order: after
    contacts, and in analytics also after the user's own accounts and the
    resource host; #4882 states the rule that keeps a payee from borrowing a
    catalog merchant's name.

  - **Mutation-tested:** the `saljare.name` read, the flat fallback, the
    length bound, whitespace collapse, invisible-character strip, the
    no-break space, case-insensitive address matching, the string-type guard
    and the newest-receipt order (prove-red cells, all caught).

  Perimeter unchanged.
