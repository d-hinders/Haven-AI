- **#4871 — a per-agent switch for sharing checkout details, and the agent's read of them (epic #4868).** Migration 135 adds `agents.checkout_details_sharing_enabled BOOLEAN NOT NULL DEFAULT false`; an owner-session route turns it on and off; an agent-key route returns the owner's stored receipt email, billing address and shipping address when the switch is on. Nothing here moves, signs or authorises a payment.

  What changed (`packages/backend/src/`):
  - **`db/migrations/135_agent_checkout_details_sharing.ts`.** One boolean column on `agents`, `NOT NULL DEFAULT false`, no constraint and no backfill. Existing agents read `false`; every path that creates an agent leaves the column at its default. `down()` drops exactly the column.
  - **`infra/repositories/agents.ts`.** `SET_AGENT_CHECKOUT_DETAILS_SHARING_ENABLED_SQL` is owner-scoped (`id = $1 AND user_id = $2`) and gated IN SQL, directionally: switching ON requires the deployment flag (`NOT $3 OR $4`), switching OFF is never gated. `GET_AGENT_CHECKOUT_DETAILS_SQL` joins `owner_company_details` on the agent's `user_id` and returns the switch plus the three stored fields. The column is added to the list, single, create and profile-update reads so the `Agent` response shape stays complete.
  - **`modules/agents/checkout-details.ts`.** A pure resolver: `feature_disabled` → `disabled` → `no_details`, then `{ available: true, checkout_details }` with a field the owner has not saved OMITTED, never `null`. No db handle, no config read, no clock.
  - **`routes/agent-checkout-details.ts`.** Its own route module (not `routes/agents.ts`, whose instance-level `authMiddleware` would answer an agent key with the generic 401 instead of the named 403). `PUT /agents/:id/checkout-details-sharing` is owner-only (`refuseAgentKey` then `authMiddleware`); `GET /agents/:id/checkout-details` is agent-key only and refuses a foreign id with a 403 before any company-details row is read.
  - **`index.ts`, `openapi/spec.ts`, `openapi/route-modules.generated.ts`, `packages/core/src/api-types.ts`.** The module is registered on the `/agents` prefix and added to `enforcedModules` (born enforced — a genuinely new module never enters shadow). The two paths, five schemas and the new `Agent` field are declared; both generated files are regenerated.

  Why the CASP perimeter is unaffected:
  - **No authority, custody or money movement.** The switch is one boolean that gates DATA shared with a merchant. It grants no spend authority, changes no budget, delegation, allowance or payment term, and nothing in the delegation, budget or enforcement path reads it. #4872 attaches the answer to the paid request; this slice sends nothing.
  - **The read is scoped to the authenticated agent.** The agent key IS the tenant scope: a path id that is not the authenticated agent's is refused before any owner row is read, so one agent cannot read another's (even the same owner's) details.
  - **The owner's consent is the only way on.** An agent API key is refused with a named 403 on the toggle; the write is owner-scoped in its WHERE clause, so a foreign agent id updates zero rows.
  - **No sign-up-email fallback.** The read returns only a receipt email the owner saved (owner decision 2026-11-17, epic #4868). With sharing on and no receipt email saved, the content has no `receipt_email` key at all — pinned by a test that also asserts the owner's sign-up email appears nowhere in the body.
  - **Erasure still works.** `DELETE /user/company-details` removes the stored fields with the row; the switch is turned off in the agent's settings. Turning it off stops future answers and does not recall an answer already attached to a request (the accepted residual on the issue).

  Tests (real Postgres, `routes/__tests__/agent-checkout-details.test.ts` and `db/migrations/__tests__/135_agent_checkout_details_sharing.test.ts`):
  - **Migration.** The column is `NOT NULL` with a `false` default; an existing agent reads `false` after the column is dropped and re-applied; a new agent that never mentions it reads `false`; `up()` is idempotent; `down()` drops exactly the column; deleting the owner cascades the agent row.
  - **Owner toggle.** Succeeds with the flag on even when nothing is stored; refuses with a structured 409 `feature_disabled` and writes nothing when the flag is off; never gates switching OFF; refuses an agent API key with a named 403; 404s a foreign agent; refuses a missing or extra body field with a 400.
  - **Agent read.** Returns the three stored fields under the decided names and address shape; `disabled` when sharing was never on and when it was switched back off; `no_details` when sharing is on with nothing stored and when the owner has no company-details row; `feature_disabled` when the flag goes off after sharing was turned on; omits an unsaved field rather than sending `null`; has no email when sharing is on and no receipt email is saved; the two switches are independent in BOTH directions (sharing on / tax off, then tax on / sharing off); a foreign agent id is a 403; an unauthenticated caller is a 401. Every 200 body is checked against the OpenAPI schema with `expectMatchesSpec`.
  - **Pure resolver.** Nine cases pin the reason priority, the omission rule, the no-email rule and the verbatim address pass-through.

  Mutation-shaped assertions, not a mutation run: the response bodies are pinned with exact `toEqual` (a widened or narrowed shape fails), the "no email" case asserts the key is absent AND the sign-up email is absent from the serialised body, and the independence case reads both routes end to end rather than the two columns.

  Perimeter unchanged. `packages/backend/src/db/migrations/**` is on the money-path list and this migration is owner-reviewed; `infra/repositories/agents.ts` is already on the runtime list through `infra/repositories/**`.

  Verdict: **Perimeter unchanged.** One boolean of owner consent and a read of the owner's own stored data by the owning agent; no key, no signing, no funds, no authority.
