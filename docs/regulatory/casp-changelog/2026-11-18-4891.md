- **#4891**: the merchant kit's public discovery document and the package
  README, in `@haven_ai/paywall-proxy` (`packages/paywall-proxy/`). The proxy
  now serves `GET /.well-known/x402`, built from the products file and the
  deployment's settings, and the package README takes a merchant from clone to a
  first paid call.

  What it does:
  - The document lists every product in the products file with its route,
    price, model, output-token cap and description, plus the network, the USDC
    asset, the receiving address, the settlement block and who operates the
    endpoint. It carries nothing that is not in the file, and no demo-merchant
    field (`mcp_url`, `chain_id`, `environment`, `hosted_urls`, `routing`,
    `settlement_methods`, per-product `price_usdc` / `tools` / `category`).
  - It is served at the x402 well-known path only, outside `BASE_PATH`, and
    answering it makes no verify call, no settle call, no chain read and no
    upstream call.
  - The document is built once at startup from the products file, so a change
    to the file reaches readers when the proxy restarts.
  - Four settings carry the document's required fields: `ENDPOINT_NAME` and
    `ENDPOINT_DESCRIPTION` (required), `OPERATOR_CONTACT` and `ICON_URL`
    (optional). The design's §4 field table requires `name` and `description`
    and §12 named no source for them; §12 now names the settings.
  - The README states what Haven does not do (not in the payment path, does not
    hold the merchant's keys, does not settle), that only a Haven agent with an
    open budget can pay, that the merchant uses its own Coinbase key, that the
    kit has no licence yet and is used under written permission during the
    pilot, and what the merchant must run and monitor. It adds no Base mainnet
    step: that waits on the review in #4888.

  Why the perimeter is unaffected:
  - The route reads the products file and the deployment's settings and returns
    them. It holds no key, signs nothing, submits no transaction and calls no
    facilitator. It cannot move funds or change what the proxy settles.
  - The new settings are identity strings for the document. None is a
    credential, and none reaches a payment decision: `PAY_TO`, `NETWORK` and the
    products file still decide what is charged and where it goes.
  - The README is merchant-facing prose. It states the non-custody posture
    rather than implying Haven holds funds, controls keys or settles.
  - Money-path list: `packages/paywall-proxy/src/**` stays a control glob, by
    the owner decision on #4893.

  Pinned by tests (no mutation run): the discovery tests fail if the document
  gains a field the products file does not carry, if a product is dropped or its
  price or route changes, if the path moves to the demo merchant's, if the
  document is served under `BASE_PATH`, or if answering it makes a facilitator,
  chain or upstream call. The example products file is parsed by the
  products-file validator in a test.

  Perimeter unchanged.
