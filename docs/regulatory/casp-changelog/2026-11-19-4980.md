- **#4980** — the demo merchant's receipt writes its human-readable values in
  English by default instead of Swedish. Every JSON key and every code stays as
  it was. The merchant still sells only its own demo products, and no
  third-party funds are received or moved.

  What changed:
  - **`packages/merchant-payments/src/receipt.ts`** (the shared core).
    `buildReceipt` takes an optional `locale`, which defaults to `sv`. It picks
    the line's billing-period word, `betalningssatt` and `status`. The paywall
    proxy passes no locale, so its receipt is byte for byte unchanged (its tests
    pass unedited). The English render's status line takes either language.
  - **`packages/demo-merchant-mcp/src/`.**
    - `invoice.ts` builds the document in the paid call's locale, English by
      default. The product description and both Stripe blocks' `status`
      (`Pending` / `Not available at the time of purchase`) follow that locale.
    - `http.ts` reads `locale` from the paid tool call's arguments. Only `sv`
      gives Swedish; anything else, or no locale (plain-HTTP x402), gives
      English.
    - `server.ts` passes its locale to the invoice and updates the `locale`
      parameter's description. `products.ts` adds `isMerchantLocale`.

  Why the perimeter is unaffected:
  - No settlement, refusal, amount or authority decision reads the receipt's
    values. The change is to display text after settlement.
  - Haven's readers read only keys and codes. `receipt-statement.ts` reads
    `beskrivning` as free text and `valuta` / `momsbehandling` as codes, and
    `receipt-underlag.ts` and the analytics seller lookup read `saljare`.
    Neither the Stripe record (`stripe.ts`: `fakturanummer`, `momsbehandling`,
    the declaration) nor the sale report (`sales.ts`: `product.name`,
    `fakturanummer`, `momsbehandling`) reads a value whose language changed.
  - The VAT figures, the treatment code, the receipt number and the OCR are
    identical in both locales. A test pins that the English and Swedish
    documents have the same keys at every depth and the same codes.
  - The backend accounting fixtures are still the Swedish output, byte for
    byte (`receipt-fixtures.test.ts` now passes `locale: 'sv'`). No backend
    file changed.

  Tests:
  - `receipt-fixtures.test.ts`: the English snapshots are now the default's
    output, the Swedish ones are unchanged, and a new `receipt-joke.sv.json`
    is the Swedish JSON. It also checks key and code parity, and that the
    default field-notes and joke receipts carry no Swedish value outside the
    keys, the `blockkedjeadress` code and the seller block.
  - `invoice.test.ts`: English statuses for all three settlement states, plus
    the Swedish render of an English document.
  - `network-text.test.ts`: English `betalningssatt`.
  - `http.test.ts`: the default receipt header is English, and a
    `locale: 'sv'` call gets the Swedish header.
  - `cdp-settlement`, `skip-settle-guard` and `stripe-recording` tests now
    expect the English values.
  - `merchant-payments` `receipt.test.ts`: `locale: 'en'`, and Swedish when
    no locale is given.

  Perimeter unchanged.
