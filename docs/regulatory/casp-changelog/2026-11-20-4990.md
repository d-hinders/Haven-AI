- **#4990**: the merchant kit's discovery document now states the price, the
  network and the rules of the sale, so a buyer's agent can read them before it
  pays. Additive, read-only fields in `packages/paywall-proxy/src/discovery.ts`
  and `products.ts`; version 1 is unchanged and every new field is optional for
  readers.

  What changed:
  - **`packages/paywall-proxy/src/discovery.ts`**: each product carries
    `price_usdc`, the same price as a decimal USDC string with no trailing zeros
    (`"0.01"` for `"10000"`, `"0.018"` for `"18000"`, `"0.0001"` for `"100"`),
    computed in pure bigint math. `price` stays the atomic string, byte for
    byte. The top level gains `network_name` and `testnet` from `chains.ts`,
    `asset_symbol: "USDC"`, `asset_decimals: 6`, a `terms` object and a
    `payment` object. A product's optional `output_schema` is served when the
    products file carries one.
  - **`terms`** is the merchant's own plain statement about its own endpoint,
    true for every product (owner decision 1, 2026-11-19): `one_payment_one_call:
    true`; `replay` (`payment_already_delivered`); `payment_response` (the
    `PAYMENT-RESPONSE` header on every answer after settlement);
    `upstream_answered` (a 3xx/4xx wrapped into a 200, with 401/402/403/407 as
    `upstream_auth_refused` and 408/429/5xx as failures); and
    `on_failure_after_settlement` (`upstream_failed_after_settlement`, with the
    merchant's `operator.contact` when set, and a statement that none was
    published when it is not). It says nothing about retries or the payer-signed
    `SIGN-IN-WITH-X` proof: that recourse policy stays with the owner on #4884
    (owner decision 2, 2026-11-19).
  - **`payment`** names the accepted headers (`PAYMENT-SIGNATURE`, preferred,
    and `X-PAYMENT`), `x402_version: 2`, and the x402 v2 specification. It is a
    documentation pointer, not a recipe.
  - **`packages/paywall-proxy/src/products.ts`**: `output_schema` joins
    `PRODUCT_FIELDS` (an unknown field refuses startup) and must be a JSON
    object; anything else is refused at load, naming the product. It is served
    only, never enforced.
  - **`docs/architecture/12-merchant-kit.md`** §3 and §4 and
    **`packages/paywall-proxy/README.md`** list every new field, and the README's
    sale-rules paragraph points at `terms` so the two cannot drift. The
    "nothing that is not in the file" passage is reconciled: `terms` and
    `payment` are kit constants, not products-file content.
  - **The challenge is unchanged.** `accepts[].extra` still carries only the
    USDC signing domain; adding keys there is a compatibility risk for every
    x402 client, so the discovery document is where the rules live.

  Why the perimeter is unaffected:
  - The document is read-only. Answering it verifies nothing, settles nothing
    and makes no facilitator call; the existing test that asserts zero
    facilitator calls, zero chain reads and zero upstream calls still passes.
  - Nothing changes what is paid, settled or delivered. `price`, `pay_to`,
    `network`, `asset` and `settlement` are byte-identical, the challenge is
    untouched, and no settlement, refusal or authority decision reads the new
    fields. `terms` describes codes the handler already answers with; a test
    drives each case end to end and asserts the code in `terms` is the code the
    handler returns.
  - `output_schema` is display data. It is never compiled, never enforced, and
    cannot gate a purchase; a malformed one refuses startup rather than reaching
    a payment decision.
  - Haven's catalogue reader (#4899) still reads the document: the kit pins the
    document to a committed fixture byte for byte, and the backend's real
    `parseDiscoveryDocument` parses that fixture and reads the same products at
    the same atomic prices.
  - Money-path list: `packages/paywall-proxy/src/**` stays a control glob, by
    the owner decision on #4893.

  Pinned by tests: `discovery.test.ts` (the version-1 snapshot byte-identical;
  `price_usdc` for `"10000"`, `"18000"` and `"100"` and the formatter's edge
  cases past 2^53; `network_name`/`testnet`/`asset_symbol`/`asset_decimals`;
  `terms` present and free of any retry or `SIGN-IN-WITH-X` mention; the contact
  named when set and "published no contact" when not; each `terms` code driven
  end to end against the handler; `payment` always; `output_schema` served when
  present and absent otherwise), `discovery-fixtures.test.ts` (the backend
  fixture regenerated byte for byte from the builder over the largest example
  products file), `products.test.ts` (a non-object `output_schema` refused,
  naming the product), and the backend's `kit-merchant-x402.test.ts` (the
  fixture parses `ok: true` with the same products and prices, and stays under
  `MERCHANT_CATALOGUE_MAX_BYTES`).

  No mutation-testing run (prove-red cells) was performed for this slice. The
  tests pin the behaviour directly instead: the version-1 fields are pinned as a
  literal snapshot, the fixture is compared byte for byte, and each `terms` code
  is asserted against the handler's own answer.

  Perimeter unchanged.
