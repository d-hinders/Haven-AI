- **#5006**: the merchant kit's proxy now starts with fewer required settings.
  Four settings gain a default that is safe on Base Sepolia — `RPC_URL`,
  `ENDPOINT_NAME`, `ENDPOINT_DESCRIPTION` and `SALES_OUTBOX` — so nine settings
  are required in code instead of twelve. No safety check is weakened: every
  setting that gates a payment decision stays required.

  What changed:
  - **`packages/paywall-proxy/src/config.ts`**: `RPC_URL` defaults to
    `https://sepolia.base.org` on `eip155:84532` (`DEFAULT_RPC_URLS`) and stays
    required on `eip155:8453`. With `NETWORK` missing or invalid there is no
    chain to default for, so the refusal names only the `NETWORK` problem.
    `ENDPOINT_NAME` defaults to `OPERATOR_NAME`. `ENDPOINT_DESCRIPTION` becomes
    optional (`ProxyConfig.endpointDescription?`). `SALES_OUTBOX` defaults to
    `sales-outbox.jsonl` in `dirname(PAYMENTS_DB)`. `ProxyConfig` gains
    `rpcUrlDefault`, so the startup line can say the default is in use without
    printing a URL.
  - **`packages/paywall-proxy/src/discovery.ts`**: `defaultEndpointDescription`
    builds the sentence once, in `buildDiscoveryDocument`, which already
    receives the products — `loadConfig` never reads the products file. A set
    `ENDPOINT_DESCRIPTION` always wins.
  - **`packages/paywall-proxy/src/main.ts`**: the `started` line gains
    `rpc: "default (public Base Sepolia)"` or `rpc: "configured"`. It never
    prints the URL, because a provider URL can embed a key
    (`docs/operations/railway-services.md`).
  - **Copy**: `packages/paywall-proxy/.env.example` (REQUIRED markers on the
    endpoint fields and `RPC_URL` become OPTIONAL with the defaults named),
    `packages/paywall-proxy/README.md` (Step 4 tables, the RPC lines in
    *Requirements* and *Before you start*, the discovery-field table, the demo
    table's `RPC_URL` row, and the `started` line's fields),
    `docs/architecture/12-merchant-kit.md` §4 and §12, and the README entry's
    `last-verified` in `scripts/docs/package-docs.mjs`.

  Why the perimeter is unaffected:
  - **`RPC_URL`** is used only for the chain reads that resolve a lost settle
    answer and a used authorization (`main.ts:77`; design §12). The default is
    the value `.env.example` already suggested, and the public Base Sepolia node
    serves a 200-block `eth_getLogs` window that the core already narrows to fit
    (`merchant-payments/src/cdp.ts`, `LOG_CHUNK_BLOCKS`, #4866). Builder check:
    a public-RPC failure during recovery fails the same way an unreachable
    configured `RPC_URL` does today — `createViemChainReadClient` builds the
    same `http(rpcUrl, { timeout, retryCount: 0 })` transport for either string,
    so the failure arrives through the same `withCdpTimeout('chain_read', …)`
    path. No new failure class. Base mainnet keeps `RPC_URL` required, so no
    real-money deployment can silently rest on a rate-limited public node.
  - **`ENDPOINT_NAME` / `ENDPOINT_DESCRIPTION`** are display fields of the
    discovery document. The x402 challenge is untouched: `resource.description`
    is the product's own description (`challenge.ts:22`). No settlement,
    refusal or authority decision reads either field. Haven's catalogue reader
    (`packages/backend/src/modules/catalog/merchant-products.ts`) reads `name`
    and `operator.name` as independent trimmed strings with no uniqueness rule,
    so a name equal to the operator's reads correctly.
  - **`SALES_OUTBOX`** is a path only. The outbox's behaviour, its
    10,000-record bound and its 60 s replay cadence are unchanged, and the
    default sits beside `PAYMENTS_DB` — the disk the README already requires it
    on.
  - **Nothing that gates a payment became optional.** `NETWORK`, `PAY_TO`,
    `OPERATOR_NAME`, `PRODUCTS_FILE`, `PAYMENTS_DB`, `UPSTREAM_BASE_URL`,
    `UPSTREAM_API_KEY`, `CDP_API_KEY_ID` and `CDP_API_KEY_SECRET` stay required,
    and `HAVEN_SALES_URL` stays required with `HAVEN_MERCHANT_KEY`. The design's
    rule that a deployment cannot come up without a network, a receiving address
    or an operator (§3) is untouched.

  Pinned by tests: `config.test.ts` (the `it.each` refusal list drops the three
  names that now default; `RPC_URL` unset on Base Sepolia yields
  `https://sepolia.base.org` with `rpcUrlDefault: true`; unset on Base mainnet
  refuses with `RPC_URL is required`; a set value wins and is not reported as
  the default; `NETWORK` missing or invalid adds no `RPC_URL` problem line;
  `ENDPOINT_NAME` defaults to `OPERATOR_NAME` and `ENDPOINT_DESCRIPTION` is
  absent when unset; `SALES_OUTBOX` defaults beside `PAYMENTS_DB` and a set
  value overrides it; the `started` line names the public default and never the
  configured URL), and `discovery.test.ts` (the document's `name` equals
  `OPERATOR_NAME` and `description` is the generated sentence for three
  products and for one, and a set value wins).

  No mutation-testing run (prove-red cells) was performed for this slice. The
  tests pin the behaviour directly: each default and each refusal is asserted
  as a literal, and the mainnet refusal is a separate case from the Sepolia
  default.

  Perimeter unchanged.
