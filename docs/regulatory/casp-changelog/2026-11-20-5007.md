- **#5007**: the merchant kit's container image and its publishing workflow, in
  `@haven_ai/paywall-proxy` (`packages/paywall-proxy/`) and
  `.github/workflows/publish-paywall-proxy-image.yml`. A developer now runs one
  `docker run` with an env file, a products file and a volume, and never clones,
  installs Node or builds.

  What it does:
  - `packages/paywall-proxy/Dockerfile` is a multi-stage build from the
    repository root, in the shape `packages/mcp-server/Dockerfile` already uses:
    a builder stage installs and builds the workspace slice (`sdk`,
    `merchant-payments`, `paywall-proxy`), and a runner stage on `node:24-alpine`
    keeps production dependencies only. `node:sqlite` is built into Node 24, so
    there is no native module to compile.
  - The image runs as the non-root `node` user, sets
    `PRODUCTS_FILE=/config/products.json` and `PAYMENTS_DB=/data/payments.sqlite`,
    declares `/data` a volume, and its entrypoint is the existing CLI
    (`dist/index.js`), so `report-sale` and `check` run through it.
  - `packages/paywall-proxy/Dockerfile.dockerignore` is Dockerfile-specific, so
    the mcp-server image's build context is unchanged (there is no root
    `.dockerignore`).
  - The paywall-proxy CI job builds the image on every PR that touches the
    package (`push: false`), so a broken Dockerfile is red on the PR.
  - `.github/workflows/publish-paywall-proxy-image.yml` builds and pushes
    `ghcr.io/d-hinders/haven-paywall-proxy` with the workflow's `GITHUB_TOKEN`
    and `permissions: packages: write`. A push to `dev` publishes
    `dev-<short-sha>` and moves `dev`; a push to `main` publishes
    `pilot-<short-sha>` and moves `pilot`; nothing publishes `latest`.
  - `packages/paywall-proxy/src/sqlite-store.ts` gains `StorePermissionError`, so
    a store whose directory cannot be written says so in words instead of
    printing "The proxy cannot start (Error)."

  Why the perimeter is unaffected:
  - The image runs the same code the perimeter already covers:
    `packages/paywall-proxy/src/**` is a control glob (owner decision on #4893)
    and `packages/merchant-payments/src/**` is a runtime glob. The Dockerfile
    adds no behaviour — it packages what those files already do.
  - The publishing workflow decides **which image a merchant runs**, which is the
    same class as `publish.yml`: a change to it decides what reaches the channel
    users install from. It joins `controlGlobs`, so a PR weakening it gets the
    `money-path` label, the `money.md` playbook and a human read. It is not a
    runtime glob: the money-flow harness cannot exercise a CI config change, so a
    green run would prove nothing about it.
  - The tag rule is a script check, not a credential boundary. `packages: write`
    lets any run of the workflow push any tag, so the rule that `dev` never moves
    `pilot` rests on the workflow's structure (the `pilot` push is its own
    `main`-only job, and every job is gated on the upstream repository) and on a
    refusal in the tag computation. A run that skipped the script could still
    push any tag the token permits; what the script buys is that the ordinary
    path cannot compute a wrong tag, and that a test fails if someone widens the
    rule.
  - The Dockerfile does not join either list, following the mcp-server precedent:
    it is build plumbing the harness cannot distinguish a change to. It is pinned
    to the README's run step through `scripts/docs/package-docs.mjs`'s `covers:`
    instead, so a Dockerfile change re-checks the prose that tells a merchant how
    to run it.
  - `publish.yml` is unchanged: its `paths:` names only the five npm packages,
    and widening it would cut `0.0.0-dev.*` snapshots of all five on every kit
    push to `dev`.

  Pinned by tests: `scripts/ci/paywall-proxy-image-tags.test.mjs` refuses
  `pilot` on `dev`, `dev` on `main` and `latest` everywhere, and pins the
  workflow's structure (the `pilot` job is `main`-only, every job carries the
  repository gate, both jobs compute tags through the script) and its place in
  the three perimeter copies. Reverting the refusal turns the test red.
  `packages/paywall-proxy/src/sqlite-store.test.ts` pins the missing-directory
  and not-writable messages.

  Perimeter: `.github/workflows/publish-paywall-proxy-image.yml` added to
  `controlGlobs`. Nothing else moves.
