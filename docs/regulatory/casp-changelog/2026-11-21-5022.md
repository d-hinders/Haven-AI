- **#5022**: the merchant kit's image publishing printed bare tags, so no image
  was ever published. `scripts/ci/paywall-proxy-image-tags.mjs` now prints full
  image references.

  What was wrong:
  - `.github/workflows/publish-paywall-proxy-image.yml` passes the script's
    stdout to `docker/build-push-action` as `tags:`, which reads each line as an
    image reference.
  - The script printed `dev-<short-sha>` and `dev`. The action read those as the
    Docker Hub images `docker.io/library/dev-<short-sha>`, so every run on `dev`
    since #5007 failed on Docker Hub auth and pushed nothing.
  - The `pilot` job had the same defect.

  What changed:
  - The script's CLI prints `ghcr.io/d-hinders/haven-paywall-proxy:<tag>`, one
    per line, the immutable tag first.
  - A new `imageRefs()` adds the registry path to what `imageTags()` returns.
  - The tag rule is unchanged. `assertTagAllowed` and `imageTags` still check
    the bare tag: `dev` and `dev-<short-sha>` on `dev`, `pilot` and
    `pilot-<short-sha>` on `main`, never `latest`, and a refusal exits 1 with
    nothing on stdout.
  - The workflow's `on.push.paths` gains the script, so a change to it
    republishes, as a change to the workflow file already does. Nothing else
    in the workflow changes: same jobs, gates, permissions and push step.

  Why the CASP perimeter is unaffected: this changes which registry the same
  tags go to, from a Docker Hub name the job could not push to, to the GitHub
  registry the workflow already logs in to. No key, signing, funds or authority
  is involved, and what a merchant runs is still the image built from
  `packages/paywall-proxy/src/**`.

  Pinned by tests: `scripts/ci/paywall-proxy-image-tags.test.mjs` now runs the
  real CLI, and pins the script in the workflow's push paths and in the three
  perimeter copies it reads (the JSON, `labeler.yml`, the perimeter reference). It asserts the printed lines for both channels, and that a refused
  ref exits 1 with a `GUARD:` line and no stdout. The earlier test of the same
  name exercised only `parseArgs` and never ran the CLI. It is renamed to say
  so.

  Mutation-tested: with the CLI printing bare tags again, the new test fails.

  Perimeter: `scripts/ci/paywall-proxy-image-tags.mjs` added to `controlGlobs`,
  in all four copies (`.github/money-path-globs.json`, `.github/labeler.yml`,
  the ship-next perimeter reference, and this doc's guardrails `covers:`). The
  #5007 entry said the tag rule lives in the script but did not list it. This
  defect shows that the script alone decides what is pushed. Nothing else moves.
