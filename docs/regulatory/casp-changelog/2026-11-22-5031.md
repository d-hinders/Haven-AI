- **#5031**: the local MCP answers a checkout-details refusal per stage, and
  the SDK's resume refusal names its payment.

  What was wrong: `haven_resume_x402_payment`, refused because a merchant
  requires a checkout detail the agent cannot share, answered with the same
  fixed "…then retry" step as a refusal before payment, and with no `phase`
  and no payment id. The payment is already funded at that point, so "retry"
  could lead an agent to start a new purchase and pay twice. The SDK never put
  the payment id on that refusal.

  What changed:
  - `packages/sdk`: `resumeX402Payment` passes its `paymentId` to
    `checkoutDetailsHeaderFor`, which puts it on the
    `CheckoutDetailsUnavailableError` (an optional field the error already
    had).
  - `packages/mcp`: the local `normalizeError` answers per stage with the
    hosted MCP's `phase` words, and the `funded` step names
    `haven_resume_x402_payment` with the same `resume_state` (not
    `payment_id` alone: a resume by id rebuilds the challenge without the
    merchant's request and would deliver without the field), else
    `haven_get_payment_status` then `haven_sweep_delegate`. The
    before-payment answer is unchanged.

  Why the CASP perimeter is unaffected: guidance text and fields on a
  refusal; nothing is signed, authorised or moved, and the refusal still
  happens before the re-sign.

  Pinned by tests: `packages/mcp/src/checkout-details-refusal.test.ts` drives
  the real SDK resume path over a stubbed wire (phase, payment id, the
  resume step, no merchant call); `packages/sdk/src/x402-checkout-details-flow.test.ts`
  asserts the error's payment id and stage; the hosted package's
  `local-hosted-refusal-parity.test.ts` compares code and `phase` per stage
  and that the local funded reason is not the before-payment one.

  Mutation-tested: the local mapper given the fixed reason again turns the
  local and parity tests red; the resume no longer passing the payment id
  turns the local and SDK tests red.

  Release order: `packages/mcp` pins `@haven_ai/sdk` exactly, so an installed
  local MCP shows the payment id only after an SDK release and the pin bump;
  the local mapper treats it as optional.
