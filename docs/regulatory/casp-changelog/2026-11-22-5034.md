- **#5034**: the merchant kit's discovery document now lists each product's
  route with the deployment's `BASE_PATH` in front of the path, so the route a
  reader stores is the path the handler serves. Before, with `BASE_PATH` set,
  the document listed the products-file spelling (`POST /v1/chat/completions`)
  while the handler served the product only under the base path
  (`POST /api/v1/chat/completions`): every listed route answered 404
  `unknown_route`, and that answer's `discovery_url` pointed back at the same
  document, so an agent that followed it looped.

  What changed:
  - **`packages/paywall-proxy/src/discovery.ts`**: a new `listedRoute(product,
    basePath)` returns `METHOD <basePath><path>`, and `buildDiscoveryDocument`
    emits it as each product's `route`. With no `BASE_PATH` the route is the
    products-file spelling, byte-identical to before. The document's shape,
    version and every other field are unchanged.
  - **`docs/architecture/12-merchant-kit.md`** and
    **`packages/paywall-proxy/README.md`**: the products-file `route` row and
    the document's `products[]` row now say the listed route carries the base
    path, and the `BASE_PATH` setting says the document lists each route with
    it in front. **`packages/paywall-proxy/.env.example`** says the same beside
    `BASE_PATH`.

  Why the perimeter is unaffected:
  - The discovery document is a catalogue. It holds no key, signs nothing,
    submits no transaction and calls no facilitator; answering it verifies
    nothing and settles nothing. The change moves no funds and changes no
    price, receiving address, payment requirement, signing step or key.
  - The listed route is derived from two things the handler already applies:
    the products file's path and the deployment's `BASE_PATH`. It is the same
    path the handler already serves, so the document now names what the proxy
    does rather than a path it refuses. It grants no new authority: a buyer
    still pays the same challenge at the same route.
  - Haven's reader stores the route as the document gives it and never uses it
    as a payment destination (`packages/backend/src/modules/catalog/merchant-products.ts`
    only labels the catalogue; `pay_to` is compared, never paid). The reader
    and outside agents work unchanged.
  - No live listing changes: the demo deployments do not set `BASE_PATH`, and
    with it unset the document is byte-identical to the one already pinned.
