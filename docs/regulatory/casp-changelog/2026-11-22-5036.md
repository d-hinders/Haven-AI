- **#5036**: the Fortnox voucher `Comments` text carried a resource host's port
  and an IPv6 literal's brackets, characters the field refuses (error 2000359).

  What was wrong:
  - `feedDescription` built `Resource ${new URL(tx.resourceUrl).host}.`, and
    `URL.host` keeps a non-default port (`merchant.example.com:8443`) and an
    IPv6 literal's brackets (`[2001:db8::1]`); `URL.hostname` keeps the brackets
    and an underscore in a host name. None of those is in the set the Comments
    field accepts.
  - The host was the one part of the comment that never passed through
    `fortnoxSafeText`. The token symbol did not either.
  - The tests passed with the defect because their "Fortnox-safe" regex
    (`[A-Za-z0-9 ,.:+/@()#&=_-]`) was wider than the declared set.

  What changed:
  - The declared set is one exported constant (`FORTNOX_SAFE_TEXT_CHARS` /
    `FORTNOX_SAFE_TEXT`), and `fortnoxSafeText` derives its strip regex from it.
  - `feedDescription` folds the resource host through `fortnoxSafeText`, and
    drops the part when a host folds to nothing rather than sending a bare
    `Resource .`. A host already inside the set renders byte-identically.
  - The token symbol is folded too: it is `token_symbol` from the payment row,
    and the generated test showed it reaching the comment with `_` in it.
  - The three existing "Fortnox-safe" tests assert the shared constant, and a
    seeded generated-input test varies description, resource URL, token, receipt
    lines, VAT treatment and product sources over 200 cases.

  Why the CASP perimeter is unaffected: this changes characters in a free-text
  field of an unattested supplier invoice. No account, VAT figure, voucher row,
  amount, currency, supplier identity or settlement decision moves, and
  `assertNonAsserting()` still runs on the payload. The invoice remains
  unbooked until a human attests it in Fortnox, so nothing here asserts
  accounting judgment or touches custody, keys, signing or authority.

  Mutation-tested: with `URL.host` passed through unsanitised, the pinned
  port/IPv6/underscore cases and the generated test fail; with the token
  unsanitised, the generated test fails on a `_` in the symbol.

  Perimeter unchanged.
