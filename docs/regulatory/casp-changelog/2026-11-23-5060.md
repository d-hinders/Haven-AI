- **#5060**: four small merchant-kit fixes from the 2026-11-23 cold run, in
  `@haven_ai/merchant-payments` and `@haven_ai/paywall-proxy` (the Coinbase
  secret preflight, the `check` line's failure names, the keyless upstream, and
  the image's revision label).

  What changed:
  - **`packages/merchant-payments/src/cdp.ts`**: `preflightCdpSecret` builds one
    CDP auth header locally, with no network call — the same JWT the facilitator
    client signs for `GET …/supported` — through `@coinbase/x402`'s
    `createAuthHeader`, the builder `createCdpFacilitator` already uses. A
    failure throws `CdpSecretError`, whose message names `CDP_API_KEY_SECRET`
    and never its value. `@coinbase/cdp-sdk` stays a transitive dependency; the
    lockfile does not change.
  - **`packages/paywall-proxy/src/main.ts`**: startup runs the dry run after
    `loadConfig` and before the store is opened or the port is bound. Its
    problem joins the same `ConfigError` refusal message. The `started` line
    gains `upstream_auth: "key" | "none"`.
  - **`packages/paywall-proxy/src/check.ts`**: the `coinbase key` line runs the
    dry run before `getSupported`, so a secret that cannot sign prints
    `CDP_API_KEY_SECRET cannot sign a request (not a usable Ed25519 or EC key)`
    instead of `did not answer (Error)`. The 401/403 and other-status mappings
    are unchanged, and only a real transport failure keeps `did not answer`. The
    `UserInputValidationError` branch folds into the same "cannot sign" line.
  - **`packages/paywall-proxy/src/config.ts`, `forward.ts`**: `UPSTREAM_AUTH`
    accepts only `none`. With it, `UPSTREAM_API_KEY` is not required, setting it
    (or `UPSTREAM_AUTH_HEADER` / `UPSTREAM_AUTH_SCHEME`) is refused, and the
    proxy sends no upstream auth header. Unset, today's rule stands.
  - **`.github/workflows/publish-paywall-proxy-image.yml`**: both build-push
    steps pass `org.opencontainers.image.revision=${{ github.sha }}`, which
    merges with the Dockerfile's `LABEL`s (verified with a local `docker build
    --label` + `docker inspect`: all labels present). `scripts/ci/paywall-proxy-image-tags.test.mjs`
    asserts the line on both steps.
  - **Copy**: `packages/paywall-proxy/README.md` (Quickstart step 2's "what you
    should see", the settings table, the Coinbase-key paragraph, the `check`
    table's `coinbase key` row, the `started` line's fields, the `UPSTREAM_AUTH`
    row in *All settings*, and how to read the revision label with
    `docker inspect`), `packages/paywall-proxy/.env.example`, and
    `docs/architecture/12-merchant-kit.md` §7 and §12.

  Why the perimeter is unaffected:
  - **Nothing changes about what settles or who is paid.** The dry run signs a
    JWT and discards it; it sends no request, calls no facilitator, reads no
    chain and writes no store. `check` still makes no call that can move money
    (no verify, no settle, no sale record), and the tests inject a `fetch` stub
    that fails if it is called.
  - **The refusal is a startup gate, not a new authority.** A deployment with a
    placeholder or junk `CDP_API_KEY_SECRET` stops starting on its next image
    pull. That is intended: today it starts and then fails every payment at
    signing time, after the buyer has paid. The refusal names the variable and
    never prints its value; `ConfigError` still never echoes a secret.
  - **`UPSTREAM_AUTH=none` narrows what the proxy sends.** It removes an auth
    header rather than adding one, and the buyer's own `Authorization` is still
    stripped. The explicit opt-out keeps a forgotten key a startup refusal
    instead of an upstream 401 after settlement.
  - **The revision label is metadata.** It changes no runtime behaviour and no
    tag rule; `dev-<short-sha>` and `pilot-<short-sha>` are unchanged.
  - Money-path list: `packages/paywall-proxy/src/**` and the image workflow stay
    control globs, and `packages/merchant-payments/src/**` stays a runtime glob,
    by the owner decisions recorded on #4893 and #5007.

  Pinned by tests: `merchant-payments/src/cdp.test.ts` (a generated Ed25519 pair
  is accepted; the `.env.example` placeholder and 64 random bytes are refused
  with `CdpSecretError`; a `fetch` stub is never called), `config.test.ts`
  (startup refuses the placeholder and random bytes with a `ConfigError` naming
  `CDP_API_KEY_SECRET` and not the value; `UPSTREAM_AUTH=none` starts without a
  key and refuses the three key settings; any other value is refused; unset
  keeps `UPSTREAM_API_KEY is required`), `check.test.ts` (the cold run's input
  prints "cannot sign" with no network call; a 401 still prints `refused the key
  (401)`; a `TypeError: fetch failed` prints `did not answer`), `proxy.test.ts`
  (`UPSTREAM_AUTH=none` sends no auth header, strips the buyer's, and the
  `started` line says `none`), and
  `scripts/ci/paywall-proxy-image-tags.test.mjs` (both build-push steps carry
  the revision label). Prove-red: the new assertions fail against `origin/dev`
  and pass with the change.

  Perimeter unchanged.
