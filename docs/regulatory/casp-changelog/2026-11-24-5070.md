- **#5070**: the demo merchant refuses, at startup, a `MERCHANT_ADDRESS` that is
  not an address. Before this change it checked only that the variable was set,
  then cast it to `Address`. Any non-empty string started a merchant that
  advertised that string as the 402 `payTo` of every product without its own
  receiving address, and in `/healthz` and the discovery document. The
  merchant could therefore not be paid.

  What changed:
  - **`packages/demo-merchant-mcp/src/merchant-address.ts`** has a new
    `resolveMerchantAddress(raw)`. It applies these rules:
    - **Missing, empty or whitespace-only.** Refused, with the message the
      startup check already printed. Surrounding whitespace is trimmed first.
    - **Not an address under viem's strict `isAddress`.** Refused, naming the
      variable. This covers a malformed value, a wrong EIP-55 checksum, and an
      all-uppercase value.
    - **All lowercase.** Accepted, and normalised with `getAddress` to the
      checksummed form.
  - **`packages/demo-merchant-mcp/src/index.ts`** calls the new function in
    place of the presence check, and exits 1 with its message.
  - **`packages/demo-merchant-mcp/README.md`** states the rule.

  Why the perimeter is unaffected:
  - **Nothing new can start.** The change only refuses startup for values
    that could never be paid. It does not touch the key, the settlement path,
    prices or verification.
  - **A valid address behaves as before.** A checksummed value is used
    unchanged.
  - **Normalising an all-lowercase value cannot redirect funds.** It changes
    only letter case. Every downstream comparison of a recipient address is
    case-insensitive: `payment-checks.ts` compares `getAddress(...)`
    lowercased, `sales.ts` compares lowercased, and the authorization digest
    lowercases `to`. So the money still goes to the same account.
  - **One operator note.** A deployment whose `MERCHANT_ADDRESS` is mixed-case
    with a wrong checksum now refuses to start. Such a value was a mistyped
    address, quoted as `payTo` to every buyer.

  Tests:
  - `merchant-address.test.ts` covers:
    - missing, empty and whitespace values;
    - malformed values;
    - a wrong checksum and all-uppercase;
    - a checksummed value unchanged;
    - an all-lowercase value normalised.

    Disabling the address check turns two of its tests red (mutation run).
  - The package's 25 test files (491 tests) pass, and `tsc --noEmit` is clean.

  Perimeter unchanged.
