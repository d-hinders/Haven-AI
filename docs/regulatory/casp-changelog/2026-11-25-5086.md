- **#5086** — A hosted MCP payment whose merchant names `mcp://tool/<name>`
  as its x402 resource address (the public `@x402/mcp` form) is payable on the
  EIP-3009 bridge. Owner decision (a1) of 2026-11-25, "Check against the
  stored server address".
  - **What changes:** where a funded payment's signed header may be
    delivered. Delivery is checked against the MCP endpoint Haven itself
    called and stored with the payment's call context, instead of the
    payment's stored address. An explicit `merchant_url` is compared with the
    endpoint read from Haven's own record — never with itself — and a
    different one is refused before funding (settle) or before delivery
    (complete). A failed read refuses. #5084's pay-time refusal is removed,
    since such a challenge is now payable.
  - **What does not change:** the stored address (the merchant's declared
    value — the payment's identity, what the signer binds and what the
    evidence report carries), the signer and its binding, amounts, recipients,
    budgets, expiry, replay matching, custody and authority. Amount, recipient
    and expiry stay enforced on-chain. No backend change, no migration.
  - **Residual:** a payment with no stored call context (`haven_pay_x402_quote`
    with an MCP challenge), funded through `haven_submit` and completed with a
    different explicit `merchant_url`, is refused after funding but before
    delivery, as before. Stated in
    `docs/architecture/04-x402-payment-sequence.md`.

  Perimeter unchanged.
