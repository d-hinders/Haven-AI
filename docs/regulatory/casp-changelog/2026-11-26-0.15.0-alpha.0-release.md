  **What the release carries into published packages, by effect on authority:**
  - **#5089 (#5099): `quoteMcpX402` and `completeX402MerchantCall` accept a stateless MCP server.** A streamable-HTTP server that answers `initialize` with this request's JSON-RPC result but no `Mcp-Session-Id` is no longer refused; later MCP requests carry `Accept: application/json, text/event-stream`. Any other session-less answer is refused as before. It changes which merchant endpoints the buyer will talk to, not what is signed or how much is paid; its own record is `2026-11-26-5089.md`.
  - **#4872 (#4979, #4992, #4994), epic #4868: checkout details on the paid x402 request.** When a merchant's challenge asks under `extensions["haven-checkout-details"]`, the SDK reads the agent's own saved details (`GET /agents/:id/checkout-details`) and attaches only the fields asked for as `X-Checkout-Details`, unsigned, to the seller only, within a 1,536-byte budget and the 16 KB header block. A required field the agent cannot share throws `CHECKOUT_DETAILS_UNAVAILABLE` **before** `authorizeX402`, so no payment is created; on resume it is decided before the re-sign. This shares owner data with a merchant; it moves no money and changes no signed byte. Sharing is off unless the owner turns it on per agent (migration 135).
  - **#5031 (#5057): a checkout-details refusal on a funded payment says to resume that payment**, carrying `paymentId` and `phase`, so an agent does not start a second purchase and pay twice.
  - **#5030 (#5053): the local MCP fails closed on a failed stored-challenge read** and counts the caller's headers toward the block budget.
  - **#5086 (#5092): `completeX402MerchantCall` can bind delivery to a stored MCP endpoint** (`approvedEndpoint`), so an `mcp://tool/<name>` resource address is payable. The comparison is still string for string against a value Haven stored; omitted, it is unchanged.
  - **#4829 (#4837): the signer reports a 5xx, a 429 or a non-JSON body on the sign-context fetch as `SIGN_CONTEXT_UNREACHABLE`**, not `SIGN_CONTEXT_REFUSED`. The x402 and direct flows offer the existing `typed_data_b64` relay. Every refusal code is unchanged.
  - **#4825 (#4842): a `--local` install refuses task budgets** with `TASK_BUDGET_SIGNING_UNAVAILABLE` before contacting anything, instead of pointing at a signer tool that install does not have. This narrows what a local runtime offers.
  - **#4830 (#4834): `haven_quote_x402` never skips a stated `expected_amount` silently**; when the comparison cannot be made it says so and returns `safe_to_continue: false`.
  - **#4808 (#4814): the SDK's tool definitions name only callable tools, and `haven_sweep_delegate` runs** — `sweepDelegate()` reads nothing from the model's input, so no amount, asset or destination is chosen by the model.
  - **#4896 (#4936): the connector redacts and the CLI refuses the `sk_merchant_…` Sales key.**
  - **#5035 (#5054), #4826 (#4846):** touch package files for typed results on the sweep and on a submitted x402 replay; the behaviour change is in the backend.
