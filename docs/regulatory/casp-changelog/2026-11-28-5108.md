- **#5108**: three merchant-kit fixes from the first paid inference run, in
  `@haven_ai/paywall-proxy` (an `empty_answer` log event, an `upstream` line in
  `check`, and the README's Railway and reasoning-model notes).

  What changed:
  - **`packages/paywall-proxy/src/handler.ts`**: after a delivered chat
    completion, `logEmptyAnswer` logs `empty_answer` when the first choice has
    `finish_reason: "length"` and empty or absent `message.content`, with `key`,
    `product_id`, `completion_tokens` and `reasoning_tokens` when the upstream
    reports them. It never logs the content. A choice whose `content` is null but
    whose `tool_calls` is non-empty is an answer, not an empty one. A product
    with no cap logs nothing, because the proxy did not truncate that call. A
    streamed (SSE) answer is not JSON, so it logs nothing. The function cannot
    throw: an unparseable body still delivers, as `logOverage` already did.
  - **`packages/paywall-proxy/src/config.ts`**: `UPSTREAM_CHECK_PATH` is a new
    optional setting, read into `config.upstream.checkPath`. It is a path, not a
    URL: it must start with `/` and carry no spaces, query string or fragment,
    because it is joined onto `UPSTREAM_BASE_URL` the way a paid call's path is.
    A malformed value refuses startup with a `ConfigError` naming the variable.
  - **`packages/paywall-proxy/src/check.ts`**: a new `upstream` line, fourth in
    `CHECK_NAMES`. It sends one authenticated `GET` to the configured path, with
    the header `buildUpstreamHeaders` builds for a paid call, and classifies the
    status with `classifyUpstreamStatus` — the live path's own rule — so the
    check and the live path cannot disagree. `401`/`402`/`403`/`407` fail naming
    a refused key (with `UPSTREAM_AUTH=none`, a refused call without a key);
    `408`/`429`/`5xx` fail with the status; any other non-2xx, such as a `404`,
    fails naming the path; an unreachable upstream fails naming the host only.
    The response body is never read, so it can never be printed, and a `GET`
    buys no inference call. `skipped` when the path is unset.
  - **Copy**: `packages/paywall-proxy/README.md` (the `upstream` row in the
    `check` table and its example output, the `UPSTREAM_CHECK_PATH` row in *All
    settings*, the `empty_answer` bullet under *You monitor*, the
    reasoning-model caveat, and the `railway up` linking note in the Railway
    recipe's step 1), `packages/paywall-proxy/.env.example`, and
    `docs/architecture/12-merchant-kit.md` §7, §12 and the monitor list.

  Why the perimeter is unaffected:
  - **Nothing changes about what settles or who is paid.** The new event is a
    log line written after `markDelivered`, and it reads only the upstream's own
    response body. It changes no status, no body, no header and no store write.
    The `upstream` line is a read-only `GET` that runs with the proxy stopped,
    like every other `check` line: no verify, no settle, no sale record, and no
    inference call bought.
  - **The new setting narrows nothing and grants nothing.** It names a path the
    pre-flight check calls; the proxy's forwarding path never reads it. A
    malformed value refuses startup, which is the kit's existing rule for an
    optional setting that cannot be used as written.
  - **The check cannot leak the key or the upstream's answer.** The request
    carries the same header a paid call carries, and the response body is never
    read. The line is built from a status code and the host only, as the `rpc`
    line already is.
  - Money-path list: `packages/paywall-proxy/src/**` stays a control glob, by the
    owner decisions recorded on #4893 and #5007.

  Pinned by tests: `proxy.test.ts` (a capped reasoning answer with empty content
  logs `empty_answer` with both token counts; a capped answer with content, a
  `stop` answer, a product with no cap, an unparseable body and an SSE body log
  nothing new; `content: null` with tool calls is an answer and without them is
  empty; `overage` is covered beside it), `check.test.ts` (the all-ok fixture
  sets the path and every `CHECK_NAMES` line is `ok`; `ok` against a 200 stub
  with the key on a `GET` to the joined path; `fail` on 401, 402, 503 and 404;
  `skipped` when the path is unset; `UPSTREAM_AUTH=none` sends no key and reads
  an `auth_refused` status as a refused call without a key; a distinctive key
  and body appear nowhere in the output), and `config.test.ts` (the setting is
  optional, and a value that is not a path is refused). Prove-red: the new
  assertions fail against `origin/dev` and pass with the change.

  Perimeter unchanged.
